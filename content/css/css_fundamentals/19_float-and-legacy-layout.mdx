## 왜 이 편이 필요한가

지금 CSS를 처음 배우는 사람은 `float`(플로트, 띄우기)를 레이아웃(전체 화면 구조를 짜는 일)에 쓸 일이 사실상 없습니다. 그런데도 이 편을 두는 이유가 있습니다. 첫째, 오래된 코드베이스·튜토리얼·면접 질문에는 여전히 float 기반 레이아웃이 등장합니다. 둘째, `float`를 이해해야 17편의 BFC가 "왜" 필요했는지, Flexbox·Grid가 "왜" 그렇게 설계됐는지가 온전히 이해됩니다. `float`의 한계를 모르면 최신 레이아웃 도구의 고마움도 반쪽만 이해하게 됩니다.

> **쉽게 말하면:** float는 원래 신문 편집에서 쓰던 "그림을 한쪽에 놓고 글자가 그 주위를 흘러가게 하는" 도구였습니다. 이걸 억지로 늘려 빌딩 전체(레이아웃)를 짓다 보니 여기저기서 무너진 것입니다.

## float 본연의 목적 — 텍스트 감싸기

`float`의 원래이자 지금도 유효한 용도는 이미지 옆으로 글이 흐르게(wrap) 하는 것입니다.

```html
<figure class="side-image">
  <img src="photo.jpg" alt="설명" />
</figure>
<p>
  이 문단은 왼쪽에 띄워진 이미지를 감싸며 흐릅니다. float된 요소는 정상 흐름에서
  빠져나가지만, 뒤따르는 인라인 콘텐츠(텍스트)는 그 주위를 피해서 배치됩니다.
</p>
```

```css
.side-image {
  float: left;
  width: 160px;
  margin: 0 16px 8px 0;
}
```

`float: left`(왼쪽으로 띄움) 또는 `float: right`(오른쪽으로 띄움)를 받은 요소는 정상 흐름에서 빠져나와 지정한 방향의 벽에 붙습니다. 그리고 **뒤에 오는 인라인 콘텐츠(텍스트, 인라인 요소)만** 그 주위를 감싸며 흐릅니다. 이 "감싸기"가 오늘날까지도 유효한, 대체 불가능한 float의 역할입니다. 잡지·신문 스타일의 본문에서 사진 옆에 글이 흐르는 효과는 지금도 `float`로 만듭니다.

## float가 레이아웃 도구로 오용된 배경

Flexbox·Grid가 없던 시절, 개발자들은 "옆으로 나란히 놓기"라는 float의 부수 효과를 이용해 여러 칸짜리 레이아웃(2단, 3단 구성)을 만들었습니다.

```css
.column {
  float: left;
  width: 33.33%;
}
```

세 개의 `.column`에 이 규칙을 걸면 세 칸이 나란히 배치됩니다. 문제는 이것이 float의 **설계 목적이 아니라 부수 효과를 억지로 끌어다 쓴 것**이라는 점입니다. 그 대가로 두 가지 고질적인 문제가 따라왔습니다.

## 문제 1 — 부모(컨테이너) 높이 붕괴

앞선 17편(BFC)에서 이미 확인한 현상입니다. float 자식만 담은 부모는, 자기가 새로운 BFC가 아닌 이상 float 자식의 높이를 계산에 포함하지 않습니다. 그 결과 부모의 배경색·테두리가 자식들의 실제 높이를 무시하고 찌그러집니다.

```mermaid
graph TD
  P["부모 .row (일반 요소, BFC 아님)"] --> C1["칸 1 (float: left)"]
  P --> C2["칸 2 (float: left)"]
  P --> C3["칸 3 (float: left)"]
  P -."float 자식 높이를 무시.-> H["부모 높이 = 0에 수렴"]
```

## 문제 2 — 뒤따르는 요소가 float 옆으로 파고든다

float 다음에 오는 일반 블록 요소는 float가 차지한 공간을 피하지 않고, float 옆의 남은 공간으로 파고들어 배치가 뒤엉킵니다. 이걸 막으려면 `clear`(정리) 속성으로 "이 요소는 float 옆에 붙지 말고 float가 끝난 아래로 내려가라"고 지정해야 했습니다.

```css
.footer {
  clear: both; /* 좌우 float 모두를 피해 아래로 내려간다 */
}
```

## clearfix — 두 문제를 한 번에 봉합하는 기법

**clearfix**(클리어픽스)는 부모 요소 끝에 보이지 않는 가상 요소를 만들어 `clear`를 걸어 주는 기법입니다. 17편에서 배운 "BFC는 내부 float를 포함해서 높이를 계산한다"는 원리와도 연결됩니다.

```css
.clearfix::after {
  content: '';
  display: block;
  clear: both;
}
```

`::after`(가장 마지막 자식 뒤에 가상의 콘텐츠를 만드는 의사 요소, 07편)로 보이지 않는 블록 요소를 하나 만들고, 거기에 `clear: both`를 걸어 두 float를 모두 피해 아래로 내려가게 만듭니다. 그러면 이 가상 요소의 위치가 곧 "float가 모두 끝난 지점"이 되고, 부모는 이 가상 요소까지 포함해서 높이를 계산하므로 결과적으로 높이가 정상으로 돌아옵니다.

`.clearfix::after` 규칙을 지우고 다시 실행해 보면 노란 배경이 사라지듯 찌그러지는 것을 볼 수 있습니다. 이것이 2010년대 CSS 코드에서 `.clearfix` 클래스가 거의 모든 레이아웃 컨테이너에 습관처럼 붙어 있던 이유입니다.

## float 레이아웃이 가진 근본적 한계

clearfix는 float의 부수 효과가 만든 문제를 봉합할 뿐, float 자체를 레이아웃에 적합한 도구로 바꿔주지는 않습니다. 근본적인 한계는 다음과 같습니다.

| 한계 | 설명 |
|------|------|
| 세로 정렬 불가 | float는 가로 배치만 다루며, 칸 높이가 다를 때 세로 중앙 정렬 같은 것을 표현할 방법이 없다 |
| 순서 재배치 불가 | 시각적 순서를 DOM 순서와 다르게 바꾸는 기능이 없다(Flexbox의 `order`에 해당하는 것이 없다) |
| 간격(gap) 계산이 수동 | 칸 사이 여백을 `margin`으로 일일이 계산해야 하고, 퍼센트 폭과 마진이 섞이면 반올림 오차로 줄바꿈이 깨지기도 한다 |
| 2차원 배치 불가 | 행과 열을 동시에 다루는 격자(grid) 개념 자체가 없다 |
| 매번 clearfix 필요 | 컨테이너를 만들 때마다 높이 붕괴를 막는 처리를 잊지 않아야 한다 |

## Flexbox·Grid가 등장한 이유

이 표의 한계들이 정확히 20편(Flexbox)·23편(Grid)에서 배울 기능들이 해결하는 지점입니다. Flexbox는 "정렬"이라는 것 자체를 1차원 축 개념으로 정의해 세로 정렬·순서 변경·간격을 속성 하나로 처리하고, Grid는 행과 열을 모두 가진 진짜 2차원 격자를 언어 차원에서 지원합니다. 두 도구 모두 **"레이아웃을 짜는 것"을 목적으로 처음부터 설계**되었다는 점이 float와 근본적으로 다릅니다. float는 텍스트 감싸기라는 원래 목적에 맞게 지금도 쓰이지만, 여러 칸을 나란히 배치하는 용도로는 은퇴했다고 봐도 됩니다.

## 접근성 관점

float로 만든 레이아웃은 시각적 순서를 바꾸는 수단이 마땅치 않기 때문에, 대체로 DOM 순서와 화면에 보이는 순서가 일치했습니다. 이는 스크린 리더 사용자 입장에서는 오히려 안전한 특성이었습니다. Flexbox의 `order`나 Grid의 배치 속성으로 시각적 순서를 자유롭게 바꿀 수 있게 된 지금은, 화면에 보이는 순서와 스크린 리더가 읽는 DOM 순서가 어긋나지 않도록 더 신경 써야 합니다. 이 내용은 22편(Flexbox 실전 패턴)에서 다시 다룹니다.

## 자주 틀리는 점

- **`float`가 완전히 폐기된 기능이라고 오해하는 것.** 여러 칸 레이아웃 용도로는 은퇴했지만, 이미지 옆 텍스트 감싸기라는 원래 목적으로는 지금도 유효하고 대체품이 마땅치 않습니다.
- **`clear: both`를 float 요소 자신에게 거는 것.** `clear`는 float가 걸린 요소가 아니라 **float 다음에 오는, float를 피해야 할 요소**에 거는 속성입니다.
- **clearfix가 float 문제를 "해결"한다고 생각하는 것.** clearfix는 float가 만든 높이 붕괴를 우회하는 봉합책일 뿐, float 자체를 레이아웃에 적합하게 만들지는 못합니다. 지금 새로 레이아웃을 짠다면 애초에 Flexbox나 Grid를 쓰는 것이 정답입니다.

## 핵심 정리

- `float`의 원래이자 여전히 유효한 목적은 이미지 옆으로 텍스트가 흐르게 감싸는 것이다.
- float 자식만 있는 부모는(새 BFC가 아닌 이상) 자식 높이를 계산에서 제외해 컨테이너가 붕괴한다.
- clearfix는 `::after` 가상 요소에 `clear: both`를 걸어 부모가 float 높이까지 포함하게 만드는 봉합 기법이다.
- float 레이아웃은 세로 정렬·순서 변경·간격 계산·2차원 배치가 근본적으로 어려워 Flexbox·Grid로 대체되었다.
