  **이번 문서의 목표:** 이 문서를 다 읽으면 `transition`으로 버튼 hover 같은 상태 변화를 부드럽게 만들고, `transform`으로 요소를 이동·확대·회전시킬 수 있으며, 왜 이 두 기능이 다른 속성 애니메이션보다 화면이 매끄러운지 개요 수준에서 설명할 수 있게 됩니다.
</Callout>

## 왜 필요한가

11편에서 배운 박스 모델과 18편의 `position` 값을 조합하면 요소를 원하는 위치에 배치할 수 있습니다. 하지만 지금까지 배운 방법으로는 값이 **순간적으로 뚝** 바뀝니다. 마우스를 버튼에 올렸을 때 배경색이 즉시 바뀌거나, 메뉴가 열릴 때 갑자기 나타나는 식입니다. 실무에서는 이런 변화가 사용자 눈에 **부드럽게 흘러가듯** 보이길 원하는 경우가 많습니다. 이 요구에 답하는 것이 **전환**(transition)입니다.

또한 지금까지의 방법으로 요소를 옮기려면 `top`·`left`나 `margin` 같은 속성을 바꿔야 했는데, 이 방식은 뒤에서 다룰 문제(리플로우 비용)를 안고 있습니다. 요소의 위치·크기·회전을 흐름에 영향을 주지 않으면서 바꾸는 별도의 도구가 **변형**(transform)입니다.

> **쉽게 말하면:** transition은 "값이 바뀔 때 그 사이 과정을 부드럽게 채워라"는 지시이고, transform은 "요소를 원래 자리는 그대로 둔 채 시각적으로만 옮기거나 늘리거나 돌려라"는 지시입니다.

## transition — 상태 변화 사이를 채우기

`transition`은 CSS 속성 값이 A에서 B로 바뀔 때, 그 중간 과정을 자동으로 계산해 보여줍니다. 대상 속성, 지속 시간, 이징 함수, 지연 시간 네 가지를 지정합니다.

```css
.button {
  background-color: #6366f1;
  transition: background-color 0.3s ease-in-out;
}

.button:hover {
  background-color: #4338ca; /* hover 상태가 되는 순간, 색이 0.3초에 걸쳐 서서히 바뀐다 */
}
```

`transition` 축약형(shorthand, 여러 속성을 한 줄로 묶어 쓰는 표기법)에 들어가는 값의 의미는 다음과 같습니다.

| 값 위치 | 이름 | 의미 |
|---------|------|------|
| `background-color` | transition-property | 어떤 속성의 변화에 전환을 적용할지 |
| `0.3s` | transition-duration | 전환이 완료되기까지 걸리는 시간 |
| `ease-in-out` | transition-timing-function | 시간에 따라 속도가 변하는 곡선(이징 함수) |
| (생략 가능) | transition-delay | 전환을 시작하기 전 대기 시간 |

**이징 함수**(timing function, 타이밍 함수)는 "시간이 지나는 속도와 값이 변하는 속도가 항상 같지는 않다"는 감각을 표현합니다.

| 값 | 동작 |
|----|------|
| `linear` | 처음부터 끝까지 일정한 속도 |
| `ease` (초기값) | 처음엔 서서히, 중간에 빠르게, 끝날 때 다시 서서히 |
| `ease-in` | 처음엔 느리게 시작해 점점 빨라짐 |
| `ease-out` | 처음엔 빠르게 시작해 점점 느려짐 |
| `ease-in-out` | 시작과 끝 모두 느리고 중간이 가장 빠름 |

<Callout type="warning">
  **자주 틀리는 점:** `transition`을 걸어두기만 하면 요소가 스스로 움직인다고 착각하는 것입니다. `transition`은 "값이 바뀌는 과정을 부드럽게 만드는 지시"일 뿐이며, 실제로 값을 바꾸는 다른 계기(`:hover`, 자바스크립트로 클래스 추가 등)가 반드시 함께 있어야 합니다.
</Callout>

## transform — 흐름을 건드리지 않고 옮기고 늘리고 돌리기

`transform`(변형)은 요소의 모양이나 위치를 시각적으로 바꾸는 함수들을 값으로 받습니다. 대표적인 세 함수는 다음과 같습니다.

| 함수 | 역할 | 예시 |
|------|------|------|
| `translate()` | 이동 | `translate(20px, 10px)` — 오른쪽으로 20px, 아래로 10px 이동 |
| `scale()` | 확대·축소 | `scale(1.2)` — 원래 크기의 1.2배 |
| `rotate()` | 회전 | `rotate(15deg)` — 시계 방향으로 15도 회전 |

```css
.card {
  transition: transform 0.2s ease-out;
}

.card:hover {
  transform: scale(1.05) translateY(-4px); /* 살짝 커지면서 위로 살짝 뜨는 효과 */
}
```

`transform`으로 요소를 옮기면, 그 요소는 **원래 차지하던 자리를 그대로 유지**한 채 시각적으로만 이동합니다. 이는 18편에서 다룬 `position: relative`의 `top`/`left` 이동과 비슷한 성질이지만, `transform`은 뒤에 설명할 성능상 이유로 애니메이션에 훨씬 더 널리 쓰입니다.

## transform이 리플로우 없이 동작하는 이유 (개요)

`top`이나 `margin`, `width` 같은 속성을 바꾸면 브라우저는 주변 요소들의 위치까지 다시 계산해야 하는 **레이아웃**(layout, `javascript/web_apis` 03편에서 다루는 리플로우 단계) 작업을 다시 수행합니다. 요소가 많은 페이지에서 이 재계산이 자주 일어나면 화면이 버벅입니다.

반면 `transform`과 `opacity`(불투명도)는 레이아웃 단계를 건드리지 않고, 그리기가 끝난 화면 조각을 **컴포지터**(compositor, 화면을 합성하는 별도 단계)가 이동·확대·회전·투명도만 바꿔 다시 합성하는 방식으로 처리될 수 있습니다. 그래서 같은 "요소를 옮긴다"는 결과라도 `transform: translateX(20px)`이 `left: 20px`보다 일반적으로 더 매끄럽습니다. 이 렌더링 파이프라인(파싱→스타일 계산→레이아웃→페인트→컴포지트)의 세부 동작은 `javascript/web_apis` 03편을 참조하세요. 여기서는 "왜 애니메이션에 `transform`을 우선 고려하는지"에 대한 실무적 이유만 기억하면 충분합니다.

<Callout type="warning">
  **자주 틀리는 점:** "`transform`을 쓰면 항상 빠르다"고 무조건 단정하는 것입니다. 브라우저 최적화 여부는 요소의 다른 속성, 페이지 복잡도, 브라우저 구현에 따라 달라질 수 있습니다. 다만 `top`/`left`/`width`/`margin` 같은 레이아웃에 영향을 주는 속성보다 `transform`·`opacity`가 애니메이션에 유리한 경향이 있다는 정도로 이해하는 것이 정확합니다.
</Callout>

## 실전 예 — 버튼 hover 전환

11편(박스 모델)과 18편(position)에서 만든 버튼에 전환을 더하면 다음과 같은 조합이 흔합니다.

```css
.btn {
  padding: 10px 20px;
  background-color: #6366f1;
  color: white;
  border: none;
  border-radius: 6px;
  transition: background-color 0.2s ease, transform 0.2s ease;
}

.btn:hover {
  background-color: #4f46e5;
  transform: translateY(-2px); /* 살짝 떠오르는 느낌 */
}

.btn:active {
  transform: translateY(0); /* 눌렀을 때 원래 자리로 */
}
```

두 개 이상의 속성에 전환을 걸 때는 쉼표(`,`)로 나열합니다. 각 속성마다 지속 시간과 이징 함수를 다르게 줄 수도 있습니다.

## 접근성 관점

전환·변형 효과는 시각적으로는 매력적이지만, 일부 사용자는 움직임이 어지럼증이나 메스꺼움을 유발하는 **전정 장애**(vestibular disorder)를 겪습니다. 운영체제 수준에서 "동작 줄이기"를 켜둔 사용자를 위해, 실무에서는 `prefers-reduced-motion` 같은 미디어 특성(media feature)으로 애니메이션을 최소화하는 처리를 하는 경우가 많습니다. 이 속성 자체는 `@media` 문법을 확장한 최신 기능이라 이 과목의 범위(26편에서 다룬 `min-width`/`max-width` 전통 문법) 밖이지만, "움직임에는 대가가 따르는 사용자가 있다"는 감각만은 이 편에서 함께 기억해 둘 필요가 있습니다.

## 자주 틀리는 점

- **`transition`만 걸어두고 상태 변화 계기(`:hover`, 클래스 토글 등)를 빼먹는 것.** `transition`은 값이 바뀌는 과정을 부드럽게 만들 뿐, 값을 스스로 바꾸지 않습니다.
- **`transform`으로 옮긴 요소가 실제로 자리를 옮겼다고 착각하는 것.** `transform`은 시각적 이동일 뿐, 문서 흐름에서 차지하는 원래 자리는 그대로 유지됩니다.
- **`all`로 모든 속성에 전환을 거는 것.** `transition: all 0.3s;`는 편리해 보이지만 의도치 않은 속성까지 전환되어 버벅임의 원인이 될 수 있으므로, 실제로 바뀌는 속성만 명시하는 편이 안전합니다.

## 핵심 정리

- `transition`은 지정한 속성의 값이 바뀔 때 그 과정을 지속 시간·이징 함수에 따라 부드럽게 채운다. 값을 실제로 바꾸는 계기는 별도로 필요하다.
- `transform`의 `translate()`·`scale()`·`rotate()`로 요소를 흐름 속 원래 자리는 유지한 채 이동·확대·회전시킬 수 있다.
- `transform`과 `opacity`는 레이아웃 재계산 없이 컴포지터 단계에서 처리될 수 있어, 애니메이션에 일반적으로 더 유리하다.
- 움직임에 민감한 사용자를 위해 애니메이션을 과용하지 않고, 최소화 옵션을 고려하는 습관이 필요하다.
