## 왜 필요한가

27편의 `transition`은 **시작 값과 끝 값, 딱 두 지점** 사이만 부드럽게 이어줍니다. 그런데 로딩 스피너가 계속 빙글빙글 도는 것처럼 "끝없이 반복되는 움직임"이나, "0퍼센트 지점에서 살짝 커졌다가 50퍼센트 지점에서 작아졌다가 100퍼센트 지점에서 원래대로" 같은 **여러 단계를 거치는 움직임**은 `transition`만으로 표현할 수 없습니다. `transition`은 상태 변화가 있어야만 시작되기 때문입니다.

이 문제를 풀기 위해 CSS는 별도의 도구를 제공합니다. 움직임의 각 단계를 미리 정의해 두는 `@keyframes`(키프레임, 핵심 장면들)와, 그 정의된 움직임을 요소에 적용해 재생하는 `animation`(애니메이션) 속성군입니다.

> **쉽게 말하면:** `@keyframes`는 영화의 콘티(각 장면의 그림)를 그리는 작업이고, `animation`은 그 콘티를 "몇 초짜리로, 몇 번 반복해서, 어떤 순서로 재생할지" 정하는 영사기 설정입니다.

## @keyframes — 움직임의 중간 단계 정의하기

`@keyframes`는 애니메이션의 **이름**을 짓고, 그 안에 진행률(0퍼센트부터 100퍼센트까지)에 따라 어떤 스타일이어야 하는지를 나열합니다.

```css
@keyframes pulse {
  0% {
    transform: scale(1);
    opacity: 1;
  }
  50% {
    transform: scale(1.1);
    opacity: 0.8;
  }
  100% {
    transform: scale(1);
    opacity: 1;
  }
}
```

- `0%`는 `from`으로, `100%`는 `to`로 바꿔 쓸 수 있습니다. 시작과 끝만 있는 단순한 애니메이션이라면 `from`/`to`가 더 읽기 쉽습니다.
- 중간에 원하는 만큼 퍼센트 지점을 추가할 수 있습니다(`0%`, `30%`, `70%`, `100%`처럼).

이렇게 정의한 `@keyframes`는 그 자체로는 아무 요소에도 적용되지 않습니다. **이름표를 만들어 둔 것**일 뿐이며, 실제로 사용하려면 `animation-name`(또는 축약형 `animation`)으로 요소에 연결해야 합니다.

## animation 속성군 — 재생 방식 제어하기

```css
.spinner {
  width: 32px;
  height: 32px;
  border: 4px solid #c7d2fe;
  border-top-color: #6366f1;
  border-radius: 50%;
  animation: spin 1s linear infinite;
}

@keyframes spin {
  from {
    transform: rotate(0deg);
  }
  to {
    transform: rotate(360deg);
  }
}
```

`animation` 축약형에 들어가는 값들의 의미는 다음과 같습니다.

| 값 위치(예시) | 개별 속성 | 의미 |
|----------------|-----------|------|
| `spin` | animation-name | 적용할 `@keyframes`의 이름 |
| `1s` | animation-duration | 한 바퀴(0퍼센트에서 100퍼센트까지) 재생 시간 |
| `linear` | animation-timing-function | 이징 함수 — 27편의 transition과 같은 종류의 값 |
| `infinite` | animation-iteration-count | 반복 횟수. 숫자를 쓰거나 `infinite`(무한)로 끝없이 반복 |

축약형에 자주 함께 쓰이는 개별 속성이 두 가지 더 있습니다.

| 속성 | 값 | 의미 |
|------|-----|------|
| `animation-direction` | `normal` (초기값) / `reverse` / `alternate` | `alternate`는 홀수 번째는 정방향, 짝수 번째는 역방향으로 재생해 왕복 움직임을 만든다 |
| `animation-play-state` | `running` (초기값) / `paused` | 자바스크립트나 `:hover` 등으로 애니메이션을 일시정지·재개할 때 사용 |

## transition vs animation — 근본적인 차이는 트리거 유무

두 기능 모두 값의 변화를 부드럽게 보여준다는 점은 같지만, **누가 그 변화를 시작시키는가**가 결정적으로 다릅니다.

| 기준 | transition | animation |
|------|------------|-----------|
| 시작 계기(트리거) | `:hover`, 클래스 토글 같은 **상태 변화가 있어야만** 시작 | `@keyframes`가 연결되는 순간 **스스로** 시작할 수 있음(별도 트리거 불필요) |
| 정의할 수 있는 지점 | 시작과 끝, 두 지점만 | 0퍼센트부터 100퍼센트까지 원하는 만큼 여러 지점 |
| 반복 | 상태가 바뀔 때마다 한 번씩만 재생 | `animation-iteration-count`로 반복 횟수(또는 무한) 지정 가능 |
| 적합한 상황 | hover·포커스·클래스 추가 같은 "상태 A에서 B로의 전환" | 로딩 스피너, 배너 등 "계기 없이 계속되거나 여러 단계를 거치는 움직임" |

<Callout type="warning">
  **자주 틀리는 점:** 로딩 스피너처럼 페이지가 로드되자마자 계속 도는 움직임을 `transition`으로 만들려고 하는 것입니다. `transition`은 반드시 어떤 상태 변화(예: 클래스가 붙는 순간)가 있어야 시작되므로, 계기 없이 스스로 반복되는 움직임에는 애초에 맞지 않는 도구입니다. 이런 경우는 처음부터 `animation`과 `@keyframes`를 씁니다.
</Callout>

## 실전 예 — 배너에 등장 애니메이션 주기

```css
.banner {
  animation: fade-in-up 0.6s ease-out;
}

@keyframes fade-in-up {
  0% {
    opacity: 0;
    transform: translateY(16px);
  }
  100% {
    opacity: 1;
    transform: translateY(0);
  }
}
```

이 예는 `animation-iteration-count`를 생략했으므로 초기값인 `1`(한 번만 재생)이 적용됩니다. 페이지가 로드되고 이 요소가 렌더링되는 순간 자동으로 한 번 재생되며, 별도의 `:hover`나 클래스 토글 없이도 동작한다는 점이 `transition`과 다릅니다.

## 접근성 관점

27편에서 언급한 전정 장애(vestibular disorder) 문제는 `animation`에서 더 두드러집니다. `transition`은 사용자의 특정 동작(hover, 클릭)에 반응해 짧게 한 번 일어나지만, `animation`은 `infinite`로 설정하면 사용자의 의사와 무관하게 페이지에 머무는 내내 계속 움직입니다. 계속 움직이는 배경이나 장식 요소는 주의를 산만하게 하고, 일부 사용자에게는 실질적인 신체 반응(어지럼증)을 유발할 수 있습니다. 실무에서는 꼭 필요한 곳에만 무한 반복 애니메이션을 쓰고, 자바스크립트로 `animation-play-state: paused`를 걸어 사용자가 멈출 수 있게 하는 방법도 고려됩니다.

## 자주 틀리는 점

- **`@keyframes`만 정의하고 `animation`으로 연결하지 않아 "왜 아무 효과가 없냐"고 묻는 것.** `@keyframes`는 이름표를 만드는 선언일 뿐, 요소에 `animation-name`(또는 축약형)으로 연결해야 실제로 재생됩니다.
- **`animation-iteration-count`를 생략하고 왜 한 번만 재생되고 멈추는지 궁금해하는 것.** 초기값이 `1`이므로 반복이 필요하면 숫자나 `infinite`를 명시해야 합니다.
- **`transition`과 `animation`을 아무 기준 없이 섞어 쓰는 것.** 상태 변화에 반응하는 짧은 전환은 `transition`, 계기 없이 스스로 반복되거나 여러 단계를 거치는 움직임은 `animation`이라는 기준으로 나눠 쓰는 것이 유지보수에 유리합니다.

## 핵심 정리

- `@keyframes`는 0퍼센트부터 100퍼센트까지 진행률에 따른 스타일 변화를 정의하는 선언이며, 그 자체로는 어떤 요소에도 적용되지 않는다.
- `animation` 속성군(`animation-name`·`animation-duration`·`animation-timing-function`·`animation-iteration-count` 등)으로 `@keyframes`를 요소에 연결하고 재생 방식을 제어한다.
- `transition`은 상태 변화라는 트리거가 있어야 시작되는 반면, `animation`은 별도 트리거 없이 스스로 시작하고 반복할 수 있다는 것이 두 기능의 근본적인 차이다.
- 무한 반복 애니메이션은 전정 장애가 있는 사용자에게 불편을 줄 수 있으므로 신중하게 사용한다.
