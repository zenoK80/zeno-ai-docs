## 이번 편에서 만드는 것

이 과목의 마지막 실습입니다. 지금까지 배운 것을 최대한 많이 한 페이지에 모읍니다. 완성할 랜딩 페이지(landing page, 방문자가 처음 도착하는 홍보용 한 페이지)의 요구사항은 다음과 같습니다.

1. 상단 네브바(navigation bar, 이동 막대)는 Flexbox로 좌측 로고와 우측 메뉴를 양 끝에 배치하고, 스크롤해도 화면 위에 계속 붙어 있어야 한다(`position: sticky`).
2. 히어로(hero, 페이지 최상단의 큰 소개 영역) 섹션은 Grid로 텍스트와 버튼을 배치하고, 배경 장식 도형은 `position: absolute`로 히어로 영역 안에만 겹쳐야 한다.
3. 히어로의 제목은 페이지가 열리자마자 아래에서 위로 살짝 떠오르며 나타나는 `@keyframes` 애니메이션을 가진다.
4. 버튼은 마우스를 올리면(`:hover`) 배경색이 `transition`으로 부드럽게 바뀐다.
5. 하단에는 31편에서 만든 반응형 카드 그리드 패턴을 재사용한 소개 카드 섹션을 둔다.

> **쉽게 말하면:** 지금까지 따로 배운 부품(캐스케이드, 박스 모델, Flexbox, Grid, position, 전환, 애니메이션, 스택 컨텍스트)을 실제 제품 페이지 하나에 처음부터 끝까지 조립하는 실습입니다.

### 2단계 — Flexbox 네브바를 sticky로 고정하기

```css
.네브바 {
  position: sticky;
  top: 0;
  z-index: 10;
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 1rem 1.5rem;
  background: white;
  border-bottom: 1px solid #e9ecef;
}

.네브바 nav {
  display: flex;
  gap: 1.25rem;
}
```

18편에서 배운 대로 `position: sticky`는 스크롤이 진행되는 동안 원래 자리에 있다가, 뷰포트 기준 `top: 0` 지점에 닿는 순간 그 자리에 고정됩니다. `sticky`가 실제로 붙는 범위는 **가장 가까운 스크롤 조상**을 기준으로 하므로, 부모 중 하나가 `overflow: hidden` 같은 값으로 스크롤 컨테이너를 만들면 그 안에서만 고정된다는 점을 기억해야 합니다. `z-index: 10`을 함께 준 것은 뒤이어 만들 히어로 섹션의 장식 도형이 스크롤 중 네브바 위로 겹쳐 보이지 않게 하기 위해서입니다. 29편에서 배운 대로, `z-index`는 `position`이 `static`이 아닌 요소에만 적용되므로 `sticky`와 함께 써야 의미가 있습니다.

### 3단계 — Grid와 position으로 히어로 섹션 배치하기

```css
.히어로 {
  position: relative;   /* 장식 도형의 containing block을 여기로 고정 */
  overflow: hidden;      /* 장식 도형이 히어로 밖으로 새어나가지 않게 자른다 */
  display: grid;
  place-items: center;
  text-align: center;
  padding: 4rem 1.5rem;
  background: #eef2ff;
}

.히어로-장식 {
  position: absolute;
  top: -60px;
  right: -60px;
  width: 220px;
  height: 220px;
  border-radius: 50%;
  background: #c7d2fe;
  z-index: 0;
}

.히어로-내용 {
  position: relative;
  z-index: 1;
  max-width: 480px;
}
```

`.히어로`에 `position: relative`를 준 것이 이번 편에서 가장 중요한 한 줄입니다. 18편에서 배운 대로 `position: absolute` 요소는 **가장 가까운 positioned 조상**을 containing block으로 삼습니다. `.히어로`에 `relative`가 없었다면 `.히어로-장식`은 문서 전체(초기 containing block)를 기준으로 배치되어 페이지 어딘가 엉뚱한 곳에 나타났을 것입니다. `overflow: hidden`은 장식 도형이 히어로 영역 경계를 넘어가는 부분을 잘라, 다른 섹션까지 침범하지 않게 막습니다. `display: grid`와 `place-items: center`는 자식(`.히어로-내용`)을 가로·세로 모두 정중앙에 놓는 Grid의 정렬 지름길입니다.

`.히어로-장식`과 `.히어로-내용`에 각각 `z-index: 0`, `z-index: 1`을 준 것도 우연이 아닙니다. `.히어로` 자신이 `position: relative`이지만 `z-index`를 지정하지 않았다면 새 스택 컨텍스트를 만들지 않으므로, 두 자식은 `.히어로` 내부에서 이 숫자로 순서가 갈립니다. 장식 도형이 텍스트 뒤로 가야 하므로 더 작은 값을 줬습니다.

### 4단계 — 히어로 제목에 등장 애니메이션 주기

```css
@keyframes 떠오르기 {
  from {
    opacity: 0;
    transform: translateY(16px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.히어로-내용 h1 {
  margin: 0 0 0.75rem;
  font-size: 2rem;
  animation: 떠오르기 0.6s ease-out;
}
```

`@keyframes`는 애니메이션의 중간 단계를 이름 붙여 정의하는 규칙입니다. `from`(시작 상태)에서 `opacity: 0`(완전히 투명)과 `translateY(16px)`(원래 자리보다 16px 아래)로 시작해, `to`(끝 상태)에서 완전히 보이는 원래 자리로 이동합니다. `transform`으로 위치를 옮기는 것은 27편에서 배울 대로 레이아웃을 다시 계산(리플로우)시키지 않아 애니메이션이 가볍다는 장점이 있습니다. `animation` 속성에 `떠오르기`(정의한 keyframes 이름), `0.6s`(지속 시간), `ease-out`(처음엔 빠르고 끝에서 느려지는 이징 함수)을 지정했습니다. `transition`과 달리 `animation`은 `:hover` 같은 상태 변화 없이도 **페이지가 로드되는 순간 스스로 트리거**된다는 차이를 28편에서 확인했습니다.

### 5단계 — 버튼에 hover 전환 효과 주기

```css
.시작버튼 {
  padding: 0.75rem 1.5rem;
  border: none;
  border-radius: 999px;
  background: #4c6ef5;
  color: white;
  font-weight: 600;
  cursor: pointer;
  transition: background-color 0.2s ease, transform 0.2s ease;
}

.시작버튼:hover {
  background-color: #364fc7;
  transform: translateY(-2px);
}
```

`transition`은 27편에서 배운 대로 **어떤 속성을(`background-color`, `transform`) 얼마 동안(`0.2s`) 어떤 속도 곡선으로(`ease`)** 바꿀지 미리 예약해 둡니다. 상태 변화(`:hover`)가 실제로 일어날 때만 동작한다는 점이 `animation`과의 결정적인 차이입니다. 마우스를 올리는 순간 색이 즉시 바뀌지 않고 0.2초에 걸쳐 부드럽게 바뀌는 것을 실습기에서 직접 확인하세요.

### 6단계 — 31편 카드 그리드 패턴 재사용하기

```css
.기능카드 {
  padding: 3rem 1.5rem;
  text-align: center;
}

.카드그리드 {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1.25rem;
  list-style: none;
  padding: 0;
  margin: 2rem auto 0;
  max-width: 900px;
  text-align: left;
}

@media (min-width: 700px) {
  .카드그리드 {
    grid-template-columns: repeat(3, 1fr);
  }
}

.카드 {
  border: 1px solid #dee2e6;
  border-radius: 10px;
  padding: 1.25rem;
}
```

31편에서 완성한 Grid 카드 그리드를 그대로 가져왔습니다. 새 개념을 다시 설명하지 않는 이유는, 이 실습의 목적이 "새로운 CSS를 더 배우는 것"이 아니라 **이미 배운 패턴을 다른 맥락에서도 알아보고 재사용할 수 있는가**를 확인하는 것이기 때문입니다.

## 01편 완료 기준 5가지 자가 점검

`01_학습방향.md`가 과목을 시작하기 전에 정해 둔 기준입니다. 이번 실습에서 만든 랜딩 페이지를 근거 삼아 하나씩 스스로 판정해 보세요.

### 기준 1 — 두 선택자의 충돌을 명시도·소스 순서로 설명하기

> 두 선택자가 같은 속성에 충돌하는 CSS를 보고, 계산 없이도 어느 규칙이 이길지 명시도·소스 순서로 설명할 수 있다.

**확인 방법**: 이번 실습 코드에서 `.카드그리드`는 31편과 32편 두 파일에 똑같은 클래스 이름으로 등장합니다. 만약 두 파일이 한 페이지에 동시에 로드되고 서로 다른 `gap` 값을 줬다면 어느 값이 이길지, 파일이 로드되는 순서와 선택자의 명시도만으로 설명할 수 있는지 스스로 물어보세요.

- 막히면: 08편(캐스케이드)·09편(명시도)으로 돌아가세요.

### 기준 2 — border-box·content-box 차이와 마진 상쇄 재현하기

> `border-box`와 `content-box`의 차이를 DevTools 박스 모델 다이어그램으로 직접 확인하고, 마진 상쇄가 일어나는 상황을 재현할 수 있다.

**확인 방법**: 완성 코드의 `* { box-sizing: border-box; }`를 DevTools에서 잠시 꺼 보고(Styles 패널 체크박스), `.카드`의 실제 렌더링 폭이 달라지는지 박스 모델 다이어그램으로 확인하세요. 그다음 `.기능카드`의 `padding`과 `.히어로`의 `padding`을 인접한 블록 마진으로 바꿔 상쇄가 일어나는 상황도 직접 만들어 보세요.

- 막히면: 11편(박스 모델)·12편(마진 상쇄)으로 돌아가세요.

### 기준 3 — 네브바·카드 그리드·반응형 레이아웃을 처음부터 만들기

> 네브바·카드 그리드·2단 반응형 레이아웃을 Flexbox와 Grid 중 적절한 것을 골라 처음부터 만들 수 있다.

**확인 방법**: 지금 백지 상태에서 이번 실습의 완성 코드를 보지 않고, 네브바(Flexbox)와 카드 그리드(Grid)를 다시 짜 보세요. 어떤 상황에 Flexbox를, 어떤 상황에 Grid를 골랐는지 그 이유를 25편의 선택 기준으로 설명할 수 있어야 합니다.

- 막히면: 20~22편(Flexbox)·23~25편(Grid)으로 돌아가세요.

### 기준 4 — absolute 요소의 위치를 containing block으로 추적하기

> `position: absolute` 요소가 "왜 저기에" 배치되는지 containing block을 추적해 설명할 수 있다.

**확인 방법**: `.히어로-장식`에서 `.히어로`의 `position: relative`를 제거해 보고, 장식 도형이 어디로 튀는지, 왜 그곳이 새로운 containing block인지(문서 최상위, 즉 초기 containing block으로 넘어갔기 때문에) 설명할 수 있는지 확인하세요.

- 막히면: 18편(position과 containing block)으로 돌아가세요.

### 기준 5 — z-index 오작동 상황에서 스택 컨텍스트 진단하기

> `z-index`가 의도대로 동작하지 않는 상황을 보고 스택 컨텍스트 형성 조건을 확인해 원인을 진단할 수 있다.

**확인 방법**: `.네브바`의 `z-index: 10`을 지워보고, 스크롤 시 `.히어로-장식`(반투명한 원)이 고정된 네브바 위로 겹쳐 보이는지 확인하세요. 왜 겹치는지, `.네브바`가 어떤 조건으로 스택 컨텍스트를 만들고 있었는지 29편의 개념으로 설명해 보세요.

- 막히면: 29편(오버플로와 스택 컨텍스트)으로 돌아가세요.

## 핵심 정리

- 하나의 랜딩 페이지 안에서 sticky 네브바(Flexbox), 히어로(Grid + position), 카드 섹션(Grid, 31편 재사용)이 서로 다른 역할로 공존할 수 있다.
- `position: relative`인 부모가 `position: absolute` 자식의 containing block이 되어야 장식 요소가 의도한 자리에 남는다.
- `animation`은 상태 변화 없이 스스로 시작되고, `transition`은 `:hover` 같은 상태 변화가 있어야 동작한다는 차이가 실전에서도 그대로 나타난다.
- sticky 네브바처럼 `z-index`를 지정한 positioned 요소는 새 스택 컨텍스트를 만들어, 뒤이어 등장하는 다른 요소가 의도치 않게 위로 겹치는 것을 막는다.
- 01편 완료 기준 5가지는 지식이 아니라 이 실습 코드를 직접 고쳐보는 행동으로 점검해야 한다.
