<Callout type="info">
  **이번 문서의 목표:** 이 문서를 다 읽으면 `cqw`/`cqh`/`cqi`/`cqb` 컨테이너 단위로 "컨테이너 폭에 비례하는" 크기 값을 만들 수 있고, 컨테이너 스타일 쿼리(`style()`)가 무엇을 하는 기능이며 왜 아직 실무 기본값으로 쓰기엔 이르다고 판단해야 하는지 설명할 수 있게 됩니다.
</Callout>

## 왜 필요한가 — 픽셀 조건만으로는 부족하다

07편에서 `@container (width >= 380px)`처럼 **컨테이너 폭이 특정 값을 넘는지** 조건을 걸어봤습니다. 그런데 조건을 넘는 순간 급격하게 레이아웃이 바뀌는 대신, **컨테이너 폭에 비례해서 서서히 커지거나 작아지는 값**이 필요할 때가 있습니다. 예를 들어 카드 안 제목의 글자 크기를, 카드가 놓인 자리가 넓어질수록 조금씩 커지게 하고 싶다면 어떻게 해야 할까요?

뷰포트 단위(`vw`, `vh`)로는 뷰포트 크기에 비례하는 값만 만들 수 있었습니다. 컨테이너에도 똑같은 개념이 필요했고, 그래서 **컨테이너 단위**(container query units)가 함께 도입되었습니다.

> **쉽게 말하면:** `vw`가 "뷰포트 폭의 몇 퍼센트"라면, `cqw`는 "컨테이너 폭의 몇 퍼센트"입니다. 자를 뷰포트가 아니라 지금 들어있는 상자에 대고 재는 것입니다.

## 정의와 기본 문법 — 네 가지 컨테이너 단위

| 단위 | 의미 | 뷰포트 단위와의 대응 |
|------|------|------------------------|
| `cqw` | 가장 가까운 컨테이너의 **가로 폭**의 1퍼센트 | `vw`에 대응 |
| `cqh` | 가장 가까운 컨테이너의 **세로 높이**의 1퍼센트 | `vh`에 대응 |
| `cqi` | 가장 가까운 컨테이너의 **인라인 축** 크기의 1퍼센트 (가로쓰기 문서에서는 보통 `cqw`와 같다) | `vi`에 대응 |
| `cqb` | 가장 가까운 컨테이너의 **블록 축** 크기의 1퍼센트 (가로쓰기 문서에서는 보통 `cqh`와 같다) | `vb`에 대응 |

`cq`라는 접두어는 **container query**의 약자입니다. `cqi`와 `cqb`가 따로 있는 이유는 12편에서 다룰 논리 속성(logical properties)과 같은 이유입니다 — 세로쓰기(vertical writing mode) 문서처럼 인라인·블록 축이 뒤집히는 경우에도, "글이 흐르는 방향(인라인)"과 "줄이 쌓이는 방향(블록)"을 물리적 가로세로가 아니라 논리적으로 표현하기 위해서입니다. 실무 대부분(가로쓰기 한국어·영어 문서)에서는 `cqw ≈ cqi`, `cqh ≈ cqb`로 생각해도 무방하지만, 국제화(internationalization, i18n)를 고려한다면 `cqi`/`cqb`를 기본값으로 쓰는 편이 더 안전합니다.

```css
.card-wrapper {
  container-type: inline-size;
}

.card h3 {
  /* 컨테이너 폭의 5%만큼 커지되, 최소 1rem 최대 1.75rem으로 제한 */
  font-size: clamp(1rem, 4cqi, 1.75rem);
}
```

`clamp()`는 18편에서 자세히 다루지만, 컨테이너 단위와 결합하면 "컨테이너가 넓어질수록 자연스럽게 커지되 상한과 하한을 벗어나지 않는" 값을 만들 수 있습니다. 뷰포트 단위로 만든 유동 타이포그래피(fluid typography)를 컨테이너 단위로 옮긴 것이라고 이해하면 됩니다.

## 컨테이너 스타일 쿼리 — 크기가 아니라 스타일 값으로 조건 걸기

07편의 `@container`는 전부 **크기**(width, height)를 조건으로 삼았습니다. 그런데 크기가 아니라 **커스텀 속성(custom property) 값이나 다른 CSS 속성 값**을 조건으로 걸고 싶을 때가 있습니다. 예를 들어 "이 컨테이너의 `--테마` 커스텀 속성이 `dark`이면"이라는 조건입니다. 이를 위한 것이 **컨테이너 스타일 쿼리**(container style query)이며, `style()` 함수로 작성합니다.

```css
.card-wrapper {
  container-type: inline-size;
  --테마: light;
}

.card-wrapper.어두운모드 {
  --테마: dark;
}

@container style(--테마: dark) {
  .card {
    background: #1a1a1a;
    color: #eee;
  }
}
```

커스텀 속성은 13편에서 캐스케이드 안에서 상속·재정의되는 방식을 자세히 다루지만, 여기서는 "컨테이너에 붙은 커스텀 속성 값을 조건으로 그 안의 자식 스타일을 바꾼다"는 구조만 확인하면 충분합니다.

## 컨테이너 스타일 쿼리의 지원 상태 — 크기 쿼리와 구분해야 한다

여기서 **01편의 사실 확인 기준을 그대로 지켜야 하는 지점**이 나옵니다. 앞서 다룬 `container-type`과 크기 기반 `@container`는 널리 사용 가능(Widely available) 상태이지만, **컨테이너 스타일 쿼리(`style()`)는 지원 시점이 그보다 뒤이고 별도로 확인이 필요합니다.** "컨테이너 쿼리"라는 이름 하나로 뭉뚱그려 "다 됐다"고 판단하면 안 되는 대표적인 사례입니다.

<Callout type="warning">
  **자주 틀리는 점:** "컨테이너 쿼리는 널리 사용 가능하다"는 사실을 크기 쿼리에만 적용하고, 스타일 쿼리에는 확대 적용하지 말아야 합니다. 실무에 스타일 쿼리를 도입하기 전에는 반드시 MDN이나 webstatus.dev에서 해당 브라우저 조합의 최신 지원 표를 직접 확인하고, `@supports` 폴백(02편에서 다룬 점진적 향상 절차)을 함께 설계해야 합니다.
</Callout>

```css
/* 지원하지 않는 브라우저를 위한 기본값을 먼저 정의 */
.card {
  background: white;
  color: #111;
}

/* 지원하는 브라우저에서만 스타일 쿼리로 덮어쓴다 */
@container style(--테마: dark) {
  .card {
    background: #1a1a1a;
    color: #eee;
  }
}
```

스타일 쿼리를 지원하지 않는 브라우저는 `@container style(...)` 블록 자체를 무시하므로, 위처럼 기본 스타일을 먼저 정의해 두면 자연스러운 폴백(fallback, 대체 수단)이 됩니다.

## 컴포넌트 단위 반응형 설계 원칙

07~08편의 컨테이너 쿼리·컨테이너 단위를 실무에 들일 때 지침이 되는 원칙 세 가지입니다.

1. **컴포넌트는 자신이 놓일 위치를 모른다고 가정한다.** 메인 영역에 놓일지 사이드바에 놓일지, 그 컴포넌트를 만드는 시점에는 알 수 없는 경우가 많습니다. 뷰포트 기준 미디어 쿼리 대신 컨테이너 쿼리를 기본으로 삼으면 이 가정이 자연스럽게 지켜집니다.
2. **레이아웃 전환의 기준값(breakpoint)은 디자인 시스템의 표준 뷰포트 폭이 아니라, 그 컴포넌트가 실제로 받는 폭 구간을 실험해 정한다.** 사이드바 폭이 240픽셀이라면, `@container`의 기준값도 그 근처에서 실제로 레이아웃이 부자연스러워지는 지점을 찾아 정해야 합니다.
3. **크기 쿼리를 기본으로, 스타일 쿼리는 점진적 향상으로.** 스타일 쿼리는 지원이 갈리므로, "있으면 더 좋은" 부가 기능으로 설계하고 없어도 컴포넌트가 정상 동작하도록 기본 스타일을 항상 먼저 정의합니다.

## 접근성 관점

컨테이너 단위(`cqw`, `cqi` 등)로 글자 크기를 만들 때 가장 조심해야 할 것은 **사용자의 브라우저 확대(zoom) 설정을 무시하지 않는 것**입니다. `clamp()`로 최소·최대 상한을 반드시 걸어, 컨테이너가 아주 좁아지거나 넓어져도 글자가 읽지 못할 만큼 작아지거나 과도하게 커지지 않도록 해야 합니다. 이 점은 18편(유동 타이포그래피)에서 뷰포트 단위 기준으로 더 자세히 다루는데, 컨테이너 단위에도 똑같은 원칙이 적용됩니다.

## 핵심 정리

- `cqw`/`cqh`/`cqi`/`cqb`는 뷰포트 단위(`vw`/`vh`)의 컨테이너 버전이다. `cqi`/`cqb`는 논리 축 기준이라 국제화에 더 안전하다.
- 컨테이너 단위와 `clamp()`를 결합하면 컨테이너 폭에 비례하면서도 상한·하한이 있는 유동 값을 만들 수 있다.
- 컨테이너 스타일 쿼리(`@container style(...)`)는 크기가 아니라 커스텀 속성 등 스타일 값을 조건으로 삼는다.
- 크기 기반 `@container`는 널리 사용 가능(Widely available)이지만, 스타일 쿼리는 지원 시점이 더 최근이므로 별도로 확인하고 `@supports` 폴백과 함께 도입해야 한다.
- 컴포넌트 단위 반응형 설계는 "위치를 모른다고 가정", "실제 폭 구간으로 기준값 결정", "크기 쿼리 기본 + 스타일 쿼리는 점진적 향상"이라는 세 원칙을 따른다.
