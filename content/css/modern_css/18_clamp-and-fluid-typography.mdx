  **이번 문서의 목표:** 이 문서를 다 읽으면 `min()`·`max()`·`clamp()`의 계산 규칙을 정확히 알고, 두 개의 기준점(최소 화면 폭에서의 글자 크기, 최대 화면 폭에서의 글자 크기)만으로 `clamp()` 공식을 손으로 유도해 어떤 값에도 스스로 적용할 수 있게 됩니다.
</Callout>

## 1. 왜 필요한가 — 계단식 반응형의 한계

### 문제 상황

CSS Fundamentals에서 배운 미디어 쿼리(media query) 기반 반응형은 화면 폭을 몇 개의 구간으로 나누고, 구간이 바뀌는 순간 값을 **계단식으로** 바꿉니다.

```css
h1 { font-size: 1.5rem; }

@media (min-width: 768px) {
  h1 { font-size: 2rem; }
}

@media (min-width: 1280px) {
  h1 { font-size: 3rem; }
}
```

이 방식은 767px에서 768px로 폭이 1px 늘어나는 순간 글자 크기가 1.5rem에서 2rem으로 **뚝 튑니다.** 브라우저 창을 천천히 늘려보면 제목 크기가 계단처럼 몇 번 점프하는 것이 보입니다. 화면 폭은 연속적으로 변하는데 글자 크기만 불연속적으로 변하는 부조화가 생깁니다.

> **쉽게 말하면:** 계단식 반응형은 엘리베이터입니다. 층과 층 사이에서는 멈추지 않고 정해진 층에서만 섭니다. 유동 타이포그래피(fluid typography, 유동적 타이포그래피)는 경사로입니다. 어느 지점에서 멈추든 그 지점에 맞는 높이가 있습니다.

### 정의 — `min()`, `max()`, `clamp()`

세 함수는 모두 여러 값을 받아 그중 하나를 계산값으로 고르는 **비교 함수**입니다.

| 함수 | 규칙 |
|------|------|
| `min(a, b, ...)` | 인자들 중 **가장 작은** 값을 선택 |
| `max(a, b, ...)` | 인자들 중 **가장 큰** 값을 선택 |
| `clamp(최솟값, 선호값, 최댓값)` | 선호값을 쓰되, 최솟값보다 작아지면 최솟값에, 최댓값보다 커지면 최댓값에 고정(clamp, 죄어 고정하다) |

`clamp(MIN, PREFERRED, MAX)`는 사실 `max(MIN, min(PREFERRED, MAX))`와 동일한 계산입니다. "선호값과 최댓값 중 작은 쪽을 고르고, 그 결과와 최솟값 중 큰 쪽을 고른다"는 뜻이죠. 세 인자 중 하나라도 뷰포트 단위(`vw`, `vh` 등)처럼 값이 화면 크기에 따라 변하는 표현을 포함하면, 화면이 커지고 작아질 때마다 계산값이 매끄럽게 다시 계산됩니다.

## 2. 계산 전 과정 — 공식을 직접 유도하기

### 목표를 숫자로 정하기

유동 타이포그래피를 설계할 때는 "화면이 얼마나 좁을 때 글자가 얼마나 작아야 하고, 얼마나 넓을 때 얼마나 커야 하는가"라는 **두 개의 기준점**을 먼저 정합니다. 이 문서에서는 다음 목표로 계산을 진행합니다.

- 화면 폭이 **320px**일 때, 제목 글자 크기는 **16px**(=1rem, 루트 글자 크기 16px 기준)
- 화면 폭이 **1280px**일 때, 제목 글자 크기는 **24px**(=1.5rem)
- 그 사이 폭에서는 두 점을 잇는 **직선**(1차 함수)으로 매끄럽게 커진다

이 관계를 그래프로 그리면 가로축은 뷰포트 폭, 세로축은 글자 크기인 직선입니다. 중학교 수학의 "두 점을 지나는 직선의 방정식"을 그대로 CSS 값으로 옮기는 작업입니다.

### 1단계 — 기울기(slope) 구하기

직선의 기울기는 "폭이 1px 늘어날 때 글자 크기가 몇 px 늘어나는가"입니다.

$$
기울기 = \frac{최대글자px - 최소글자px}{최대폭px - 최소폭px}
$$

- $최대글자px$: 가장 넓은 기준 폭에서의 글자 크기(px) — 여기서는 24
- $최소글자px$: 가장 좁은 기준 폭에서의 글자 크기(px) — 여기서는 16
- $최대폭px$: 가장 넓은 기준 뷰포트 폭(px) — 여기서는 1280
- $최소폭px$: 가장 좁은 기준 뷰포트 폭(px) — 여기서는 320

숫자를 넣어 계산합니다.

$$
기울기 = \frac{24 - 16}{1280 - 320} = \frac{8}{960} = 0.008333\ldots
$$

이 값은 "화면 폭이 1px 늘어날 때마다 글자 크기가 약 0.00833px씩 커진다"는 뜻입니다.

### 2단계 — 뷰포트 단위로 바꾸기

CSS의 `vw` 단위는 뷰포트 폭의 1퍼센트를 1로 삼습니다. 즉 뷰포트가 1280px이면 `1vw`는 12.8px입니다. 기울기를 그대로 px로 쓰면 뷰포트 폭이 바뀔 때 자동으로 재계산되지 않으므로, 기울기에 100을 곱해 `vw` 단위로 바꿔야 매 순간 뷰포트 폭에 비례해 재계산됩니다.

$$
기울기_{vw} = 기울기 \times 100 = 0.008333\ldots \times 100 = 0.8333\ldots
$$

즉 앞으로 CSS에는 `0.8333vw`라고 씁니다. 이 값이 "화면 폭이 1vw(=폭의 1퍼센트)만큼 늘어날 때 글자 크기가 늘어나는 양"입니다.

### 3단계 — 절편(y절편) 구하기

직선의 방정식은 $y = 기울기 \times x + 절편$ 형태입니다. 여기서 $x$는 뷰포트 폭(px), $y$는 글자 크기(px)입니다. 절편은 "뷰포트 폭이 0일 때(가상의 값) 글자 크기가 얼마인가"를 구하는 것으로, 최소 기준점을 대입해 역산합니다.

$$
절편px = 최소글자px - 기울기 \times 최소폭px
$$

숫자를 대입합니다.

$$
절편px = 16 - 0.008333\ldots \times 320 = 16 - 2.6667 = 13.3333
$$

### 4단계 — 절편을 rem으로 바꾸기

`vw` 항은 화면 크기에 비례해 자동으로 커지지만, 절편은 화면 크기와 무관한 **고정된 시작점**입니다. 이 고정 부분을 `px`로 그대로 쓰면 사용자가 브라우저의 기본 글자 크기 설정(텍스트 확대, text zoom)을 키워도 반응하지 않습니다. 그래서 고정 부분은 `rem`(루트 요소의 글자 크기를 1로 삼는 단위)으로 바꿉니다. 루트 글자 크기를 16px로 가정합니다.

$$
절편_{rem} = \frac{절편px}{16} = \frac{13.3333}{16} = 0.8333
$$

### 5단계 — 완성된 선호값 조립하기

이제 두 조각을 더해 `clamp()`의 가운데 인자(선호값)를 완성합니다.

$$
선호값 = 0.8333rem + 0.8333vw
$$

우연히도 이 예시에서는 절편의 rem 값과 기울기의 vw 값이 같은 숫자(0.8333)로 나왔습니다. 이는 루트 글자 크기 16px과 최소 기준 글자 크기 16px이 같기 때문에 생긴 우연이며, 항상 두 숫자가 같지는 않습니다. 각 항은 독립적으로 계산해야 합니다.

### 6단계 — 최솟값·최댓값과 함께 `clamp()`로 감싸기

$$
font\text{-}size = clamp(1rem,\ 0.8333rem + 0.8333vw,\ 1.5rem)
$$

- 첫 번째 인자 `1rem`(=16px): 화면이 아무리 좁아져도 이보다 작아지지 않을 하한선
- 두 번째 인자 `0.8333rem + 0.8333vw`: 화면 폭에 선형으로 비례하는 선호값
- 세 번째 인자 `1.5rem`(=24px): 화면이 아무리 넓어져도 이보다 커지지 않을 상한선

이 값을 CSS로 옮기면 다음과 같습니다.

```css
h1 {
  font-size: clamp(1rem, 0.8333rem + 0.8333vw, 1.5rem);
}
```

### 결과 해석

이 한 줄은 "뷰포트 폭이 320px 이하일 때는 16px, 1280px 이상일 때는 24px, 그 사이에서는 두 점을 잇는 직선을 따라 매끄럽게 변하는 글자 크기"를 뜻합니다. 320px에서 계산해보면 $0.8333 \times 16 + 0.8333 \times 3.2 = 13.33 + 2.67 = 16$px로 정확히 최솟값과 맞아떨어지고, 1280px에서는 $13.33 + 0.8333 \times 12.8 = 13.33 + 10.67 = 24$px로 최댓값과 맞아떨어집니다. 두 점 사이 어떤 폭에서도 이 직선 위의 값이 그대로 적용되며, 320px 미만·1280px 초과에서는 `clamp()`가 각각 하한·상한으로 고정합니다.

## 3. 접근성 — 확대 배율을 해치지 않는가

### 두 종류의 "확대"를 구분하기

브라우저에는 서로 다른 확대 방식이 두 가지 있습니다.

| 구분 | 무엇이 커지는가 | `vw` 기반 유동 값의 반응 |
|------|-----------------|--------------------------|
| 페이지 확대(브라우저 줌, `Ctrl` + `+`) | 뷰포트 자체가 배율만큼 축소된 것처럼 계산되어 페이지 전체(레이아웃 포함)가 커짐 | 뷰포트 계산에 배율이 반영되므로 함께 커짐 |
| 텍스트 전용 확대(브라우저 설정의 기본 글자 크기 조정) | 루트 요소의 기본 글자 크기(대개 16px)만 커짐, 레이아웃 폭은 그대로 | `rem` 부분만 반응하고 `vw` 부분은 반응하지 않음 |

<Callout type="warning">
  **자주 틀리는 점:** 선호값을 `0.8333vw`처럼 뷰포트 단위 **하나만으로** 채우면, 텍스트 전용 확대를 쓰는 저시력 사용자에게는 글자가 전혀 커지지 않는 접근성 문제가 생깁니다. 위 계산 과정에서 `rem`과 `vw`를 **더한 형태**로 조립한 이유가 이것입니다 — 절편을 `rem`으로 표현해 텍스트 전용 확대에도 최소한의 비율만큼은 반응하게 만들었습니다.
</Callout>

이 때문에 유동 타이포그래피 값은 순수 `vw` 하나가 아니라 항상 `rem + vw` 조합으로 짜는 것이 접근성 관점의 모범 사례입니다. `clamp()`의 최솟값·최댓값 역시 `px`가 아니라 `rem`으로 쓰는 것을 권장합니다 — 하한·상한 자체도 사용자의 텍스트 확대 설정에 비례해 움직여야 하기 때문입니다. 위 예시에서 `1rem`, `1.5rem`을 그대로 쓴 것도 같은 이유입니다.

## 핵심 정리

- `min()`은 최솟값, `max()`는 최댓값, `clamp(최소, 선호, 최대)`는 선호값을 최소·최대 범위 안으로 가두는 함수다.
- 유동 타이포그래피 공식은 "두 기준점(최소 폭·최소 글자, 최대 폭·최대 글자)을 잇는 직선의 방정식"을 세우는 것과 같다 — 기울기 → vw 단위 환산 → 절편 → rem 환산 → 조립의 순서로 유도한다.
- 선호값을 `vw` 단독이 아니라 `rem + vw` 조합으로 짜야 텍스트 전용 확대(text zoom)를 쓰는 사용자에게도 최소한의 반응이 남는다.
- `clamp()`의 최소·최대 인자도 `px`가 아니라 `rem`으로 써야 확대 배율에 비례해 하한·상한도 함께 움직인다.
- `clamp()`, `min()`, `max()`는 지원 상태가 널리 사용 가능(widely available)이라 폴백 없이 바로 쓸 수 있다.
