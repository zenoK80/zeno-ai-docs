<Callout type="info">
  **이번 문서의 목표:** 이 실습을 끝내면 `@starting-style`로 진입 애니메이션을 만들고, 뷰 전환(View Transitions)으로 상태 변화에 자연스러운 움직임을 입히고, 스크롤 연동 애니메이션(scroll-driven animation)에 `@supports` 폴백을 갖춰 붙일 수 있게 됩니다. 마지막으로 이 과목 전체의 완료 기준 다섯 가지를 스스로 점검하며 Modern CSS 과목을 마무리합니다.
</Callout>

## 이 실습에서 하나로 모으는 것

모션(motion) 계열 기능들은 이 과목에서 유독 "지원이 갈리는" 정도가 심합니다. 20편의 `@starting-style`은 최신 브라우저 기준이고, 21편의 same-document 뷰 전환은 2025년 10월에야 Baseline에 들어왔으며, 22편의 cross-document 뷰 전환과 23편의 스크롤 연동 애니메이션은 아직 제한적입니다. 이번 실습은 이 세 기능을 한 페이지에 모두 넣되, "**Baseline 상태 확인 → `@supports` 폴백 설계 → 점진적 향상**"이라는 이 과목 전체를 관통하는 절차(01_학습방향.md 깊이 기준 2번)를 마지막으로 한 번 더 반복해서 몸에 익힙니다.

세 기능이 푸는 문제는 각각 다릅니다. `@starting-style`은 "화면에 없던 것이 나타나는 순간"을, 뷰 전환은 "한 상태에서 다른 상태로 넘어가는 순간"을, 스크롤 연동 애니메이션은 "사용자가 스크롤하는 동안 계속 진행되는 움직임"을 다룹니다.

## 준비 — 무엇을 이미 안다고 전제하는가

`transition`·`animation`·`@keyframes`의 기본 문법과 타이밍 함수는 `content/css/css_fundamentals`에서 다뤘다고 전제합니다. 이 실습은 그 기본기 위에서 "예전에는 아예 안 됐던 것"에 집중합니다.

## 구현 절차

<Steps>

1. **`display: none` 전환이 안 됐던 문제를 `@starting-style`로 푼다**: 패널이 나타나고 사라질 때 페이드(fade, 서서히 사라짐)와 함께 `display`까지 애니메이션되도록 만든다.
2. **버튼 클릭 시 상태 전환에 뷰 전환을 적용한다**: `document.startViewTransition`으로 DOM 변경 전후를 자동으로 크로스페이드(crossfade)시키고, `view-transition-name`으로 특정 요소만 따로 애니메이션시킨다.
3. **스크롤 진행률 바를 스크롤 연동 애니메이션으로 만들고 `@supports` 폴백을 준비한다**: `animation-timeline: scroll()`을 지원하지 않는 브라우저를 위해 자바스크립트 스크롤 이벤트로 같은 결과를 흉내 낸 대체 코드를 함께 넣는다.
4. **`prefers-reduced-motion`으로 모션을 줄이길 원하는 사용자를 배려한다**: 세 기능 모두 애니메이션 지속 시간을 크게 줄이거나 없앤다.
5. **과목 전체의 완료 기준 다섯 가지를 점검한다**: `01_학습방향.md`가 제시한 체크리스트를 이 문서 마지막에서 직접 확인한다.

</Steps>

## 1단계 — @starting-style로 진입 애니메이션 만들기

오래된 CSS의 근본적인 한계 하나는 `display: none`과 `display: block` 사이에는 트랜지션이 걸리지 않는다는 것이었습니다. `display`는 **이산 값**(discrete value, 중간값이 없는 값)이라 브라우저가 "그 사이"를 계산할 방법이 없었기 때문입니다. `transition-behavior: allow-discrete`와 `@starting-style`이 이 문제를 함께 풉니다.

```css
.panel {
  display: none;
  opacity: 0;
  translate: 0 -8px;
  transition:
    opacity 240ms ease,
    translate 240ms ease,
    display 240ms allow-discrete;
}

.panel.is-open {
  display: block;
  opacity: 1;
  translate: 0 0;
}

/* 진입 애니메이션의 "시작 값"을 별도로 지정 */
@starting-style {
  .panel.is-open {
    opacity: 0;
    translate: 0 -8px;
  }
}
```

`transition`에 `display 240ms allow-discrete`를 추가하면, 브라우저는 `display: none`에서 `display: block`으로 바뀌는 순간 곧바로 `none`을 지우는 대신 **애니메이션이 끝날 때까지 `display: block`을 유지하다가 사라질 차례에만 마지막에 `none`으로 바꿉니다.** `@starting-style` 블록은 "이 요소가 방금 화면에 나타나는 바로 그 순간에는 이 값에서 출발하라"는 지시입니다. 이 블록이 없으면 `is-open`이 붙는 순간 목표값(`opacity: 1`)에서 바로 시작해 페이드인 효과가 사라집니다.

| 방식 | 이산 값(`display`) 전환 | 지원 상태 |
|------|--------------------------|-----------|
| `visibility` + `opacity`만 사용 | 레이아웃 공간은 계속 차지 | 널리 사용 가능 |
| `@starting-style` + `allow-discrete` | 레이아웃에서 완전히 빠졌다가 다시 참여 | 최신 브라우저 기준(2024-08 newly available) |

<Callout type="warning">
  **자주 틀리는 점:** `@starting-style`을 지원하지 않는 브라우저는 이 블록을 그냥 무시합니다. 그 결과 애니메이션 없이 즉시 나타나고 사라질 뿐 레이아웃이 깨지지는 않으므로, 폴백을 따로 작성하지 않아도 안전하게 성능이 저하(graceful degradation, 우아한 성능 저하)됩니다.
</Callout>

## 2단계 — 뷰 전환으로 상태 변화에 움직임 입히기

뷰 전환(View Transitions)은 "전"과 "후" 두 장의 스냅샷을 브라우저가 자동으로 찍어 크로스페이드시켜 주는 기능입니다. 같은 문서 안에서 상태가 바뀔 때 쓰는 것을 same-document(동일 문서) 뷰 전환이라 부르며, 이번 실습은 2025년 10월 Baseline newly available에 진입해 실무에 쓸 수 있는 단계인 이 부분만 다룹니다. 페이지 자체를 이동하는 cross-document(교차 문서) 전환은 아직 크로미움(Chromium) 계열에만 적용되는 제한적 기능이라 22편에서 이미 다룬 대로 이번 실습에서는 제외합니다.

```js
function 카운트올리기() {
  if (!document.startViewTransition) {
    // 뷰 전환 API 자체가 없는 브라우저 — 그냥 즉시 갱신
    갱신();
    return;
  }
  document.startViewTransition(() => 갱신());
}

function 갱신() {
  const 숫자칸 = document.getElementById("숫자");
  숫자칸.textContent = String(Number(숫자칸.textContent) + 1);
}
```

```css
#숫자 {
  view-transition-name: counter-number;
}
```

`view-transition-name`을 붙인 요소는 전체 화면을 뭉뚱그려 크로스페이드하는 대신 **그 요소만 따로** 옛 모습에서 새 모습으로 부드럽게 넘어갑니다. `document.startViewTransition` 자체가 없는 브라우저를 위해 `if (!document.startViewTransition)`로 기능 감지를 해 두면, 지원하지 않는 환경에서도 숫자는 정상적으로 바뀌고 애니메이션만 생략됩니다 — 이것이 자바스크립트 쪽 점진적 향상입니다.

## 3단계 — 스크롤 연동 애니메이션과 @supports 폴백

스크롤 연동 애니메이션은 애니메이션의 진행률을 시간이 아니라 **스크롤 위치**에 연결하는 기능입니다. `animation-timeline: scroll()`을 쓰면, 사용자가 스크롤을 40퍼센트 내렸을 때 애니메이션도 정확히 40퍼센트 진행된 상태로 멈춰 있습니다. 01편 사실 확인 표에서 짚었듯 이 기능은 2026년 9월 기준 **제한적**(Limited availability — not Baseline)입니다. 크로미움 계열이 중심이고 Safari·Firefox는 지원이 최근이거나 부분적이므로, 반드시 대체 수단을 함께 준비해야 합니다.

```css
.progress-bar {
  position: fixed;
  inset-block-start: 0;
  inset-inline-start: 0;
  block-size: 4px;
  background: var(--color-brand, #6941c6);
  inline-size: 0%;
}

@supports (animation-timeline: scroll()) {
  .progress-bar {
    animation: 진행률-채우기 linear;
    animation-timeline: scroll(root block);
    animation-range: 0% 100%;
  }

  @keyframes 진행률-채우기 {
    from { inline-size: 0%; }
    to { inline-size: 100%; }
  }
}
```

```js
// CSS 자체 기능으로 지원하지 않는 브라우저를 위한 자바스크립트 대체 구현
if (!CSS.supports("animation-timeline: scroll()")) {
  const 바 = document.querySelector(".progress-bar");
  window.addEventListener("scroll", () => {
    const 전체높이 = document.documentElement.scrollHeight - window.innerHeight;
    const 진행률 = 전체높이 > 0 ? (window.scrollY / 전체높이) * 100 : 0;
    바.style.inlineSize = 진행률 + "%";
  });
}
```

이 코드는 `@supports`(CSS 쪽 조건)와 `CSS.supports()`(자바스크립트 쪽 같은 조건)를 나란히 써서, **CSS 애니메이션을 지원하면 CSS가 계산을 전담하고, 지원하지 않으면 자바스크립트가 스크롤 이벤트로 같은 시각 효과를 대신 계산**하도록 역할을 완전히 나눕니다. 두 코드가 동시에 실행되는 일은 없습니다 — 조건이 서로 정반대이기 때문입니다.

<Callout type="warning">
  **자주 틀리는 점:** 웹 검색으로 얻은 요약 중에는 "스크롤 연동 애니메이션이 이미 전 브라우저에서 Baseline"이라고 소개하는 블로그 글이 있었지만, MDN 브라우저 호환성 표를 직접 대조한 결과 이는 **오검증된 틀린 정보**였습니다(01_학습방향.md). 이 과목처럼 표준이 빠르게 움직이는 주제는 블로그 요약이 아니라 MDN·webstatus.dev의 호환성 표를 그 시점에 직접 확인해야 합니다.
</Callout>

## 4단계 — prefers-reduced-motion 배려

모션에 민감하거나 전정 기관(vestibular, 균형 감각) 장애가 있는 사용자는 화면이 크게 움직이면 어지럼증을 느낄 수 있습니다. 운영체제 설정에서 "동작 줄이기"를 켠 사용자는 `prefers-reduced-motion: reduce` 미디어 특징으로 감지할 수 있습니다.

```css
@media (prefers-reduced-motion: reduce) {
  .panel,
  #숫자,
  .progress-bar {
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
  }
}
```

지속 시간을 0으로 만들지 않고 극히 짧은 값(0.01밀리초)으로 두는 이유는, 일부 브라우저가 지속 시간 0을 "트랜지션 없음"으로 취급해 `transitionend` 이벤트 자체가 발생하지 않는 경우가 있기 때문입니다. 그 이벤트에 의존하는 자바스크립트 로직이 있다면 이 값이 안전합니다.

## 접근성 — 모션 세 가지 모두에서 확인할 것

패널 버튼은 `aria-expanded`로 열림·닫힘 상태를 전달합니다. 뷰 전환은 순수하게 시각 효과이므로 스크린 리더가 읽는 콘텐츠(숫자 값 자체)에는 영향을 주지 않지만, 애니메이션이 진행되는 동안 포커스가 엉뚱한 곳으로 튀지 않는지 확인해야 합니다. 스크롤 진행률 바처럼 순전히 장식적인 요소는 `aria-hidden="true"`를 붙여 스크린 리더 탐색 목록에서 제외하는 것이 좋습니다. 세 기능 모두 `prefers-reduced-motion`을 확인하는 것이 접근성의 최소 기준입니다.

## 핵심 정리

- `@starting-style`과 `transition-behavior: allow-discrete`를 함께 쓰면 `display: none`처럼 중간값이 없는 이산 값도 트랜지션이 걸리며, 지원하지 않는 브라우저는 애니메이션 없이 안전하게 즉시 전환된다.
- same-document 뷰 전환(`document.startViewTransition`)은 2025년 10월 Baseline에 진입해 실무에 쓸 수 있는 단계이고, `view-transition-name`으로 특정 요소만 골라 애니메이션시킬 수 있다.
- 스크롤 연동 애니메이션(`animation-timeline: scroll()`)은 2026년 9월 기준 제한적 지원이다. `@supports`(CSS)와 `CSS.supports()`(자바스크립트)를 나란히 써서 지원 여부에 따라 계산 주체를 완전히 나누는 것이 안전한 폴백 설계다.
- `prefers-reduced-motion: reduce`를 감지해 지속 시간을 극히 짧게 줄이는 것이 모션 기능 전체에 공통으로 필요한 접근성 최소선이다.
- 이 과목의 완료 기준은 레이어·명시도 순서, 컨테이너 쿼리+서브그리드 컴포넌트, 색 토큰 시스템, Baseline 확인+`@supports` 폴백 설계, CSS 아키텍처 선택 근거 다섯 가지이며, 표준은 계속 움직이므로 확인 습관 자체가 최종 결과물이다.
