## 왜 스펙 읽는 법을 따로 배우는가

이 과목은 앞으로 22편 동안 계속 MDN(Mozilla Developer Network, 모질라 개발자 네트워크)과 WHATWG 문서를 인용합니다. 그런데 "링크가 있으니 궁금하면 클릭해 보세요"라고만 하면, 처음 보는 사람은 그 페이지에서 어디를 봐야 할지 몰라 그냥 닫아 버립니다. 이번 편은 지도 없이 원서를 펼치는 상황을 막기 위한 **사용 설명서**입니다. 두 문서를 정확히 구분하는 것부터 시작합니다.

> **쉽게 말하면:** WHATWG 문서는 법전이고, MDN은 그 법전을 풀어서 설명하는 참고서입니다. 법을 만드는 곳과, 그 법을 일반인이 이해하도록 정리해 주는 곳의 차이입니다.

| 구분 | WHATWG HTML Living Standard | MDN |
|------|------------------------------|-----|
| 성격 | 표준을 정의하는 1차 출처(primary source, 원전) | 표준을 풀어 설명하는 참고 문서 |
| 문체 | 알고리즘·정의 중심, 브라우저 구현자를 대상으로 함 | 예제·설명 중심, 개발자를 대상으로 함 |
| 정확도 | 최종 권위. 애매하면 여기가 정답 | 매우 정확하지만 스펙 자체는 아니다 |
| 쓰임새 | "정확히 어떻게 정의되어 있는가"를 확인할 때 | "이 요소를 실제로 어떻게 쓰는가"를 빠르게 익힐 때 |

## 1. MDN 레퍼런스 페이지 뜯어보기

### 요소 하나를 검색하면 나오는 화면

`<abbr>` 요소를 예로 들어 MDN 레퍼런스 페이지의 전형적인 구조를 봅니다. MDN의 HTML 요소 페이지는 대체로 다음 순서로 구성됩니다.

1. **요약(Summary)** — 이 요소가 무엇인지 한두 문단으로 설명
2. **속성(Attributes)** — 이 요소가 가질 수 있는 속성 목록과 각 속성의 의미
3. **콘텐츠 카테고리(Content categories)** — 이 요소가 어떤 분류에 속하는지(05편에서 자세히 다룹니다)
4. **허용되는 콘텐츠(Permitted content)** — 이 요소 안에 무엇을 넣을 수 있는지
5. **예제(Examples)** — 실제로 동작하는 코드 조각
6. **접근성 고려사항(Accessibility concerns)** — 스크린 리더 등 보조 기술과 관련된 주의점
7. **브라우저 호환성 표(Browser compatibility)** — 각 브라우저가 이 기능을 언제부터 지원했는지 정리한 표

이 순서를 알아 두면 "이 요소 안에 뭘 넣을 수 있지?"가 궁금할 때 곧장 4번 항목으로 건너뛸 수 있습니다. 매번 페이지 전체를 처음부터 읽을 필요가 없습니다.

### 브라우저 호환성 표 읽는 법

호환성 표는 크롬(Chrome)·엣지(Edge)·파이어폭스(Firefox)·사파리(Safari) 같은 주요 브라우저별로 "버전 몇부터 지원했는가"를 나타냅니다. 숫자가 적혀 있으면 그 버전부터 지원한다는 뜻이고, 표에 특정 셀이 비어 있거나 별도 표시가 있으면 부분 지원이나 제한 사항이 있다는 뜻이므로 각주를 반드시 확인해야 합니다.

<Callout type="warning">
  **자주 틀리는 점:** 호환성 표에 숫자가 있다고 해서 "모든 사용자 환경에서 100퍼센트 정상 동작한다"는 뜻은 아닙니다. 특정 옵션 값만 부분적으로 지원되거나, 오래된 버전 사용자가 실제로 얼마나 남아 있는지는 별개의 문제입니다. 이 과목에서 어떤 기능의 지원 상태를 이야기할 때는 "널리 사용 가능", "최신 브라우저 기준", "제한적·실험적" 세 단계로만 표현하고, 구체적인 점유율 수치는 지어내지 않습니다.
</Callout>

## 2. WHATWG 스펙 읽는 법

### 무서워 보이는 이유

WHATWG의 HTML Living Standard 페이지를 처음 열면 방대한 분량과 법률 문서 같은 문체에 압도되기 쉽습니다. 하지만 필요한 정보는 대개 특정 절(section, 섹션) 하나에만 있고, 전체를 처음부터 읽을 필요는 없습니다.

### 목차와 URL 구조 활용하기

WHATWG 스펙은 `https://html.spec.whatwg.org/multipage/` 뒤에 주제별 파일 이름이 붙는 구조입니다. 예를 들어 파싱 규칙은 `parsing.html`에, 폼 관련 요소는 `forms.html`에 모여 있습니다. 페이지 상단이나 사이드바의 목차에서 원하는 절을 찾아 클릭하면 그 절로 곧장 이동합니다. 이 과목의 각 편 끝 "참고 자료"에 있는 링크도 이런 식으로 구체적인 절까지 짚어 둔 것입니다.

### 정의문과 알고리즘 구분해서 읽기

스펙 문서 안에는 크게 두 종류의 글이 섞여 있습니다.

- **정의문(definition)** — "이 요소는 이런 콘텐츠 카테고리에 속한다"처럼 규칙을 선언하는 문장. 개발자가 실제로 알아야 하는 부분이 대부분 여기 있습니다.
- **알고리즘(algorithm)** — "1. 다음을 수행한다. 2. 만약 ~라면 3번으로 간다"처럼 브라우저 구현자가 코드로 옮길 수 있도록 단계별로 적은 절차. 파싱 규칙, 폼 제출 처리 같은 부분이 이런 식으로 적혀 있습니다.

개발자 입장에서는 알고리즘 절 전체를 한 줄씩 따라갈 필요는 거의 없습니다. 이 과목의 22편(브라우저 파싱)이나 16편(폼 제출)에서 알고리즘의 핵심만 골라 풀어서 설명하니, 처음부터 스펙의 알고리즘 절을 완독하려 하지 말고 "이 알고리즘이 왜 이런 순서로 되어 있는지 궁금할 때 원전을 확인한다"는 용도로 쓰면 충분합니다.

## 3. 지원 상태 표기를 판단하는 습관

### 왜 판단이 필요한가

HTML은 오래된 언어이다 보니, 인터넷에는 "예전엔 맞았지만 지금은 아닌" 설명이 많이 남아 있습니다. 반대로 최근에 추가된 기능은 아직 모든 브라우저가 지원하지 않을 수도 있습니다. 정보를 볼 때 다음 세 단계로 스스로 분류하는 습관을 들여야 합니다.

| 표기 | 의미 | 이 과목에서 쓰는 기준 |
|------|------|------------------------|
| 널리 사용 가능 | 오래전부터 있었고 사실상 모든 브라우저가 지원 | 별도 언급 없이 바로 사용 |
| 최신 브라우저 기준 | 비교적 최근 Baseline에 들어와 대부분 지원하지만 아주 오래된 환경은 예외일 수 있음 | 등장할 때 이 표기를 함께 적음 |
| 제한적·실험적 | 일부 브라우저만 지원하거나 아직 표준화 논의 중 | `@supports` 폴백이나 점진적 향상과 함께 소개 |

이 세 단계 표기는 `01_학습방향.md`의 "사실 확인 기준" 표에서 정한 규칙이며, 이 과목 전체에서 동일하게 적용됩니다. 예를 들어 04편에서 `<!doctype html>`을 다룰 때는 "널리 사용 가능"이라고 명시하고, 뒤에서 `html/modern_html` 과목으로 넘기는 기능들은 "이 과목에서는 다루지 않지만 그쪽에서 지원 상태를 확인한다"고 안내합니다.

### MDN의 실험적 표시 아이콘

MDN 페이지에는 제목 옆에 작은 아이콘으로 "실험적(Experimental)"이나 "표준이 아님(Non-standard)"을 표시해 두는 경우가 있습니다. 이런 표시가 있는 기능은 실무 코드에 그대로 쓰기 전에 반드시 호환성 표와 함께 확인해야 합니다. 이 과목의 범위(01_학습방향.md)에는 실험적 기능이 거의 없지만, `html/modern_html` 과목으로 넘어가면 이런 표시를 자주 만나게 됩니다.

<Callout type="warning">
  **자주 틀리는 점:** "MDN에 나와 있으니 최신 기능이어도 다 써도 된다"고 단정하면 안 됩니다. MDN은 실험 단계 기능도 문서화해 두는데, 이는 "존재한다"는 사실을 알리는 것이지 "지금 당장 프로덕션에 써도 안전하다"는 보증이 아닙니다. 호환성 표와 실험적 표시를 함께 확인하는 습관이 필요합니다.
</Callout>

## 핵심 정리

- WHATWG HTML Living Standard는 표준을 정의하는 1차 출처이고, MDN은 이를 풀어 설명하는 참고 문서다. 정확한 근거가 필요하면 WHATWG로, 빠른 사용법이 필요하면 MDN으로 간다.
- MDN 요소 페이지는 요약 → 속성 → 콘텐츠 카테고리 → 허용 콘텐츠 → 예제 → 접근성 → 브라우저 호환성 순서로 구성되며, 필요한 항목으로 바로 건너뛸 수 있다.
- WHATWG 스펙은 정의문과 알고리즘으로 나뉘며, 알고리즘 전체를 완독하기보다 필요할 때 원전 확인용으로 쓴다.
- 지원 상태는 "널리 사용 가능 / 최신 브라우저 기준 / 제한적·실험적" 세 단계로 판단하고, 수치를 지어내지 않는다.
- 호환성 표에 버전이 있다고 완전한 지원을 뜻하지 않으며, MDN의 실험적 표시는 사용 가능이 아니라 존재 사실만 알린다.
