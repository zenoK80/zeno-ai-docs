## 왜 링크 하나에도 이렇게 많은 규칙이 있는가

**하이퍼텍스트**(hypertext)라는 말은 01편에서 이미 다뤘습니다. HTML의 첫 글자 H가 바로 이 하이퍼텍스트에서 왔고, 그 핵심 기능이 문서와 문서를 연결하는 것입니다. 그 연결을 실제로 만드는 요소가 `<a>`(anchor, 닻 — 원래는 문서 안의 특정 지점에 "닻을 내려" 표시를 남긴다는 뜻에서 붙은 이름)입니다.

`<a>` 자체는 단순해 보이지만, `href`(hypertext reference, 하이퍼텍스트 참조) 속성에 들어가는 값의 형태에 따라 브라우저의 동작이 완전히 달라집니다. 같은 페이지 안에서 스크롤만 이동시킬 수도, 새 문서를 통째로 불러올 수도, 이메일 앱을 띄울 수도 있습니다. 이 편에서는 그 형태들을 하나씩 뜯어보고, 링크가 새 탭에서 열릴 때 반드시 챙겨야 할 보안 속성까지 다룹니다.

05편에서 배운 콘텐츠 카테고리 기준으로 `<a>`는 `href`가 있을 때 **interactive 콘텐츠**에 속하고, 콘텐츠 모델은 "Transparent"였습니다. 즉 `<a>`가 flow 콘텐츠 자리에 있으면 안에 flow를, phrasing 콘텐츠 자리에 있으면 안에 phrasing만 담되, 다른 interactive 콘텐츠(`<button>`, 다른 `<a>` 등)는 자식으로 넣을 수 없다는 규칙을 이미 배웠습니다.

## 1. href의 종류

### 절대 경로 — 완전한 주소

**절대 경로**(absolute path)는 스킴(scheme, 통신 방식)부터 시작하는 완전한 URL(Uniform Resource Locator, 자원 위치 지정자)입니다.

```html
<a href="https://developer.mozilla.org/">MDN으로 이동</a>
```

브라우저가 어느 페이지에서 클릭하든 항상 같은 곳으로 갑니다. 외부 사이트로 연결할 때는 절대 경로가 유일한 선택지입니다.

### 상대 경로 — 지금 문서를 기준으로

**상대 경로**(relative path)는 스킴과 호스트를 생략하고, **현재 문서의 위치를 기준**으로 계산되는 경로입니다. 같은 사이트 안의 다른 페이지로 이동할 때 주로 씁니다.

```html
<!-- 현재 문서: /html/html_fundamentals/07_links-and-navigation.html -->
<a href="08_images-basics.html">다음 편으로</a>
<!-- 실제로 이동하는 곳: /html/html_fundamentals/08_images-basics.html -->

<a href="../modern_html/01_intro.html">다른 과목으로</a>
<!-- ../ 는 한 단계 상위 폴더로 이동 -->

<a href="/">사이트 루트로</a>
<!-- 맨 앞의 / 는 도메인 바로 다음, 즉 사이트 루트를 가리킨다 -->
```

| 표기 | 계산 기준 | 예시 |
|------|-----------|------|
| `파일명.html` | 현재 문서와 같은 폴더 | `08_images-basics.html` |
| `../` | 한 단계 상위 폴더 | `../modern_html/01_intro.html` |
| `/`로 시작 | 사이트 루트(도메인 바로 다음)부터 | `/html/html_fundamentals/` |

<Callout type="warning">
  **자주 틀리는 점:** 상대 경로는 파일이 저장된 서버 디스크 위치가 아니라 **URL 경로**를 기준으로 계산됩니다. 로컬 컴퓨터에서 파일 탐색기 폴더 구조를 떠올리며 상대 경로를 짜면, 배포 서버의 URL 구조가 다를 때 링크가 깨집니다. 브라우저 주소창에 실제로 뜨는 URL 기준으로 생각해야 합니다.
</Callout>

### 프래그먼트 — 같은 문서 안의 특정 지점

**프래그먼트**(fragment, 조각)는 URL 끝에 `#`과 식별자를 붙여, 문서를 새로 불러오지 않고 그 안의 특정 요소로 스크롤 이동하는 방식입니다.

```html
<a href="#참고-자료">참고 자료로 바로가기</a>

<!-- 문서 어딘가에 이런 요소가 있어야 한다 -->
<h2 id="참고-자료">참고 자료</h2>
```

`href="#참고-자료"`는 같은 문서 안에서 `id="참고-자료"`를 가진 요소를 찾아 그 위치로 스크롤합니다. 다른 문서의 특정 지점으로 이동하고 싶다면 경로와 프래그먼트를 합칩니다.

```html
<a href="04_document-skeleton-and-head.html#head-메타데이터">04편의 메타데이터 부분으로</a>
```

`#` 하나만 있는 `href="#"`도 흔히 보이는데, 이는 "지금 문서의 맨 위"를 가리키는 관용적 표기입니다. 다만 실제로는 자바스크립트 이벤트 핸들러를 걸기 위한 임시 자리표시자로 쓰이는 경우가 많은데, 이는 이 과목 범위를 벗어나는 얘기이므로 `javascript/web_apis` 과목에서 다룹니다.

### mailto와 tel — 다른 프로그램을 여는 링크

`href`에 `mailto:`나 `tel:` 스킴을 쓰면 브라우저가 페이지를 이동하는 대신 **다른 프로그램을 실행**하도록 운영체제에 요청합니다.

```html
<a href="mailto:contact@example.com">이메일 보내기</a>
<a href="tel:+821012345678">전화 걸기</a>
```

`mailto:`는 쿼리스트링(query string, 물음표 뒤에 붙는 추가 정보)으로 제목·본문까지 미리 채울 수 있습니다.

```html
<a href="mailto:contact@example.com?subject=문의&body=안녕하세요">문의 메일 작성</a>
```

<Callout type="warning">
  **자주 틀리는 점:** `mailto:`/`tel:` 링크는 사용자 기기에 메일 클라이언트나 전화 앱이 연결되어 있지 않으면 아무 반응이 없거나 오류 화면이 뜰 수 있습니다. 데스크톱 환경에서는 특히 등록된 메일 프로그램이 없는 경우가 흔하므로, 중요한 연락처 정보는 눈에 보이는 텍스트로도 함께 제공하는 것이 안전합니다.
</Callout>

## 2. target — 어디에 열 것인가

`target` 속성은 링크를 클릭했을 때 결과 문서를 **어느 브라우징 컨텍스트**(browsing context, 탭·창·프레임 같은 문서가 표시되는 단위)에 표시할지 정합니다.

| 값 | 동작 |
|-----|------|
| `_self` | 현재 탭에서 열기 (기본값, 생략 시 동작) |
| `_blank` | 새 탭(또는 새 창)에서 열기 |
| `_parent` | 이 문서를 포함한 부모 프레임에서 열기 |
| `_top` | 최상위 브라우징 컨텍스트(모든 프레임을 벗어난 전체 창)에서 열기 |

```html
<a href="https://developer.mozilla.org/" target="_blank">새 탭에서 MDN 열기</a>
```

`_parent`와 `_top`은 `<iframe>`(인라인 프레임)으로 문서를 중첩했을 때만 의미가 있는 값이라, 이 과목에서는 존재만 언급하고 실습으로 다루지 않습니다. `<iframe>`은 embedded 콘텐츠로 05편에서 이름만 등장했던 요소입니다.

## 3. target="_blank"와 rel — 새 탭을 열 때 반드시 챙길 것

`target="_blank"`를 쓰면 새로 열린 탭이 원래 페이지의 `window` 객체에 `window.opener`라는 참조로 접근할 수 있게 됩니다. 이 자체는 편리한 기능(예: 새 탭에서 원래 탭을 다시 포커스하는 용도)이지만, 악의적인 외부 사이트로 연결하는 링크라면 그 사이트가 원래 탭의 주소를 바꿔치기하는 **탭내빙**(tabnabbing) 같은 공격에 악용될 수 있습니다.

이를 막기 위해 `rel`(relationship, 관계) 속성에 `noopener`를 함께 씁니다.

```html
<a href="https://외부사이트.example" target="_blank" rel="noopener noreferrer">외부 링크</a>
```

| rel 값 | 뜻 |
|--------|-----|
| `noopener` | 새 탭이 `window.opener`로 원래 탭에 접근하지 못하게 차단 |
| `noreferrer` | 새 탭으로 이동할 때 어느 페이지에서 왔는지(Referer 정보)를 전달하지 않음 |
| `nofollow` | 검색 엔진에게 "이 링크를 신뢰 투표로 취급하지 말라"고 알림(광고·사용자 게시물 링크 등에 사용) |
| `external` | 외부 사이트로 나가는 링크임을 표시하는 관용적 값 |

<Callout type="warning">
  **자주 틀리는 점:** "최신 브라우저는 `target="_blank"`만 써도 `noopener`를 자동으로 적용한다"는 설명을 보고 `rel` 속성을 생략하는 경우가 있습니다. 이 자동 적용은 **최신 브라우저 기준**으로는 대체로 사실이지만, 모든 환경·모든 브라우저 버전에서 동일하게 보장된다고 단정할 수는 없습니다. `rel="noopener"`를 명시적으로 쓰는 습관이 여전히 더 안전한 선택입니다.
</Callout>

## 4. rel의 다른 값들

`rel`은 보안 목적 외에도 문서 사이의 관계를 나타내는 다양한 값을 가질 수 있습니다.

```html
<link rel="stylesheet" href="styles.css">
<a rel="license" href="/license">라이선스 보기</a>
<a rel="author" href="/about">작성자 소개</a>
```

`<link>`에서 쓰이는 `rel="stylesheet"`처럼 metadata 콘텐츠에서도 등장하는데, `<a>`와 `<link>` 둘 다 "이 자원과 지금 문서의 관계가 무엇인가"를 표현한다는 점에서 같은 속성을 공유합니다.

## 5. 브라우저가 링크를 실제로 어떻게 처리하는가

아래 실습기에서 자바스크립트의 `URL` 객체(내장 API로, HTML 자체 기능은 아니지만 여기서는 관찰용으로만 사용합니다 — 자세한 내용은 `/javascript/web_apis` 과목 참조)를 이용해, 같은 상대 경로가 현재 문서 위치에 따라 실제로 어떤 절대 URL로 계산되는지 확인해 보세요.

### 접근성 관점 한 문단

링크 텍스트는 스크린 리더 사용자가 **문맥 없이 링크만 모아서** 훑어 듣는 기능(링크 목록 탐색)을 자주 사용한다는 점을 고려해 작성해야 합니다. "여기를 클릭하세요"나 "더보기"처럼 목적지를 알 수 없는 텍스트를 링크 목록에서 여러 개 들으면 어디로 가는 링크인지 구분할 수 없습니다. "07편: 링크와 내비게이션 읽기"처럼 링크 텍스트 자체에 목적지 정보를 담는 것이 좋습니다. 또한 `target="_blank"`로 새 탭을 여는 링크는 시각적으로 화면이 갑자기 바뀌지 않아 스크린 리더 사용자가 "새 탭이 열렸다"는 사실을 놓치기 쉬우므로, 링크 텍스트나 근처에 "(새 탭에서 열림)"과 같은 안내를 덧붙이는 것이 권장됩니다.

## 핵심 정리

- `href`는 절대 경로(완전한 URL), 상대 경로(현재 문서 기준), 프래그먼트(`#id`, 같은 문서 안 이동), `mailto:`/`tel:`(다른 프로그램 실행) 네 형태로 크게 나뉜다.
- 상대 경로는 파일 시스템이 아니라 브라우저 주소창에 뜨는 URL 경로를 기준으로 계산된다.
- `target="_blank"`로 새 탭을 열 때는 `rel="noopener noreferrer"`를 함께 써서 새 탭이 원래 탭을 조작하거나 출처 정보를 유출하지 못하게 막아야 한다.
- `rel`은 `nofollow`·`author`·`license` 등 링크가 가리키는 자원과 현재 문서의 관계를 나타내는 다양한 값을 가질 수 있다.
- 링크 텍스트는 "여기를 클릭"이 아니라 목적지를 알 수 있는 문구로 써야 스크린 리더의 링크 목록 탐색에서도 의미가 통한다.
