</Callout>

## 전역 속성이란 무엇인가

02편에서 속성(attribute)은 요소를 여는 태그 안에 이름과 값으로 붙는 추가 정보라고 배웠습니다. 그런데 `<img>`의 `src`나 `<a>`의 `href`처럼 **특정 요소에서만 의미가 있는 속성**이 있는가 하면, `<div>`든 `<p>`든 `<button>`이든 **어떤 요소에 붙여도 항상 똑같이 작동하는 속성**도 있습니다. 후자를 **전역 속성**(global attribute, 글로벌 어트리뷰트)이라고 부릅니다.

> **쉽게 말하면:** 전역 속성은 모든 요소가 공통으로 갖고 태어나는 옵션입니다. 어떤 자동차 모델을 사든 핸들과 브레이크가 기본으로 달려 있는 것과 같습니다.

이번 편에서 다루는 `id`·`class`·`style`·`title`·`lang`·`dir`·`hidden`·`tabindex`·`data-*`는 전부 이 전역 속성에 속합니다. 지금까지 06~11편에서 개별 요소의 전용 속성을 배웠다면, 이번 편은 그 요소들 **위에 얹어 쓸 수 있는 공통 도구 상자**를 정리하는 자리입니다.

## 1. `id`와 `class` — 이름표 두 종류

### 왜 둘 다 필요한가

문서 안의 특정 요소 하나를 콕 집어 가리키고 싶을 때도 있고, 여러 요소를 하나의 그룹으로 묶어 한꺼번에 다루고 싶을 때도 있습니다. `id`(identifier, 식별자)와 `class`(분류, 클래스)는 이 두 가지 서로 다른 필요에 대응합니다.

```html
<p id="공지-1">서버 점검 안내</p>
<p class="공지">이벤트 안내</p>
<p class="공지">배송 지연 안내</p>
```

### 비교

| 구분 | `id` | `class` |
|------|------|---------|
| 문서 안 유일성 | 문서 전체에서 **단 하나**만 가져야 함 | 여러 요소가 **같은 값을 공유** 가능 |
| 값 개수 | 요소 하나에 값 하나만 | 요소 하나에 여러 값을 공백으로 나열 가능(`class="공지 긴급"`) |
| CSS 선택자 | `#`(우물 정 기호) 접두사 | `.`(마침표) 접두사 |
| 대표 용도 | 페이지 내 특정 지점 이동(`#`을 붙인 프래그먼트 링크, 07편 참조), JS로 단일 요소 지정 | 여러 요소에 같은 스타일·동작을 반복 적용 |

CSS 문법 자체(선택자를 실제로 어떻게 쓰는지)는 `css/css_fundamentals` 과목에서 다루지만, `id`와 `class`가 애초에 **왜 두 개로 나뉘어 있는지**는 이 편에서 짚어야 할 개념입니다. "유일한 것 하나 vs 반복되는 분류"라는 구분이 스타일링뿐 아니라 자바스크립트로 요소를 찾을 때도(`javascript/web_apis` 과목 참조) 그대로 이어집니다.

<Callout type="warning">
  **자주 틀리는 점:** 같은 `id` 값을 문서 안에 두 번 쓰는 실수가 흔합니다. `id`는 유일해야 한다는 규칙이 있지만, 브라우저는 이 규칙을 어겨도 화면을 띄웁니다(22편에서 다룰 오류 복구 때문입니다). 다만 페이지 내 이동 링크나 `label`의 `for`(13편에서 다룰 예정) 연결이 첫 번째로 발견된 요소에만 적용되어 예상과 다르게 동작하므로, Nu HTML Checker(21편)로 반드시 중복 여부를 검증해야 합니다.
</Callout>

## 2. `style`과 `title` — 요소에 직접 얹는 두 정보

### `style` — 인라인 스타일

`style` 속성은 CSS 선언을 요소에 직접 적습니다.

```html
<p style="color: red;">중요 안내</p>
```

이 방식을 **인라인 스타일**(inline style)이라고 부릅니다. 값을 바로 확인할 수 있어 편리해 보이지만, 스타일 규칙이 여러 파일에 흩어져 유지보수가 어려워지므로 실무에서는 별도의 CSS 파일이나 `<style>` 요소를 쓰는 방식이 권장됩니다. CSS를 어디에 어떻게 적용하는지는 `css/css_fundamentals` 과목의 몫이며, 이 편에서는 "요소에 직접 스타일을 붙이는 속성이 존재한다"는 사실만 짚습니다.

### `title` — 보충 설명 툴팁

`title` 속성은 마우스를 요소 위에 올렸을 때 나타나는 짧은 보충 설명(툴팁)을 담습니다.

```html
<abbr title="Hypertext Markup Language">HTML</abbr>
```

`title`은 06편에서 다룬 `abbr`처럼 약어를 풀어 설명하는 용도로 특히 자주 쓰이지만, 어떤 요소에도 붙일 수 있는 전역 속성입니다.

<Callout type="warning">
  **자주 틀리는 점:** `title`을 필수 정보를 전달하는 유일한 수단으로 쓰면 안 됩니다. 툴팁은 마우스로 정확히 그 지점에 올려야만 보이므로, 터치스크린 사용자나 키보드만으로 탐색하는 사용자는 이 정보를 놓치기 쉽습니다. 중요한 정보는 화면에 항상 보이는 텍스트로 제공하고, `title`은 보조 정보에만 씁니다.
</Callout>

## 3. `lang`과 `dir` — 언어와 쓰기 방향

### `lang` — 이 텍스트가 어떤 언어인가

`lang` 속성은 요소 안 텍스트의 언어를 표준화된 언어 코드로 선언합니다. 04편에서 문서 전체의 언어를 `<html lang="ko">`처럼 최상위에 선언한다고 배웠는데, 문서 중간에 다른 언어가 섞여 들어가는 부분에도 각각 `lang`을 붙일 수 있습니다.

```html
<p>그는 <span lang="en">Good morning</span>이라고 인사했다.</p>
```

이 선언은 시각적으로는 아무 변화를 주지 않지만, 스크린 리더에는 결정적입니다. `lang="en"`이 없으면 한국어 음성 엔진이 "Good morning"을 한글 발음 규칙으로 억지로 읽어 알아들을 수 없는 소리를 냅니다. `lang`이 정확히 붙어 있으면 스크린 리더가 그 구간만 영어 음성 엔진으로 전환해 자연스럽게 읽습니다.

### `dir` — 텍스트가 흐르는 방향

`dir`(direction, 방향) 속성은 텍스트가 왼쪽에서 오른쪽으로 흐르는지, 오른쪽에서 왼쪽으로 흐르는지를 선언합니다.

| 값 | 뜻 |
|----|-----|
| `ltr` | left to right, 왼쪽에서 오른쪽(한국어·영어 등 대부분의 언어) |
| `rtl` | right to left, 오른쪽에서 왼쪽(아랍어·히브리어 등) |
| `auto` | 브라우저가 내용을 보고 자동 판단 |

```html
<p dir="rtl" lang="ar">مرحبا</p>
```

한국어만 다루는 문서에서는 `dir`을 거의 신경 쓸 일이 없지만, 아랍어·히브리어 콘텐츠가 섞이는 다국어 문서에서는 `dir`이 없으면 문장 전체의 읽기 순서 자체가 뒤집혀 보이는 문제가 생깁니다.

## 4. `hidden` — 요소를 통째로 감추기

**히든**(hidden, 숨김) 속성은 boolean 속성(02편에서 배운, 값 없이 이름만 적으면 참이 되는 속성 형식)으로, 요소 전체를 화면과 접근성 트리 양쪽에서 감춥니다.

```html
<p hidden>아직 공개되지 않은 내용입니다.</p>
```

`hidden`이 붙은 요소는 화면에 보이지 않을 뿐만 아니라, 스크린 리더도 이 요소를 완전히 건너뜁니다. 즉 "시각적으로만 숨기고 스크린 리더에는 읽히게" 하려는 목적에는 `hidden`이 맞지 않습니다(그런 경우는 CSS로 화면 밖에 배치하는 별도 기법이 필요하며, 이는 `css/css_fundamentals`·접근성 심화 주제입니다).

<Callout type="warning">
  **자주 틀리는 점:** CSS의 `display: none`과 `hidden` 속성은 결과가 거의 같아 보이지만 층이 다릅니다. `display: none`은 스타일 규칙이고, `hidden`은 HTML 속성입니다. 20편(접근성 기초)에서 `visibility`·`display`·`hidden`의 차이를 표로 다시 정리합니다.
</Callout>

## 5. `tabindex` — 키보드 탐색 순서

### 왜 필요한가

마우스 없이 `Tab` 키만으로 페이지를 이동하는 사용자에게는, 포커스(focus, 지금 조작 대상으로 선택된 상태)가 어떤 순서로 옮겨 다니는지가 핵심입니다. 기본적으로 링크(`a`)나 폼 요소(`input`·`button` 등)처럼 원래 상호작용 가능한 요소만 `Tab` 순서에 자동으로 포함됩니다. `<div>`나 `<span>`처럼 원래 포커스를 받지 않는 요소를 탐색 가능하게 만들거나, 순서를 바꾸고 싶을 때 `tabindex`를 씁니다.

| 값 | 동작 |
|----|------|
| `tabindex="0"` | 이 요소를 문서 순서대로 `Tab` 탐색에 포함시킨다 |
| 양수(`tabindex="3"`) | 지정한 숫자 순서대로 강제 배치한다 |
| `tabindex="-1"` | `Tab`으로는 도달할 수 없지만, 자바스크립트로 `focus()`를 호출해 포커스를 줄 수는 있다 |

```html
<div tabindex="0" role="button">클릭 또는 Enter로 실행</div>
```

<Callout type="warning">
  **자주 틀리는 점:** 양수 `tabindex`를 여러 요소에 남발하면 문서의 시각적 순서와 실제 `Tab` 이동 순서가 어긋나 사용자를 혼란스럽게 만듭니다. 실무에서는 대부분 `0`(순서에 끼워 넣기)과 `-1`(탐색에서 빼되 프로그램적으로는 포커스 가능)만 쓰고, 애초에 상호작용 요소(`button`·`a` 등)를 올바르게 골라 쓰면 `tabindex`를 아예 손댈 일이 줄어듭니다.
</Callout>

## 6. `data-*` — 커스텀 데이터 속성

### 왜 필요한가

HTML이 정의하지 않은, 이 페이지에서만 필요한 데이터를 요소에 붙이고 싶을 때가 있습니다. 예를 들어 상품 목록의 각 항목에 "재고 수량"이나 "상품 코드"를 마크업 안에 함께 담아 두고 싶은 경우입니다. 이런 값을 아무 이름의 속성에나 적으면(`stock="12"`처럼) 브라우저나 검증기가 "정의되지 않은 속성"이라고 오류를 낼 수 있습니다.

WHATWG는 이 문제를 위해 `data-`로 시작하는 이름은 전부 유효한 **커스텀 데이터 속성**(custom data attribute)으로 정의해 두었습니다.

```html
<li data-상품코드="A1029" data-재고="12">무선 마우스</li>
```

이렇게 담아둔 값은 `css/css_fundamentals`의 속성 선택자나 `javascript/web_apis`의 `dataset` API로 읽어올 수 있습니다(각 과목에서 자세히 다룹니다). 이 편에서 기억할 것은 **"data-로 시작하면 항상 유효한 속성이다"** 라는 규칙 자체와, 이 속성이 순전히 스크립트나 스타일링을 위한 저장 공간이지 사용자에게 직접 보여줄 정보가 아니라는 점입니다.

<Callout type="warning">
  **자주 틀리는 점:** `data-*`에 사용자가 반드시 봐야 하는 정보(가격, 설명 등)를 담아 놓고 화면에는 아무것도 표시하지 않는 경우가 있습니다. `data-*`는 화면에 자동으로 나타나지 않으므로, 사람이 봐야 할 정보라면 별도로 눈에 보이는 텍스트를 함께 마크업해야 합니다.
</Callout>

## 핵심 정리

- 전역 속성은 어떤 요소에도 똑같이 작동하는 공통 속성이다. `id`(문서 안 유일한 이름표)와 `class`(여러 요소가 공유하는 분류표)는 서로 다른 목적을 가진다.
- `style`은 인라인 스타일을, `title`은 마우스 오버 시 보이는 보충 설명을 담지만 필수 정보 전달 수단으로는 부적합하다.
- `lang`은 텍스트의 언어를(스크린 리더의 발음 엔진 전환에 직결), `dir`은 텍스트가 흐르는 방향을 선언한다.
- `hidden`은 요소를 화면과 접근성 트리 양쪽에서 완전히 제거하며, CSS의 `display: none`과는 층이 다르다. `tabindex`는 `Tab` 키 탐색 순서를 통제하며, `0`과 `-1`이 실무에서 가장 흔히 쓰인다.
- `data-`로 시작하는 이름은 항상 유효한 커스텀 데이터 속성이며, 화면에 자동으로 보이지 않으므로 스크립트·스타일 전용 저장 공간으로 쓴다.
