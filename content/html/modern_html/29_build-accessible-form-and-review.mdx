## 이번 편에서 만드는 것

12~15편에서 폼 입력 타입과 Constraint Validation API, 모바일 키보드 속성, `autocomplete` 토큰을 배웠고, 22~24편에서 메타데이터·JSON-LD·보안 속성을 배웠습니다. 이번 편은 이 두 축을 "회원가입 문의 폼" 한 페이지에 모두 모읍니다. 폼과 메타데이터는 서로 다른 주제처럼 보이지만, 실제 서비스 페이지 하나에는 **항상 함께** 존재합니다.

> **쉽게 말하면:** 실제로 배포해도 될 만큼 폼 검증과 문서 메타데이터를 함께 갖춘 페이지를 완성하는 실습입니다.

완성할 페이지의 요구사항은 다음과 같습니다.

1. 이메일·전화번호 입력에 알맞은 `type`과 `inputmode`, `autocomplete` 토큰을 붙인다.
2. Constraint Validation API로 이름 필드에 커스텀 오류 메시지를 붙이고, `:valid`/`:invalid`로 입력값에 따라 스타일이 바뀌게 한다.
3. `<head>`에 Open Graph 태그, `theme-color`, JSON-LD 구조화 데이터를 넣는다.
4. 외부 iframe에는 `sandbox`를, 외부로 나가는 링크에는 `rel="noopener noreferrer"`를 붙인다.
5. 마지막으로 이 과목 전체의 완료 기준 다섯 가지를 체크리스트로 점검한다.

## Steps로 조립하기

<Steps>

### 1단계 — 입력 타입과 모바일 속성 정하기

각 필드가 어떤 종류의 값을 받는지에 따라 `type`·`inputmode`·`autocomplete`를 함께 정합니다. 세 속성은 역할이 각각 다릅니다.

| 속성 | 역할 |
|---|---|
| `type` | 값의 형식을 정의하고 브라우저 내장 검증(형식 오류 표시, 네이티브 피커)을 켠다 |
| `inputmode` | 모바일 가상 키보드의 **레이아웃**만 바꾼다 (값 형식 검증과는 무관) |
| `autocomplete` | 이 필드가 무엇을 의미하는지 브라우저·비밀번호 관리자에게 알려 자동 채움을 가능하게 한다 |

```html
<label for="fullName">이름</label>
<input id="fullName" name="fullName" type="text" autocomplete="name" required minlength="2">

<label for="email">이메일</label>
<input id="email" name="email" type="email" inputmode="email" autocomplete="email" required>

<label for="phone">전화번호</label>
<input id="phone" name="phone" type="tel" inputmode="tel" autocomplete="tel" pattern="[0-9\-]{9,13}">
```

`type="tel"`은 값의 형식을 강제하지 않는 대신 국가별 전화번호 표기가 다양하다는 점을 인정한 설계입니다. 대신 `pattern`으로 우리 서비스가 원하는 형식을 직접 지정하고, `inputmode="tel"`로 모바일에서 숫자 키패드가 뜨게 합니다. 전통적인 입력 타입의 기본 동작 자체는 html_fundamentals 과목에서 다뤘으므로 여기서는 반복하지 않고, 이 세 속성을 **조합하는 판단 기준**에 집중합니다.

### 2단계 — Constraint Validation API로 커스텀 검증 메시지 붙이기

이름 필드에 숫자가 들어가면 브라우저 기본 오류 메시지 대신 우리 서비스의 문구를 보여주고 싶다고 합시다.

```js
const fullNameInput = document.getElementById('fullName');

fullNameInput.addEventListener('input', () => {
  const hasDigit = /\d/.test(fullNameInput.value);
  if (hasDigit) {
    fullNameInput.setCustomValidity('이름에는 숫자를 넣을 수 없습니다.');
  } else {
    fullNameInput.setCustomValidity('');
  }
});
```

`setCustomValidity`에 빈 문자열이 아닌 메시지를 넣으면 그 입력 요소는 `ValidityState`(값 검증 결과를 담는 객체)의 `customError` 플래그가 켜지면서 `:invalid`로 취급됩니다. **반드시 조건이 해소되면 다시 빈 문자열로 돌려놓아야** 합니다. 그렇지 않으면 값이 올바르게 바뀌어도 계속 오류 상태로 남습니다.

```css
input:user-invalid {
  border-color: #d92d20;
}

input:valid {
  border-color: #12b76a;
}
```

`:invalid`는 값이 비어 있는 첫 화면에도 곧바로 적용되어 사용자가 아직 아무것도 안 썼는데 빨간 테두리부터 보게 되는 경우가 많습니다. `:user-invalid`는 사용자가 실제로 값을 건드린 뒤에만 적용되는 의사 클래스라, 이런 문제를 피할 수 있습니다.

### 3단계 — 제출 시점에 reportValidity로 오류를 한 번에 알리기

```js
const form = document.getElementById('contactForm');

form.addEventListener('submit', (event) => {
  if (!form.checkValidity()) {
    event.preventDefault();
    form.reportValidity();
  }
});
```

`checkValidity()`는 폼 전체가 유효한지 참·거짓만 알려주고, 화면에 아무것도 띄우지 않습니다. `reportValidity()`는 유효하지 않은 첫 필드로 포커스를 옮기고 브라우저 내장 말풍선으로 오류 메시지를 보여줍니다. 이 둘을 나눠 쓰면 "검증 결과만 조용히 확인하고 싶을 때"와 "사용자에게 즉시 알리고 싶을 때"를 구분할 수 있습니다.

### 4단계 — 문서 메타데이터 채우기

폼 아래가 아니라 `<head>`에 들어가는 정보입니다. 소셜 공유·검색 결과·브라우저 UI 색상을 결정합니다.

```html
<meta property="og:title" content="문의하기 - 제노 서비스">
<meta property="og:description" content="궁금한 점을 남겨주시면 24시간 안에 답변드립니다.">
<meta property="og:image" content="https://example.com/og-contact.png">
<meta property="og:type" content="website">
<meta name="theme-color" content="#2563eb">

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "ContactPage",
  "name": "문의하기",
  "url": "https://example.com/contact"
}
</script>
```

Open Graph(OG) 태그는 메신저나 SNS에 링크를 붙였을 때 나오는 미리보기 카드를 구성합니다. `theme-color`는 모바일 브라우저의 주소창·상단 바 색상을 우리 서비스 색으로 맞춥니다. JSON-LD(JavaScript Object Notation for Linked Data, 연결된 데이터를 위한 JSON 표기법)는 검색 엔진에게 "이 페이지가 무엇인지"를 기계가 읽을 수 있는 형태로 알려주어, 검색 결과에 리치 스니펫(rich snippet, 일반 링크보다 정보가 풍부한 검색 결과 카드)이 뜰 가능성을 높입니다. 수치로 된 효과(클릭률 상승 몇 퍼센트 등)는 사이트·검색어마다 달라 이 문서에서 단정하지 않습니다.

### 5단계 — 보안 속성 붙이기

```html
<iframe
  src="https://example.com/map-widget"
  sandbox="allow-scripts allow-same-origin"
  title="오시는 길 지도"
  loading="lazy"
></iframe>

<p>
  자세한 이용약관은
  <a href="https://partner.example.com/terms" target="_blank" rel="noopener noreferrer">파트너사 페이지</a>
  에서 확인할 수 있습니다.
</p>

<meta http-equiv="Content-Security-Policy" content="default-src 'self'; img-src 'self' https:;">
```

`sandbox` 속성은 iframe 안 콘텐츠가 할 수 있는 일을 화이트리스트(허용 목록) 방식으로 제한합니다. 아무 토큰도 없는 `sandbox=""`는 스크립트 실행부터 폼 제출까지 거의 모두 막고, `allow-scripts`처럼 필요한 토큰만 하나씩 열어줍니다. `target="_blank"`로 새 탭을 여는 링크에 `rel="noopener"`를 빼먹으면 새로 열린 페이지의 자바스크립트가 `window.opener`를 통해 원래 페이지를 조작할 수 있는 보안 허점이 생깁니다. `noreferrer`는 여기에 더해 이동 전 페이지 주소(Referer 헤더)까지 상대 사이트에 넘기지 않습니다. CSP(Content Security Policy, 콘텐츠 보안 정책) `<meta>` 태그는 응답 헤더로 설정하는 CSP보다 적용 범위가 좁아(`frame-ancestors` 등 일부 지시문은 `<meta>`에서 동작하지 않습니다), 가능하면 서버 헤더를 우선하고 `<meta>`는 보조 수단으로 씁니다.

</Steps>

## 완료 기준 자가 점검

이 과목의 첫 편(01편)에서 다음 다섯 가지를 이 과목의 완료 기준으로 정했습니다. 27~29편의 실습을 마쳤다면 아래 각 항목을 실제로 설명할 수 있는지 스스로 점검하세요.

<Steps>

### 1. `<dialog>`로 포커스가 트랩되는 모달, popover로 라이트 디스미스되는 툴팁/메뉴를 JS 라이브러리 없이 만들 수 있다

27편에서 `showModal()`과 `popovertarget`만으로 두 오버레이를 구현했습니다. 별도의 모달 라이브러리 없이도 포커스 트랩과 라이트 디스미스가 브라우저 기본 동작으로 처리되는 것을 확인했다면 이 항목은 충족입니다.

### 2. `<details name>`으로 아코디언을, `inert`로 배경 비활성화를 JS 없이 구현할 수 있다

27편에서 `<details name="faq">` 세 개만으로 exclusive accordion을 만들었습니다. 다만 "처리 중인 임의 영역을 잠그기"처럼 브라우저가 자동으로 처리해주지 않는 경우에는 `inert`를 자바스크립트로 직접 켜고 꺼야 한다는 점도 함께 확인했는지 점검하세요.

### 3. `srcset`/`sizes`/`<picture>`/`loading`/`fetchpriority`를 조합해 화면 크기·우선순위에 맞는 이미지 로딩 전략을 설계할 수 있다

28편에서 히어로 이미지와 목록 이미지에 정반대의 로딩 전략을 적용했습니다. "이 이미지가 화면에 언제 보이는가"를 먼저 판단한 뒤 속성을 고르는 순서로 설명할 수 있다면 충족입니다.

### 4. 새 입력 타입과 Constraint Validation API로 서버 검증 이전에 브라우저 단에서 의미 있는 폼 검증을 구현할 수 있다

29편에서 `setCustomValidity`와 `reportValidity`로 커스텀 오류 메시지와 제출 시점 검증을 구현했습니다. 브라우저 단 검증은 사용자 경험을 돕는 보조 수단일 뿐, 서버 측 검증을 대체하지 않는다는 점도 함께 기억해야 합니다.

### 5. 어떤 기능을 프로덕션에 써도 되는지 MDN 호환성 표·Baseline 배지를 직접 찾아 스스로 판단할 수 있다

이 과목 전체에서 "널리 사용 가능 / 최신 브라우저 기준 / 제한적·실험적"이라는 세 단계 표기를 반복해서 봤습니다. 26편의 Customizable `<select>`처럼 아직 크로스 브라우저 지원이 없는 기능을 실무에 바로 쓰지 않는 판단을 스스로 내릴 수 있다면 이 과목의 목표를 달성한 것입니다.

</Steps>

## 핵심 정리

- `type`·`inputmode`·`autocomplete`는 각각 값 형식 검증, 모바일 키보드 레이아웃, 자동 채움이라는 서로 다른 역할을 맡으며 함께 조합해야 한다.
- `setCustomValidity`는 조건이 해소되면 반드시 빈 문자열로 되돌려야 하고, `checkValidity`는 조용히 확인만, `reportValidity`는 사용자에게 즉시 알린다.
- Open Graph·`theme-color`·JSON-LD는 폼과 별개로 `<head>`에서 공유·SEO를 담당하며, 리치 스니펫 여부는 검색 엔진의 판단에 달려 있어 수치로 단정하지 않는다.
- `sandbox`·`rel="noopener noreferrer"`·CSP `<meta>`는 각각 iframe 권한 제한, 새 탭 창 탈취 방지, 콘텐츠 출처 제한을 맡으며 CSP는 헤더 설정을 우선한다.
- 이 과목의 완료 기준은 기능을 암기하는 것이 아니라, 언제 브라우저가 자동으로 처리해주고 언제 개발자가 직접 판단해야 하는지 구분하는 능력이다.
