## 왜 선택자가 여러 종류인가

02편에서 `p`처럼 태그 이름 하나로 요소를 고르는 선택자를 봤습니다. 그런데 실무 페이지에는 문단(`<p>`)이 수십 개 있는데 그중 딱 하나만, 혹은 특정 그룹만 다르게 꾸며야 하는 상황이 항상 생깁니다. 태그 이름만으로 고르는 방법 하나로는 이런 "일부만 콕 집어 고르기"가 불가능합니다. 그래서 CSS는 "무엇을 기준으로 고를지"가 다른 여러 선택자 종류를 제공합니다.

> **쉽게 말하면:** 반 전체 학생을 부르는 방법은 여러 가지입니다. "학생 전원"(타입), "3분단 학생들"(클래스, 그룹), "출석번호 7번"(ID, 유일한 하나), "안경 쓴 학생 전원"(속성, 특징 기준) — 상황에 맞는 호출 방식을 고르는 것이 선택자 공부입니다.

## 타입 선택자 — 태그 이름으로 고르기

**타입 선택자**(type selector)는 HTML 태그 이름을 그대로 적어 그 태그로 만들어진 요소 전부를 고릅니다. 지금까지 써온 `p`, `h1`이 전부 타입 선택자입니다.

```css
p {
  line-height: 1.6;
}
```

이 규칙은 문서 안의 **모든** `<p>` 요소에 적용됩니다. 태그 하나가 대개 문서에 여러 개 있으므로, 타입 선택자는 "이 태그를 쓰는 요소는 기본적으로 다 이렇게 보여야 한다"는 전역 기본값을 정할 때 주로 씁니다.

## 클래스 선택자 — 그룹으로 고르기

**클래스 선택자**(class selector)는 마침표(`.`)를 앞에 붙여, HTML의 `class` 속성 값이 일치하는 요소들을 고릅니다.

```html
<p class="경고문">배터리가 부족합니다.</p>
<p class="경고문">저장 공간이 부족합니다.</p>
<p>이 문단은 평범한 문단입니다.</p>
```

```css
.경고문 {
  color: crimson;
  font-weight: bold;
}
```

`class="경고문"`을 가진 두 문단만 빨갛고 굵게 표시되고, 클래스가 없는 세 번째 문단은 영향을 받지 않습니다. 한 요소는 클래스를 여러 개 가질 수 있습니다. `class="경고문 강조"`처럼 공백으로 구분해 여러 개를 나열하면, `.경고문`과 `.강조` 선택자가 둘 다 이 요소에 적용됩니다. 클래스는 "재사용 가능한 이름표"입니다. 같은 클래스 이름을 문서 안 몇 개 요소에든 붙일 수 있습니다.

## ID 선택자 — 유일한 하나로 고르기

**ID 선택자**(ID selector)는 우물 정자(`#`)를 앞에 붙여, HTML의 `id` 속성 값이 일치하는 요소를 고릅니다.

```html
<header id="메인헤더">사이트 제목</header>
```

```css
#메인헤더 {
  background-color: navy;
  color: white;
}
```

**HTML 문서 규칙상 `id` 값은 한 문서 안에서 유일해야 합니다.** 같은 `id` 값을 두 요소에 붙이면 HTML 문법 위반이며(브라우저가 강제로 막지는 않지만 잘못된 마크업입니다), 자바스크립트의 `document.getElementById()` 같은 API도 첫 번째로 찾은 요소만 돌려줘 예측하기 어려워집니다.

## 전체 선택자 — 모든 것 고르기

**전체 선택자**(universal selector)는 별표(`*`) 하나로, 문서 안의 **모든** 요소를 고릅니다.

```css
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}
```

이 코드는 모든 요소의 기본 여백을 0으로 밀어버리는, 흔히 **리셋**(reset, 초기화)이라 부르는 관행에서 자주 쓰이는 패턴입니다. `box-sizing: border-box`를 전역으로 까는 이유는 11편(박스 모델)에서 정확히 다룹니다. 전체 선택자는 강력하지만 문서의 모든 요소를 훑어야 하므로, 아주 넓은 범위의 기본값을 정할 때가 아니면 잘 쓰지 않습니다.

## 속성 선택자 — 속성 존재·값으로 고르기

**속성 선택자**(attribute selector)는 대괄호(`[]`)를 써서, HTML 속성의 존재 여부나 값을 기준으로 요소를 고릅니다.

| 문법 | 의미 |
|------|------|
| `[attr]` | `attr`라는 속성을 **가지고 있기만** 하면 (값 무관) |
| `[attr="value"]` | `attr` 속성의 값이 정확히 `value`와 **일치**하면 |
| `[attr~="value"]` | `attr` 속성값이 공백으로 구분된 여러 단어 중 `value`를 **포함**하면 |
| `[attr^="value"]` | `attr` 속성값이 `value`로 **시작**하면 |
| `[attr$="value"]` | `attr` 속성값이 `value`로 **끝**나면 |
| `[attr*="value"]` | `attr` 속성값 어딘가에 `value`가 **포함**되면 |

```css
input[type="email"] {
  border-color: dodgerblue;
}

a[href^="https://"] {
  color: green;
}

a[href$=".pdf"]::after {
  content: " (PDF)";
}
```

첫 번째 규칙은 `input` 요소 중 `type` 속성값이 정확히 `email`인 것만 고릅니다(`<input type="email">`). 두 번째는 `href` 속성값이 `https://`로 시작하는 링크만 고릅니다. 세 번째는 `.pdf`로 끝나는 링크 뒤에 자동으로 "(PDF)" 문구를 붙입니다(`::after`와 `content`는 07편에서 자세히 다룹니다). 속성 선택자는 클래스를 따로 안 붙여도 이미 HTML에 있는 정보(입력 타입, 링크 주소 등)를 그대로 활용할 수 있어, 폼(form) 요소나 링크를 스타일링할 때 특히 유용합니다.

> **접근성 참고:** 폼 요소의 `type` 속성으로 스타일을 다르게 주는 것은 시각적 구분에만 의존하지 않고, 스크린 리더 사용자에게도 `<input type="email">`이 이메일 입력임을 전달하는 시맨틱(semantic, 의미) 정보와 함께 갑니다. 시각 스타일과 별개로 `type` 속성 자체를 정확히 쓰는 것이 접근성의 출발점입니다.

## 클래스 vs ID 사용 관행

두 선택자는 문법도 비슷하고 하는 일도 비슷해 보이지만(둘 다 HTML 속성값으로 요소를 고름), 실무에서는 용도를 명확히 나눠 씁니다.

| 구분 | 클래스(`.이름`) | ID(`#이름`) |
|------|------------------|-------------|
| 문서 안 개수 제한 | 여러 요소에 반복 사용 가능 | 문서 안에서 유일해야 함 |
| 한 요소에 여러 개 부여 | 가능(`class="a b c"`) | 불가능(요소당 `id`는 하나) |
| CSS에서의 주 용도 | 재사용 가능한 스타일 그룹 | 페이지 안 특정 지점을 가리키는 이정표 |
| 자바스크립트에서의 흔한 용도 | `querySelectorAll`로 여러 요소 다루기 | `getElementById`로 특정 요소 하나를 정확히 지목 |
| 명시도(09편에서 자세히) | 상대적으로 낮음 | 클래스보다 높아 나중에 재정의하기 어려움 |

실무 관행은 **스타일링은 클래스로, 페이지 내 이동 지점(앵커 링크의 목적지)이나 자바스크립트가 딱 하나의 요소를 정확히 지목해야 할 때만 ID로**입니다. ID를 스타일링에 남발하면, 나중에 그 스타일을 다른 요소에도 적용하고 싶을 때 ID는 "유일해야 한다"는 제약 때문에 재사용할 수 없어 코드를 복사하게 됩니다. 게다가 표에 적었듯 ID는 명시도가 높아서, 나중에 클래스로 그 스타일을 덮어쓰려 해도 잘 안 먹히는 상황이 자주 생깁니다. 이 문제의 정확한 원리는 09편(명시도)에서 다룹니다.

<Callout type="warning">
  **자주 틀리는 점:** 클래스는 마침표(`.`), ID는 우물 정자(`#`)입니다. HTML 쪽에서는 반대로 `class="..."`와 `id="..."`처럼 속성 이름 자체에 기호가 없다는 점도 함께 기억하십시오. CSS 선택자에서만 `.`과 `#` 기호가 붙습니다.
</Callout>

## 선택자를 조합할 때의 우선순위 직관

선택자를 이어 붙이면(공백 없이) "이 조건들을 **모두** 만족하는" 요소를 고릅니다.

```css
p.경고문 {
  text-decoration: underline;
}
```

이 규칙은 "`p` 태그이면서 동시에 `경고문` 클래스를 가진" 요소만 고릅니다. `<div class="경고문">`에는 적용되지 않습니다(태그가 `p`가 아니므로). 이렇게 여러 종류의 선택자를 이어 붙일수록 더 좁고 구체적인 대상을 고르게 되고, 대체로(항상은 아니지만) 더 구체적인 선택자가 캐스케이드에서 더 강하게 작용하는 경향이 있습니다. "왜" 더 강한지, 정확히 얼마나 강한지를 숫자로 계산하는 방법은 09편(명시도)의 핵심 주제입니다. 지금은 "좁혀 쓸수록 더 구체적이고, 구체적인 쪽이 대체로 이긴다"는 직관만 잡아 두십시오.

## 핵심 정리

- 타입 선택자(`p`)는 태그 이름 전부, 클래스 선택자(`.이름`)는 재사용 가능한 그룹, ID 선택자(`#이름`)는 문서 안 유일한 하나, 전체 선택자(`*`)는 모든 요소를 고른다.
- 속성 선택자(`[attr]`, `[attr="value"]` 등)는 HTML 속성의 존재·값을 기준으로 고르며, 폼 요소나 링크 스타일링에 특히 유용하다.
- 클래스는 재사용을, ID는 유일성을 위해 쓴다는 실무 관행이 있으며, ID를 스타일링에 남발하면 재사용성과 명시도 관리 양쪽에서 문제가 생긴다.
- 선택자를 이어 붙이면 모든 조건을 동시에 만족하는 요소만 고르며, 대체로 더 구체적인 선택자가 캐스케이드에서 더 강하게 작용한다(정확한 계산은 09편).
