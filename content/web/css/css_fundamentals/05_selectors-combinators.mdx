## 왜 관계로 골라야 하는가

04편에서 배운 타입·클래스·ID·속성 선택자는 전부 "요소 하나"를 고르는 방법이었습니다. 그런데 실제 화면은 요소가 혼자 있지 않습니다. 목록(`ul`) 안에 항목(`li`)이 있고, 항목 안에 링크(`a`)가 있는 식으로 **중첩된 구조**입니다.

만약 "이 목록 안의 링크만" 또는 "이 제목 바로 다음에 오는 문단만" 같은 요구를 클래스 없이 표현하고 싶다면, 요소 하나가 아니라 **요소 사이의 관계**를 선택자에 적어야 합니다. 그 관계를 표현하는 기호가 **결합자**(combinator, 결합 기호)입니다. "결합"이라는 한자어는 어렵게 들리지만 뜻은 단순합니다. 선택자 두 개를 이어 붙여 "이것 안(또는 옆)에 있는 저것"을 가리키는 접착제 역할을 합니다.

## 1. 자손 결합자 — 띄어쓰기 하나의 의미

### 정의와 예시

**자손 결합자**(descendant combinator, 후손 결합자)는 선택자 두 개를 **공백 한 칸**으로 이어 씁니다. 기호가 따로 있는 게 아니라 "빈칸 자체가 결합자"라는 점이 특이합니다.

> **쉽게 말하면:** `A B`는 "A 안 어딘가에 있는 B"입니다. 몇 겹 안에 있든 상관없습니다.

```css
nav a {
  color: navy;
}
```

이 규칙은 `nav` 요소 **내부에 있는 모든** `a` 요소를 고릅니다. `nav` 바로 아래에 있든, `nav` 안의 `ul` 안의 `li` 안에 있든, 몇 단계를 거쳐 들어가 있든 상관없이 전부 걸립니다.

```html
<nav>
  <ul>
    <li><a href="/">홈</a></li>
    <li><span><a href="/about">소개</a></span></li>
  </ul>
</nav>
```

위 마크업에서 `nav a`는 두 `a` 요소를 **모두** 고릅니다. 두 번째 `a`는 `nav` → `ul` → `li` → `span` → `a`로 4단계 아래에 있지만, 자손 결합자는 "몇 촌"인지 따지지 않고 "안에 있기만 하면" 통과시킵니다.

### 브라우저가 실제로 하는 일

브라우저는 이 선택자를 만나면 오른쪽 끝(`a`)에 맞는 요소를 먼저 찾고, 그 요소의 조상(ancestor, 부모의 부모…) 체인을 거슬러 올라가며 `nav`가 있는지 확인합니다. 이 방향(오른쪽에서 왼쪽)은 08~10편에서 다룰 캐스케이드 계산과 직접 관련은 없지만, 규칙이 많아질수록 왼쪽을 너무 넓게(예: `div span`) 잡으면 브라우저가 확인해야 할 조상 체인이 늘어나 스타일 계산 비용이 커진다는 점만 기억해 둡니다.

## 2. 자식 결합자 — 딱 한 단계만

### 정의와 예시

**자식 결합자**(child combinator)는 `>` 기호로 씁니다. 자손 결합자와 달리 **바로 한 단계 아래**에 있는 요소만 고릅니다.

> **쉽게 말하면:** `A > B`는 "A의 친자식인 B"입니다. 손주(`B`의 자식의 자식)는 해당하지 않습니다.

```css
nav > ul {
  list-style: none;
}
```

앞의 마크업에서 `nav > ul`은 `nav` 바로 아래의 `ul`만 고릅니다. 만약 `nav` 안에 `div`가 하나 끼어 있고 그 `div` 안에 `ul`이 있다면, `nav > ul`은 그 `ul`을 고르지 못합니다. `nav ul`(자손 결합자)이라면 여전히 고릅니다.

### 자손 vs 자식 — 표로 비교

| 구분 | `nav ul` (자손) | `nav > ul` (자식) |
|------|------------------|---------------------|
| 기호 | 공백 한 칸 | `>` |
| 걸리는 범위 | `nav` 내부 몇 단계든 전부 | `nav` 바로 아래 한 단계만 |
| `nav` → `div` → `ul` 구조에서 | 걸림 | 안 걸림 |
| 실무 선택 기준 | "안에만 있으면 다 적용" | "구조가 바뀌어도 이 계층만 정확히 적용" |

### 왜 자식 결합자가 필요한가

자손 결합자만 쓰면 편하지만 위험합니다. `nav ul`로 목록 스타일을 지정해 두면, 나중에 다른 개발자가 `nav` 안에 드롭다운 메뉴로 `ul`을 하나 더 중첩해 넣었을 때 **의도하지 않은 곳까지** 스타일이 번집니다. 자식 결합자는 "딱 이 계층 구조에서만"이라는 안전장치입니다. 실무에서 컴포넌트 단위로 CSS를 짤 때 자식 결합자를 선호하는 이유가 이것입니다.

## 3. 인접 형제 결합자 — 바로 다음 요소

### 정의와 예시

**형제**(sibling)는 같은 부모를 둔 요소들입니다. **인접 형제 결합자**(adjacent sibling combinator)는 `+` 기호로 쓰며, 어떤 요소 **바로 다음에 이어지는** 형제 하나만 고릅니다.

> **쉽게 말하면:** `A + B`는 "A 바로 뒤에 곧장 나오는 B". A와 B 사이에 다른 요소가 끼면 안 됩니다.

```css
h2 + p {
  margin-top: 0;
}
```

```html
<h2>제목</h2>
<p>이 문단은 h2 바로 뒤라서 걸립니다.</p>
<p>이 문단은 앞 p 뒤에 있어서 h2 + p로는 안 걸립니다.</p>
```

두 번째 `p`는 `h2`의 형제이긴 하지만 `h2` **바로 다음**이 아니라 첫 번째 `p` 다음에 있으므로 `h2 + p`가 고르지 못합니다. 대신 `p + p`라면 두 번째 문단이 걸립니다.

### 실전 용도

인접 형제 결합자는 "제목 바로 다음 문단의 위쪽 여백을 없앤다", "라디오 버튼(`input`) 바로 다음 라벨(`label`)만 강조한다"처럼 **레이아웃 순서에 의존하는 미세 조정**에 자주 쓰입니다.

## 4. 일반 형제 결합자 — 뒤에 나오는 모든 형제

### 정의와 예시

**일반 형제 결합자**(general sibling combinator)는 `~` 기호로 쓰며, 어떤 요소 뒤에 나오는 **같은 부모의 형제 전부**를 고릅니다. 바로 다음일 필요가 없습니다.

> **쉽게 말하면:** `A ~ B`는 "A보다 뒤에 있고 A와 형제인 B는 전부". 사이에 다른 요소가 몇 개 끼어도 상관없습니다.

```css
h2 ~ p {
  color: gray;
}
```

같은 마크업에서 `h2 ~ p`는 `h2` 뒤에 나오는 두 `p` 요소를 **모두** 고릅니다. `+`는 딱 하나(바로 다음)만, `~`는 그 뒤로 이어지는 전부를 고른다는 점이 유일한 차이입니다.

<Callout type="warning">
  **자주 틀리는 점:** 인접 형제(`+`)와 일반 형제(`~`)는 둘 다 "뒤에 나오는" 형제만 고릅니다. 앞에 나온 형제는 어떤 결합자로도 고를 수 없습니다. CSS는 이미 그려진 앞쪽 요소를 뒤쪽 요소 때문에 되돌아가 바꾸는 방향의 선택자를 지원하지 않습니다(이 한계를 채우는 `:has()`는 Modern CSS에서 다룹니다).
</Callout>

## 5. 네 결합자 한눈에 비교

| 결합자 | 기호 | 의미 | 예시 |
|--------|------|------|------|
| 자손 | 공백 | 내부 몇 단계든 전부 | `nav a` |
| 자식 | `>` | 바로 한 단계 아래만 | `nav > ul` |
| 인접 형제 | `+` | 바로 다음 형제 하나 | `h2 + p` |
| 일반 형제 | `~` | 뒤에 나오는 형제 전부 | `h2 ~ p` |

## 6. 선택자 목록 — 콤마로 규칙 묶기

결합자와 별개로, **선택자 목록**(selector list)은 콤마(`,`)로 여러 선택자를 나열해 **같은 선언 블록을 공유**하게 만드는 문법입니다.

```css
h1, h2, h3 {
  font-family: sans-serif;
}
```

이 규칙은 사실상 `h1 { font-family: sans-serif; }`, `h2 { font-family: sans-serif; }`, `h3 { font-family: sans-serif; }` 세 규칙을 하나로 압축한 것과 같습니다. 콤마는 결합자가 아니라 "규칙을 반복해서 쓰지 않기 위한 묶음 기호"라는 점에서 성격이 다릅니다.

<Callout type="warning">
  **자주 틀리는 점:** 콤마(`,`)와 공백(자손 결합자)을 헷갈리면 완전히 다른 결과가 나옵니다. `nav, a`는 "`nav` 요소 전부와 `a` 요소 전부"(관계 없음)이고, `nav a`는 "`nav` 안의 `a`"(포함 관계)입니다. 기호 하나 차이지만 뜻은 정반대입니다.
</Callout>

## 접근성 관점 한 문단

결합자 자체는 스크린 리더 동작에 영향을 주지 않습니다. 다만 `nav > ul > li > a`처럼 구조에 지나치게 의존한 선택자를 남발하면, 나중에 마크업 구조를 접근성 개선을 위해 바꿀 때(예: 의미 없는 `div`를 걷어내는 리팩터링) 선택자가 한꺼번에 깨지기 쉽습니다. 가능하면 구조 의존 선택자보다 의미 있는 클래스를 함께 두는 편이, 마크업이 바뀌어도 스타일이 버티게 하는 데 유리합니다.

## 핵심 정리

- 자손 결합자(공백)는 내부 몇 단계든 전부, 자식 결합자(`>`)는 바로 한 단계 아래만 고른다.
- 인접 형제 결합자(`+`)는 바로 다음 형제 하나, 일반 형제 결합자(`~`)는 그 뒤로 이어지는 형제 전부를 고른다.
- 네 결합자 모두 "뒤에 있거나 안에 있는" 방향으로만 작동하며, 앞쪽 요소를 뒤쪽 요소 조건으로 선택할 수는 없다.
- 콤마(`,`)는 결합자가 아니라 여러 독립된 선택자를 하나의 선언 블록에 묶는 선택자 목록 문법이다.
