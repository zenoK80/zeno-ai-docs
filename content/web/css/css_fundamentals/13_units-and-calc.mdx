<Callout type="info">
  **이번 문서의 목표:** 이 문서를 다 읽으면 `width: 50%`와 `font-size: 1.5em`이 "무엇의 50퍼센트", "무엇의 1.5배"인지 정확히 짚어낼 수 있고, `px`·`%`·`em`·`rem`·뷰포트 단위 중 상황에 맞는 것을 고르며, `calc()`로 단위가 다른 값끼리 계산식을 세울 수 있게 됩니다.
</Callout>

## 왜 단위부터 다시 짚어야 하는가

지금까지 색이나 배치를 이야기할 때 `10px`, `50%`, `1rem` 같은 값을 별생각 없이 써 왔습니다. 그런데 이 숫자 뒤에 붙는 짧은 문자 몇 개가 사실은 **"이 숫자를 어떤 기준으로 계산하라"는 지시**입니다. 기준을 착각하면 화면 크기를 바꿨을 때, 또는 부모 요소의 크기가 바뀌었을 때 레이아웃이 예상과 다르게 움직입니다. `10편`(상속과 값이 결정되는 4단계)에서 다룬 지정값(specified value)이 최종적으로 화면에 찍히는 실제값(actual value)이 되기까지, 단위는 그 계산 과정에서 "무엇을 곱할 것인가"를 정하는 역할을 합니다.

> **쉽게 말하면:** 단위는 자, 단위마다 눈금이 다른 자를 골라 쓰는 것과 같습니다. `px`는 항상 같은 길이의 눈금을 가진 자이고, `%`나 `em`은 옆에 있는 다른 물건(부모 크기, 글자 크기)에 맞춰 눈금 길이가 늘었다 줄었다 하는 고무 자입니다.

## 1. 절대 단위 — px, 흔들리지 않는 자

**절대 단위**(absolute unit)는 다른 어떤 값에도 의존하지 않고 항상 같은 크기를 가리키는 단위입니다. CSS에서 실무적으로 거의 유일하게 쓰이는 절대 단위가 **px**(픽셀, pixel)입니다.

여기서 중요한 함정이 하나 있습니다. `1px`이 실제 모니터의 물리적 점 1개와 같지 않다는 점입니다. CSS의 `px`는 **CSS 픽셀**(CSS reference pixel, 기준 픽셀)이라는 논리적 단위로, 팔 길이만큼 떨어진 화면에서 사람 눈에 비슷한 크기로 보이도록 브라우저가 계산해 둔 값입니다. 스마트폰처럼 화면 밀도가 높은 기기에서는 CSS 픽셀 1개가 물리적 점 여러 개(예: 3개)로 그려집니다. 이 배율을 **기기 픽셀 비율**(device pixel ratio, DPR)이라고 부르며, 이미지 해상도 대응 같은 심화 주제와 엮이지만 이 과목에서는 "px가 물리적 점과 1대1이 아니다"라는 사실만 기억하면 충분합니다.

```css
.box {
  width: 200px; /* 항상 200 CSS 픽셀. 부모나 글자 크기와 무관 */
  border: 1px solid #333;
}
```

<Callout type="warning">
  **자주 틀리는 점:** "px는 절대적이니까 어디서나 똑같이 보인다"고 생각하기 쉽지만, 사용자가 브라우저의 확대(zoom) 배율을 바꾸거나 운영체제의 글자 크기 설정을 바꾸면 px 값도 화면에서 실제로 차지하는 크기가 달라집니다. 완전히 고정된 것은 "다른 CSS 값에 대한 의존이 없다"는 점이지, "사용자 환경과 무관하다"는 뜻이 아닙니다.
</Callout>

## 2. 상대 단위 — 기준이 되는 것이 무엇인가

**상대 단위**(relative unit)는 다른 값을 기준 삼아 크기를 계산하는 단위입니다. 이 과목에서 가장 자주 쓰는 세 가지는 `%`, `em`, `rem`이며, 셋의 차이는 오직 **무엇을 기준으로 삼는가**입니다.

### %(퍼센트) — 부모(또는 관련 박스)의 크기 기준

`%`는 속성마다 기준이 되는 상자가 다릅니다. 가장 흔한 경우는 `width`·`height`가 **부모 요소의 콘텐츠 박스**를 기준으로 계산되는 것입니다.

```css
.parent {
  width: 400px;
}
.child {
  width: 50%; /* 부모 콘텐츠 박스 400px의 50% = 200px */
}
```

부모의 `width`가 바뀌면 자식의 실제 픽셀 크기도 함께 바뀝니다. 반응형 레이아웃의 가장 오래된 도구가 바로 이 성질입니다.

<Callout type="warning">
  **자주 틀리는 점:** `margin`이나 `padding`에 `%`를 쓰면, 위·아래 방향이라도 기준은 부모의 **너비**(width)입니다. 높이가 아닙니다. 이는 CSS 초기 사양에서 세로쓰기가 없던 시절 "블록 흐름의 가로 폭"을 기준으로 통일해 둔 규칙이 지금까지 이어진 것으로, 세로 여백을 퍼센트로 주다가 예상과 다른 값이 나오는 흔한 원인입니다.
</Callout>

### em — 요소 자신의(또는 부모의) 글자 크기 기준

**em**은 원래 인쇄 조판 용어로, 대문자 M자 하나의 너비만큼의 길이를 가리키던 단위입니다. CSS의 `em`은 **해당 요소에 적용된 `font-size`**를 1로 놓고 계산합니다.

```css
.card {
  font-size: 16px;
  padding: 1em;      /* 16px */
  margin-bottom: 2em; /* 32px */
}
```

여기서 반드시 짚어야 할 함정이 있습니다. `font-size` 자신에 `em`을 쓰면, 기준이 **자기 자신이 아니라 부모의 계산된 `font-size`**가 됩니다. 즉 `em`이 계속 곱해지며 누적됩니다.

```css
.outer { font-size: 20px; }
.outer .inner { font-size: 1.5em; } /* 20px × 1.5 = 30px */
.outer .inner .deepest { font-size: 1.5em; } /* 30px × 1.5 = 45px, 계속 누적 */
```

중첩된 요소마다 `font-size`를 `em`으로 지정하면, 깊이가 깊어질수록 의도치 않게 글자가 점점 커지거나 작아지는 **복리 효과**가 생깁니다. 이것이 다음에 나올 `rem`이 만들어진 이유입니다.

### rem — 문서 루트 하나만 기준

**rem**은 "root em"(루트 엠)의 줄임말로, 문서의 뿌리 요소인 `<html>`(HTML 문서 구조는 `html/html_fundamentals` 참조)의 `font-size` 딱 하나만을 기준으로 삼습니다. 얼마나 깊이 중첩되어 있든 기준이 바뀌지 않습니다.

```css
html { font-size: 16px; } /* 브라우저 기본값도 보통 16px */

.outer .inner .deepest {
  font-size: 1.5rem; /* 몇 겹으로 중첩되어도 항상 16px × 1.5 = 24px */
}
```

| 항목 | `em` | `rem` |
|------|------|-------|
| 기준 | 요소 자신의 `font-size`(단, `font-size` 속성 자체는 부모 기준) | `<html>`의 `font-size` 하나로 고정 |
| 중첩 시 | 값이 곱해져 누적될 수 있다 | 항상 같은 기준이라 예측이 쉽다 |
| 자주 쓰는 곳 | 한 컴포넌트 안에서 글자 크기에 비례한 여백(아이콘 간격 등) | 문서 전체의 일관된 글자 크기·간격 |

> **쉽게 말하면:** `rem`은 "학교 전체 공통 자(기준자)"이고, `em`은 "지금 서 있는 반의 담임 선생님 키"입니다. `em`은 반을 옮길 때마다(요소가 중첩될 때마다) 기준이 바뀔 수 있지만, `rem`은 학교(문서) 전체에서 하나뿐입니다.

<Callout type="warning">
  **자주 틀리는 점:** `<html>`의 `font-size`를 브라우저 기본값 `16px`이 아니라 다른 값으로 재정의해 두면(예: `62.5%`로 줄여 `1rem = 10px`처럼 계산하기 쉽게 만드는 관행), 사용자가 브라우저 설정에서 기본 글자 크기를 키워도 `rem` 기반 레이아웃은 그 비율을 그대로 따라갑니다. 이는 접근성 관점에서 오히려 장점입니다 — 사용자가 글자를 키우면 `rem`을 쓴 여백·글자 크기가 함께 커져 레이아웃이 깨지지 않고 자연스럽게 확대됩니다. 반대로 모든 값을 `px`로만 고정하면 사용자의 글자 크기 설정이 무시됩니다.
</Callout>

## 3. 뷰포트 단위 — 화면 자체를 기준으로

**뷰포트**(viewport)는 브라우저가 실제로 콘텐츠를 보여주는 화면 영역을 말합니다(웹 페이지를 내다보는 창문에 해당합니다). 뷰포트 단위는 이 창문의 가로·세로 크기를 기준으로 계산됩니다.

| 단위 | 기준 |
|------|------|
| `vw` | viewport width, 뷰포트 너비의 1퍼센트 |
| `vh` | viewport height, 뷰포트 높이의 1퍼센트 |
| `vmin` | 뷰포트의 너비와 높이 중 **더 작은 쪽**의 1퍼센트 |
| `vmax` | 뷰포트의 너비와 높이 중 **더 큰 쪽**의 1퍼센트 |

```css
.hero {
  width: 100vw;   /* 뷰포트 너비 전체 */
  height: 60vh;   /* 뷰포트 높이의 60퍼센트 */
}
.square {
  width: 20vmin;  /* 화면을 세로로 들어도 가로로 들어도 항상 짧은 변 기준 20퍼센트 */
  height: 20vmin;
}
```

`%`와 다른 점은, `%`는 부모 요소를 기준으로 삼지만 뷰포트 단위는 **부모가 무엇이든 상관없이 항상 브라우저 창 크기**를 기준으로 삼는다는 것입니다. 창을 넘어가는 요소를 부모 크기와 무관하게 화면 전체 폭에 맞추고 싶을 때(히어로 섹션의 배경 등) 주로 씁니다. HTML 문서에는 `<meta name="viewport">` 태그로 모바일 브라우저의 뷰포트 배율을 지정하는 관행이 있는데, 이는 `html/html_fundamentals`에서 다루는 내용이며 이 편의 미디어 쿼리·반응형 설계는 26편에서 이어집니다.

<Callout type="warning">
  **자주 틀리는 점:** `100vh`는 모바일 브라우저에서 주소창이 나타났다 사라졌다 하는 동안 값이 흔들릴 수 있습니다(주소창이 차지하는 영역을 뷰포트 높이에 넣을지 뺄지가 순간순간 바뀌기 때문입니다). 이 문제를 완화하는 동적 뷰포트 단위(`dvh` 등)는 비교적 최근에 Baseline에 들어온 기능이라 이 과목에서는 이름만 언급하고, 자세한 지원 상태와 활용은 `css/modern_css`로 넘깁니다.
</Callout>

## 4. calc() — 단위가 다른 값끼리 계산하기

지금까지의 단위는 서로 성격이 다릅니다. `px`는 고정, `%`는 부모 기준, `vw`는 화면 기준입니다. 그런데 실무에서는 "화면 전체 너비에서 고정된 사이드바 240픽셀을 뺀 나머지"처럼, **서로 다른 기준을 가진 값을 한 번에 계산**해야 하는 상황이 자주 생깁니다. 이럴 때 쓰는 함수가 **calc()**(calculate, 계산하다의 줄임)입니다.

```css
.content {
  width: calc(100% - 240px); /* 부모의 100%에서 240px을 뺀 나머지 */
}
.gap-aware {
  width: calc(100vw - 2rem); /* 화면 전체 너비에서 좌우 여백 1rem씩 뺀 값 */
}
```

`calc()`는 `+`, `-`, `*`, `/` 네 연산을 지원하며, 다음 세 가지 문법 규칙을 반드시 지켜야 합니다.

1. `+`와 `-` 앞뒤에는 **반드시 공백**이 있어야 합니다. `calc(100%-240px)`처럼 붙여 쓰면 파싱 오류로 무시됩니다.
2. `*`와 `/`는 둘 중 한쪽이 **단위 없는 순수 숫자**여야 합니다. `calc(100px * 2)`는 되지만 `calc(100px * 2px)`(둘 다 단위 있음)는 의미가 없어 오류입니다.
3. 서로 다른 단위끼리도 `+`, `-`로 섞을 수 있습니다. 브라우저가 계산 시점에 각 단위를 실제 픽셀 값으로 환산한 뒤 더하고 뺍니다.

  **자주 틀리는 점:** `calc(100% - 240px)`에서 `100%`가 정확히 무엇의 100퍼센트인지는 앞서 배운 `%`의 규칙 그대로, **부모 요소의 콘텐츠 박스**를 기준으로 계산됩니다. `calc()`는 계산 방식만 바꿀 뿐, 각 값이 원래 어떤 기준을 따르는지는 그대로 유지합니다.
</Callout>

## 5. 언제 무엇을 쓸까 — 실전 감각

| 상황 | 추천 단위 | 이유 |
|------|-----------|------|
| 테두리 두께, 그림자 오프셋처럼 항상 똑같아야 하는 값 | `px` | 부모나 글자 크기에 따라 흔들리면 안 되는 미세한 값 |
| 문서 전체의 글자 크기, 컴포넌트 간 공통 여백 | `rem` | 사용자의 글자 크기 설정을 존중하면서 일관성 유지 |
| 아이콘 옆 간격처럼 그 요소의 글자 크기에 비례해야 하는 값 | `em` | 글자가 커지면 간격도 같은 비율로 커져야 자연스러운 경우 |
| 부모 너비에 맞춰 늘었다 줄었다 해야 하는 카드·이미지 너비 | `%` | 부모 크기 변화에 그대로 따라가야 함 |
| 화면 전체를 채우는 히어로 섹션, 뷰포트에 비례한 여백 | `vw`/`vh`/`vmin` | 부모 크기와 무관하게 브라우저 창 자체가 기준이어야 함 |
| 고정 요소를 뺀 나머지, 서로 다른 기준값의 혼합 계산 | `calc()` | 단위가 다른 값끼리 한 번에 계산해야 할 때 |

## 핵심 정리

- 단위는 "이 숫자를 무엇을 기준으로 계산할지"를 정한다. `px`는 다른 값에 의존하지 않는 절대 단위, `%`·`em`·`rem`·뷰포트 단위는 각자 다른 기준(부모 크기, 자신 또는 부모의 글자 크기, `<html>`의 글자 크기, 뷰포트 크기)을 갖는 상대 단위다.
- `em`은 중첩될 때마다 값이 곱해져 누적될 수 있어 예측이 어렵고, `rem`은 항상 `<html>`의 `font-size` 하나만 기준으로 삼아 문서 전체에서 일관된 계산 결과를 준다.
- `vw`/`vh`/`vmin`/`vmax`는 부모가 아니라 브라우저 뷰포트 자체를 기준으로 삼는다.
- `calc()`는 단위가 다른 값끼리 `+`·`-`·`*`·`/`로 계산할 때 쓴다. `+`·`-` 앞뒤 공백은 필수이며, `*`·`/`는 한쪽이 단위 없는 숫자여야 한다.
