## 왜 타이포그래피가 레이아웃의 일부인가

글자는 단순히 "읽히는 것"이 아니라 **박스를 차지하는 콘텐츠**입니다. 글자 크기가 커지면 줄이 차지하는 높이가 늘어나고, 글꼴이 바뀌면 같은 글자 수라도 가로 폭이 달라지며, 줄 간격이 좁으면 글자끼리 겹쳐 보일 수도 있습니다. 즉 타이포그래피(typography, 활자 조판)는 `11편`(박스 모델)에서 배운 콘텐츠 박스의 크기 자체를 결정하는 요인입니다. 그래서 이 편은 "글자를 예쁘게 꾸미는 법"이 아니라 "글자가 차지하는 공간을 정확히 계산하는 법"으로 읽어야 합니다.

## 1. font-family — 글꼴 목록을 나열하는 이유

**font-family**는 사용할 글꼴의 이름을 지정하는 속성입니다. 그런데 보통 하나가 아니라 여러 개를 콤마로 나열합니다.

```css
body {
  font-family: 'Noto Sans KR', 'Malgun Gothic', sans-serif;
}
```

이 목록은 우선순위가 있는 **폴백 체인**(fallback chain, 대체 사슬)입니다. 브라우저는 왼쪽부터 순서대로 "이 글꼴이 사용자 기기에 설치되어 있는가?"를 확인하고, 없으면 다음 글꼴로 넘어갑니다. 목록의 마지막에는 항상 **글꼴군 키워드**를 두는 것이 관행입니다.

| 키워드 | 의미 |
|--------|------|
| `serif` | 획 끝에 삐침(세리프)이 있는 글꼴군 |
| `sans-serif` | 삐침이 없는 글꼴군(산세리프) |
| `monospace` | 모든 글자가 같은 너비를 갖는 글꼴군(코드 표시에 사용) |
| `cursive` | 손글씨풍 글꼴군 |

이 키워드는 특정 글꼴 이름이 아니라 "이 중 아무 글꼴도 못 찾으면 이 종류 중 브라우저 기본값을 써라"는 **최종 안전망**입니다. 목록에 이 키워드를 빠뜨리면, 나열한 글꼴이 전부 없는 기기에서 브라우저가 임의의 글꼴을 골라 디자인이 예측 불가능해집니다.

### 웹폰트 — @font-face로 직접 공급하기

사용자 기기에 원하는 글꼴이 설치되어 있지 않을 수도 있으므로, 글꼴 파일 자체를 서버에서 내려받게 하는 방법이 **@font-face**입니다.

```css
@font-face {
  font-family: 'PretendardVariable';
  src: url('/fonts/pretendard.woff2') format('woff2');
  font-weight: 100 900;
  font-display: swap;
}

body {
  font-family: 'PretendardVariable', sans-serif;
}
```

`@font-face`로 등록한 이름은 이후 `font-family`에서 마치 시스템 글꼴처럼 사용합니다. `font-display: swap`은 글꼴 파일이 아직 로드되지 않은 동안 폴백 글꼴로 먼저 텍스트를 보여주고, 로드가 끝나면 교체하라는 지시입니다(글꼴이 늦게 와도 텍스트 자체는 즉시 보이게 하는 관행입니다). 웹폰트 파일 최적화나 서브셋팅 같은 심화 주제는 이 과목의 범위 밖이며, 여기서는 "글꼴도 이미지처럼 네트워크로 내려받는 자원"이라는 개념만 잡으면 충분합니다.

## 2. font-size와 font-weight

**font-size**는 글자 크기이며, `13편`에서 다룬 단위(`px`, `rem`, `em`)를 그대로 씁니다. 문서 전체 기준값은 보통 `rem`으로, 컴포넌트 내부의 비례 조정은 `em`으로 하는 방식이 실무에서 흔합니다.

**font-weight**는 글자 굵기입니다. 숫자로 100(가장 얇음)부터 900(가장 굵음)까지 지정하며, `normal`(400)과 `bold`(700)는 그 숫자의 별칭입니다.

```css
p { font-weight: 400; }      /* normal과 동일 */
strong { font-weight: 700; } /* bold와 동일 */
h1 { font-weight: 800; }     /* 숫자로 더 세밀하게 지정 가능 */
```

<Callout type="warning">
  **자주 틀리는 점:** `font-weight: 800`처럼 시스템에 설치된 글꼴이 지원하지 않는 굵기를 지정해도 빌드나 렌더링 오류는 나지 않습니다. 브라우저가 가장 가까운 굵기로 대체해 보여주는데, 이 경우 진짜 글꼴 파일이 아니라 **인위적으로 두껍게 그려낸(faux bold, 가짜 볼드)** 흐릿한 글자가 나올 수 있습니다. 굵기별 글꼴 파일이 실제로 있는지 확인하는 것이 안전합니다.
</Callout>

## 3. line-height — 줄 간격이 계산되는 방식

**line-height**(줄 높이)는 한 줄의 텍스트가 차지하는 세로 공간을 정합니다. 글자 자체의 높이보다 보통 더 크게 잡아, 줄과 줄 사이에 여백을 만듭니다.

값을 주는 방법은 여러 가지지만, 계산 방식이 완전히 다른 두 그룹으로 나뉩니다.

### 단위 없는 숫자 — 그 요소 자신의 font-size에 비례

```css
.paragraph {
  font-size: 16px;
  line-height: 1.5; /* 16px × 1.5 = 24px */
}
```

단위 없는 숫자는 **비율**입니다. 자식 요소가 `font-size`를 다르게 가져가면, `line-height`도 자식의 새 `font-size`를 기준으로 다시 계산됩니다.

```css
.paragraph {
  font-size: 16px;
  line-height: 1.5; /* 이 자체는 24px이지만, 자식에게는 "1.5"라는 비율로 상속된다 */
}
.paragraph .큰글자 {
  font-size: 32px; /* line-height는 상속된 비율 1.5 × 32px = 48px로 재계산됨 */
}
```

### 고정 단위(px 등) — 계산된 값 그대로 상속

```css
.paragraph {
  font-size: 16px;
  line-height: 24px; /* 이미 계산이 끝난 값 */
}
.paragraph .큰글자 {
  font-size: 32px; /* line-height는 그대로 24px 물려받음 — 32px 글자에 24px 줄 높이는 너무 좁음 */
}
```

이 차이 때문에 실무에서는 **단위 없는 숫자**를 압도적으로 선호합니다. 자식 요소의 글자 크기가 달라져도 항상 그 자신의 크기에 비례한 줄 간격을 자동으로 얻기 때문입니다.

<Callout type="warning">
  **자주 틀리는 점:** `line-height`에 `px`나 `rem` 같은 고정 단위를 주면, 그 값이 **상속되는 것은 최종 계산값(px)이지 비율이 아닙니다.** 부모와 자식의 `font-size`가 다를 때 이 차이가 곧바로 줄 간격이 좁아지거나 넓어지는 버그로 나타납니다.
</Callout>

## 4. 텍스트 정렬과 줄바꿈

### text-align — 가로 정렬

```css
.center { text-align: center; }
.right { text-align: right; }
```

`text-align`은 인라인 콘텐츠(글자·인라인 요소)의 가로 위치를 정합니다. `16편`에서 다룰 블록 요소 자체의 위치(마진 자동 등)와는 다른 이야기입니다.

### white-space — 줄바꿈과 공백을 다루는 규칙

**white-space**는 소스 코드 안의 줄바꿈과 연속된 공백을 브라우저가 화면에 어떻게 반영할지 정합니다.

| 값 | 연속 공백 | 소스의 줄바꿈 | 넘칠 때 자동 줄바꿈 |
|-----|-----------|----------------|----------------------|
| `normal`(초기값) | 하나로 합침 | 무시함 | 함 |
| `nowrap` | 하나로 합침 | 무시함 | 안 함(한 줄로 계속 이어짐) |
| `pre` | 그대로 유지 | 그대로 반영 | 안 함 |
| `pre-wrap` | 그대로 유지 | 그대로 반영 | 함 |

`nowrap`은 "이 텍스트는 절대 두 줄로 꺾이면 안 된다"는 상황(버튼 라벨, 표 헤더 등)에 씁니다.

### text-overflow — 넘친 글자를 표시하는 방법

**text-overflow**는 박스보다 텍스트가 길어 넘칠 때, 넘친 부분을 어떻게 보여줄지 정합니다. 다만 이 속성 혼자서는 동작하지 않습니다. "한 줄로 유지하고(`white-space: nowrap`), 넘치는 부분은 숨기고(`overflow: hidden`), 그 지점에 말줄임표를 보여줘라(`text-overflow: ellipsis`)"라는 **세 속성의 조합**이 필요합니다.

```css
.카드제목 {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
  max-width: 200px;
}
```

  **접근성 관점:** `text-overflow: ellipsis`로 잘린 텍스트는 화면에서만 짧아 보일 뿐, 스크린 리더는 여전히 전체 텍스트를 읽어줍니다. 반대로 시각적으로 잘린 정보(예: 표 셀의 긴 값)가 사용자에게 꼭 필요하다면, `title` 속성(HTML 문서 구조는 `html/html_fundamentals` 참조)으로 마우스오버 시 전체 내용을 보여주는 보완을 함께 고려해야 합니다.
</Callout>

## 핵심 정리

- `font-family`는 콤마로 나열한 폴백 체인이며, 마지막에는 반드시 `serif`/`sans-serif` 같은 글꼴군 키워드를 두어야 어떤 기기에서도 예측 가능한 결과를 얻는다.
- `font-weight`는 100–900 숫자로 지정하며, 존재하지 않는 굵기는 브라우저가 가짜 볼드로 대체할 수 있다.
- `line-height`에 단위 없는 숫자를 주면 그 요소의 `font-size`에 비례하는 값으로 매번 재계산되어 상속되지만, 고정 단위를 주면 이미 계산이 끝난 값 그대로 상속되어 자식의 글자 크기가 다를 때 줄 간격이 어긋날 수 있다.
- 한 줄로 자르고 말줄임표를 보여주려면 `white-space: nowrap` + `overflow: hidden` + `text-overflow: ellipsis` 세 속성을 함께 써야 한다.
