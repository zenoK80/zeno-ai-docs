<Callout type="info">
  **이번 문서의 목표:** 이 문서를 다 읽으면 `@media` 규칙으로 화면 너비에 따라 CSS를 다르게 적용하고, 왜 실무에서 좁은 화면을 기준으로 먼저 설계하는지(모바일 우선)를 근거를 들어 설명하며, 브레이크포인트를 기기 이름이 아니라 콘텐츠 기준으로 정할 수 있게 됩니다.
</Callout>

## 왜 필요한가

지금까지 배운 Flexbox(20~22편)와 Grid(23~25편)로는 한 화면 크기에서의 레이아웃을 짤 수 있습니다. 하지만 같은 웹 페이지가 폭 360픽셀짜리 스마트폰 화면과 폭 1920픽셀짜리 모니터 화면에서 똑같은 모습으로 보이면 문제가 생깁니다. 3개 열로 짠 카드 그리드를 스마트폰이 그대로 렌더링하면 카드 하나의 너비가 100픽셀 남짓으로 찌그러들어 글자를 읽을 수 없습니다.

이 문제를 풀려면 "화면이 이 정도 너비 이상(또는 이하)일 때만 이 스타일을 적용해라"라는 **조건부 스타일링**이 필요합니다. 이를 가능하게 하는 것이 **미디어 쿼리**(media query, 매체 질의)입니다. 이름을 풀어보면 미디어(media, 매체 — 여기서는 화면·인쇄물 같은 출력 대상)에게 질의(query, 질문을 던져 조건을 확인하는 것)한다는 뜻입니다. "지금 이 화면이 어떤 조건에 해당하는지" 브라우저에게 묻고, 그 답에 따라 정해둔 스타일을 적용하는 구조입니다.

> **쉽게 말하면:** 미디어 쿼리는 "화면이 이만큼 넓으면 이 스타일, 아니면 저 스타일"을 나누는 CSS 안의 if문입니다.

## @media 문법 — 조건과 스타일 블록

미디어 쿼리는 `@media`로 시작하는 **at-규칙**(at-rule, `@`으로 시작하는 특수 규칙 — 08편에서 다룬 `@import`와 같은 종류입니다)입니다. 조건을 괄호 안에 쓰고, 그 조건이 참일 때 적용할 CSS 규칙을 중괄호 블록 안에 통째로 넣습니다.

```css
/* 화면 너비가 768px 이상일 때만 이 블록 안의 규칙이 적용된다 */
@media (min-width: 768px) {
  .card-grid {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

- `min-width`(최소 너비): 뷰포트(viewport, 브라우저가 실제로 콘텐츠를 그리는 화면 영역) 너비가 지정한 값 **이상**일 때 참이 됩니다.
- `max-width`(최대 너비): 뷰포트 너비가 지정한 값 **이하**일 때 참이 됩니다.

두 조건을 함께 쓰면 "이 구간에서만" 적용되는 스타일을 만들 수 있습니다.

```css
/* 480px 이상 768px 미만 구간에서만 적용 */
@media (min-width: 480px) and (max-width: 767px) {
  .sidebar {
    display: none;
  }
}
```

| 지원 상태 | 비고 |
|-----------|------|
| 널리 사용 가능 | `@media`와 `min-width`/`max-width` 문법은 오래전부터 모든 주요 브라우저가 지원하는 전통적인 방식이다. 최근 등장한 `(width >= 768px)` 같은 범위(range) 문법은 이 과목에서 다루지 않으며, 자매 과목 `css/modern_css`에서 다룬다 |

<Callout type="warning">
  **자주 틀리는 점:** `min-width`와 `max-width`의 방향을 헷갈리는 것입니다. `min-width: 768px`은 "768px **이상**일 때"이지 "768px **이하**일 때"가 아닙니다. "min(최소)이니까 좁은 화면 조건"이라고 거꾸로 외우면 계속 틀립니다. **min은 그 값을 넘어서야 참이 되는 하한선**이라고 기억하는 편이 정확합니다.
</Callout>

## 모바일 우선 vs 데스크톱 우선

미디어 쿼리를 어느 방향으로 쌓을지 정하는 두 가지 설계 철학이 있습니다.

- **데스크톱 우선**(desktop-first): 기본 CSS를 넓은 화면 기준으로 작성하고, `max-width`로 좁은 화면에서 스타일을 **줄여나가는** 방식.
- **모바일 우선**(mobile-first): 기본 CSS를 좁은 화면 기준으로 작성하고, `min-width`로 넓은 화면에서 스타일을 **더해나가는** 방식.

```css
/* 모바일 우선 — 기본값은 좁은 화면(1개 열), 넓어질수록 열이 늘어난다 */
.card-grid {
  display: grid;
  grid-template-columns: 1fr; /* 기본: 1개 열 */
}

@media (min-width: 600px) {
  .card-grid {
    grid-template-columns: repeat(2, 1fr); /* 600px 이상: 2개 열 */
  }
}

@media (min-width: 1024px) {
  .card-grid {
    grid-template-columns: repeat(3, 1fr); /* 1024px 이상: 3개 열 */
  }
}
```

실무에서는 **모바일 우선**이 사실상 표준으로 자리 잡았습니다. 이유는 두 가지입니다.

1. **접속 비중**: 전 세계 웹 트래픽에서 스마트폰 비중이 이미 절반을 넘어선 지 오래이므로, 가장 많은 사용자가 보는 화면을 기본값으로 두는 편이 합리적입니다.
2. **CSS 우선순위와의 궁합**: 08~09편에서 배운 캐스케이드는 소스 순서가 늦은 규칙이 (명시도가 같다면) 이깁니다. 모바일 우선 방식은 `min-width` 조건을 화면이 넓어질수록 순서대로 "추가"하는 구조라, 나중에 온 규칙이 이전 규칙 위에 자연스럽게 덧씌워집니다. 반대로 데스크톱 우선 방식은 넓은 화면용 스타일을 좁은 화면에서 `max-width`로 하나하나 "제거하거나 덮어써야" 하므로, 조건이 늘어날수록 어떤 규칙이 최종적으로 이겼는지 추적하기 어려워집니다.

> **쉽게 말하면:** 모바일 우선은 좁은 도화지에 기본 그림을 그려두고, 도화지가 넓어질 때마다 살을 붙이는 방식입니다. 데스크톱 우선은 큰 그림을 그려놓고 도화지가 좁아질 때마다 지우개로 지우는 방식이라, 지우다 보면 뭘 지웠는지 헷갈리기 쉽습니다.

## 브레이크포인트는 기기가 아니라 콘텐츠 기준으로

**브레이크포인트**(breakpoint, 분기점 — 레이아웃이 바뀌는 화면 너비 지점)를 정할 때 흔히 저지르는 실수가 "아이폰은 375px이니까 375px에서 바꾸자", "아이패드는 768px이니까 768px에서 바꾸자"처럼 **특정 기기의 화면 크기**를 기준으로 삼는 것입니다.

이 방식은 두 가지 이유로 오래가지 못합니다.

1. 기기 종류와 화면 크기는 계속 늘어나고 바뀝니다. 특정 기기 하나를 기준으로 삼으면 새 기기가 나올 때마다 브레이크포인트를 추가해야 합니다.
2. 같은 375px 너비라도 콘텐츠(글자 크기, 이미지, 카드 개수)에 따라 "언제 레이아웃이 어색해지는지"가 다릅니다.

그래서 실무 원칙은 **콘텐츠 기준**(content-based)입니다. 브라우저 창을 실제로 천천히 늘려보면서, 줄바꿈이 이상해지거나 카드가 너무 좁아지거나 여백이 답답해 보이는 **그 순간의 너비**를 브레이크포인트로 정합니다.

| 기준 | 기기 기준 브레이크포인트 | 콘텐츠 기준 브레이크포인트 |
|------|--------------------------|----------------------------|
| 정하는 방법 | "아이폰은 375px" 같은 특정 기기 값을 그대로 사용 | 창을 늘려보며 레이아웃이 어색해지는 지점을 직접 찾음 |
| 장기 유지보수 | 새 기기가 나올 때마다 값 추가 필요 | 콘텐츠가 안 바뀌면 계속 유효 |
| 정확도 | 우연히 그 기기에서만 맞음 | 실제 문제가 발생하는 지점과 일치 |

## HTML의 viewport 메타 태그와의 관계

미디어 쿼리가 제대로 동작하려면 반드시 HTML 문서의 `<head>` 안에 뷰포트 메타 태그가 있어야 합니다.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

이 태그가 없으면 모바일 브라우저는 페이지를 실제 화면 너비(예: 375px)가 아니라 약 980px 같은 가상의 넓은 캔버스로 렌더링한 뒤 축소해서 보여줍니다. 이 상태에서는 `min-width: 480px` 같은 조건이 스마트폰에서도 거짓으로 평가되어, 애써 만든 미디어 쿼리가 전혀 작동하지 않는 것처럼 보입니다. `width=device-width`는 "뷰포트 너비를 기기의 실제 화면 너비와 같게 하라"는 뜻이고, `initial-scale=1`은 "처음 로드될 때 확대·축소 배율을 1배(원본 크기)로 하라"는 뜻입니다. 이 태그 자체의 HTML 문법은 이미 안다고 가정하며 자세한 내용은 `/web/html/html_fundamentals` 과목을 참조하세요.

<Callout type="warning">
  **자주 틀리는 점:** viewport 메타 태그를 빠뜨린 채 "미디어 쿼리가 스마트폰에서 안 먹힌다"고 착각하는 것입니다. 실제로는 미디어 쿼리 자체는 정상이고, 뷰포트가 잘못 설정되어 브라우저가 엉뚱한 너비를 기준으로 계산하고 있는 경우가 대부분입니다.
</Callout>

## 접근성 관점

반응형 설계는 시각적 레이아웃뿐 아니라 접근성과도 직접 연결됩니다. 확대(zoom)해서 보는 저시력 사용자나, 화면을 세로로 길게 두고 쓰는 사용자에게는 뷰포트가 사실상 좁은 화면과 똑같은 상황이 됩니다. 모바일 우선으로 설계하면 좁은 화면에서도 콘텐츠가 한 줄로 읽기 쉽게 쌓이도록 이미 검증된 상태이므로, 별도의 추가 작업 없이도 확대 사용자·저시력 사용자에게 더 안정적인 경험을 제공하게 됩니다. 또한 `initial-scale=1`은 지정하되, 사용자의 확대·축소 자체를 막는 `user-scalable=no` 같은 설정은 저시력 사용자의 접근을 막으므로 피해야 합니다.

## 자주 틀리는 점

- **`min-width`와 `max-width`의 방향을 반대로 아는 것.** `min-width`는 그 값 이상일 때, `max-width`는 그 값 이하일 때 참이 됩니다.
- **브레이크포인트를 특정 기기 이름에 맞춰 정하는 것.** 기기는 계속 늘어나므로, 콘텐츠가 어색해지는 지점을 직접 찾아 정해야 오래갑니다.
- **viewport 메타 태그 없이 미디어 쿼리만 작성하는 것.** 이 태그가 없으면 모바일 브라우저가 실제 화면 너비를 기준으로 계산하지 않습니다.
- **데스크톱 우선으로 시작해 놓고 좁은 화면에서 하나씩 `display: none`으로 지워나가는 것.** 규칙이 늘어날수록 어떤 스타일이 최종적으로 적용됐는지 추적하기 어려워집니다.

## 핵심 정리

- `@media (min-width: 값)` 또는 `@media (max-width: 값)`으로 화면 너비 조건에 따라 CSS 블록을 조건부로 적용한다.
- 모바일 우선은 좁은 화면을 기본값으로 두고 `min-width`로 스타일을 더해나가는 방식이며, 캐스케이드의 소스 순서 규칙과 궁합이 좋아 실무 표준이다.
- 브레이크포인트는 특정 기기 크기가 아니라, 창을 늘려보며 레이아웃이 실제로 어색해지는 지점을 콘텐츠 기준으로 정한다.
- 뷰포트 메타 태그(`width=device-width, initial-scale=1`)가 없으면 미디어 쿼리가 모바일 브라우저에서 의도대로 동작하지 않는다.
