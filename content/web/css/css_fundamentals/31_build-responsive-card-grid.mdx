<Callout type="info">
  **이번 문서의 목표:** 이 문서를 다 읽고 실습기를 직접 완성하면, Grid로 전체 틀을 짜고 Flexbox로 각 카드 내부를 정렬하며 미디어 쿼리로 화면 폭에 따라 열 수를 바꾸는 반응형 카드 그리드를, 완성 코드를 보지 않고도 처음부터 만들 수 있게 됩니다.
</Callout>

## 이번 편에서 만드는 것

23~26편에서 배운 Grid 트랙, Flexbox 정렬, 미디어 쿼리를 한 화면에 모읍니다. 실무에서 상품 목록·블로그 글 목록·팀원 소개 페이지에 가장 흔하게 쓰이는 레이아웃인 **반응형 카드 그리드**를 요구사항부터 완성 코드까지 직접 만들어 봅니다.

완성할 페이지의 요구사항은 다음과 같습니다.

1. 화면 폭이 좁을 때(모바일)는 카드가 **1열**로 쌓인다.
2. 화면 폭이 600px 이상이면 **2열**, 900px 이상이면 **3열**로 자동 조정된다.
3. 각 카드는 이미지·제목·설명·버튼을 세로로 담되, 설명 길이가 서로 달라도 버튼은 항상 카드 맨 아래에 나란히 맞춰진다.
4. 카드 사이 간격과 카드 안쪽 여백은 `rem` 단위로, 카드 목록 전체의 좌우 여백은 `calc()`로 계산한다.

왜 이 요구사항 하나에 Grid와 Flexbox가 동시에 필요한지가 25편의 결론과 정확히 맞물립니다. **카드들을 몇 개의 열로 늘어놓는 큰 틀**은 2차원 문제(가로 위치와 세로 위치를 동시에 신경 써야 함)라 Grid가 맞고, **카드 하나 내부에서 이미지-제목-설명-버튼을 세로로 쌓고 버튼만 바닥에 붙이는 것**은 한 방향으로 흐르는 1차원 문제라 Flexbox가 맞습니다.

## Steps로 조립하기

<Steps>

### 1단계 — 뼈대 HTML 작성하기

먼저 카드 4개가 들어갈 목록 구조를 잡습니다. 각 카드는 이미지, 제목, 설명, 버튼을 담습니다.

```html
<main class="컨테이너">

  <ul class="카드그리드">

      <p>노을 시간대에 걷기 좋은 완만한 3km 코스입니다.</p>
      <button type="button">코스 담기</button>
    </li>
    <li class="카드">
      <img src="https://picsum.photos/seed/2/300/180" alt="숲속 등산로">

      <p>초보자도 무리 없이 오를 수 있는 완만한 경사의 산길로, 중간에 쉼터가 두 곳 있어 여유롭게 휴식하며 오를 수 있습니다.</p>
      <button type="button">코스 담기</button>
    </li>
    <li class="카드">
      <img src="https://picsum.photos/seed/3/300/180" alt="도심 야경 코스">
      <h2>도심 야경 코스</h2>
      <p>퇴근 후 가볍게 걷기 좋은 야경 명소 코스입니다.</p>
      <button type="button">코스 담기</button>
    </li>
    <li class="카드">
      <img src="https://picsum.photos/seed/4/300/180" alt="강변 자전거길">

      <button type="button">코스 담기</button>
    </li>
  </ul>

```

목록 요소로 `ul`을 쓴 이유는 카드 여러 장이 "같은 종류의 항목이 나열된 것"이라는 의미를 시맨틱하게 담기 때문입니다. `list-style`은 뒤에서 CSS로 제거합니다.

### 2단계 — Grid로 전체 틀 짜기

```css
.카드그리드 {
  display: grid;
  grid-template-columns: 1fr;   /* 모바일 기본값: 1열 */
  gap: 1.25rem;
  list-style: none;
  padding: 0;
  margin: 0;
}
```

`grid-template-columns: 1fr`은 트랙(track)을 하나만 만들고 그 트랙이 컨테이너 너비를 전부 차지하게 합니다. `fr`(fraction, 부분) 단위는 23편에서 배운 대로 "남는 공간을 비율로 나눠 가지라"는 뜻이므로, 트랙이 하나뿐이면 결과적으로 전체 너비를 그대로 가져갑니다. `gap`은 `1.25rem`으로 지정해 13편에서 배운 상대 단위 중 루트(root, 최상위) 요소의 글자 크기를 기준으로 삼는 `rem`을 그대로 씁니다. 사용자가 브라우저 글자 크기를 키우면 간격도 함께 늘어나야 자연스럽기 때문입니다.

### 3단계 — Flexbox로 카드 내부 정렬하기

```css
.카드 {
  display: flex;
  flex-direction: column;
  background: white;
  border: 1px solid #dee2e6;
  border-radius: 12px;
  padding: 1rem;
  box-sizing: border-box;
}

.카드 img {
  width: 100%;
  border-radius: 8px;
  margin-bottom: 0.75rem;
}

.카드 h2 {
  font-size: 1.1rem;
  margin: 0 0 0.5rem;
}

.카드 p {
  margin: 0 0 1rem;
  color: #495057;
  line-height: 1.5;
}

.카드 button {
  margin-top: auto;   /* 21편의 자동 마진 — 버튼을 카드 맨 아래로 밀어낸다 */
  padding: 0.6rem 1rem;
  border: none;
  border-radius: 6px;
  background: #339af0;
  color: white;
  font-weight: 600;
  cursor: pointer;
}
```

`flex-direction: column`으로 카드 내부의 메인 축을 세로로 바꾸면, `margin-top: auto`를 받은 버튼은 21편에서 확인했던 "남는 공간을 전부 자기 앞으로 끌어와 밀어내는" 자동 마진 규칙에 따라 카드 맨 아래에 붙습니다. 두 번째 카드의 설명이 더 길어 카드 전체 높이가 달라져도, 버튼은 항상 각 카드의 바닥선에 맞춰집니다. `box-sizing: border-box`(11편)를 함께 줘 `padding`을 늘려도 카드 폭 자체는 변하지 않게 고정했습니다.

### 4단계 — 미디어 쿼리로 열 수 조정하기

```css
@media (min-width: 600px) {
  .카드그리드 {
    grid-template-columns: repeat(2, 1fr);
  }
}

@media (min-width: 900px) {
  .카드그리드 {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

26편에서 배운 **모바일 우선**(mobile-first) 원칙 그대로, 기본값(2단계에서 정한 `1fr` 한 열)을 가장 좁은 화면 기준으로 두고, `min-width`로 화면이 넓어질 때마다 규칙을 **추가**했습니다. `repeat(2, 1fr)`은 `1fr 1fr`을 반복해서 적은 것과 완전히 같은 뜻이며, 열 개수가 늘어나도 반복 횟수만 바꾸면 되므로 트랙을 일일이 나열하는 것보다 실수가 적습니다.

<Callout type="warning">
  **자주 틀리는 점:** `max-width`로 "좁아지면 줄이는" 방식으로 거꾸로 설계하면, 가장 많은 사용자가 접속하는 모바일 화면의 스타일이 미디어 쿼리 안에 갇혀 우선순위 관리가 헷갈리기 쉽습니다. 26편에서 다뤘듯, 이 과목에서는 `min-width` 기반 모바일 우선 설계를 원칙으로 삼습니다.
</Callout>

### 5단계 — 컨테이너 좌우 여백을 calc()로 계산하기

```css
.컨테이너 {
  max-width: 960px;
  margin: 0 auto;
  padding: 1.5rem calc(1rem + 2vw);
}
```

좌우 `padding`을 고정된 `1rem`이 아니라 `calc(1rem + 2vw)`로 지정했습니다. 13편에서 배운 대로 `vw`(viewport width, 뷰포트 너비)는 화면 폭의 1퍼센트를 나타내는 단위이므로, 화면이 넓어질수록 좌우 여백이 함께 조금씩 넓어져 카드 그리드가 화면 가장자리에 너무 바짝 붙지 않게 됩니다. `calc()`는 서로 다른 단위(`rem`과 `vw`)를 섞어 계산할 수 있는 유일한 방법이라는 것을 13편에서 확인했습니다.

</Steps>

## 마무리 점검

완성 코드를 DevTools(30편)로 직접 검사해 보세요. `.카드그리드`에 뜨는 `grid` 배지를 눌러 오버레이를 켜면 화면 폭에 따라 트랙 개수가 실제로 바뀌는 것이 격자선으로 보이고, 카드 하나를 선택해 `flex` 배지를 누르면 세로로 흐르는 메인 축과 버튼을 밀어낸 자동 마진의 빈 공간이 함께 보입니다. 지금까지 배운 두 도구가 실제로 어떻게 협력하는지, 코드가 아니라 화면에서 확인하는 것이 이 실습의 마지막 목표입니다.

## 핵심 정리

- 카드 여러 장을 몇 개의 열로 배치하는 큰 틀은 2차원 문제이므로 Grid가 맡고, 카드 하나 내부의 세로 정렬은 1차원 문제이므로 Flexbox가 맡는다.
- `grid-template-columns: repeat(n, 1fr)`은 균등한 n개 트랙을 만드는 관용구이며, 미디어 쿼리의 `min-width` 값이 커질 때마다 반복 횟수만 늘려 열 수를 조정한다.
- `margin-top: auto`는 `flex-direction: column` 컨테이너 안에서 카드 내용 길이가 서로 달라도 버튼을 항상 바닥에 고정하는 실전 패턴이다.
- `rem`은 사용자의 글자 크기 설정에 반응하는 간격에, `vw`는 화면 폭에 비례하는 여백에 적합하며, `calc()`로 두 단위를 섞어 계산할 수 있다.
- 완성한 레이아웃은 DevTools의 Grid·Flexbox 오버레이로 실제 트랙과 축을 시각적으로 재확인하는 것이 좋은 마무리 습관이다.
