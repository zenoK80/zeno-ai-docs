## 개념 정리

`@layer`는 스타일시트를 이름 붙은 여러 층으로 나누는 규칙이다. `@layer`는 기존 캐스케이드 순서 위에 **레이어 순서**라는 우선순위를 하나 더 얹는다.

| 규칙 | 설명 |
|------|------|
| 레이어 순서가 명시도보다 우선한다 | 명시도가 낮아도 **나중 레이어**가 이긴다 |
| 레이어 순서는 등장 순서가 아니라 **선언한 순서**다 | `@layer reset, tokens, base, components, utilities;`로 순서를 미리 고정한다 |
| unlayered 스타일은 **항상 모든 레이어를 이긴다** | `@layer` 밖에 적은 규칙은 명시도와 무관하게 최우선이다. 외부 라이브러리 CSS를 레이어에 넣으면 내 커스텀 CSS가 항상 이긴다 |
| 같은 이름의 `@layer` 블록은 여러 파일에 나눠 적어도 하나로 합쳐진다 | `tokens.css`, `styles.css`에 각각 `@layer base { ... }`를 적어도 같은 레이어로 병합된다 |

레이어 이름은 역할별로 5개로 나눈다.

| 레이어 | 담는 내용 |
|--------|-----------|
| `reset` | 브라우저 기본값 제거(`box-sizing`, `margin`) |
| `tokens` | 커스텀 속성(색·간격·타이포 변수) |
| `base` | 기본 요소 스타일(`body`, `img`, `a`) |
| `components` | 클래스 단위 컴포넌트 |
| `utilities` | 한 가지 스타일만 강제하는 예외용 클래스. 항상 마지막 |

순서 선언은 **프로젝트에 한 번만** 쓴다. `tokens.css`(가장 먼저 로드되는 파일) 맨 위에 적어, 이후 어떤 파일이 레이어 블록을 추가하든 순서가 고정되게 한다.

## 실습

<Steps>

### 1. tokens.css 수정

```css
/* portfolio/css/tokens.css */
@layer reset, tokens, base, components, utilities;

@layer tokens {
  :root {
    --color-bg: #ffffff;
    --color-surface: #f6f7f9;
    --color-text: #1f2328;
    --color-text-muted: #59636e;
    --color-primary: #0969da;
    --color-primary-hover: #0550ae;
    --color-border: #d0d7de;
    --color-accent: #bf3989;

    --font-sans: "Pretendard", "Noto Sans KR", system-ui, sans-serif;
    --font-mono: "JetBrains Mono", ui-monospace, monospace;
    --text-xs: 0.75rem;
    --text-sm: 0.875rem;
    --text-base: 1rem;
    --text-lg: 1.25rem;
    --text-xl: 1.5rem;
    --text-2xl: 2rem;

    --leading: 1.6;

    --space-2: 0.5rem;
```

`tokens.css`가 `styles.css`보다 먼저 로드되므로, 순서 선언을 여기 맨 위에 둔다. `styles.css`에서 레이어 블록이 어떤 순서로 나오든 최종 우선순위는 이 문장을 따른다.

`components`보다 `utilities`가 **나중** 레이어라 버튼은 분홍색(`u-bg-accent`)으로 보인다. 첫 줄을 `@layer utilities, components;`로 바꿔 순서를 뒤집으면, 명시도는 그대로인데 버튼이 파란색(`button`)으로 바뀐다 — **레이어 순서가 명시도보다 먼저 판정된다**는 뜻이다.

- 개발자 도구 `Styles` 패널에서 버튼을 선택하면 규칙 옆에 레이어 이름이 표시된다.

## 직접 해보기

1. `order-demo.css`에 `reset` 레이어를 추가해 `button { all: unset; }`을 넣는다. 순서를 `reset, components, utilities`로 두면 버튼이 어떻게 보이는지 확인한다.
2. `portfolio/css/styles.css`의 `utilities` 레이어에 `.u-mt-0 { margin-top: 0; }`를 추가하고 프로젝트 카드의 `button[data-open-project]`에 임시로 붙여, `components`의 `margin-top: auto`를 이기는지 확인한다(확인 후 제거한다).

<details>
<summary>정답 예시</summary>

1. `reset`이 가장 먼저라 `all: unset`이 먼저 적용되고, 이후 `components`의 배경·글자색이 다시 씌워진다.
2. `u-mt-0`를 `button[data-open-project]`에 붙이면 카드 아래쪽 여백이 사라진다. `utilities`가 나중 레이어라 명시도가 같아도 이긴다.

</details>

## 자주 하는 실수

| 증상 | 원인 | 고치는 법 |
|------|------|-----------|
| 레이어로 나눴는데 스타일이 안 먹는다 | unlayered 규칙과 섞여 있다 | unlayered는 항상 이긴다. 레이어 안으로 옮긴다 |
| 레이어 순서를 파일마다 다르게 선언했다 | `tokens.css`, `styles.css`에 서로 다른 순서를 적었다 | 순서 선언은 **한 번만** 둔다 |
| `@media`가 레이어 안에서 안 먹는다고 착각했다 | 실제로는 정상 동작한다 | `@layer` 안 `@media`는 정상이다. 선택자 오타를 먼저 의심한다 |
