</Callout>

## 왜 그룹 선택자가 필요해졌는가

CSS를 쓰다 보면 서로 다른 여러 조상 아래에 있는 같은 태그에 같은 스타일을 주고 싶을 때가 자주 있습니다.

```css
header a:hover,
main a:hover,
footer a:hover {
  text-decoration: underline;
}
```

`header`, `main`, `footer` 세 조상 아래의 `a:hover`에 똑같은 규칙을 주려고 선택자 목록(selector list)을 콤마로 나열했습니다. 조상이 두 개, 세 개면 이렇게 나열해도 괜찮습니다. 그런데 조합이 늘어나면 문제가 생깁니다.

```css
header nav a,
header nav a:visited,
main article a,
main article a:visited,
footer nav a,
footer nav a:visited {
  color: royalblue;
}
```

조상 3개 곱하기 상태 2개만 돼도 여섯 줄입니다. 조상이 하나 더 늘면 또 두 줄이 늘어납니다. **같은 뒷부분(`a`, `a:visited`)을 매번 손으로 반복해서 곱하는 것**이 문제의 본질입니다. 이 반복을 없애기 위해 표준화된 것이 **`:is()`와 `:where()`**입니다.

> **쉽게 말하면:** `:is()`와 `:where()`는 수학의 인수분해와 같습니다. `ab + ac`를 `a(b + c)`로 묶듯이, "header 아래거나 main 아래거나 footer 아래인 a"를 조상 부분만 괄호 안에 묶어버립니다.

## 기본 문법 — 목록을 괄호 안으로

```css
/* 이전: 선택자 목록을 매번 나열 */
header a:hover,
main a:hover,
footer a:hover {
  text-decoration: underline;
}

/* :is()로 압축 */
:is(header, main, footer) a:hover {
  text-decoration: underline;
}
```

`:is(header, main, footer)`는 "header이거나 main이거나 footer인 요소"를 뜻하는 하나의 선택자로 동작합니다. 그 뒤에 이어지는 `a:hover`는 이렇게 압축된 조상들 **각각의 자손** `a:hover`를 가리킵니다. 즉 브라우저 입장에서는 앞서 콤마로 나열한 세 줄짜리 선택자와 완전히 동일하게 해석합니다. `:is()`는 묶어서 쓰는 **문법적 단축키**일 뿐, 새로운 매칭 규칙을 만드는 것이 아닙니다.

앞의 여섯 줄짜리 예시도 이렇게 줄어듭니다.

```css
:is(header nav, main article, footer nav) :is(a, a:visited) {
  color: royalblue;
}
```

## `:is()`와 `:where()`의 유일한 차이 — 명시도

`:is()`와 `:where()`는 **매칭 대상이 완전히 동일**합니다. 어떤 요소를 고르는지는 둘이 똑같이 동작합니다. 차이는 딱 하나, **명시도를 계산하는 방식**입니다.

| 함수 | 명시도 계산 방식 |
|---|---|
| `:is(선택자목록)` | 목록 안에서 **가장 명시도가 높은 선택자**의 값을 통째로 가져온다 |
| `:where(선택자목록)` | 목록 안에 무엇이 있든 상관없이 **항상 (0, 0, 0)** — 명시도가 아예 없는 것으로 취급 |

```css
/* :is() 안에 ID 선택자가 하나 섞여 있으면, 전체 명시도가 ID 선택자 수준으로 올라간다 */
:is(#sidebar, .card, article) p {
  color: gray;
}
/* 명시도 = (1, 0, 1) — #sidebar의 (1,0,0)이 가장 높으므로 그 값 + p의 (0,0,1) */

/* :where()는 안에 무엇이 있든 명시도가 0이다 */
:where(#sidebar, .card, article) p {
  color: gray;
}
/* 명시도 = (0, 0, 1) — where() 부분은 통째로 0으로 계산, + p의 (0,0,1) */
```

CSS Fundamentals 09편에서 배운 (a, b, c) 튜플 계산법을 그대로 적용하면, `:is()`는 "목록 중 최댓값을 대표로 세우는 그룹"이고, `:where()`는 "그룹 전체를 명시도 계산에서 투명 인간 취급"하는 것입니다.

<Callout type="warning">
  **자주 틀리는 점:** "`:is()`와 `:where()`는 성능 차이만 있고 결과는 똑같다"고 오해하는 것입니다. 매칭 결과(어떤 요소가 선택되는지)는 똑같지만, **다른 규칙과 충돌했을 때 누가 이기는지는 명시도에 따라 완전히 달라집니다.** 이건 성능 문제가 아니라 우선순위 설계의 문제입니다.
</Callout>

## `:where()`가 명시도 0이라서 유용한 이유

명시도가 0이라는 것이 왜 실전에서 강력한 무기가 될까요? 바로 **"나중에 아무나 쉽게 덮어쓸 수 있는 기본값"을 만들 때** 그렇습니다.

디자인 시스템이나 컴포넌트 라이브러리를 만든다고 생각해 봅시다. 기본 스타일을 여러 선택자 조합으로 주고 싶지만, 이 스타일을 나중에 사용하는 쪽에서 **클래스 하나만 붙여도 쉽게 덮어쓸 수 있게** 하고 싶습니다.

```css
/* :is()로 기본 스타일을 주면 명시도가 예상보다 높아져 나중에 덮어쓰기 어렵다 */
:is(article, aside, section) h2 {
  font-size: 1.25rem;
}
/* 명시도 (0, 0, 2) — 타입 선택자 2개 수준 */

/* 사용하는 쪽에서 클래스 하나로 덮어쓰려 하면... */
.custom-heading {
  font-size: 2rem;
}
/* 명시도 (0, 1, 0) — (0,0,2)보다 b 자리가 커서 실제로는 이긴다.
   하지만 조상 목록이 늘어날수록, 또는 목록 안에 ID가 섞이면
   예상 밖으로 명시도가 튀어 오를 위험이 항상 남는다 */
```

이런 위험을 원천 차단하려고 컴포넌트 라이브러리의 기본 스타일은 흔히 `:where()`로 감쌉니다.

```css
:where(article, aside, section) h2 {
  font-size: 1.25rem;
}
/* 명시도 (0, 0, 1) — where() 부분이 0이 되어 h2 하나만큼만 계산된다 */

.custom-heading {
  font-size: 2rem;
}
/* 명시도 (0, 1, 0) — 확실하고 예측 가능하게 이긴다 */
```

> **쉽게 말하면:** `:where()`로 감싼 스타일은 "덮어써 주세요"라는 팻말을 붙인 기본값입니다. 나중에 누가 클래스 하나만 붙여도 걱정 없이 이길 수 있습니다.

이 패턴은 3편에서 배운 캐스케이드 레이어(`@layer`)와 함께 쓰이는 경우가 많습니다. 레이어로 "이 스타일 뭉치는 낮은 우선순위"라는 큰 순서를 정하고, 그 레이어 안의 선택자는 `:where()`로 명시도까지 0으로 만들어, 레이어 순서와 명시도 **두 축 모두에서 언제든 덮어쓸 수 있는 기본값**임을 확실히 합니다.

```css
@layer reset;

@layer reset {
  :where(ul, ol) {
    list-style: none;
    margin: 0;
    padding: 0;
  }
}
```

## `:is()`가 더 적합한 경우

그렇다고 `:where()`가 항상 더 나은 선택은 아닙니다. 이 스타일은 **의도적으로 강하게 이겨야 한다**는 경우에는 `:is()`가 맞습니다.

```css
/* 폼 유효성 검증 상태처럼, 다른 웬만한 스타일보다 우선해서 보여야 하는 경우 */
:is(input:invalid, select:invalid, textarea:invalid) {
  border-color: crimson;
}
```

경고나 오류 상태처럼 "어지간해서는 밀리면 안 되는" 스타일에 `:where()`를 쓰면, 명시도 0 때문에 별생각 없이 붙인 클래스 하나에도 쉽게 묻혀버릴 수 있습니다. 이런 자리는 오히려 `:is()`의 "목록 중 최댓값" 방식이 안전합니다.

| 상황 | 추천 |
|---|---|
| 나중에 자유롭게 덮어써야 하는 기본값·리셋 스타일 | `:where()` |
| 반복되는 선택자를 줄이되 명시도는 원래 계산대로 유지하고 싶을 때 | `:is()` |
| 유효성 검증, 오류 상태처럼 쉽게 밀리면 안 되는 스타일 | `:is()` (또는 명시도를 의도적으로 높게) |

## `:not()`과의 조합

`:is()`, `:where()`는 부정 선택자 `:not()`과도 자주 함께 쓰입니다.

```css
/* card 클래스를 가지지만 featured 클래스는 아닌 요소 안의 제목 */
.card:not(.featured) h3 {
  color: gray;
}

/* 여러 예외를 한 번에 제외하고 싶을 때 */
.card:not(:is(.featured, .archived, .draft)) h3 {
  color: gray;
}
```

`:not()`도 인자로 선택자 목록을 받을 수 있게 확장되었지만, 여러 값을 나열할 때 가독성을 위해 `:is()`로 한 번 더 묶어 쓰는 경우가 흔합니다.

## 지원 상태

`:is()`와 `:where()`는 **널리 사용 가능**(Baseline: Widely available)한 오래된 안정적인 기능입니다. 두 함수 모두 주요 브라우저에 이미 오래전부터 구현되어 있어, 3편의 `@layer`와 마찬가지로 실무에서 `@supports` 폴백을 따로 준비할 필요가 거의 없습니다. 다만 아주 오래된 브라우저까지 지원해야 하는 프로젝트라면 `@supports selector(:is(a))`처럼 2편에서 배운 `selector()` 기능 쿼리로 지원 여부를 확인할 수 있습니다.

```css
@supports selector(:is(a)) {
  :is(header, main, footer) a:hover {
    text-decoration: underline;
  }
}

@supports not selector(:is(a)) {
  /* :is()를 지원하지 않는 아주 오래된 브라우저용 대체 선언 */
  header a:hover,
  main a:hover,
  footer a:hover {
    text-decoration: underline;
  }
}
```

## 핵심 정리

- `:is()`와 `:where()`는 반복되는 선택자 목록을 괄호 안에 묶어 쓰는 그룹 선택자다. 매칭 결과는 콤마로 나열한 것과 완전히 동일하다.
- 두 함수의 유일한 차이는 명시도 계산이다. `:is()`는 목록 중 가장 높은 명시도를 대표로 세우고, `:where()`는 항상 (0, 0, 0)으로 계산된다.
- `:where()`의 명시도 0은 "나중에 자유롭게 덮어쓸 수 있는 기본값"을 만들 때 유용하다. `@layer`의 낮은 레이어 안에서 함께 쓰면 우선순위를 이중으로 낮출 수 있다.
- 오류·유효성 검증처럼 쉽게 밀리면 안 되는 스타일에는 `:where()`보다 `:is()`가 더 안전할 수 있다.
- 둘 다 널리 사용 가능한 기능이라 실무 폴백이 거의 필요 없지만, `@supports selector()`로 지원 여부를 확인하는 문법도 함께 알아둔다.
