## 왜 필요한가 — 반복되는 부모 선택자

`css_fundamentals`에서 배운 일반 CSS는 선택자를 항상 평평하게(flat) 씁니다. 컴포넌트 하나의 스타일이 늘어날수록 부모 선택자를 계속 반복해서 타이핑해야 합니다.

```css
.card { padding: 1rem; border-radius: 8px; }
.card .title { font-weight: 700; }
.card .title:hover { color: dodgerblue; }
.card .body { color: #444; }
.card.featured { border: 2px solid gold; }
```

`.card`라는 이름이 다섯 줄 내내 반복됩니다. 이름이 길어지거나 리네이밍이 필요해지면 전부 손으로 바꿔야 하고, 어떤 규칙들이 같은 컴포넌트에 속하는지 시각적으로도 흩어져 보입니다. Sass 같은 전처리기(preprocessor)가 오랫동안 인기를 끈 이유 중 하나가 바로 이 중첩(nesting) 문법이었습니다. 그리고 이제는 **전처리기 없이 CSS 자체**가 이 문법을 지원합니다.

> **쉽게 말하면:** 중첩은 "부모 선택자 이름을 한 번만 적고, 그 블록 중괄호 안에서 자식·상태 규칙을 겹쳐 쓰는" 문법입니다. 서류철 하나(부모)를 펴놓고 그 안에 하위 서류(자식 규칙)를 순서대로 끼워 넣는 것과 같습니다.

## 정의와 기본 문법

CSS 중첩(nesting)은 한 선택자 블록 안에 다른 선택자 블록을 넣을 수 있게 하는 문법입니다. 안쪽 블록의 선택자는 바깥 블록의 선택자와 **자손 결합자(공백)로 합쳐진 것처럼** 해석됩니다.

```css
.card {
  padding: 1rem;
  border-radius: 8px;

  .title {
    font-weight: 700;

    &:hover {
      color: dodgerblue;
    }
  }

  .body {
    color: #444;
  }

  &.featured {
    border: 2px solid gold;
  }
}
```

위 코드는 다음과 완전히 같은 뜻입니다.

```css
.card { padding: 1rem; border-radius: 8px; }
.card .title { font-weight: 700; }
.card .title:hover { color: dodgerblue; }
.card .body { color: #444; }
.card.featured { border: 2px solid gold; }
```

## `&` — 부모를 가리키는 자리표시자

`&`는 **넌스팅 셀렉터**(nesting selector, 중첩 선택자)라고 부르는 특수 기호로, "지금 이 블록을 감싼 바로 위 부모 선택자"를 그대로 가리킵니다. 결합자 없이 바로 뒤에 붙이면 "부모 자신에 조건을 더한다"는 뜻이 됩니다.

- `&:hover` → `.card:hover` (부모 자신이 hover 상태일 때)
- `&.featured` → `.card.featured` (부모 자신에 featured 클래스가 추가로 붙었을 때)
- `& + &` → `.card + .card` (부모 요소 바로 다음에 같은 부모 요소가 또 올 때)

## Sass 중첩과의 핵심 차이 — 자동 `&` 삽입 규칙

Sass(SCSS 문법)에 익숙한 개발자가 네이티브 중첩에서 가장 자주 놀라는 지점이 바로 이 규칙입니다. **Sass는 자식 선택자를 자손 결합자로 이어 붙일지, `&`로 붙일지를 문맥으로 추측해서 자동으로 처리**합니다. 반면 **네이티브 CSS 중첩은 시작 문자가 무엇이냐에 따라 규칙이 갈립니다.**

| 안쪽 선택자의 시작 | Sass(SCSS)에서의 해석 | 네이티브 CSS 중첩에서의 해석 |
|---------------------|--------------------------|-------------------------------|
| 태그 이름로 시작 (`p`, `span`) | `.card p` (자손 결합자로 자동 연결) | 태그 이름 선택자만 단독으로는 모호해질 수 있어, 실무에서는 명확히 하려고 `& p`처럼 `&`를 앞에 쓰는 것을 권장한다 |
| 클래스로 시작 (`.title`) | `.card .title` (자손 결합자로 자동 연결) | `.card .title`과 동일하게 자손 결합자로 해석된다 — 이 경우는 Sass와 같다 |
| `&`로 시작 (`&:hover`, `&.featured`) | `.card:hover`, `.card.featured` (결합자 없이 바로 붙임) | Sass와 동일하게 결합자 없이 바로 붙는다 |
| `@media` 같은 중첩 규칙 | 바깥 선택자를 그대로 감싼다 | 표준 CSS 중첩 규칙(nesting rule)으로 동일하게 지원된다 |

가장 조심할 지점은 **태그 이름으로 시작하는 안쪽 선택자**입니다. `span { color: red; }`가 `.card` 안에 중첩되어 있을 때 이것을 명세는 자손 결합자로 처리하도록 정의했지만, 태그 이름이 CSS 중첩 규칙 파싱 초기 단계에서 다른 앳-룰(at-rule) 문법과 혼동될 여지가 있었던 역사 때문에, 실무 스타일 가이드에서는 자손 관계를 표현할 때도 명시적으로 `& span`처럼 쓰는 것을 권장하는 경우가 많습니다. 어떤 브라우저에서나 정확히 같은 결과를 보장받으려면 **애매하게 두지 말고 `&`를 붙이는 습관**을 들이는 편이 안전합니다.

<Callout type="warning">
  **자주 틀리는 점:** "Sass 중첩을 알면 네이티브 중첩도 똑같다"고 넘기면, 나중에 태그 이름 선택자나 복잡한 조합 선택자를 중첩할 때 예상과 다른 결과를 만납니다. 헷갈릴 때는 항상 `&`를 명시적으로 붙이는 것이 가장 안전한 습관입니다.
</Callout>

## 중첩된 선택자의 명시도 계산

중첩 문법 자체는 **명시도 계산 규칙을 새로 만들지 않습니다.** 중첩된 선택자는 결국 평평하게 풀어 쓴 선택자와 똑같이 취급되어, `css_fundamentals`에서 배운 명시도 계산(인라인, id, 클래스/속성/가상클래스, 태그 순서)이 그대로 적용됩니다.

```css
.card {
  &.featured {
    border: 2px solid gold;
  }
}
```

이 규칙의 명시도는 `.card.featured`를 평평하게 쓴 것과 완전히 같은 (0, 2, 0)입니다. 다만 **04편·05편에서 다룬 `:is()`, `:where()`, `:has()`를 중첩 안에서 함께 쓰면**, 그 안쪽 선택자들의 명시도 규칙까지 그대로 이어받습니다.

```css
.card {
  &:where(.featured, .highlighted) {
    border-color: gold;
  }
}
```

`:where()`는 명시도 0이므로, 위 규칙의 전체 명시도는 `.card` 하나만큼인 (0, 1, 0)입니다. 중첩과 04편의 `:is()`/`:where()`, 05편의 `:has()`를 조합하면, "재정의하기 쉬운 낮은 명시도를 유지하면서도 선택자를 짧게 쓰는" 설계가 가능해집니다.

## `@media` 등 앳-룰도 그대로 중첩된다

CSS 중첩은 선택자뿐 아니라 `@media`, `@supports`(2편에서 다뤘습니다) 같은 조건부 그룹 규칙도 감쌀 수 있습니다.

```css
.card {
  padding: 1rem;

  @media (width >= 768px) {
    padding: 2rem;
  }

  @supports (container-type: inline-size) {
    container-type: inline-size;
  }
}
```

바깥 선택자 `.card`를 다시 적을 필요 없이, 조건이 참일 때만 적용될 규칙을 같은 블록 안에 그대로 이어 쓸 수 있습니다.

## 접근성 관점

중첩 문법 자체는 최종적으로 평평한 CSS 규칙으로 풀리기 때문에, 브라우저가 만드는 접근성 트리(accessibility tree)나 스크린 리더의 동작에는 아무 영향이 없습니다. 다만 중첩이 주는 "가독성"이 과하게 깊어지면(3~4단계 이상), 실제로 적용되는 최종 선택자가 무엇인지 사람이 눈으로 추적하기 어려워져 **의도치 않게 높은 명시도의 선택자**를 만들기 쉬워집니다. 이는 곧 04편에서 다룬 것처럼 나중에 접근성 개선을 위해 포커스 스타일이나 상태 스타일을 덮어쓰려 할 때, 명시도 전쟁의 원인이 됩니다. 중첩 깊이를 2~3단계 이내로 제한하는 것이 실무 권장 사항입니다.

## 핵심 정리

- CSS 네이티브 중첩은 전처리기 없이 선택자 블록 안에 다른 선택자 블록을 겹쳐 쓰는 표준 문법이며, 최종적으로는 평평한 선택자로 풀린다.
- `&`는 바로 위 부모 선택자를 가리키는 중첩 선택자다. 결합자 없이 붙이면 부모 자신에 조건을 더하는 뜻이다.
- Sass는 문맥에 따라 자손 결합자 삽입 여부를 자동 추측하지만, 네이티브 중첩은 시작 문자에 따라 규칙이 갈린다. 태그 이름으로 시작하는 안쪽 선택자는 명시적으로 `&`를 붙이는 편이 안전하다.
- 중첩은 새로운 명시도 규칙을 만들지 않는다 — 평평하게 풀어 쓴 것과 동일한 명시도 계산이 적용되며, `:is()`/`:where()`/`:has()`와 결합하면 그 규칙까지 그대로 이어받는다.
- `@media`, `@supports` 같은 조건부 규칙도 그대로 중첩할 수 있다.
