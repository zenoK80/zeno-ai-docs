## 왜 필요한가 — 뷰포트 기준의 한계

`css_fundamentals`에서 배운 미디어 쿼리(`@media`)는 **뷰포트**(viewport, 브라우저 창의 보이는 영역)의 폭을 기준으로 스타일을 바꿉니다. 그런데 실무의 컴포넌트는 뷰포트가 아니라 **자신이 놓인 부모 컨테이너의 폭**에 맞춰 모양을 바꿔야 하는 경우가 훨씬 많습니다.

카드 컴포넌트 하나를 예로 들어봅시다. 이 카드는 화면 전체 폭을 차지하는 메인 영역에 놓일 수도 있고, 폭이 좁은 사이드바에 놓일 수도 있습니다. 뷰포트는 두 경우 모두 똑같이 넓을 수 있습니다(예: 데스크톱 화면). 하지만 카드가 실제로 받는 공간은 완전히 다릅니다. 미디어 쿼리는 뷰포트만 보기 때문에, "이 카드가 좁은 자리에 놓였을 때"를 감지할 방법이 없습니다. 그래서 개발자들은 오랫동안 "메인 영역용 카드 클래스"와 "사이드바용 카드 클래스"를 따로 만들어 중복 코드를 감수해야 했습니다.

> **쉽게 말하면:** 미디어 쿼리는 "지금 창문이 얼마나 큰가"를 봅니다. 컨테이너 쿼리는 "지금 내가 들어 있는 상자가 얼마나 큰가"를 봅니다. 같은 창문 안에서도 상자는 크거나 작을 수 있습니다.

## 정의와 기본 문법

**컨테이너 쿼리**(container query)를 쓰려면 두 단계가 필요합니다. 먼저 어떤 요소를 "쿼리를 받을 수 있는 컨테이너"로 선언하고, 그 다음 그 컨테이너의 자식들에 조건부 스타일을 겁니다.

### 1단계 — `container-type`으로 컨테이너 선언

```css
.card-wrapper {
  container-type: inline-size;
}
```

`container-type`이 취할 수 있는 주요 값은 다음과 같습니다.

| 값 | 의미 |
|-----|------|
| `inline-size` | 인라인 축(보통 가로 폭)만 크기 쿼리 대상으로 삼는다. 실무에서 가장 많이 쓴다 |
| `size` | 인라인 축과 블록 축(가로와 세로) 모두를 대상으로 삼는다. 부모가 명시적인 높이를 가져야 의미가 있다 |
| `normal` (기본값) | 컨테이너가 아니다 — 크기 기반 쿼리의 대상이 되지 않는다 |

인라인(inline)·블록(block) 축은 12편(논리 속성)에서 자세히 다루지만, 여기서는 가로쓰기 문서 기준으로 인라인 축은 가로, 블록 축은 세로라고 생각해도 충분합니다.

### 2단계 — `@container`로 조건부 스타일 작성

```css
@container (width >= 400px) {
  .card {
    display: grid;
    grid-template-columns: 120px 1fr;
  }
}
```

`@container` 안의 조건은 미디어 쿼리와 비슷한 비교 문법을 씁니다. `(width >= 400px)`는 "가장 가까운 조상 컨테이너의 폭이 400픽셀 이상일 때"라는 뜻입니다.

### 이름 붙이기 — `container-name`

컨테이너가 여러 겹 중첩되면 `@container`가 "가장 가까운" 컨테이너 대신 특정 컨테이너를 지목해야 할 때가 있습니다. 이때 `container-name`으로 이름을 붙입니다.

```css
.card-wrapper {
  container-type: inline-size;
  container-name: card;
}

@container card (width >= 400px) {
  .card { grid-template-columns: 120px 1fr; }
}
```

두 선언은 단축 속성 `container`로 한 줄에 합칠 수 있습니다.

```css
.card-wrapper {
  container: card / inline-size;
}
```

## 미디어 쿼리 vs 컨테이너 쿼리 — 근본적인 차이

| 구분 | 미디어 쿼리 (`@media`) | 컨테이너 쿼리 (`@container`) |
|------|--------------------------|-------------------------------|
| 기준 | 뷰포트(브라우저 창) 크기 | 가장 가까운 조상 컨테이너 크기 |
| 적용 범위 | 문서 전체에 한 번에 영향 | 컨테이너로 선언된 요소마다 독립적으로 반응 |
| 컴포넌트 재사용성 | 놓이는 위치마다 별도 클래스가 필요할 수 있다 | 어디에 놓이든 자신이 받은 공간에 스스로 반응한다 |
| 사전 준비 | 필요 없음 — 바로 사용 가능 | 조상 요소에 `container-type` 선언이 반드시 필요하다 |
| 대표 단위 | `vw`, `vh` (뷰포트 단위) | `cqw`, `cqh`, `cqi`, `cqb` (컨테이너 단위, 08편에서 다룬다) |

가장 중요한 차이는 "누구의 크기를 보는가"입니다. 미디어 쿼리는 문서 전체에 걸쳐 단 하나의 기준(뷰포트)을 공유하지만, 컨테이너 쿼리는 **컨테이너로 선언된 개수만큼 독립적인 기준**을 가집니다. 그래서 같은 카드 컴포넌트를 메인 영역에 놓든 사이드바에 놓든, 컴포넌트 스스로 "내가 받은 공간"만 보고 레이아웃을 결정할 수 있습니다.

## 지원 상태 — 널리 사용 가능

컨테이너 쿼리(`container-type`, `@container`)는 2026년 9월 기준 **널리 사용 가능**(Widely available) 상태입니다. 2023년 2월 Baseline 신규 진입(newly available)을 거쳐 2025년 8월 전면 사용 가능(widely available)으로 넘어갔습니다. 기본 문법(크기 기반 쿼리)은 지금 실무에 바로 써도 되는 수준입니다. 다만 08편에서 다룰 **컨테이너 스타일 쿼리**(`style()`)는 지원 시점이 더 최근이라 별도로 확인이 필요합니다.

## 왜 부모 자신에는 쿼리를 걸 수 없는가

컨테이너 쿼리를 처음 쓸 때 자주 만나는 함정이 있습니다. **컨테이너로 선언한 요소 자신은 자기 자신을 기준으로 하는 `@container` 조건의 대상이 될 수 없습니다.**

```css
/* 이렇게 쓰면 순환 참조가 된다 */
.card-wrapper {
  container-type: inline-size;
}

@container (width >= 400px) {
  .card-wrapper {
    /* 이 스타일이 카드-wrapper의 폭을 바꾸면
       그 폭이 다시 조건을 평가해야 하는 순환이 생긴다 */
    padding: 2rem;
  }
}
```

브라우저는 이런 순환 참조를 막기 위해, `container-type`이 선언된 요소 자신에는 그 컨테이너를 기준으로 한 크기 쿼리 스타일이 적용되지 않도록 정의해 두었습니다. 그래서 실무에서는 **컨테이너 역할을 하는 래퍼(wrapper) 요소와, 실제로 스타일이 바뀌는 안쪽 요소를 분리**하는 것이 표준 패턴입니다. 위 예시에서 `container-type`은 `.card-wrapper`에 선언하고, `@container` 조건에 반응해 스타일이 바뀌는 대상은 그 안의 `.card`로 둔 이유가 바로 이것입니다.

## 접근성 관점

컨테이너 쿼리는 시각적 레이아웃만 바꾸는 CSS 기능이라 DOM 구조나 포커스 순서를 바꾸지 않습니다. 다만 컨테이너 폭에 따라 그리드 열 순서나 표시 여부(`display: none`)를 크게 바꾸는 설계를 할 때는, 시각적 순서와 DOM 상의 실제 순서가 벌어지지 않는지 확인해야 합니다. 스크린 리더는 시각적 배치가 아니라 DOM 순서를 따라 콘텐츠를 읽으므로, 컨테이너 쿼리로 "시각적으로는 이미지가 먼저 보이게" 만들었다고 해도 스크린 리더 사용자에게는 마크업 순서 그대로 전달됩니다.

## 핵심 정리

- 컨테이너 쿼리는 뷰포트가 아니라 가장 가까운 조상 컨테이너의 크기를 기준으로 스타일을 바꾼다.
- `container-type: inline-size`로 조상을 컨테이너로 선언하고, `@container (조건)`으로 그 컨테이너에 반응하는 스타일을 작성한다. 여러 컨테이너가 중첩되면 `container-name`으로 특정 컨테이너를 지목한다.
- 미디어 쿼리는 문서 전체가 하나의 기준을 공유하지만, 컨테이너 쿼리는 컨테이너 개수만큼 독립적인 기준을 가져 컴포넌트 재사용성이 높다.
- 컨테이너로 선언한 요소 자신은 순환 참조를 막기 위해 자기 자신을 기준으로 한 쿼리 대상이 될 수 없다 — 래퍼와 안쪽 스타일 대상을 분리하는 것이 표준 패턴이다.
- 2026-09 기준 기본 크기 쿼리는 널리 사용 가능(Widely available)이다.
