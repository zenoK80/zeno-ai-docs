## 왜 필요한가 — 그리드가 못 푸는 한 가지

**10편**에서 배운 서브그리드는 부모의 트랙을 자식이 물려받는 문제를 풉니다. 하지만 CSS 그리드(Grid)에는 원래부터 풀지 못하는 배치 방식이 하나 있습니다. 사진이나 카드처럼 **세로 길이가 제각각인 항목들**을 마치 벽돌을 쌓듯 빈틈없이 채우는 배치입니다. 사진 공유 사이트에서 흔히 보는, 사진마다 높이가 다른데도 다음 줄로 넘어갈 때 빈 공간 없이 촘촘히 이어지는 레이아웃을 떠올리면 됩니다.

일반 CSS 그리드는 행(row, 가로줄)을 미리 정한 트랙에 맞춰 배치합니다. 항목 높이가 제각각이면 같은 행에 있는 다른 칸들도 그 높이에 맞춰 억지로 늘어나거나, 다음 항목이 그 빈 공간을 채우지 못하고 다음 행으로 밀려나 버립니다. 그 결과 원치 않는 빈 공간(gap, 격차)이 생깁니다.

> **쉽게 말하면:** 일반 그리드는 줄을 맞춰 짓는 아파트이고, masonry는 크기가 다른 벽돌을 요령껏 빈틈없이 쌓는 돌담입니다.

**masonry**라는 단어 자체가 "석공술, 벽돌 쌓기"라는 뜻입니다. 크기가 다른 돌을 빈틈없이 쌓아 올리는 모습에서 이름을 따왔습니다. 지금까지는 이 배치를 CSS만으로 구현할 방법이 없어 JavaScript 라이브러리(대표적으로 Masonry.js)나 다단(multi-column) 레이아웃의 변형으로 흉내를 냈습니다.

## 1. 지금 논의 중인 두 가지 문법 — 아직 하나로 정해지지 않았다

masonry를 네이티브 CSS 기능으로 만들자는 제안은 오래전부터 있었지만, 2026년 9월 현재까지도 **어떤 문법으로 표준화할지조차 확정되지 않았습니다.** 크게 두 갈래의 접근이 경쟁하고 있습니다.

### 접근 1 — `grid-template-rows: masonry`

기존 CSS 그리드 문법을 확장하는 방식입니다. 열(column)은 평소처럼 `grid-template-columns`로 정의하고, 행 트랙 자리에 `masonry`라는 키워드를 넣습니다.

```css
/* 제안 1: 그리드 문법 확장 (Firefox가 실험적으로 지원해온 방식) */
.gallery {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-template-rows: masonry;
  gap: 12px;
}
```

이 방식은 "grid를 그대로 쓰되 한 축만 masonry로 바꾼다"는 점에서 기존 그리드 지식을 재사용할 수 있다는 장점이 있습니다. Firefox가 실험적 플래그 뒤에서 오랫동안 시험해 온 문법입니다.

### 접근 2 — `display: masonry` (grid-lanes)

반면 Chrome 진영은 grid와 masonry를 아예 별도의 레이아웃 모드로 분리하자는 방향(내부적으로 "grid-lanes"라는 이름으로 논의)으로 전환하고 있습니다.

```css
/* 제안 2: 별도의 display 값으로 분리 (Chrome이 제안 중인 방향) */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(4, 1fr);
  gap: 12px;
}
```

이 방식은 masonry 특유의 배치 규칙(어느 열에 다음 항목을 넣을지 결정하는 방식 등)을 grid 문법에 억지로 끼워 맞추지 않고 처음부터 새로 설계할 수 있다는 논리입니다.

<Callout type="warning">
  **자주 틀리는 점:** "masonry는 이미 CSS 표준 문법이 있고 지원 브라우저만 늘어나면 된다"는 생각은 틀렸습니다. 지원 브라우저 수의 문제가 아니라, **어떤 문법을 표준으로 삼을지 자체가 아직 결론 나지 않은 단계**입니다. 두 진영의 논의가 합쳐지거나 한쪽으로 정리되기 전까지는 실제 스펙 문서(specification)에 실릴 최종 문법을 예측할 수 없습니다.
</Callout>

## 2. 2026-09 기준 지원 현황

| 브라우저 | 상태 |
|----------|------|
| Safari | 26 버전에서 `grid-template-rows: masonry` 방식을 먼저 정식 출시 |
| Chrome | 실험 플래그 뒤에 있으며, 자체적으로는 별도 문법(grid-lanes)으로 전환을 검토 중 |
| Firefox | 오랜 기간 실험 플래그로 `masonry` 키워드를 시험해 왔으나 아직 정식 출시 전 |

01편의 사실 확인 표에 정리했듯, masonry는 이 과목에서 다루는 기능 중 **제한적·실험적**으로 분류되는 대표 사례입니다. 브라우저 하나(Safari)가 먼저 출시했다고 해서 표준이 확정된 것은 아니며, 오히려 나머지 두 브라우저 진영이 서로 다른 방향을 검토하고 있다는 사실이 "문법 자체가 미확정"임을 보여주는 증거입니다. Baseline(newly/widely available) 판정을 받으려면 최소 세 개 주요 브라우저 엔진이 같은 문법으로 수렴해야 하는데, masonry는 그 이전 단계인 "합의조차 되지 않은" 상태입니다.

<Callout type="warning">
  **지금 실무에 쓸 수 없다.** 어느 한쪽 문법을 먼저 도입했다가 표준이 다른 쪽으로 정해지면 코드를 전부 다시 써야 합니다. 프로덕션 코드에는 아래에서 소개할 대안을 쓰고, masonry는 webstatus.dev 같은 곳에서 진행 상황만 주기적으로 확인하는 것을 권장합니다.
</Callout>

## 3. 지금 당장 쓸 수 있는 대안

### 대안 1 — 다단(multi-column) 레이아웃

`column-count`로 여러 단을 나누면, 항목이 위에서 아래로 순서대로 쌓이며 벽돌 쌓기와 비슷한 결과를 냅니다.

```css
.gallery {
  column-count: 4;
  column-gap: 12px;
}
.gallery > * {
  break-inside: avoid;
  margin-bottom: 12px;
}
```

`break-inside: avoid`는 한 항목이 단 경계에서 잘려 두 단에 걸쳐 쪼개지지 않도록 막습니다. 다만 다단 레이아웃은 항목이 **왼쪽 위에서 아래로 채워진 뒤 다음 단으로 넘어가는 방식**이라, 진짜 masonry처럼 "가장 짧은 열에 다음 항목을 채우는" 최적화된 배치는 아닙니다. 읽는 순서가 세로 우선이 되어, 시각적으로는 grid보다 masonry에 가깝지만 항목이 배치되는 순서 논리는 다릅니다.

### 대안 2 — JavaScript 라이브러리

Masonry.js 같은 라이브러리는 각 항목의 실제 렌더링 높이를 측정한 뒤 가장 짧은 열을 찾아 다음 항목을 그 자리에 배치합니다. 진짜 masonry 알고리즘에 가장 가깝지만, 레이아웃 계산을 위해 JavaScript 실행과 리플로우(reflow, 재배치 계산)가 필요해 순수 CSS보다 비용이 듭니다. 콘텐츠가 매우 많거나 자주 바뀌는 화면에서는 성능을 반드시 함께 점검해야 합니다.

| 방식 | 배치 논리 | 표준 CSS만으로 가능 | 지금 실무 적합성 |
|------|-----------|----------------------|-------------------|
| `grid-template-rows: masonry` / `display: masonry` | 가장 짧은 열에 다음 항목 배치 | 예(단, 문법 미확정) | 아직 부적합 — 실험적 |
| 다단(`column-count`) | 왼쪽 단부터 순서대로 채움 | 예 | 간단한 갤러리에 적합 |
| JavaScript 라이브러리 | 가장 짧은 열에 다음 항목 배치 | 아니오 | 정밀한 배치가 필요할 때 적합 |

## `@supports`로 실험 문법을 감지하기

혹시 실험적으로 masonry를 시도해 본다면, `@supports`로 감지해 지원하지 않는 브라우저에는 다단 레이아웃을 폴백으로 제공하는 것이 안전합니다.

```css
/* 폴백: 다단 레이아웃 */
.gallery {
  column-count: 4;
  column-gap: 12px;
}

/* masonry를 지원하는 브라우저에서만 덮어쓰기 (문법은 앞으로 바뀔 수 있다) */
@supports (grid-template-rows: masonry) {
  .gallery {
    display: grid;
    grid-template-columns: repeat(4, 1fr);
    grid-template-rows: masonry;
    column-count: initial;
  }
}
```

이 코드는 지금 시점의 한 가지 제안 문법을 기준으로 작성한 예시일 뿐이며, 표준이 확정되면 다시 확인하고 고쳐야 한다는 점을 분명히 해둡니다.

## 핵심 정리

- masonry는 세로 길이가 제각각인 항목을 빈틈없이 벽돌처럼 쌓는 배치이며, 일반 CSS 그리드는 트랙 기반이라 이 배치를 만들지 못한다.
- `grid-template-rows: masonry`(Firefox·Safari가 시도해온 방식)와 `display: masonry`/grid-lanes(Chrome이 검토 중인 방식) 두 문법이 경쟁하고 있고, 2026-09 기준 어느 쪽도 표준으로 확정되지 않았다.
- Safari 26이 먼저 출시했지만 나머지 두 브라우저 진영의 방향이 갈려 있어, 지원 브라우저 수가 아니라 문법 합의 자체가 아직 안 된 단계다.
- 지금 실무에는 다단 레이아웃(`column-count`)이나 JavaScript 라이브러리로 대체하고, masonry는 진행 상황만 지켜본다.
- 실험적으로 시도하더라도 `@supports`로 감지해 다단 레이아웃 폴백을 반드시 함께 둔다.
