  **이번 문서의 목표:** 이 문서를 다 읽으면 커스텀 속성이 왜 "그냥 변수"가 아니라 캐스케이드 안에서 상속·재정의되는 CSS 선언인지 설명하고, `var()`의 폴백 값 문법과 자바스크립트의 `getPropertyValue`/`setProperty`로 커스텀 속성을 안전하게 읽고 쓸 수 있게 됩니다.
</Callout>

## 왜 필요한가 — 반복되는 값을 한곳에서 관리하기

CSS를 쓰다 보면 같은 색, 같은 간격, 같은 글자 크기가 파일 곳곳에 흩어져 반복됩니다. 브랜드 색을 하나 바꾸려면 `#3b82f6`이라는 문자열을 파일 전체에서 찾아 바꿔야 하고, 하나라도 놓치면 화면 어딘가만 색이 어긋납니다. 프로그래밍 언어라면 이럴 때 변수(variable)를 씁니다. 값 하나를 이름에 담아 두고, 그 이름을 여기저기서 참조하면 됩니다.

CSS도 오랫동안 이런 재사용 수단이 없었습니다. Sass 같은 전처리기가 `$색상: #3b82f6;` 같은 변수를 흉내 냈지만, 이건 빌드 시점에 문자열을 그대로 치환하는 것일 뿐이라 브라우저는 변수의 존재조차 모릅니다. **커스텀 속성**(custom property)은 이 문제를 브라우저가 직접 이해하는 CSS 기능으로 끌어올린 것입니다.

## 쉽게 말하면과 정의

> **쉽게 말하면:** 커스텀 속성은 CSS 안에 심어 두는 이름표 붙은 값입니다. 이름표를 한 번 붙여 두면, 문서 어디서든 그 이름표로 값을 불러 쓸 수 있고, 이름표에 적힌 값을 바꾸면 그 이름표를 참조하는 모든 곳이 한꺼번에 바뀝니다.

**커스텀 속성**은 `--`(하이픈 두 개)로 시작하는 이름을 가진 CSS 속성입니다. 값을 선언할 때는 일반 속성처럼 쓰고, 값을 사용할 때는 `var()` 함수로 꺼내옵니다.

```css
:root {
  --브랜드색: #3b82f6;
  --기본간격: 16px;
}

.버튼 {
  background-color: var(--브랜드색);
  padding: var(--기본간격);
}
```

`:root`는 문서 최상위 요소(HTML 문서라면 `html` 요소)를 가리키는 가상 클래스입니다. 여기에 커스텀 속성을 선언하면 문서 전체에서 참조할 수 있는 전역 값처럼 동작합니다. 다만 이것이 진짜 "전역 변수"가 아니라 **캐스케이드와 상속을 따르는 CSS 선언**이라는 점이 이번 편의 핵심입니다.

`var(--브랜드색)`처럼 값을 꺼내 쓰는 함수 이름의 `var`는 variable(변수)의 줄임말이지만, CSS 명세는 커스텀 속성을 공식적으로 "변수"가 아니라 "사용자 정의 속성"이라고 부릅니다. 이 이름 차이가 괜히 붙은 것이 아닙니다. 아래에서 그 이유가 드러납니다.

## 커스텀 속성은 왜 "변수"와 다르게 동작하는가 — 상속과 재정의

자바스크립트의 변수는 스코프(scope, 유효 범위) 안에서 값이 하나로 고정됩니다. 하지만 커스텀 속성은 **일반 CSS 속성과 똑같이 캐스케이드와 상속의 대상**입니다. 즉, 같은 이름의 커스텀 속성이라도 그 값을 어느 요소에서 읽느냐에 따라 다른 값이 나올 수 있습니다.

```css
:root {
  --강조색: blue;
}

.카드 {
  --강조색: green;
}

.카드 .제목 {
  color: var(--강조색); /* green — 가장 가까운 조상에서 재정의한 값 */
}

.배경 {
  color: var(--강조색); /* blue — :root의 값을 그대로 상속 */
}
```

`.카드` 안에서 `--강조색`을 `green`으로 다시 선언하면, `.카드`의 자손 요소들은 이제부터 `green`을 상속받습니다. `.카드` 바깥의 다른 요소는 여전히 `:root`에서 내려온 `blue`를 봅니다. 이것이 바로 **재정의(override)와 상속(inheritance)이 결합된 동작**입니다. 커스텀 속성은 선언된 요소를 뿌리로 삼아, 그 아래 자손들에게 값이 흘러 내려가다가 중간에 같은 이름으로 다시 선언되면 그 지점부터 새 값으로 갈아탑니다.

<Callout type="warning">
  **자주 틀리는 점:** 커스텀 속성을 프로그래밍 언어의 전역 변수처럼 "한 번 정의하면 문서 전체에서 항상 같은 값"이라고 생각하면 안 됩니다. 실제로는 `color`나 `font-size`와 똑같이 캐스케이드 계산을 거쳐, 요소마다 "그 요소가 보는 값"이 따로 계산됩니다. 03편에서 다룬 캐스케이드 레이어(`@layer`)와 명시도 규칙도 커스텀 속성 선언 자체에 그대로 적용됩니다 — 어떤 선택자가 더 구체적인지, 어느 레이어가 나중인지에 따라 어떤 `--강조색` 선언이 이길지가 정해집니다.
</Callout>

### 브라우저가 실제로 처리하는 방식

브라우저는 스타일 계산(computed style) 단계에서 각 요소마다 커스텀 속성의 최종값을 계산해 둡니다. `var(--강조색)`을 만나면 그 시점에 이 계산된 값을 그대로 문자열처럼 치환합니다. 그래서 개발자 도구의 요소 검사(computed 탭)를 열어 보면 `--강조색: green` 같은 줄이 실제 계산된 값으로 나타납니다. 이 문자열 치환 방식 때문에 커스텀 속성은 색상뿐 아니라 속성값의 일부, 심지어 선택자 안의 숫자까지 유연하게 담을 수 있습니다.

## `var()`의 폴백 값 — 두 번째 인자

`var()` 함수는 두 번째 인자로 **폴백 값**(fallback value)을 받을 수 있습니다. 첫 번째 인자로 지정한 커스텀 속성이 선언되어 있지 않거나 유효하지 않은 값이면, 두 번째 인자가 대신 쓰입니다.

```css
.배지 {
  background-color: var(--배지색, gray);
}
```

`--배지색`이 어디에도 선언되지 않았다면 `.배지`는 회색(`gray`) 배경을 갖습니다. `--배지색`이 어딘가에서 `red`로 선언되어 있다면 그 값이 우선합니다.

### 폴백이 실제로 발동하는 두 가지 경우

| 상황 | `var(--배지색, gray)`의 결과 |
|------|------------------------------|
| `--배지색`이 아예 선언된 적 없음 | 폴백 `gray` 사용 |
| `--배지색: initial;`로 선언됨 | 폴백 `gray` 사용 (initial은 값이 없다는 뜻과 같게 취급) |
| `--배지색: ;`처럼 빈 값으로 선언됨 | 폴백 `gray` 사용 |
| `--배지색: red;`로 정상 선언됨 | `red` 사용, 폴백 무시 |
| `--배지색: 20px;`처럼 문법상 유효하지만 background-color로는 쓸 수 없는 값 | 값 자체는 `20px`로 대입 시도하지만 `background-color: 20px`가 무효하므로 해당 선언 전체가 무효 처리 — 폴백이 아니라 **상속되었을 원래 background-color 값이나 초기값**으로 되돌아감 |

마지막 행이 특히 헷갈립니다. `var()`의 폴백은 "커스텀 속성이 정의되지 않았을 때"만 작동하지, "커스텀 속성 값이 이 속성에 어울리지 않을 때"는 작동하지 않습니다. 후자의 경우는 CSS 문법 오류와 똑같이 취급되어 **그 선언 자체가 무시**됩니다.

<Callout type="warning">
  **자주 틀리는 점:** `var(--없는변수)`처럼 폴백 없이 정의되지 않은 커스텀 속성을 참조하면 에러가 나지 않습니다. 대신 그 값은 빈 문자열처럼 취급되어, 최종 선언이 유효하지 않으면 해당 속성이 **상속받은 값이나 초기값으로 되돌아갑니다.** 콘솔에 아무 경고도 뜨지 않으므로, 스타일이 안 먹힐 때 오탈자로 커스텀 속성 이름을 잘못 쓴 것은 아닌지 개발자 도구의 computed 탭에서 직접 확인해야 합니다.
</Callout>

폴백 값 자체에 쉼표가 들어가는 값(예: `rgb(0, 0, 0)`)을 쓰고 싶다면, 첫 쉼표까지만 첫 번째 인자와 구분자로 해석되고 **나머지 전체가 폴백**으로 취급됩니다.

```css
.패널 {
  color: var(--글자색, rgb(0, 0, 0)); /* 폴백 전체가 rgb(0, 0, 0) */
}
```

## 자바스크립트와 커스텀 속성 주고받기

커스텀 속성의 큰 장점 중 하나는 자바스크립트가 CSS 값을 직접 읽고 쓸 수 있는 통로가 된다는 점입니다. 일반 CSS 속성값(예: 계산된 `padding`)도 읽을 수는 있지만, 커스텀 속성은 **의미 있는 이름을 가진 값을 애플리케이션 상태와 CSS 사이에 다리처럼 놓을 수 있다**는 점에서 다릅니다.

```js
const 루트 = document.documentElement; // <html> 요소

// 읽기 — 계산된 스타일에서 커스텀 속성 값을 가져온다
const 현재강조색 = getComputedStyle(루트).getPropertyValue('--강조색').trim();
console.log(현재강조색); // "royalblue" 같은 문자열

// 쓰기 — 인라인 스타일로 커스텀 속성을 설정한다
루트.style.setProperty('--강조색', 'crimson');
```

- `getComputedStyle(요소).getPropertyValue('--이름')`은 그 요소에서 최종적으로 계산된 커스텀 속성 값을 문자열로 돌려줍니다. 앞뒤 공백이 포함될 수 있어 보통 `.trim()`을 함께 씁니다.
- `요소.style.setProperty('--이름', 값)`은 그 요소의 **인라인 스타일**로 커스텀 속성을 얹습니다. 인라인 스타일은 캐스케이드에서 매우 높은 우선순위를 가지므로(09편에서 다루는 명시도 규칙과 별개로, 인라인 스타일은 일반 선택자보다 강합니다), 이 요소와 그 자손들이 보는 `--이름` 값을 사실상 즉시 덮어씁니다.

이 패턴은 사용자 입력(슬라이더로 색을 고르거나, 다크모드 토글을 누르는 것)을 CSS 스타일에 실시간으로 반영할 때 자주 쓰입니다. 자바스크립트는 값 하나만 커스텀 속성에 써 넣고, 실제로 그 값을 어떻게 쓸지(어느 속성에 적용할지, 어떻게 계산할지)는 CSS가 전담하는 역할 분리가 가능해집니다.

<Callout type="warning">
  **자주 틀리는 점:** `element.style.getPropertyValue('--이름')`은 그 요소의 **인라인 스타일에 직접 적힌 값만** 읽습니다. 캐스케이드를 거쳐 상속되거나 스타일시트에서 온 값은 보이지 않습니다. 최종적으로 화면에 적용된 값을 읽고 싶다면 반드시 `getComputedStyle(요소)`를 거쳐야 합니다.
</Callout>

## 비교표 — 커스텀 속성 vs Sass 변수

| 구분 | CSS 커스텀 속성(`--x`) | Sass 변수(`$x`) |
|------|------------------------|------------------|
| 처리 시점 | 브라우저가 런타임에 해석 | 빌드 시점에 문자열로 치환되어 사라짐 |
| 캐스케이드·상속 | 따른다 — 요소마다 다른 값 가능 | 없음 — 컴파일 시 정적으로 하나의 값 |
| 자바스크립트 연동 | `getPropertyValue`/`setProperty`로 실시간 읽기·쓰기 가능 | 불가능 — 이미 값으로 치환되어 흔적이 없음 |
| 미디어 쿼리 안에서 값 재정의 | 가능 — `@media` 안에서 다시 선언하면 그 조건에서만 다른 값 | 조건부 컴파일로 흉내는 가능하나 런타임 반응은 아님 |
| 값이 없을 때 | `var()`의 폴백으로 대응 | 컴파일 오류 |

## 핵심 정리

- 커스텀 속성(`--이름: 값;`)은 `var(--이름)`으로 꺼내 쓰는 CSS 선언이며, 명세상 정식 이름은 "사용자 정의 속성"이다 — 캐스케이드와 상속을 그대로 따르기 때문이다.
- 같은 이름의 커스텀 속성이라도 어느 요소의 자손이냐에 따라 다른 값을 상속받을 수 있다. 조상에서 재정의하면 그 지점부터 자손들이 새 값을 본다.
- `var(--이름, 폴백)`의 폴백은 그 커스텀 속성이 선언되지 않았거나 값이 비었을 때만 작동하며, 값이 있지만 해당 속성에 맞지 않는 경우는 선언 자체가 무효 처리된다.
- `getComputedStyle(요소).getPropertyValue()`로 최종 계산값을 읽고, `요소.style.setProperty()`로 인라인 스타일 수준의 값을 실시간으로 써넣을 수 있다.
- Sass 변수와 달리 커스텀 속성은 런타임에 살아 있는 값이라, 자바스크립트와 CSS 사이의 실시간 다리 역할을 한다.
