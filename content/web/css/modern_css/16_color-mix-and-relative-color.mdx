</Callout>

<Callout type="warning">
  **지원 상태:** `color-mix()`는 2026년 9월 기준 **널리 사용 가능**(2023-05 Baseline widely available)합니다. 반면 상대 색 문법(relative color syntax, `from` 키워드)은 **최신 브라우저 기준**입니다. 주요 브라우저가 지원하지만 세부 기능(어떤 색 함수와 조합되는지)마다 지원 편차가 있으므로, 실무에 쓰기 전 사용하려는 정확한 조합을 MDN 브라우저 호환성 표에서 개별 확인하는 것이 안전합니다.
</Callout>

## 왜 필요한가 — 팔레트 색 하나마다 손으로 변형을 만들던 문제

버튼 하나에도 기본 색, 마우스를 올렸을 때(hover) 살짝 어두워지는 색, 눌렀을 때(active) 더 어두워지는 색, 배경에 옅게 깔리는 톤(tint)까지 여러 변형이 필요합니다. 지금까지는 이 변형들을 디자이너가 하나하나 손으로 골라 별도의 색상 값으로 저장해 두는 것이 보통이었습니다. 브랜드 색을 하나 바꾸면 이 파생 색들도 전부 다시 골라야 했습니다.

**`color-mix()`**와 **상대 색 문법**(relative color syntax)은 이 문제를 "기준 색 하나만 정해 두면 나머지는 계산으로 뽑아낸다"는 방식으로 풀어냅니다. 색을 값이 아니라 **함수의 입력**으로 다루기 시작한 것입니다.

## `color-mix()` — 색 공간을 지정해 두 색을 섞기

### 정의와 기본 문법

> **쉽게 말하면:** `color-mix()`는 물감을 섞듯 두 색을 지정한 비율로 섞어 새 색을 만드는 함수입니다. 다만 어떤 "물통"(색 공간) 안에서 섞을지도 함께 정해야 합니다.

```css
.버튼 {
  background-color: color-mix(in oklch, royalblue 70%, white 30%);
}
```

- `in oklch`: 어느 색 공간에서 섞을지 지정합니다. `srgb`, `hsl`, `oklab`, `oklch` 등 여러 색 공간을 쓸 수 있습니다.
- `royalblue 70%`: 첫 번째 색과 그 비율.
- `white 30%`: 두 번째 색과 그 비율. 두 비율의 합이 `100%`가 안 되면 나머지만큼 결과색이 반투명해지고, 비율을 하나만 적으면 나머지는 자동으로 남은 비율로 계산됩니다.

### 실제 숫자로 계산하기

`color-mix()`는 지정한 색 공간의 각 채널을 **비율대로 선형 평균**합니다. 15편에서 확인한 `royalblue`에 가까운 예로, 빨강의 oklch 근사값 `oklch(62.8% 0.2577 29.23)`을 기준 색으로 삼아 흰색과 검은색을 각각 섞어 보겠습니다. 흰색과 검은색은 oklch에서 채도(C)가 `0`이라 색상 각도(H)가 무의미(powerless, 파워리스)해지므로, 섞은 결과의 색상 각도는 기준 색의 값을 그대로 물려받습니다.

$$
L_{결과} = 62.8\% \times 0.5 + 100\% \times 0.5 = 81.4\%
$$

- $L_{결과}$: 흰색과 5대5로 섞었을 때 결과의 밝기(L)
- $62.8\%$: 기준 빨강의 밝기, 비율 $0.5$(50%)만큼 반영
- $100\%$: 흰색의 밝기, 마찬가지로 비율 $0.5$만큼 반영

$$
C_{결과} = 0.2577 \times 0.5 + 0 \times 0.5 = 0.129
$$

- $C_{결과}$: 결과의 채도(C). 흰색의 채도가 `0`이므로 절반으로 옅어짐

즉 `color-mix(in oklch, oklch(62.8% 0.2577 29.23) 50%, white 50%)`의 결과는 대략 `oklch(81.4% 0.129 29.23)` — 원래 빨강보다 훨씬 밝고 채도는 낮아진, "옅은 살구빛에 가까운 색"이 됩니다. 같은 기준 색을 검정과 섞으면 반대로 어두워집니다.

$$
L_{결과} = 62.8\% \times 0.5 + 0\% \times 0.5 = 31.4\%
$$

검정과 50대50으로 섞은 결과는 `oklch(31.4% 0.129 29.23)`에 가까운, 짙게 가라앉은 빨강이 됩니다. 두 계산 모두 **밝기(L)만 절반씩 옮겨 가고 색상 각도(H)는 그대로 유지**된다는 점이 핵심입니다. 이것이 바로 "흰색을 섞으면 밝아지고 검정을 섞으면 어두워지되, 원래 색상 정체성은 유지된다"는, 우리가 물감으로 직관적으로 기대하는 결과와 정확히 일치합니다.

<Callout type="warning">
  **자주 틀리는 점:** `color-mix(in srgb, ...)`처럼 색 공간을 `srgb`로 지정하면 RGB 채널을 그대로 선형 평균합니다. `hsl()`처럼 지각적으로 불균일한 공간에서는 섞는 색 공간에 따라 중간색이 탁하게 나오거나 예상과 다른 색으로 나올 수 있습니다. 특히 색상 각도가 있는 색끼리 섞을 때는 `in oklch`나 `in hsl`처럼 원기둥 색 공간을 지정하면 색상 각도가 두 각도의 중간값(더 짧은 호 방향)으로 자연스럽게 보간되지만, `in srgb`(직교좌표)에서는 채널별 산술 평균이라 전혀 다른 색상으로 보이는 중간색이 나올 수 있습니다. 어떤 색 공간을 쓸지는 "색상이 부드럽게 도는 느낌"을 원하면 원기둥 공간을, "RGB 값 자체의 평균"이 필요하면 `srgb`를 고르는 식으로 목적에 맞게 정합니다.
</Callout>

## 상대 색 문법 — 기존 색의 채널만 골라 바꾸기

### 왜 필요한가

`color-mix()`는 "두 색을 섞는" 문제를 풀지만, "이 색은 그대로 두고 밝기만 20% 올리고 싶다"처럼 **한 색의 특정 채널 하나만 조작**하고 싶을 때는 어울리지 않습니다. 예전에는 이런 조작을 하려면 자바스크립트로 색을 파싱해서 채널을 계산한 뒤 다시 문자열로 조립하거나, Sass의 `lighten()`/`darken()` 같은 전처리기 함수에 의존해야 했습니다. **상대 색 문법**은 이 계산을 CSS 안에서 직접 할 수 있게 해줍니다.

### 정의와 기본 문법

> **쉽게 말하면:** 상대 색 문법은 "이 색에서, 밝기만 이만큼 바꿔서 새 색을 만들어줘"라고 브라우저에게 시키는 문법입니다.

```css
.버튼:hover {
  background-color: oklch(from var(--브랜드색) calc(l - 0.15) c h);
}
```

`from var(--브랜드색)`은 "이 색을 기준으로 삼겠다"는 선언입니다. 그 뒤에 오는 `l`, `c`, `h`는 기준 색을 oklch로 분해했을 때의 각 채널을 가리키는 **자리 표시자**(placeholder)입니다. 이 자리 표시자는 일반 숫자처럼 `calc()` 연산에 그대로 쓸 수 있습니다.

### 실제 숫자로 계산하기

`--브랜드색`이 `oklch(55% 0.18 250)`이라고 하면, `oklch(from var(--브랜드색) calc(l - 0.15) c h)`의 계산은 다음과 같습니다.

$$
L_{새값} = 55\% - 15\% = 40\%
$$

- $L_{새값}$: 새로 만들어질 색의 밝기
- $55\%$: 기준 색(`--브랜드색`)의 원래 밝기, `l`이 가리키는 값
- $15\%$: `calc()`로 빼기로 지정한 만큼(오클치의 `L` 채널은 `0`~`1` 사이 숫자 또는 `0%`~`100%` 백분율로 다룰 수 있으며, 여기서는 백분율 단위로 계산)

`c`와 `h`는 그대로 두었으므로(`c`, `h`를 그대로 적으면 원래 값 유지) 채도(`0.18`)와 색상 각도(`250`)는 바뀌지 않고 밝기만 `40%`로 낮아진 `oklch(40% 0.18 250)`이 결과값입니다. 원래 색의 색상 정체성은 그대로 유지한 채 "더 어두운 버전"만 정확히 뽑아낸 것입니다.

같은 방식으로 옅은 배경 톤을 만들 때는 채도를 낮추고 밝기를 올립니다.

$$
L_{새값} = 55\% + 35\% = 90\%
$$

$$
C_{새값} = 0.18 \times 0.2 = 0.036
$$

`oklch(from var(--브랜드색) calc(l + 0.35) calc(c * 0.2) h)`로 쓰면 밝기는 `90%`로 올라가고 채도는 원래의 `20%`(`0.036`)로 옅어져, 원래 색과 같은 색상 각도(`250`)를 유지한 은은한 배경 톤이 만들어집니다.

<Callout type="warning">
  **자주 틀리는 점:** 상대 색 문법에서 `l`, `c`, `h` 같은 채널 이름은 **어떤 색 함수로 결과를 감싸는지에 따라 달라집니다.** `oklch(from ... l c h)`에서는 `l`/`c`/`h`를 쓰지만, `hsl(from ... h s l)`에서는 `h`/`s`/`l` 순서로 다른 이름을 씁니다. 함수 이름과 채널 이름 조합이 맞지 않으면 값이 무효 처리되므로, 사용하는 색 함수의 채널 이름표를 그때그때 확인해야 합니다.
</Callout>

## 비교표 — `color-mix()` vs 상대 색 문법

| 구분 | `color-mix()` | 상대 색 문법(`from`) |
|---|---|---|
| 입력 | 색 두 개(와 비율) | 색 하나 |
| 하는 일 | 두 색을 지정한 색 공간에서 섞는다 | 한 색의 특정 채널만 계산으로 바꾼다 |
| 대표 용도 | 반투명 오버레이, 브랜드 색과 배경색을 섞은 중간 색 | 같은 색상의 밝기·채도만 다른 hover·톤 변형 |
| 채널 접근 | 불가능(채널 단위 조작이 아님) | 가능(`l`, `c`, `h` 등 채널을 이름으로 직접 참조) |
| 2026-09 지원 상태 | 널리 사용 가능 | 최신 브라우저 기준 |

## 실전 패턴 — 브랜드 색 하나로 테마 변형 자동 생성

두 기능을 조합하면 브랜드 색 커스텀 속성 하나만 바꿔도 버튼의 모든 상태 색이 함께 갱신되는 구조를 만들 수 있습니다.

```css
:root {
  --브랜드색: oklch(55% 0.18 250);
  --브랜드색-호버: oklch(from var(--브랜드색) calc(l - 0.1) c h);
  --브랜드색-눌림: oklch(from var(--브랜드색) calc(l - 0.2) c h);
  --브랜드색-옅은배경: color-mix(in oklch, var(--브랜드색) 12%, white 88%);
}
```

`--브랜드색`만 새 값으로 바꾸면, 이를 참조하는 나머지 세 변수도 캐스케이드 계산 시점에 다시 계산되어 함께 바뀝니다. 13편에서 배운 커스텀 속성의 상속·재계산 원리와, 이번 편의 색 계산 함수가 만나 "기준 색 하나로 전체 팔레트를 유지 보수한다"는 실무 패턴이 완성됩니다.

## 핵심 정리

- `color-mix(in 색공간, 색1 비율1, 색2 비율2)`는 지정한 색 공간의 각 채널을 비율대로 선형 평균한다. 원기둥 색 공간(`oklch`, `hsl`)은 색상 각도를 부드럽게 보간하고, 직교 공간(`srgb`)은 채널을 그대로 평균해 다른 느낌의 중간색이 나온다.
- `oklch(from 기준색 l c h)` 같은 상대 색 문법은 기준 색의 채널을 이름으로 꺼내 `calc()`로 계산할 수 있게 해, 색상 정체성은 유지한 채 밝기나 채도만 바꾼 변형을 만든다.
- 상대 색 문법의 채널 이름표는 감싸는 색 함수에 따라 달라진다(`oklch`는 `l c h`, `hsl`은 `h s l`).
- `color-mix()`는 2026-09 기준 널리 사용 가능하지만, 상대 색 문법은 최신 브라우저 기준이라 조합별 지원 여부를 확인하며 써야 한다.
- 브랜드 색 커스텀 속성 하나에 두 기능을 조합하면, 기준 색만 바꿔도 호버·눌림·배경 톤 같은 파생 색 전체가 자동으로 갱신되는 유지보수 구조를 만들 수 있다.
