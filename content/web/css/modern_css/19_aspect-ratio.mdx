## 1. 왜 필요한가 — 레이아웃 흔들림 문제

### 문제 상황

이미지가 로드되기 전과 로드된 후를 생각해 봅시다. `<img>` 태그에 `width`·`height` 속성이 없으면, 브라우저는 이미지의 실제 크기를 **다운로드가 끝나야** 압니다. 그 전까지는 이미지가 차지할 공간을 0으로 간주하다가, 로드가 끝나는 순간 이미지 크기만큼 공간이 갑자기 생기면서 아래 콘텐츠가 밀려납니다. 이 현상을 **레이아웃 밀림**(layout shift, 배치 밀림)이라고 부릅니다. 사용자가 막 읽으려던 문장이 이미지 로드 때문에 화면 아래로 밀려나 버튼을 잘못 누르는 경험, 다들 한 번쯤 겪어봤을 것입니다.

### 예전 해법 — `padding-top` 트릭

`aspect-ratio`가 없던 시절에는 CSS의 독특한 성질 하나를 억지로 이용했습니다. 블록 요소의 `padding-top`(위쪽 안쪽 여백)을 퍼센트로 지정하면, 그 퍼센트는 **부모의 너비**를 기준으로 계산됩니다. 이를 이용해 높이가 없는 빈 상자를 너비에 비례해 강제로 늘렸습니다.

```css
.비율상자 {
  width: 100%;
  padding-top: 56.25%; /* 16:9 = 9/16 = 0.5625 */
  position: relative;
}

.비율상자 img {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

동작은 하지만 코드만 봐서는 "56.25퍼센트가 왜 여백인가"를 전혀 알 수 없고, 안쪽 요소를 `position: absolute`로 따로 겹쳐야 해서 구조가 복잡해집니다. 비율을 바꾸려면 매번 퍼센트를 다시 계산해야 하는 것도 번거롭습니다.

> **쉽게 말하면:** `padding-top` 트릭은 사진틀을 만들기 위해 종이를 접어 가짜 두께를 만드는 것과 같습니다. `aspect-ratio`는 그냥 "이 틀은 16:9 비율"이라고 치수를 말해주는 것입니다.

## 2. 정의와 문법

**종횡비**(aspect ratio, 가로세로 비율)를 선언하는 `aspect-ratio` 속성은 너비와 높이의 비율을 슬래시로 구분해 지정합니다.

```css
.비율상자 {
  aspect-ratio: 16 / 9;
}
```

| 문법 | 의미 |
|------|------|
| `aspect-ratio: 16 / 9` | 너비 대 높이가 16 대 9 |
| `aspect-ratio: 1 / 1` | 정사각형 |
| `aspect-ratio: auto` | 기본값 — 요소에 내재된 고유 비율(intrinsic ratio, 콘텐츠가 원래 가진 비율)이 있으면 그것을 따르고, 없으면 비율을 강제하지 않음 |
| `aspect-ratio: auto 16 / 9` | 고유 비율이 있으면 그것을 우선하되, 없을 때만 16:9 사용 |

동작 원리는 단순합니다. `width`(또는 `height`) 하나만 결정되면, 브라우저가 비율을 이용해 **나머지 한 축을 자동으로 계산**합니다.

```css
.썸네일 {
  width: 100%;
  aspect-ratio: 16 / 9; /* height는 자동 계산됨 */
}
```

## 3. 브라우저가 실제로 하는 일 — 대체 요소는 원래부터 특별했다

### 대체 요소란

`<img>`, `<video>`, `<canvas>`처럼 콘텐츠 자체가 외부 자원(이미지 파일, 비디오 프레임)으로 채워지는 요소를 **대체 요소**(replaced element, 교체 요소)라고 부릅니다. 대체 요소는 오래전부터 자기만의 **고유 비율**(intrinsic aspect ratio)을 가지고 있었습니다 — 가로 800px, 세로 600px짜리 이미지는 4:3이라는 비율 정보를 파일 자체에 담고 있습니다.

문제는 `<img>`에 `width`·`height` HTML 속성을 생략하면, 브라우저가 그 고유 비율을 **레이아웃 계산 단계에서 미리 반영하지 못했다**는 점입니다. `aspect-ratio` 속성이 생기면서, 최신 브라우저는 `<img width="800" height="600">`처럼 HTML 속성이 있는 이미지에 대해 사용자 에이전트 스타일시트가 자동으로 다음과 같은 규칙을 적용합니다.

```css
img, video, canvas {
  aspect-ratio: attr(width) / attr(height);
}
```

`attr()`(속성값 가져오기 함수)로 HTML의 `width`·`height` 속성값을 읽어와 CSS 비율로 미리 확보해두는 것입니다. 그래서 이제는 `<img src="..." width="800" height="600">`처럼 HTML 속성만 정확히 적어두면, 실제 파일이 아직 다운로드되지 않았어도 브라우저가 **레이아웃에 필요한 공간을 즉시 계산**해 레이아웃 밀림을 막습니다.

<Callout type="warning">
  **자주 틀리는 점:** `<img>`에 `width`·`height` HTML 속성을 넣으면 "이미지가 그 픽셀 크기로 고정된다"고 오해하기 쉽습니다. 실제로는 CSS에서 `width: 100%` 같은 반응형 규칙을 얼마든지 따로 줄 수 있고, HTML의 `width`·`height`는 **오직 비율 정보를 브라우저에 미리 알려주는 용도**로만 쓰입니다. 실제 렌더링 크기는 CSS가 최종 결정합니다.
</Callout>

## 4. 활용 — 레이아웃과 콘텐츠 넘침 함정

### 활용 예시 — 반응형 카드 썸네일

```css
.카드 {
  display: grid;
  gap: 0.5rem;
}

.카드 .썸네일 {
  width: 100%;
  aspect-ratio: 4 / 3;
  object-fit: cover; /* 비율에 안 맞는 원본은 잘라내며 채움 */
  border-radius: 8px;
}
```

`object-fit`(콘텐츠 맞춤)은 `aspect-ratio`와 짝을 이루는 속성으로, 상자 크기와 콘텐츠의 원래 비율이 다를 때 어떻게 채울지 정합니다. `cover`는 상자를 가득 채우되 남는 부분을 잘라내고, `contain`은 잘라내지 않되 여백이 남더라도 전체가 보이게 축소합니다.

### 콘텐츠 넘침 함정

`aspect-ratio`는 **박스 자체의 치수**를 고정할 뿐, 그 안에 들어가는 콘텐츠의 양은 신경 쓰지 않습니다. 텍스트처럼 길이가 가변적인 콘텐츠를 비율 고정 상자에 넣으면, 콘텐츠가 상자보다 많아졌을 때 밖으로 넘칩니다.

```css
.정사각형카드 {
  aspect-ratio: 1 / 1;
  overflow: hidden; /* 넘치는 콘텐츠를 잘라낼지 결정해야 함 */
}
```

`aspect-ratio`로 고정한 상자에 글자 수가 들쭉날쭉한 텍스트를 넣을 때는 `overflow: hidden`으로 잘라낼지, `overflow: auto`로 스크롤을 허용할지, 아니면 애초에 `min-height`만 주고 `aspect-ratio`는 이미지·비디오 영역에만 국한할지를 설계 단계에서 정해야 합니다. "비율을 고정했으니 크기 문제가 끝났다"고 안심하면 안 됩니다.

### 비교표 — `padding-top` 트릭 vs `aspect-ratio`

| 기준 | `padding-top` 트릭 | `aspect-ratio` |
|------|---------------------|----------------|
| 가독성 | 퍼센트 숫자만 봐서는 의도를 알 수 없음 | `16 / 9`처럼 의도가 코드에 그대로 드러남 |
| 구조 | 내부 요소를 `position: absolute`로 겹쳐야 함 | 일반적인 문서 흐름(normal flow) 그대로 사용 가능 |
| 비율 변경 | 퍼센트를 매번 다시 계산 | 슬래시 좌우 숫자만 바꾸면 끝 |
| 대체 요소와의 관계 | 별도 처리 필요 | `<img>`·`<video>`는 사용자 에이전트 스타일시트가 자동 처리 |
| 지원 상태 | 오래전부터 가능 | 널리 사용 가능(widely available) |

### 접근성 관점

레이아웃 밀림은 시각적 불편에 그치지 않습니다. 스크린 리더 사용자가 페이지를 순차 탐색하는 도중 이미지 로드로 위아래 요소 위치가 바뀌면 포커스(focus, 초점) 위치와 실제 화면 요소가 어긋날 수 있습니다. `aspect-ratio`(또는 HTML의 `width`·`height` 속성)로 공간을 미리 확보해두는 것은 시각적 안정성뿐 아니라 보조 기술 사용자의 탐색 일관성에도 도움이 됩니다.

## 핵심 정리

- `aspect-ratio: 너비 / 높이`는 한 축이 정해지면 나머지 축을 자동 계산해, `padding-top` 퍼센트 트릭 없이도 비율을 고정한다.
- `<img>`·`<video>` 같은 대체 요소는 원래 고유 비율을 가지며, HTML의 `width`·`height` 속성이 있으면 사용자 에이전트 스타일시트가 `aspect-ratio: attr(width) / attr(height)`를 자동 적용해 레이아웃 밀림을 막는다.
- HTML의 `width`·`height` 속성은 실제 렌더링 크기를 고정하지 않는다. 오직 비율 정보를 미리 알려주는 용도이며, 최종 크기는 CSS가 결정한다.
- `aspect-ratio`는 박스의 치수만 고정할 뿐 콘텐츠 양은 신경 쓰지 않으므로, 가변 길이 콘텐츠를 넣을 때는 넘침 처리 방식(`overflow`)을 함께 설계해야 한다.
- `aspect-ratio`는 널리 사용 가능(widely available)한 기능이라 폴백 없이 바로 쓸 수 있다.
