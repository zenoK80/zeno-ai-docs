<Callout type="info">
  **이번 문서의 목표:** 이 문서를 다 읽으면 `display`처럼 중간값이 없는 속성이 왜 그동안 전환(transition, 트랜지션)되지 않았는지 정확히 설명하고, `@starting-style`과 `transition-behavior: allow-discrete`를 조합해 `display: none`으로 사라지는 요소에도 CSS만으로 부드러운 진입·퇴장 애니메이션을 만들 수 있게 됩니다.
</Callout>

## 1. 왜 필요한가 — 두 가지 오래된 문제

### 문제 1 — 사라지는 요소는 전환되지 않는다

CSS의 `transition`(전환)은 속성값이 A에서 B로 바뀔 때 그 중간 단계를 계산해 부드럽게 보여주는 기능입니다. `opacity: 1`에서 `opacity: 0`으로 바뀌면 브라우저는 1, 0.9, 0.8, …처럼 중간값을 만들어 페이드아웃을 그립니다. 이것이 가능한 이유는 `opacity`가 **연속적인 숫자값**이라 중간값을 만들 수 있기 때문입니다.

그런데 `display: block`에서 `display: none`으로 바뀌는 경우를 생각해 봅시다. `display`에는 "block과 none의 중간"이라는 것이 존재하지 않습니다. 이런 속성을 **이산 속성**(discrete property, 불연속 속성)이라고 부릅니다. 오랫동안 이산 속성은 전환 목록에 넣어도 **중간 시점 없이 즉시 전환 시작 또는 종료 시점에 값이 바뀌는 것**으로 정의되어 있었습니다. 문제는 `display: none`이 적용되는 순간 요소가 렌더 트리에서 아예 빠지므로, 같이 걸어둔 `opacity` 전환이 재생될 시간조차 없이 요소가 통째로 사라져 버린다는 것입니다.

```css
/* 이렇게 써도 페이드아웃이 보이지 않는다 */
.모달 {
  opacity: 1;
  transition: opacity 0.3s;
}

.모달[hidden] {
  display: none;
  opacity: 0;
}
```

`hidden` 속성이 붙는 순간 `display: none`이 **즉시** 적용되어 요소가 화면과 접근성 트리에서 동시에 사라지므로, `opacity` 전환이 시작되기도 전에 재생할 대상이 없어집니다.

### 문제 2 — 나타나는 요소는 처음부터 최종 모습이다

반대 방향도 문제입니다. 요소를 화면에 새로 추가하면서 `opacity: 0`에서 `opacity: 1`로 페이드인시키고 싶다고 합시다.

```css
.토스트 {
  opacity: 0;
  transition: opacity 0.3s;
}

.토스트.보임 {
  opacity: 1;
}
```

`.보임` 클래스를 요소가 DOM에 추가되는 **바로 그 순간** 함께 붙이면, 브라우저는 첫 페인트(paint, 그리기) 전에 이미 `opacity: 1`이라는 최종 상태를 계산해버려 전환할 "이전 값"이 없는 것으로 처리하는 경우가 흔합니다. 그래서 예전에는 `requestAnimationFrame`을 이중으로 걸어 클래스를 한 프레임 늦게 붙이는 편법("더블 rAF 트릭")을 자바스크립트로 구현해야 했습니다.

> **쉽게 말하면:** 사진을 찍기 전에 이미 포즈를 다 잡고 있으면 "포즈를 잡아가는 과정"은 사진에 담기지 않습니다. 진입 애니메이션이 재생되려면 "잡기 전 포즈"를 브라우저에게 미리 알려줘야 합니다.

## 2. `@starting-style` — 진입 시 시작 스타일 정의하기

### 정의

**`@starting-style`**은 요소가 "이전에 렌더링되지 않다가 새로 나타나는 순간"에 적용할 **시작 스타일**을 정의하는 규칙입니다. 이렇게 정의된 시작 스타일과 실제 스타일 사이를 브라우저가 전환으로 이어줍니다.

```css
.토스트 {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 0.3s, transform 0.3s;

  @starting-style {
    opacity: 0;
    transform: translateY(-10px);
  }
}
```

이 규칙은 "이 요소가 새로 나타날 때는 `opacity: 0`, `translateY(-10px)`에서 시작해서, 지금 선언된 `opacity: 1`, `translateY(0)`으로 전환하라"는 뜻입니다. 더블 rAF 같은 자바스크립트 편법 없이, CSS 선언만으로 "시작 값"과 "끝 값"을 모두 CSS 쪽에 둘 수 있게 된 것입니다.

<Callout type="warning">
  **자주 틀리는 점:** `@starting-style` 블록은 **평소에는 적용되지 않는** 특별한 스타일입니다. 요소가 이미 렌더링되어 있는 상태에서 다른 속성이 바뀌는 일반적인 전환에는 전혀 관여하지 않고, 오직 "새로 나타나는 그 순간"에만 한 번 개입합니다.
</Callout>

## 3. `transition-behavior: allow-discrete` — 이산 속성도 전환 대상에 넣기

### 정의

**`transition-behavior`**(전환 동작 방식) 속성의 `allow-discrete` 값은 `display`, `content-visibility`처럼 원래 전환되지 않던 이산 속성도 전환 목록에 포함시킵니다. 이때 이산 속성은 중간값을 만드는 대신, **전환 시작 시점 또는 종료 시점 중 하나에서 값을 스위치**합니다.

```css
.모달 {
  transition: opacity 0.3s, display 0.3s allow-discrete;
}
```

`transition-behavior`는 단독 속성으로도 쓸 수 있지만, 위처럼 `transition` 축약 안에 마지막 키워드로 붙이는 방식이 흔합니다.

### 사라질 때와 나타날 때의 규칙이 다르다

이산 속성이 전환에 포함되면, 값이 바뀌는 방향에 따라 스위치 시점이 달라집니다.

- **사라지는 방향**(예: `display: flex` → `display: none`): 전환이 **끝나는 시점**까지 이전 값(`flex`)을 유지하다가, 전환이 끝난 후에야 `none`으로 전환됩니다. 즉 페이드아웃이 끝날 때까지 요소가 화면에 남아 있습니다.
- **나타나는 방향**(예: `display: none` → `display: flex`): 전환이 **시작되는 시점**에 즉시 `flex`로 전환됩니다. 그래야 요소가 화면에 존재해야 페이드인 전환이 눈에 보이기 때문입니다.

이 비대칭적인 규칙 덕분에 "사라질 때는 다 사라진 뒤에 `display: none`", "나타날 때는 나타나자마자 `display: flex`"라는, 우리가 직관적으로 기대하는 동작이 그대로 구현됩니다.

## 4. 둘을 합쳐 완성하는 진입·퇴장 애니메이션

두 기능은 짝을 이뤄 씁니다. `@starting-style`은 "나타날 때 어디서 출발하는가"를, `transition-behavior: allow-discrete`는 "`display: none` 단계 자체를 언제 넘나드는가"를 각각 책임집니다.

```css
.모달 {
  opacity: 0;
  transform: scale(0.9);
  display: none;
  transition: opacity 0.25s, transform 0.25s, display 0.25s allow-discrete;

  &.열림 {
    display: flex;
    opacity: 1;
    transform: scale(1);

    @starting-style {
      opacity: 0;
      transform: scale(0.9);
    }
  }
}
```

`.열림` 클래스가 붙는 순간(진입): `display`가 `allow-discrete` 덕분에 즉시 `flex`로 바뀌어 요소가 화면에 그려지고, 동시에 `@starting-style`이 지정한 "작고 투명한" 상태에서 실제 값으로 전환이 시작됩니다.

`.열림` 클래스가 빠지는 순간(퇴장): `opacity`와 `transform`이 먼저 원래 값으로 되돌아가는 전환을 재생하고, `display`는 `allow-discrete` 덕분에 그 전환이 **끝날 때까지** `flex`를 유지하다가 마지막에 `none`으로 바뀝니다. 그래서 요소가 사라지는 과정이 눈에 보입니다.

### 지원 상태와 폴백

`@starting-style`과 `transition-behavior: allow-discrete`는 둘 다 **최신 브라우저 기준**입니다(2024-08 Baseline newly available). 지원하지 않는 브라우저에서는 두 규칙이 그냥 무시되므로, 요소는 애니메이션 없이 즉시 나타나고 즉시 사라집니다. 이는 기능이 실패하는 것이 아니라 **자연스러운 성능 저하**(graceful degradation, 우아한 성능 저하)로 이어지는 경우입니다 — 모션이 빠졌을 뿐 기능 자체(모달이 열리고 닫히는 것)는 정상 동작합니다.

```css
@supports not (transition-behavior: allow-discrete) {
  /* 미지원 브라우저에서는 즉시 표시/숨김으로 충분하다는 것을 명시하는 문서화용 규칙 */
  .모달 {
    transition: none;
  }
}
```

### `@property`와의 조합 — 애니메이션 가능한 커스텀 속성까지

13편·14편에서 다룬 `@property`로 타입을 지정한 커스텀 속성은 색상·숫자처럼 연속적인 값으로 취급되어 전환이 가능해집니다. `@starting-style`은 이런 커스텀 속성에도 그대로 적용되어, 진입 시 시작 색상·숫자를 지정하는 데 함께 쓸 수 있습니다.

```css
@property --강조폭 {
  syntax: '<percentage>';
  inherits: false;
  initial-value: 0%;
}

.진행바 {
  --강조폭: 100%;
  transition: --강조폭 0.4s;

  @starting-style {
    --강조폭: 0%;
  }
}
```

## 5. `visibility` 전환과의 차이 — 완전히 새로운 기능은 아니다

사실 `display`가 최초의 이산 전환 대상은 아닙니다. `visibility`(보이기·숨기기, `hidden`/`visible`)는 오래전부터 전환 목록에 넣을 수 있었고, 방향에 따라 시작 또는 끝 시점에 스위치되는 규칙도 이미 있었습니다. 다만 `visibility: hidden`은 요소를 화면에서만 숨길 뿐 **레이아웃 공간은 그대로 차지**합니다. `display: none`은 레이아웃에서 요소를 완전히 제거해 공간까지 접습니다. `display`가 오랫동안 전환 대상이 아니었던 이유가 바로 이 완전한 제거 때문이며, `transition-behavior: allow-discrete`가 처음으로 이 간극을 메운 것입니다.

| 구분 | `visibility: hidden` | `display: none` |
|------|-----------------------|------------------|
| 레이아웃 공간 | 유지(자리 차지) | 제거(공간 접힘) |
| 이산 전환 지원 시점 | 오래전부터 가능 | `transition-behavior: allow-discrete` 등장 이후 |
| 접근성 트리 | 제거됨(스크린 리더가 못 읽음) | 제거됨(스크린 리더가 못 읽음) |
| 클릭·포커스 | 불가능 | 불가능 |

## 핵심 정리

- `display`처럼 중간값이 없는 이산 속성은 값이 바뀌는 즉시 전환되어, `display: none`이 걸리는 순간 요소가 렌더 트리에서 사라지므로 함께 건 다른 전환이 재생될 시간이 없었다.
- `@starting-style`은 요소가 새로 나타나는 순간에만 적용되는 시작 스타일을 정의해, 자바스크립트 더블 rAF 편법 없이 진입 애니메이션의 출발점을 CSS로 지정한다.
- `transition-behavior: allow-discrete`는 이산 속성을 전환 목록에 포함시키되, 사라질 때는 전환이 끝난 뒤 스위치하고 나타날 때는 전환이 시작되자마자 스위치하는 비대칭 규칙으로 동작한다.
- 두 기능은 짝을 이뤄 `display: none` 요소의 진입·퇴장 애니메이션을 완성하며, `@property`로 타입을 지정한 커스텀 속성에도 함께 적용할 수 있다.
- 둘 다 최신 브라우저 기준(2024-08 Baseline newly available)이라 미지원 브라우저에서는 모션 없이 즉시 표시·숨김으로 자연스럽게 성능이 저하된다.
