## 1. text-wrap — 줄바꿈을 브라우저가 대신 다듬는다

### 왜 필요한가

제목이나 카드 문구를 화면 폭에 맞춰 자동 줄바꿈하면 이런 모양이 자주 나옵니다.

```
모던 CSS로 만드는
반응형 레이아웃
가이드
```

마지막 줄에 단어 하나만 덩그러니 남는 현상을 **고아 텍스트**(orphan text, 고아 줄)라고 부릅니다. 디자이너 입장에서는 보기 좋지 않은 줄바꿈이고, 예전에는 이걸 고치려면 문구를 볼 때마다 `<br>`를 손으로 넣거나 자바스크립트로 폭을 재서 줄바꿈 위치를 계산하는 라이브러리를 썼습니다. 문구가 바뀌거나 화면 폭이 바뀌면 그 계산을 전부 다시 해야 했습니다.

> **쉽게 말하면:** `text-wrap`은 "줄바꿈을 예쁘게 나눠줘"라고 브라우저에 부탁하는 속성입니다. 브라우저가 전체 줄 폭을 미리 계산해서 균형 있게 나눠줍니다.

### 정의와 값

`text-wrap`(텍스트 감싸기)은 줄바꿈 알고리즘 자체를 지정하는 속성입니다.

| 값 | 동작 | 지원 상태(2026-09) |
|---|---|---|
| `wrap` | 기본값. 줄이 다 찰 때까지 채우고 넘치면 다음 줄로 | 널리 사용 가능 |
| `balance` | 문단 전체의 줄 길이를 최대한 고르게 맞춘다 | 최신 브라우저 기준(일부 줄 수 제약) |
| `pretty` | 고아 텍스트를 특히 신경 써서 줄바꿈한다 | 제한적 |
| `nowrap` | 줄바꿈하지 않는다 | 널리 사용 가능 |

### balance — 줄 길이를 저울처럼 맞춘다

**균형**(balance)이라는 이름 그대로, 브라우저는 전체 텍스트를 몇 줄로 나눌지 먼저 계산한 뒤, 그 줄 수 안에서 각 줄의 길이가 서로 비슷해지도록 나눕니다. 제목·카드 타이틀처럼 **짧은 블록**에 적합합니다.

```css
h1, .card-title {
  text-wrap: balance;
}
```

<Callout type="warning">
  **자주 틀리는 점:** `text-wrap: balance`는 아무리 긴 문단에도 무한정 적용되지 않습니다. 줄 수를 계산하는 비용이 크기 때문에 브라우저마다 상한이 있습니다(2026-09 기준 Chromium 계열은 6줄, Firefox는 10줄까지만 적용). 상한을 넘는 긴 본문에 걸면 그 줄부터는 다시 기본 줄바꿈(`wrap`)으로 돌아갑니다. 그래서 제목·부제·카드 문구처럼 짧은 텍스트에만 쓰는 것이 실무 관례입니다.
</Callout>

### pretty — 본문 마지막 줄까지 신경 쓴다

`pretty`(예쁘게)는 `balance`보다 범위가 넓은 문단에서, 특히 **문단 끝 마지막 줄에 단어 하나만 남는 것**을 피하는 데 초점을 둡니다. 다만 계산 비용이 `balance`보다도 커서, 2026년 9월 기준 지원 브라우저가 더 좁고(제한적·Limited availability) 지원 브라우저 안에서도 성능 트레이드오프가 있다고 MDN이 안내합니다. 따라서 짧은 요약 문단 몇 개에만 선택적으로 적용하고, 페이지 전체 본문에 일괄 적용하는 것은 권장되지 않습니다.

```css
@supports (text-wrap: pretty) {
  .article-lede {
    text-wrap: pretty;
  }
}
```

`@supports`(기능 쿼리, 02편에서 다룬 문법)로 감싸면 지원하지 않는 브라우저는 그냥 기본 줄바꿈을 쓰고, 지원하는 브라우저만 혜택을 받는 **점진적 향상**(progressive enhancement)이 됩니다.

## 2. field-sizing — 폼 필드가 내용만큼 커지게 하기

### 왜 필요한가

`<textarea>`는 기본적으로 `rows`·`cols`로 고정 크기를 잡습니다. 사용자가 짧게 한 줄만 쓰면 아래쪽에 빈칸이 남고, 길게 쓰면 스크롤이 생겨 내용을 한눈에 보기 어렵습니다. 예전에는 이걸 해결하려고 입력 이벤트마다 `scrollHeight`(스크롤 높이)를 읽어 자바스크립트로 `height`를 다시 계산하는 코드를 짰습니다.

> **쉽게 말하면:** `field-sizing`은 "이 입력창, 내용물 크기만큼 알아서 커져라"라고 CSS 한 줄로 시키는 속성입니다.

### 정의

**필드 크기 조절**(field-sizing)은 폼 컨트롤이 지정된 고정 크기를 쓸지, 내용에 맞춰 스스로 크기를 정할지 결정합니다.

| 값 | 동작 |
|---|---|
| `fixed` | 기본값. `width`/`height`, `rows`/`cols`로 정한 크기를 그대로 쓴다 |
| `content` | 입력된 내용의 길이만큼 크기가 자동으로 늘고 준다 |

```css
textarea {
  field-sizing: content;
  max-height: 300px; /* 무한정 커지지 않게 상한은 여전히 잡아준다 */
}
```

<Callout type="warning">
  **자주 틀리는 점:** `field-sizing: content`를 걸어도 `max-width`/`max-height`가 없으면 사용자가 아주 긴 글을 붙여넣었을 때 필드가 화면을 뒤덮을 수 있습니다. 자동 크기 조절과 상한 지정은 항상 함께 씁니다.
</Callout>

이 기능은 2026년 6월에야 Baseline **최신 브라우저 기준**(newly available)에 들어간 신생 기능입니다. 오래된 브라우저에서는 `fixed`처럼 동작할 뿐 레이아웃이 깨지지는 않으므로, 폴백 없이 써도 되는 안전한 점진적 향상입니다.

## 3. interpolate-size — 키워드 값도 전환되게 만들기

### 왜 필요한가

CSS 전환(transition)은 숫자 값끼리만 매끄럽게 보간(interpolation, 중간값 계산)됩니다. `height: 0px`에서 `height: 200px`로는 전환이 되지만, `height: 0px`에서 `height: auto`로는 전환되지 않습니다. `auto`는 숫자가 아니라 "내용에 맞춰 계산하라"는 키워드이기 때문에, 브라우저가 중간값을 계산할 방법이 없어서 그냥 순간적으로 값이 바뀌어 버립니다.

아코디언(accordion)이나 드롭다운을 열고 닫을 때 `height: auto`로 부드럽게 펼쳐지는 애니메이션을 만들고 싶은데, `auto`를 못 쓰니 오랫동안 개발자들은 자바스크립트로 `scrollHeight`를 재서 픽셀 값으로 바꿔치기하거나, `max-height`에 넉넉한 임의의 값을 걸어 우회했습니다. 두 방법 모두 번거롭거나 부정확했습니다.

> **쉽게 말하면:** `interpolate-size`는 "auto 같은 키워드도 숫자처럼 취급해서 중간값을 계산해도 된다"고 브라우저에 허락을 내리는 전역 스위치입니다.

### 정의와 문법

```css
:root {
  interpolate-size: allow-keywords;
}
```

| 값 | 동작 |
|---|---|
| `numeric-only` | 기본값. 숫자 값끼리만 전환된다(기존 동작) |
| `allow-keywords` | `auto`, `min-content`, `fit-content` 같은 크기 키워드도 전환 대상에 포함한다 |

이 속성을 `:root`(문서 최상위 요소, 선택자 `:root`는 보통 `html`과 같다)에 한 번 걸어두면, 문서 전체에서 `transition: height 0.3s`처럼 쓴 규칙이 `auto`가 낀 경우에도 부드럽게 전환됩니다.

```css
.accordion-panel {
  height: 0;
  overflow: hidden;
  transition: height 0.3s ease;
}
.accordion-panel[data-open] {
  height: auto;
}
```

### `@starting-style`과는 다른 문제를 푼다

이름이 비슷한 상황(펼침·접힘 애니메이션)에 함께 쓰이다 보니 20편에서 다루는 `@starting-style`과 혼동하기 쉽습니다. 둘은 겨냥하는 문제가 다릅니다.

| 구분 | 푸는 문제 | 자세히 |
|---|---|---|
| `@starting-style` | `display: none`처럼 **완전히 안 보이던 상태**에서 전환을 시작하는 방법 | 20편 참조 |
| `interpolate-size` | `auto`처럼 **숫자가 아닌 키워드 값**을 전환 대상에 포함하는 방법 | 이 편 |

실무에서는 두 가지를 함께 씁니다. 요소를 `display: none`에서 나타나게 하면서(`@starting-style`), 동시에 높이를 `0`에서 `auto`로 전환(`interpolate-size`)하는 식입니다.

<Callout type="warning">
  **지원 상태:** `interpolate-size`는 2026년 9월 기준 MDN이 "제한적·실험적(Limited availability, Experimental)"으로 표기합니다. Baseline에 들어가지 않은 상태이므로, 지금은 실무 기본값으로 걸어두기보다 지원 브라우저에서만 켜지는 향상 요소로 다뤄야 합니다. 반드시 `@supports`로 감싸고, 지원하지 않는 브라우저에서는 자바스크립트 높이 계산이나 `max-height` 방식 같은 기존 폴백을 유지합니다.
</Callout>

```css
@supports (interpolate-size: allow-keywords) {
  :root {
    interpolate-size: allow-keywords;
  }
}
```

## 핵심 정리

- `text-wrap: balance`는 짧은 제목의 줄 길이를 고르게 맞추지만 줄 수 상한(브라우저별로 6~10줄)이 있고, `pretty`는 문단 끝 고아 텍스트를 줄이지만 지원과 성능 비용이 더 제한적이다.
- `field-sizing: content`는 자바스크립트 없이 폼 필드를 내용 크기만큼 늘리고 줄이며, 반드시 `max-height`/`max-width`로 상한을 함께 건다.
- `interpolate-size: allow-keywords`는 `auto` 같은 키워드 값도 전환 대상에 포함시켜, 자바스크립트 높이 계산 없이 아코디언 애니메이션을 가능하게 한다.
- 세 기능 모두 지원 상태가 제각각이다(`text-wrap: balance`는 최신 브라우저 기준, `pretty`와 `interpolate-size`는 제한적). 매번 `@supports`로 확인하는 습관이 필요하다(02편 참조).
