<Callout type="info">
  **이번 문서의 목표:** 이 실습을 끝내면 `oklch` 기반 브랜드 색 하나에서 `color-mix()`로 파생 색을 계산하고, `light-dark()`와 `color-scheme`으로 라이트/다크를 동시에 지원하며, `@property`로 애니메이션 가능한 커스텀 속성까지 갖춘 색 토큰 시스템을 처음부터 끝까지 직접 만들 수 있게 됩니다.
</Callout>

## 이 실습에서 하나로 모으는 것

지금까지 15편에서 색 공간이 `hsl`에서 `oklch`로 바뀐 이유를, 16편에서 `color-mix()`로 색을 섞는 문법을, 17편에서 `light-dark()`와 `color-scheme`을, 13·14편에서 커스텀 속성과 `@property`를 각각 따로 배웠습니다. 이번 편은 그 네 조각을 실제 프로젝트에서 쓰는 순서대로 이어 붙여 하나의 **디자인 토큰**(design token, 디자인을 값 단위로 쪼갠 것) 시스템을 만듭니다.

디자인 토큰이란 색·간격·글자 크기처럼 디자인을 이루는 값 하나하나를 이름 붙은 변수로 만들어 관리하는 방식입니다. `#3366ff` 같은 값을 컴포넌트마다 직접 적는 대신 `--color-brand`라는 이름을 한 번 정의해 두고 어디서나 그 이름을 부릅니다. 이렇게 하면 브랜드 색 하나만 바꿔도 전체 화면이 따라 바뀌고, 라이트/다크 모드 전환도 값 하나를 뒤집는 문제로 줄어듭니다.

> **쉽게 말하면:** 토큰 시스템은 페인트 회사의 "색상 코드표"입니다. 벽마다 페인트 통을 새로 사 오는 대신, 코드표에 적힌 번호(`--color-brand`)만 부르면 항상 같은 색이 나옵니다. 그 코드표 자체를 밝은 버전·어두운 버전 두 벌 만들어 두는 것이 다크모드 대응입니다.

## 준비 — CSS Fundamentals에서 이미 안다고 전제하는 것

이 실습은 커스텀 속성 문법 자체(`--이름: 값`, `var()`)와 캐스케이드·상속 기본 규칙을 이미 안다고 전제합니다. 처음 보는 개념이라면 `content/web/css/css_fundamentals`를 먼저 확인하세요. 여기서는 그 위에서 "토큰을 어떻게 계산하고 전환하는가"만 다룹니다.

## 구현 절차

<Steps>

1. **기준 브랜드 색을 `oklch()`로 정의한다**: 색상(hue, 색상환의 각도)·채도(chroma)·명도(lightness) 세 축으로 브랜드 색 하나를 잡는다. `hsl`과 달리 같은 명도값이 실제로도 눈에 비슷한 밝기로 보인다는 것이 핵심 근거다(15편).
2. **`color-mix()`로 파생 색을 계산식으로 만든다**: 진한 버전·연한 버전·테두리색을 각각 `#`값으로 새로 고르지 않고, 기준 색에 검정·흰색을 섞는 비율로 계산한다. 브랜드 색 하나만 바꾸면 파생 색 전부가 따라 바뀐다.
3. **`light-dark()`와 `color-scheme`으로 배경·글자색을 라이트/다크 한 쌍으로 묶는다**: 값을 두 벌 따로 관리하지 않고 한 선언 안에 라이트용·다크용을 함께 적는다.
4. **`@property`로 애니메이션이 필요한 토큰에 타입을 준다**: 색상 각도(hue)처럼 트랜지션이 걸려야 하는 숫자 커스텀 속성은 `@property`로 등록해야 브라우저가 중간값을 계산할 수 있다(14편 원리 재사용).
5. **테마 전환 스위치를 `color-scheme` 오버라이드로 구현한다**: 시스템 설정(`prefers-color-scheme`)을 기본값으로 따르되, 사용자가 버튼을 누르면 `:root`의 `color-scheme`을 강제로 바꿔 `light-dark()`가 즉시 반응하게 한다.

</Steps>

## 1단계 — 기준 색과 파생 색 계산

브랜드 색을 색상·채도·명도 세 숫자로 쪼개 커스텀 속성에 담아 두면, 나중에 색조만 슬쩍 바꾸는 실험이 훨씬 쉬워집니다. 아래 표는 `oklch`의 세 인자가 각각 무엇을 뜻하는지 정리한 것입니다.

| 인자 | 뜻 | 예시 값 |
|------|------|---------|
| 명도(lightness) | 0퍼센트(검정)부터 100퍼센트(흰색)까지 | 60% |
| 채도(chroma) | 색의 선명함 정도, 보통 0부터 0.4 사이 | 0.15 |
| 색상(hue) | 0도부터 360도까지의 색상환 각도 | 250 |

```css
:root {
  /* 1단계 — 브랜드 색의 세 축을 각각 커스텀 속성으로 분리 */
  --brand-hue: 250;
  --brand-chroma: 0.15;
  --brand-lightness: 62%;
  --color-brand: oklch(var(--brand-lightness) var(--brand-chroma) var(--brand-hue));

  /* 2단계 — color-mix()로 파생 색을 "계산식"으로 만든다 */
  --color-brand-strong: color-mix(in oklch, var(--color-brand) 75%, black);
  --color-brand-subtle: color-mix(in oklch, var(--color-brand) 20%, white);
  --color-brand-border: color-mix(in oklch, var(--color-brand) 40%, transparent);
}
```

`color-mix()`의 첫 인자 `in oklch`는 "어느 색 공간에서 섞을 것인가"를 지정합니다. 같은 두 색이라도 `in srgb`로 섞을 때와 `in oklch`로 섞을 때 중간색이 다르게 나옵니다. `oklch`는 지각적으로 균일하도록 설계된 공간이라, 중간값이 눈에 보기에도 실제로 "딱 중간"에 가깝게 나온다는 것이 16편에서 다룬 핵심입니다.

<Callout type="warning">
  **자주 틀리는 점:** `color-mix()`는 "널리 사용 가능"(2023-05 Baseline widely available) 상태지만, 상대 색 문법(`from` 키워드로 기존 색을 변형하는 문법)은 **최신 브라우저 기준**으로 세부 기능별 지원 편차가 있습니다(16편). 이번 실습은 지원이 넓은 `color-mix()`만 사용합니다.
</Callout>

## 2단계 — light-dark()로 라이트/다크를 한 선언에 담기

`light-dark()`는 인자 두 개를 받아 "라이트 모드일 때 첫 번째, 다크 모드일 때 두 번째"를 돌려주는 함수입니다. 이 함수가 어떤 값을 돌려줄지는 그 요소에 적용된 `color-scheme` 값을 따릅니다.

```css
:root {
  /* 이 요소가 라이트/다크 둘 다 지원한다고 브라우저에 알린다 */
  color-scheme: light dark;

  --color-surface: light-dark(oklch(98% 0.01 250), oklch(22% 0.02 250));
  --color-surface-raised: light-dark(oklch(100% 0 0), oklch(28% 0.02 250));
  --color-text: light-dark(oklch(25% 0.02 250), oklch(95% 0.01 250));
  --color-text-muted: light-dark(oklch(45% 0.02 250), oklch(75% 0.01 250));
}

body {
  background: var(--color-surface);
  color: var(--color-text);
}
```

`color-scheme: light dark`는 "둘 다 준비돼 있으니 사용자 운영체제 설정(`prefers-color-scheme`)을 따르라"는 선언입니다. `light-dark()`(2024-05 Baseline newly available)는 아직 오래된 브라우저에서는 동작하지 않으므로, 지원하지 않는 환경을 위한 대비는 3단계 표에서 다시 정리합니다.

| 방식 | 코드량 | 전환 시점 | 비고 |
|------|--------|-----------|------|
| `prefers-color-scheme` 미디어 쿼리로 값 두 벌 작성 | 변수마다 두 블록 필요 | OS 설정 변경 시 | 널리 사용 가능, 자바스크립트 토글은 별도 구현 필요 |
| `light-dark()` + `color-scheme` | 변수 선언 한 줄 | OS 설정 또는 `color-scheme` 오버라이드 즉시 | 최신 브라우저 기준(2024-05 이후), 자바스크립트 토글이 자연스럽다 |

## 3단계 — @property로 애니메이션 가능한 토큰 만들기

일반 커스텀 속성은 브라우저가 "그냥 텍스트"로 취급하기 때문에, 값이 바뀌어도 중간 단계를 계산하지 못해 트랜지션이 걸리지 않습니다. `@property`로 타입을 알려주면 이 문제가 풀립니다(14편에서 다룬 원리).

```css
@property --brand-hue {
  syntax: "<number>";
  inherits: true;
  initial-value: 250;
}

.hue-demo {
  background: oklch(60% 0.15 var(--brand-hue));
  transition: --brand-hue 600ms ease;
}

.hue-demo:hover {
  --brand-hue: 340;
}
```

`syntax` 서술어(descriptor)는 "이 값이 숫자다"라고 못박는 역할을 합니다. `inherits`는 자식 요소가 이 값을 물려받을지, `initial-value`는 아무도 값을 정하지 않았을 때의 기본값입니다. 이 세 가지가 갖춰져야 브라우저가 250에서 340까지 색상 각도를 부드럽게 계산하며 넘어갈 수 있습니다.

<Callout type="warning">
  **자주 틀리는 점:** `@property`는 **최신 브라우저 기준**(2024-07 Baseline newly available) 기능입니다. 지원하지 않는 브라우저는 `@property` 블록 자체를 무시하고 `--brand-hue`를 여전히 문자열로 취급하므로, 트랜지션은 그냥 즉시 값이 바뀌는 것으로 대체됩니다. 레이아웃이 깨지지는 않으므로 안전한 점진적 향상입니다.
</Callout>

## 접근성 — 대비와 사용자 선호

색 토큰을 설계할 때 명도값만 대충 정하면 텍스트 대비(contrast, 배경과 글자색의 밝기 차이)가 기준에 못 미쳐 저시력 사용자가 읽기 어려워질 수 있습니다. `--color-text`와 `--color-surface`를 정할 때는 명도 차이를 충분히 벌려야 합니다(일반 텍스트 기준 WCAG 최소 대비 4.5대1). 또한 `prefers-contrast: more`를 감지해 대비를 더 벌린 토큰 세트를 추가로 준비하면 좋습니다. 이 미디어 기능은 26편에서 자세히 다룹니다.

## 핵심 정리

- 브랜드 색을 명도·채도·색상 세 숫자로 쪼개 `oklch()`에 담고, 파생 색은 `color-mix()`로 계산식화하면 브랜드 색 하나만 바꿔도 시스템 전체가 따라간다.
- `light-dark()`는 `color-scheme` 값을 따라 두 값 중 하나를 돌려준다. `:root`에 `color-scheme`을 강제로 덮어써 자바스크립트 없이도(속성 선택자만으로) 즉시 반응하는 테마 스위치를 만들 수 있다.
- `@property`로 `syntax`·`inherits`·`initial-value`를 지정한 커스텀 속성만 트랜지션 중간값을 계산할 수 있다. 지원하지 않는 브라우저에서는 조용히 즉시 전환으로 대체되는 안전한 향상이다.
- `color-mix()`·`light-dark()`·`@property`는 각각 널리 사용 가능, 최신 브라우저 기준, 최신 브라우저 기준으로 지원 수준이 다르다. 상태를 뭉뚱그리지 않고 매번 확인하는 습관이 이 과목 전체의 태도다.
