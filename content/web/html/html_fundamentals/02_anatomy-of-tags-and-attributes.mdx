## 왜 문법부터 정확히 봐야 하는가

앞선 01편에서 HTML이 "내용에 의미를 표시하는 언어"라고 배웠습니다. 그런데 그 표시를 실제로 코드로 적는 규칙 — 어디까지가 표시이고 어디부터가 내용인지, 표시에 옵션을 어떻게 붙이는지 — 을 정확히 모르면 이후 모든 편에서 나오는 예제 코드를 눈으로만 흉내 내게 됩니다. 이번 편은 HTML 문법의 **아나토미**(anatomy, 해부 구조)를 뜯어봅니다. 겉모습이 아니라 각 부품이 왜 그런 모양인지를 봅니다.

## 1. 태그와 요소 — 자주 섞어 쓰지만 다른 말

### 왜 구분해야 하는가

"태그를 쓴다"와 "요소를 쓴다"는 표현을 실무에서는 거의 구분 없이 씁니다. 그런데 스펙 문서나 에러 메시지를 정확히 읽으려면 이 둘의 차이를 알아야 합니다. 특히 05편에서 배울 콘텐츠 모델(content model)은 "요소"를 기준으로 규칙을 설명하기 때문에, 여기서 헷갈리면 뒤에서 계속 걸립니다.

> **쉽게 말하면:** 태그는 괄호 기호 자체이고, 요소는 그 괄호로 감싼 결과물 전체입니다.

**태그**(tag)는 `<p>`나 `</p>`처럼 꺾쇠(`<`, `>`)로 둘러싼 표시 기호 그 자체를 가리킵니다. **요소**(element)는 여는 태그부터 닫는 태그까지, 그리고 그 사이의 내용까지를 합친 전체 구조를 가리킵니다.

```html
<p>이것은 문단입니다.</p>
```

- `<p>` — 여는 태그(opening tag, start tag)
- `이것은 문단입니다.` — 콘텐츠(내용)
- `</p>` — 닫는 태그(closing tag, end tag)
- `<p>이것은 문단입니다.</p>` 전체 — **요소**(element)

즉 "`p` 태그"라는 말은 엄밀히는 `<p>`라는 기호 하나만 가리키고, "`p` 요소"라는 말이 문단 전체 구조를 가리키는 정확한 표현입니다. 실무 대화에서는 섞어 써도 뜻이 통하지만, 이 시리즈에서는 정확한 문맥이 필요할 때 "요소"를 우선 씁니다.

## 2. 여는 태그와 닫는 태그, 그리고 빈 요소

### 대부분의 요소는 짝이 있다

`<p>...</p>`, `<div>...</div>`, `<a>...</a>`처럼 대부분의 요소는 여는 태그와 닫는 태그가 짝을 이루고, 그 사이에 콘텐츠가 들어갑니다. 닫는 태그는 슬래시(`/`)를 태그 이름 앞에 붙여 "여기서 이 요소가 끝난다"는 신호를 줍니다.

### 콘텐츠 자체가 없는 요소 — 빈 요소

그런데 어떤 요소는 애초에 "안에 넣을 콘텐츠"라는 개념이 없습니다. 예를 들어 이미지를 넣는 `<img>`는 이미지 파일 경로를 속성으로 받을 뿐, 그 사이에 텍스트나 다른 요소를 넣을 자리가 없습니다. 줄바꿈을 만드는 `<br>`도 마찬가지로 "줄바꿈이라는 동작" 자체가 콘텐츠이므로 감쌀 것이 없습니다. 이런 요소를 **빈 요소**(void element, 보이드 엘리먼트)라고 부릅니다.

빈 요소는 애초에 콘텐츠를 담을 수 없으므로 닫는 태그도 필요 없습니다. 대표적인 빈 요소는 다음과 같습니다.

| 요소 | 용도 |
|------|------|
| `<img>` | 이미지 삽입 |
| `<br>` | 줄바꿈 |
| `<hr>` | 주제 구분선 |
| `<input>` | 폼 입력 필드 |
| `<meta>` | 문서 메타데이터 |
| `<link>` | 외부 리소스 연결 |

```html
<img src="cat.jpg" alt="낮잠 자는 고양이">
<br>
<hr>
```

<Callout type="warning">
  **자주 틀리는 점:** `<img src="cat.jpg"></img>`처럼 빈 요소에 닫는 태그를 따로 붙이는 코드를 종종 봅니다. HTML Living Standard 문법에서는 이것이 틀린 표기입니다. 01편에서 본 `<br />`처럼 슬래시를 태그 안에 붙이는 표기(self-closing, 자체 닫힘 표기)는 XHTML의 유산으로 지금도 허용되지만(브라우저가 무시하고 넘어갑니다), `<br></br>`처럼 별도의 닫는 태그를 만드는 것은 스펙에 없는 문법입니다.
</Callout>

### 문서 파싱까지 이어지는 이유

빈 요소인지 아닌지는 나중에 22편에서 배울 브라우저 파싱(parsing, 구문 분석) 규칙과도 직접 연결됩니다. 브라우저의 파서(parser, 구문 분석기)는 각 태그 이름마다 "이 요소는 빈 요소인가"를 미리 알고 있어서, `<br>` 뒤에 닫는 태그가 없어도 오류로 취급하지 않고 정상적으로 트리를 만듭니다. 반대로 `<p>`처럼 빈 요소가 아닌 태그를 닫지 않고 방치하면, 파서가 나름의 규칙으로 어디서 끝났는지 추측합니다. 이 추측 규칙은 05편(콘텐츠 모델)과 22편(파싱)에서 자세히 다룹니다.

## 3. 속성 — 태그에 붙이는 옵션

### 왜 필요한가

`<img>`만 놓고 보면 브라우저는 "이미지를 넣어야 한다"는 사실만 알 뿐, **어떤** 이미지를 넣어야 하는지는 모릅니다. 이런 추가 정보를 태그에 옵션 형태로 붙이는 것이 **속성**(attribute)입니다.

> **쉽게 말하면:** 속성은 택배 상자 겉면에 붙이는 라벨입니다. 상자(요소) 자체는 "이건 이미지 상자다"라는 종류만 알려주고, 라벨(속성)이 "내용물은 cat.jpg다", "설명은 낮잠 자는 고양이다"처럼 구체적인 정보를 알려줍니다.

속성은 `이름="값"` 형태로 쓰고, 여는 태그 안에 태그 이름 뒤에 공백으로 구분해 나열합니다.

```html
<img src="cat.jpg" alt="낮잠 자는 고양이" width="300" height="200">
```

- `src`(source, 출처) — 이미지 파일의 경로
- `alt`(alternative text, 대체 텍스트) — 이미지를 보여줄 수 없을 때 대신 표시할 설명
- `width`, `height` — 가로·세로 크기(픽셀 단위 정수)

### 속성값을 감싸는 인용 규칙

속성값은 큰따옴표(`"`)로 감싸는 것이 표준 관례입니다. HTML Living Standard 문법상으로는 작은따옴표(`'`)도 허용되고, 값에 공백·특수문자가 전혀 없다면 따옴표 자체를 생략할 수도 있습니다. 하지만 실무에서는 예외 없이 큰따옴표를 씁니다. 이유는 셋입니다.

1. **일관성** — 팀 전체가 같은 규칙을 쓰면 코드 스타일 도구(linter, 린터)가 자동으로 통일해 주기 쉽습니다.
2. **JS 문자열과의 충돌 회피** — 자바스크립트 코드 안에 HTML 문자열을 넣을 때 작은따옴표로 감싸는 관례가 흔한데, 그 안의 속성값까지 작은따옴표면 문자열이 중간에서 끊깁니다.
3. **공백이 있는 값의 안전성** — 값에 공백이 하나라도 있으면 따옴표 생략은 아예 불가능합니다. 처음부터 항상 따옴표를 쓰는 습관을 들이면 이 문제를 신경 쓸 필요가 없습니다.

```html
<!-- 표준 관례: 큰따옴표 -->
<input type="text" placeholder="이름을 입력하세요">

<!-- 문법상 허용되지만 실무에서 거의 안 씀: 작은따옴표 -->
<input type='text' placeholder='이름을 입력하세요'>

<!-- 문법상 허용되지만 위험: 따옴표 생략 -->
<input type=text placeholder=이름을입력하세요>
```

마지막 줄처럼 따옴표를 생략하면 값에 공백이 들어가는 순간 파서가 값이 어디서 끝나는지 잘못 판단합니다. 아래 실습기에서 직접 확인해 보십시오.

### 값이 없는 속성 — 불리언 속성

일부 속성은 값 자체가 필요 없고, **있으면 참, 없으면 거짓**으로 동작합니다. 이런 속성을 **불리언 속성**(boolean attribute)이라고 부릅니다. 대표적으로 `<input>`의 `disabled`, `checked`, `readonly`가 있습니다.

```html
<input type="checkbox" checked>
<input type="text" disabled>
```

값을 아예 안 쓰거나(`checked`), 관례상 속성 이름을 그대로 값으로 채워도(`checked="checked"`) 똑같이 "참"으로 동작합니다. 반대로 `checked="false"`처럼 값에 `false`를 넣어도 속성이 **존재하기만 하면** 여전히 참으로 처리되므로, 끄고 싶다면 속성 자체를 아예 빼야 합니다. 이 규칙은 14편(폼 입력의 전통적 타입)에서 다시 자세히 다룹니다.

## 4. 대소문자·공백·주석 표기법

### 대소문자 — 소문자가 관례다

HTML Living Standard는 태그 이름과 속성 이름의 대소문자를 구분하지 않습니다. 즉 `<P>`, `<p>`, `<Div>`, `<DIV>` 모두 브라우저에는 동일하게 해석됩니다. 그런데도 실무에서는 예외 없이 **소문자**로 씁니다. 이유는 XHTML의 엄격한 문법(태그 이름을 반드시 소문자로 써야 했음)이 관례로 굳어 내려왔고, 코드를 읽을 때 일관성이 있어야 눈에 덜 피곤하기 때문입니다.

### 공백 — 의미 있는 공백과 무시되는 공백

콘텐츠 안의 공백과 줄바꿈은 브라우저가 렌더링할 때 **연속된 공백을 하나로 합쳐서** 보여줍니다(이 동작을 공백 접기, whitespace collapsing이라고 부릅니다).

```html
<p>여러      개의     공백은
모두 하나로 합쳐집니다.</p>
```

이 문단은 코드 안에 공백과 줄바꿈이 여러 개 있어도 화면에는 "여러 개의 공백은 모두 하나로 합쳐집니다."처럼 한 줄로 붙어 나옵니다. 공백을 그대로 보존하고 싶다면 11편에서 배울 `<pre>` 요소를 써야 합니다. 반면 태그와 속성 사이의 공백(`<img src="...">`처럼 태그 이름과 속성 사이)은 문법적으로 필수이며 생략할 수 없습니다.

### 주석 — 브라우저가 무시하는 메모

코드에 메모를 남기고 싶을 때는 `<!--`와 `-->`로 감쌉니다. 이 안의 내용은 브라우저가 화면에 그리지 않고 완전히 건너뜁니다.

```html
<!-- 이 아래는 헤더 영역입니다 -->
<header>
  <h1>사이트 제목</h1>
</header>
```

<Callout type="warning">
  **자주 틀리는 점:** 주석 안에 콘텐츠를 감춰도 **브라우저 화면에만** 보이지 않을 뿐, 페이지 소스 코드를 열면 누구나 읽을 수 있습니다. 비밀번호나 내부 API 키처럼 노출되면 안 되는 정보를 주석에 적어 두면 안 됩니다.
</Callout>

## 핵심 정리

- **태그**는 `<p>`, `</p>` 같은 기호 자체이고, **요소**는 여는 태그부터 닫는 태그와 콘텐츠까지 합친 전체다.
- **빈 요소**(`<img>`, `<br>`, `<input>` 등)는 콘텐츠를 담지 않으므로 닫는 태그가 없다. `<br></br>`처럼 별도로 닫는 것은 스펙에 없는 문법이다.
- **속성**은 태그에 추가 정보를 붙이는 방법이며, 값은 항상 큰따옴표로 감싸는 것이 실무 관례다. 따옴표를 생략하면 공백이 있는 값에서 파싱이 어긋난다.
- **불리언 속성**은 값이 아니라 존재 여부로 참/거짓이 결정된다.
- 태그·속성 이름은 소문자가 관례이고, 콘텐츠 안 연속 공백은 하나로 합쳐지며, 주석은 화면에서만 감춰질 뿐 소스에는 그대로 남는다.
