</Callout>

## 왜 뼈대부터 정확히 짜야 하는가

지금까지 두 편에서 개별 태그의 문법을 배웠습니다. 이제부터는 그 태그들을 모아 실제로 브라우저가 웹 페이지로 인식하는 **완전한 문서**를 만드는 법을 봅니다. 모든 HTML 문서는 겉모습이 아무리 달라도 똑같은 뼈대 위에 서 있습니다. 이 뼈대를 정확히 이해하지 못하면, 어디에 무엇을 적어야 할지 매번 예제를 베껴서 짐작하게 됩니다.

## 1. `<!doctype html>` — 표준 모드로 켜는 스위치

### 왜 문서 맨 위에 이 문장을 적는가

브라우저는 원래 아주 오래된 웹페이지도 화면에 띄워야 합니다. 그런데 1990년대 후반 브라우저들은 지금과 다른 방식으로 레이아웃 계산을 하던 시절이 있었고, 그 시절 만들어진 페이지를 지금 방식으로 다시 계산하면 레이아웃이 깨질 수 있습니다. 그래서 브라우저는 문서 맨 앞을 보고 "이 문서를 최신 방식(표준 모드)으로 그릴지, 옛날 방식(호환 모드)으로 그릴지"를 판단합니다. 이 판단 기준이 되는 신호가 **doctype**(문서 형식 선언, document type declaration)입니다.

> **쉽게 말하면:** `<!doctype html>`은 브라우저에게 "이 문서는 최신 규칙으로 그려 주세요"라고 알리는 스위치입니다.

### 오늘날의 doctype은 딱 하나

```html
<!doctype html>
```

이 한 줄이 현재 HTML Living Standard가 정한 **유일한** doctype입니다. 대소문자는 구분하지 않아 `<!DOCTYPE html>`로 써도 동일하게 동작하지만, 실무에서는 소문자로 쓰는 것이 관례입니다.

01편에서 본 것처럼 과거 HTML4나 XHTML 시절에는 doctype이 훨씬 복잡했습니다.

```html
<!-- HTML4 Strict의 doctype 예시 — 역사적 참고용, 지금은 쓰지 않는다 -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
  "http://www.w3.org/TR/html4/strict.dtd">
```

이런 옛 doctype은 **DTD**(Document Type Definition, 문서 형식 정의)라는 문서를 실제로 가리켰습니다. DTD는 그 버전의 HTML에서 어떤 태그와 속성이 허용되는지를 정의한 규칙 파일이었습니다. 반면 지금의 `<!doctype html>`은 어떤 DTD도 실제로 가리키지 않습니다. 그저 "표준 모드로 렌더링하라"는 신호일 뿐이며, 문법 검증은 06편 이후에서 배울 별도의 검증기가 담당합니다.

<Callout type="warning">
  **자주 틀리는 점:** "doctype이 HTML 버전을 선언한다"는 옛 설명을 그대로 믿으면 안 됩니다. `<!doctype html>`은 특정 버전을 선언하지 않습니다. HTML에는 더 이상 버전이 없다는 사실은 01편에서 이미 확인했습니다. 이 한 줄의 실제 역할은 표준 모드 트리거뿐입니다.
</Callout>

### doctype이 없으면 무슨 일이 벌어지는가

doctype을 생략하면 브라우저는 **호환 모드**(quirks mode, 특이 모드)로 문서를 그립니다. 호환 모드에서는 박스 크기 계산이나 표(table) 레이아웃 같은 부분이 옛날 브라우저의 버그를 그대로 재현하는 방식으로 동작해, 지금 배우는 CSS 규칙과 다르게 보일 수 있습니다. 그래서 모든 HTML 문서는 예외 없이 첫 줄에 `<!doctype html>`을 적어야 합니다.

## 2. `<html>`·`<head>`·`<body>` — 세 칸짜리 뼈대

### 최소한의 완전한 문서

doctype 아래에는 문서 전체를 감싸는 `<html>` 요소가 옵니다. 그 안에는 딱 두 개의 자식만 옵니다. 보이지 않는 정보를 담는 `<head>`와, 실제로 화면에 그려지는 `<body>`입니다.

```html
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">
    <title>내 첫 페이지</title>
  </head>
  <body>
    <h1>안녕하세요</h1>
    <p>이것이 화면에 보이는 내용입니다.</p>
  </body>
</html>
```

| 요소 | 담는 것 | 화면 표시 여부 |
|------|---------|----------------|
| `<html>` | 문서 전체를 감싸는 최상위 요소 | 요소 자체는 보이지 않음 |
| `<head>` | 문서에 대한 정보(메타데이터) | 보이지 않음(단, 안의 `<title>`은 브라우저 탭에 표시) |
| `<body>` | 실제 콘텐츠 | 화면에 그려짐 |

> **쉽게 말하면:** `<head>`는 책의 표지 뒷면에 적힌 서지 정보(제목·저자·출판사)이고, `<body>`는 실제로 읽는 본문입니다. 표지 뒷면을 안 읽어도 책은 읽을 수 있지만, 그 정보가 없으면 서점에서 이 책을 찾기 어렵고 도서관 분류도 안 됩니다.

### `lang` 속성 — 사람을 위한 정보가 아니다

`<html lang="ko">`의 `lang` 속성은 12편에서 배울 전역 속성(global attribute) 중 하나로, 이 문서가 어떤 언어로 작성되었는지를 선언합니다. 이 값은 화면에 아무것도 표시하지 않지만, 스크린 리더가 올바른 발음 규칙을 선택하고, 브라우저의 자동 번역 기능이 원문 언어를 정확히 판단하는 데 씁니다. 문서 언어가 한국어라면 `lang="ko"`, 영어라면 `lang="en"`을 씁니다. 이 속성을 빠뜨리면 스크린 리더가 잘못된 언어 규칙(예: 영어 발음 규칙)으로 한국어 문장을 읽으려다 이상하게 발음하는 문제가 생길 수 있습니다.

## 3. `<head>` 안의 필수 메타데이터

### 왜 head라는 별도 공간이 필요한가

화면에 보이지 않는 정보를 왜 따로 모아 둘까요? 브라우저·검색 엔진·스크린 리더처럼 "사람이 아닌 소비자"가 문서를 처리할 때 필요한 정보가 있기 때문입니다. 예를 들어 브라우저는 텍스트를 화면에 그리기 전에 먼저 "이 문서가 어떤 문자 인코딩으로 저장되었는지"를 알아야 글자가 깨지지 않습니다. 이런 사전 정보를 `<head>` 안에 모아 둡니다.

### 메타데이터 ① — 문자 인코딩

```html
<meta charset="UTF-8">
```

**인코딩**(encoding)이란 사람이 읽는 문자를 컴퓨터가 저장하는 숫자(바이트, byte)로 바꾸는 규칙입니다. **UTF-8**은 현재 웹에서 사실상 표준으로 쓰이는 인코딩으로, 한글·한자·이모지를 포함한 전 세계 거의 모든 문자를 표현할 수 있습니다. 이 선언이 없거나 실제 파일 인코딩과 다르면 한글이 깨져서 알 수 없는 기호(예: `ì•ˆë…•`)로 보이는 현상이 나타납니다. `<meta charset>`은 `<head>`의 다른 어떤 요소보다도 먼저 나와야 합니다. 브라우저가 문서 앞부분을 아주 짧게(첫 1024바이트 정도) 읽으면서 인코딩을 판단하기 때문에, 이 선언이 뒤로 밀리면 이미 잘못된 인코딩으로 앞부분을 해석해 버릴 수 있습니다. 문자 참조와 인코딩의 나머지 세부 사항은 19편에서 더 다룹니다.

### 메타데이터 ② — 뷰포트

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

**뷰포트**(viewport, 보이는 영역)는 브라우저 화면에서 실제로 콘텐츠가 그려지는 영역을 가리킵니다. 데스크톱 화면을 기준으로 설계된 옛날 페이지를 스마트폰이 그대로 열면, 폰 화면보다 훨씬 넓은 캔버스(약 980px 기준)에 그려 놓고 축소해서 보여주는 방식을 씁니다. 그러면 글자가 너무 작아져 확대해야만 읽을 수 있습니다. 이 메타 태그는 그런 옛날식 축소 동작을 끄고, "화면의 실제 너비(`device-width`)를 기준으로, 처음 배율은 1배로 그려 달라"고 브라우저에 지시합니다.

- `width=device-width` — 뷰포트 너비를 기기의 실제 화면 너비와 같게 맞춘다
- `initial-scale=1` — 페이지를 처음 열었을 때 확대·축소 없이 100퍼센트 배율로 보여준다

이 메타 태그를 빠뜨리면 모바일 환경에서 레이아웃이 전부 작게 눌려 보이는 문제가 생깁니다. 실제 레이아웃이 화면 크기에 따라 어떻게 재배치되는지(반응형 디자인)는 `css/css_fundamentals` 과목이 다루고, 여기서는 "이 메타 태그 하나가 모바일 렌더링의 전제 조건"이라는 사실만 확실히 짚습니다.

### 메타데이터 ③ — 문서 제목

```html
<title>내 첫 페이지</title>
```

`<title>`은 브라우저 탭, 즐겨찾기(북마크) 목록, 검색 결과 목록에 표시되는 문서의 제목입니다. `<head>` 안에서 화면에 어떤 형태로든 흔적을 남기는 유일한 요소이며, 모든 문서에 정확히 하나씩 있어야 합니다. `<body>` 안의 `<h1>`(문서 안에서 보이는 제목)과 `<title>`(문서 자체의 제목)은 서로 다른 자리에서 다른 역할을 하므로 혼동하지 않아야 합니다. `<h1>`을 포함한 제목 레벨 구조는 17·18편에서 자세히 다룹니다.

### 메타데이터 ④ — 설명

```html
<meta name="description" content="HTML의 기초 문법과 시맨틱 요소를 처음부터 배우는 학습 자료">
```

`description` 메타 태그는 검색 엔진이 검색 결과에 보여주는 짧은 설명문으로 자주 쓰입니다. 화면에 직접 그려지지는 않지만, 검색 결과에서 이 페이지를 클릭할지 판단하는 정보로 노출됩니다. 검색 엔진 최적화(SEO)를 위한 더 정교한 메타데이터·구조화 데이터는 이 과목의 범위 밖이며 `html/modern_html` 과목에서 다룹니다.

## 4. head 안에 자주 함께 등장하는 것들

`<head>` 안에는 지금까지 본 필수 메타데이터 외에도 다음과 같은 요소가 자주 들어갑니다. 지금은 이름만 익혀 두고, 각각의 상세 내용은 해당 편에서 다룹니다.

| 요소 | 역할 | 자세한 내용 |
|------|------|--------------|
| `<link rel="stylesheet">` | 외부 CSS 파일 연결 | `css/css_fundamentals` 과목 |
| `<script>` | 자바스크립트 파일 연결·실행 | `javascript/web_apis` 과목 |
| `<link rel="icon">` | 브라우저 탭에 표시할 파비콘 지정 | `html/modern_html` 과목 |

이 과목에서는 `<head>`가 "화면에 안 보이지만 문서 처리에 필요한 정보를 모아 두는 곳"이라는 개념과, 그중 반드시 있어야 하는 네 가지(문자 인코딩·뷰포트·제목·설명)까지만 확실히 잡고 넘어갑니다.

## 핵심 정리

- `<!doctype html>`은 HTML의 유일한 표준 doctype이며, 실제로 어떤 DTD도 가리키지 않는 "표준 모드 트리거"일 뿐이다. 생략하면 호환 모드로 렌더링된다.
- HTML 문서는 `<html>`(전체) 안에 `<head>`(보이지 않는 정보)와 `<body>`(보이는 콘텐츠) 두 칸으로 이루어진다.
- `<head>`에는 최소한 `meta charset`(문자 인코딩), `meta viewport`(모바일 렌더링 기준), `title`(문서 제목), `meta description`(검색 결과용 설명) 네 가지가 있어야 한다.
- `meta charset`은 `<head>`의 다른 요소보다 먼저 와야 하며, 실제 파일 인코딩과 일치해야 한글이 깨지지 않는다.
- `lang` 속성은 화면에 보이지 않지만 스크린 리더의 발음 규칙 선택에 직접 영향을 준다.
