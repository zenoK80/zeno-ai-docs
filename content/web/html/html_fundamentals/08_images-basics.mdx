## 왜 이미지 태그 하나에 판단이 필요한가

`<img>`는 문법만 보면 아주 단순한 요소입니다. `src`에 경로만 넣으면 화면에 그림이 뜹니다.

```html
<img src="logo.png">
```

하지만 이것만으로는 부족합니다. 이미지를 보지 못하는 사용자(스크린 리더 사용자, 이미지 로딩이 실패한 상황, 검색 엔진 크롤러)에게 이 요소는 아무 정보도 전달하지 못합니다. HTML은 처음부터 이미지를 텍스트로 **대체**할 수 있는 장치를 마련해 두었고, 그것이 `alt` 속성입니다. 문제는 "`alt`에 아무 말이나 채우면 된다"가 아니라, **이 이미지가 왜 여기 있는지**를 판단해야 올바른 값을 채울 수 있다는 점입니다. 이 판단 기준이 이 편의 핵심입니다.

05편에서 배운 콘텐츠 카테고리 기준으로 `<img>`는 flow·phrasing·embedded 콘텐츠에 동시에 속하는 요소였습니다. `<p>` 안에도, `<div>` 안에도 자유롭게 들어갈 수 있는 이유가 여기 있습니다.

## 1. src — 어떤 이미지를 가져올 것인가

`src`(source, 출처)는 07편에서 배운 `href`와 똑같은 방식으로 절대 경로·상대 경로를 받습니다.

```html
<img src="https://example.com/images/logo.png">  <!-- 절대 경로 -->
<img src="images/logo.png">                       <!-- 상대 경로 -->
```

브라우저는 HTML 문서를 파싱하다가 `<img>`를 만나면 곧바로 `src`가 가리키는 자원에 대한 네트워크 요청을 시작합니다. 이 요청은 문서 본문의 파싱을 막지 않고 **병렬로** 진행되는데, 이 동작의 세부(프리로드 스캐너 등)는 렌더링 파이프라인의 영역이라 `javascript/web_apis` 과목에서 다룹니다. 여기서는 "이미지 요청은 이미지가 화면에 그려지는 시점과 별개로, 문서를 읽는 즉시 시작된다"는 사실만 기억하면 됩니다.

## 2. alt — 대체 텍스트라는 개념

**alt**는 alternative text(대체 텍스트, 얼터너티브 텍스트)의 줄임말입니다. "대체"라는 말 그대로, 이미지가 어떤 이유로든 보이지 않을 때 **그 이미지 대신 읽거나 표시할 텍스트**입니다. 대체되는 상황은 세 가지입니다.

- 스크린 리더 사용자가 화면을 보지 않고 소리로 문서를 듣는 경우
- 네트워크 오류나 잘못된 경로로 이미지 자체가 로드되지 않은 경우
- 검색 엔진 크롤러처럼 애초에 그림을 "볼" 수 없는 프로그램이 문서를 읽는 경우

```html
<img src="cat.jpg" alt="갈색 얼룩무늬 고양이가 창가에 앉아 있다">
```

### 장식용 이미지와 정보성 이미지를 구분하는 기준

`alt`를 채우는 방법은 이미지 하나로 정해지지 않습니다. **같은 이미지라도 문맥에 따라 장식용일 수도, 정보성일 수도 있습니다.** 판단 기준은 하나입니다. "이 이미지가 사라지면 사용자가 놓치는 정보가 있는가?"

| 상황 | 판단 | alt 값 | 이유 |
|------|------|--------|------|
| 기사 본문에서 사건 현장을 보여주는 사진 | 정보성 | `alt="현장을 찍은 사진 내용을 설명하는 구체적인 문장"` | 사진 자체가 기사의 정보를 담고 있다 |
| 같은 사진이지만 순수 배경 장식으로 반복 배치된 경우 | 장식용 | `alt=""` (빈 문자열) | 정보 전달 목적이 아니라 시각적 꾸밈일 뿐이다 |
| 버튼 안의 돋보기 아이콘(검색) | 정보성(기능성) | `alt="검색"` | 아이콘이 버튼의 기능을 전달하는 유일한 단서다 |
| 텍스트 옆의 장식용 구분선 이미지 | 장식용 | `alt=""` | 시각적 구분 목적일 뿐 별도 정보가 없다 |

<Callout type="warning">
  **자주 틀리는 점:** "이미지에는 항상 설명을 채워야 한다"고 단순화하면 안 됩니다. 장식용 이미지에 불필요한 설명을 채우면, 스크린 리더가 아무 의미 없는 문구를 매번 읽어줘 오히려 사용자의 탐색을 방해합니다. 장식용 이미지의 정답은 **`alt` 속성 자체를 생략하는 것이 아니라, `alt=""`처럼 빈 문자열로 명시하는 것**입니다. `alt` 속성을 아예 빼먹으면 일부 스크린 리더가 파일명(`IMG_2384.jpg` 같은)을 대신 읽어버려 오히려 더 혼란스러운 결과가 나옵니다.
</Callout>

### 좋은 alt 텍스트를 쓰는 법

- "사진", "이미지"라는 말을 반복하지 않습니다. `<img>` 요소 자체가 이미 "이것은 이미지"라는 사실을 스크린 리더에 전달하므로 중복입니다.
- 이미지가 놓인 문맥에서 필요한 정보만 담습니다. 상품 사진이면 "빨간색 운동화 옆모습"처럼 구매 판단에 필요한 정보를, 그래프 이미지면 그래프가 보여주는 핵심 수치나 추세를 요약합니다.
- 지나치게 길게 쓰지 않습니다. 한두 문장 정도의 분량이 적당하며, 그래프나 표처럼 정보량이 많다면 `alt`는 요약만 하고 본문에 상세 설명을 별도로 둡니다.

## 3. width와 height — 크기를 미리 알려주는 이유

`width`와 `height`는 이미지가 화면에 차지할 픽셀(pixel) 크기를 지정하는 속성입니다.

```html
<img src="banner.jpg" alt="가을 세일 배너" width="800" height="400">
```

<Callout type="warning">
  **자주 틀리는 점:** "이미지 크기는 CSS로 조절하면 되니 `width`/`height` 속성은 필요 없다"고 생각하기 쉽습니다. 하지만 이 속성은 크기를 **강제로 고정**하는 용도가 아니라, 브라우저에게 이미지가 로드되기 **전에** 미리 "이 자리는 가로 800, 세로 400짜리 공간"이라고 알려주는 용도입니다. 이 값이 없으면 이미지가 늦게 로드될 때 그 자리를 차지할 공간이 없어, 이미지가 나타나는 순간 주변 콘텐츠가 아래로 밀리는 **레이아웃 밀림**(layout shift, 레이아웃 시프트) 현상이 일어납니다. `width`/`height`를 명시해 두면 브라우저가 이미지 로드 전부터 정확한 크기의 빈 공간을 미리 확보해 둘 수 있습니다.
</Callout>

CSS로 이후에 실제 표시 크기를 다시 조정하더라도(`width: 100%` 같은 반응형 스타일), HTML의 `width`/`height` 속성은 원본 이미지의 **가로세로 비율**(aspect ratio, 종횡비)을 브라우저에 미리 알려주는 역할을 합니다. 브라우저는 이 비율 정보로 CSS가 적용되기 전에도 올바른 크기의 공간을 예약해 둘 수 있습니다.

## 4. 이 편에서 다루지 않는 것 — 반응형 이미지

`<picture>` 요소나 `<img>`의 `srcset`/`sizes` 속성처럼, 화면 크기나 해상도에 따라 다른 이미지 파일을 골라 보여주는 **반응형 이미지**(responsive images)는 이 편에서 다루지 않습니다. 이 과목(html_fundamentals)은 "전통적으로 항상 되어 온 기본 동작"까지만 다루기로 범위를 정했고, 반응형 이미지는 `html/modern_html` 과목의 몫입니다. 지금은 "이미지 하나에 파일 하나를 지정하는 가장 단순한 방식"까지만 익히고 넘어갑니다.

## 5. 브라우저가 실제로 어떻게 처리하는가

아래 실습기에서 일부러 잘못된 경로를 넣어 이미지 로드가 실패하는 상황을 만들고, `alt` 값이 있을 때와 없을 때 접근성 트리에 어떤 정보가 남는지 콘솔로 확인해 보세요. `activeFile`을 `/index.html`로 두고 `src` 경로나 `alt` 값을 바꿔 가며 실습하는 것이 이해에 가장 좋습니다.

  img.addEventListener("error", () => {
    console.log(img.id + " 로드 실패 -> 화면에 alt 텍스트가 노출됨:", img.alt);
  });

콘솔에서 `누락.getAttribute("alt")`가 `null`로 나오는 것을 확인했다면, `alt` 속성 자체가 아예 없는 상태(빈 문자열과는 다른 상태)라는 것을 눈으로 본 것입니다. 이미지 로드가 실패하면 `정보성`과 `장식용`은 각각 채워둔 값(설명 문구, 또는 빈 문자열)이 화면에 대체 표시되지만, `누락`은 대체할 텍스트가 없어 스크린 리더도 브라우저도 아무 단서를 얻지 못합니다.

### 접근성 관점 한 문단

`alt`는 접근성 기초 중에서도 가장 자주 인용되는 속성이지만, "채우기만 하면 끝"이 아니라 **판단**이 필요한 항목이라는 점이 이 편의 핵심입니다. 스크린 리더는 `alt`가 있는 이미지를 만나면 그 값을 읽어주고, `alt=""`인 이미지는 아예 건너뛰어(무시하여) 사용자가 장식 요소 때문에 탐색을 방해받지 않게 합니다. 반면 `alt` 속성 자체가 없는 이미지는 스크린 리더마다 처리 방식이 달라 파일명을 읽거나 "이미지"라고만 알려주는 등 예측하기 어려운 결과를 낳습니다. 접근성 기초는 20편에서 제목 구조·랜드마크와 함께 이어서 다루는데, 이 편에서 배운 대체 텍스트 판단 기준이 그 출발점이 됩니다.

## 핵심 정리

- `src`는 이미지 자원의 경로를, `alt`는 이미지를 대신할 텍스트를 지정한다. 대체 상황은 스크린 리더, 로드 실패, 검색 엔진 크롤러 세 가지다.
- 이미지가 정보를 담고 있으면 그 정보를 요약한 `alt`를, 순수 장식이면 `alt=""`(빈 문자열)을 쓴다. `alt` 속성 자체를 생략하는 것은 둘 다와 다른, 피해야 할 상태다.
- `width`/`height`는 크기를 강제 고정하는 속성이 아니라, 이미지 로드 전에 브라우저가 공간을 미리 확보해 레이아웃 밀림을 막는 용도다.
- 반응형 이미지(`srcset`/`<picture>`)는 이 과목이 아니라 `html/modern_html` 과목에서 다룬다.
- `alt` 텍스트는 "이미지"라는 말을 반복하지 않고, 문맥에 필요한 정보만 간결하게 담는다.
