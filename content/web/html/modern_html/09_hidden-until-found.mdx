## 왜 필요한가 — 숨긴 콘텐츠는 검색되지 않는다

아코디언(accordion)이나 "더 보기" 토글처럼 처음엔 접혀 있다가 클릭하면 펼쳐지는 UI를 만들 때, 지금까지 가장 흔한 구현은 CSS의 `display: none`이나 HTML의 `hidden` 전역 속성(`/web/html/html_fundamentals/12_global-attributes` 참조)으로 콘텐츠를 완전히 감추는 것이었습니다.

문제는 여기서 시작됩니다. 사용자가 페이지 안에서 특정 단어를 찾으려고 브라우저 내장 검색(대개 `Ctrl+F` 또는 `Cmd+F`로 여는 찾기 기능)을 켰다고 해봅시다. 그 단어가 접힌 아코디언 안에 있다면, 브라우저는 찾지 못합니다. `display: none`이나 `hidden`으로 감춘 요소는 렌더 트리(render tree)에서 아예 빠지기 때문에, 브라우저 입장에서는 "존재하지 않는 콘텐츠"와 다를 바 없습니다. 스크린 리더(screen reader, 화면 낭독기) 역시 이 콘텐츠를 읽어주지 않습니다.

지금까지 이 문제를 풀던 방법은 자바스크립트로 검색어를 감지해 관련 섹션을 강제로 펼치는 것이었습니다. 페이지 안의 모든 접힌 영역을 감시하고, 사용자가 무엇을 찾는지 추측해 미리 열어야 했습니다. 손이 많이 가고, 브라우저 내장 검색과는 완전히 별개로 동작하는 임시방편이었습니다.

`hidden="until-found"`는 이 문제를 표준 차원에서 풉니다. "찾을 때까지는 숨겨져 있지만, 브라우저가 찾으면 스스로 펼쳐지는" 콘텐츠를 HTML 속성 하나로 선언할 수 있게 된 것입니다.

## 일반 hidden과 무엇이 다른가

> **쉽게 말하면:** 일반 `hidden`은 그 콘텐츠를 아예 없는 셈 치는 스위치이고, `hidden="until-found"`는 "지금은 접어뒀지만 검색되면 알아서 펼치기"라는 조건부 스위치입니다.

두 방식의 차이는 브라우저가 내부적으로 적용하는 CSS를 비교하면 정확히 드러납니다.

| 구분 | `hidden` (값 없음) | `hidden="until-found"` |
|------|---------------------|--------------------------|
| 내부적으로 적용되는 CSS | `display: none` | `content-visibility: hidden` |
| 렌더 트리 포함 여부 | 제외됨 | 제외되지만 레이아웃 정보는 보존 |
| 브라우저 내장 검색(Ctrl+F) 대상 | 아니오 | 예 — 찾으면 자동으로 펼쳐짐 |
| 접근성 트리 노출 | 없음 | 검색·앵커 이동으로 펼쳐진 뒤 노출 |
| 페이지 내 앵커(`#id`) 이동 대상 | 아니오 | 예 |
| 펼쳐질 때 이벤트 발생 | 없음 | `beforematch` 이벤트 발생 |

핵심은 `content-visibility`(콘텐츠 가시성)라는 CSS 속성입니다. 이 속성의 값이 `hidden`이면 요소는 화면에 그려지지 않지만, 브라우저는 그 안에 무엇이 있는지에 대한 정보(텍스트 내용, 하위 구조)를 계속 알고 있습니다. `display: none`처럼 존재 자체를 지우는 것이 아니라, "지금 그릴 필요는 없지만 내용은 기억해 둔다"는 최적화 목적의 속성이기 때문입니다. `hidden="until-found"`는 이 성질을 빌려, 브라우저의 찾기 기능이 텍스트를 스캔할 때 이 콘텐츠까지 대상에 포함시킵니다.

## beforematch 이벤트로 지연 렌더링 감지하기

사용자가 검색해서 `hidden="until-found"` 영역이 펼쳐지기 **직전**, 브라우저는 그 요소에서 `beforematch`(비포어매치, "일치하기 전") 이벤트를 발생시킵니다. 이 이벤트를 이용하면 다음과 같은 일을 할 수 있습니다.

- 무거운 이미지나 위젯을 실제로 펼쳐질 때만 불러오는 지연 로딩(lazy loading)
- 펼쳐진 뒤 자동으로 스크롤해 초점을 맞추는 UX 개선
- 아코디언의 토글 아이콘 상태를 동기화

```html
<button aria-expanded="false" aria-controls="상세설명">자세히 보기</button>
<p id="상세설명" hidden="until-found">
  여기에 검색으로만 발견되는 상세 설명이 들어갑니다.
</p>
```

```js
const 상세설명 = document.getElementById('상세설명');

상세설명.addEventListener('beforematch', () => {
  console.log('브라우저 검색이 이 콘텐츠를 찾아 펼치려 합니다');
  // 이 시점에 hidden 속성을 직접 지워도 되고,
  // 스타일이나 아이콘 상태만 동기화해도 된다.
});
```

여기서 자주 헷갈리는 지점이 있습니다. `beforematch`가 발생했다고 해서 `hidden` 속성을 직접 제거해야 펼쳐지는 것은 **아닙니다.** 브라우저가 알아서 `hidden` 속성을 지워 콘텐츠를 보여줍니다. `beforematch`는 어디까지나 "곧 펼쳐진다"는 신호이고, 개발자는 그 신호에 반응해 부가 작업(로딩, 스타일 동기화)만 걸면 됩니다.

## 브라우저별 지원 시점 차이와 폴백

이 기능은 **최신 브라우저 기준**으로 다뤄야 합니다. 2026-09 시점 조사로는 크롬(Chrome) 102(2022년)에서 가장 먼저 들어왔고, 파이어폭스(Firefox)는 139(2025년 5월), 사파리(Safari)는 기술 미리보기(Technology Preview, 2025년 9월) 단계를 거쳐 뒤늦게 합류했습니다. 브라우저 간 도입 시점 격차가 3년 가까이 벌어졌던 셈입니다. 다만 2025년을 지나며 Baseline(베이스라인, 주요 브라우저 전반의 지원 상태를 보여주는 지표 — 자세한 읽는 법은 `/web/html/modern_html/02_reading-baseline-and-compat` 참조)에 널리 사용 가능으로 분류되었습니다. 이 문서를 읽는 시점의 실제 지원 상태는 반드시 MDN 호환성 표에서 다시 확인하세요.

지원하지 않는 구형 브라우저에서는 어떻게 될까요? `hidden="until-found"`를 이해하지 못하는 브라우저는 값이 있는 것과 없는 것을 구분하지 못하고, 그냥 일반 `hidden`처럼 취급해 콘텐츠를 계속 숨긴 채로 둡니다. `beforematch` 이벤트도 당연히 발생하지 않습니다. 즉 **콘텐츠가 사라지지는 않지만, 검색으로 자동으로 펼쳐지는 기능만 조용히 빠지는** 우아한 성능 저하(graceful degradation)가 일어납니다. 이 콘텐츠를 여는 별도의 버튼(예: 위 실습의 "자세히 보기")을 항상 같이 두면, 지원 여부와 무관하게 사용자가 콘텐츠에 접근할 방법이 남습니다.

<Callout type="warning">
  **자주 틀리는 점:** `hidden="until-found"`를 붙였다고 해서 자바스크립트로 여닫는 토글 로직을 대체할 수 있는 것은 아닙니다. 이 속성은 **브라우저의 찾기 기능·페이지 내 앵커 이동**에 반응해 펼쳐지는 것이지, 클릭으로 펼치는 일반적인 아코디언 상호작용까지 대신 해주지 않습니다. 클릭으로 여닫는 아코디언은 `<details>`/`<summary>`(자세한 exclusive accordion 구현은 `/web/html/modern_html/07_details-exclusive-accordion` 참조)가 더 적합하고, `hidden="until-found"`는 "평소엔 접혀 있지만 검색·딥링크로는 반드시 발견되어야 하는 콘텐츠"에 쓰는 것이 원래 목적입니다.
</Callout>

## 핵심 정리

- 일반 `hidden`은 내부적으로 `display: none`이 적용되어 렌더 트리에서 완전히 빠지므로, 브라우저 내장 검색·접근성 트리 모두에서 존재하지 않는 것으로 취급된다.
- `hidden="until-found"`는 내부적으로 `content-visibility: hidden`을 적용해, 화면에는 그리지 않으면서도 텍스트 내용은 보존한다. 그래서 브라우저 찾기 기능과 페이지 내 앵커 이동의 대상이 된다.
- 콘텐츠가 펼쳐지기 직전 `beforematch` 이벤트가 발생하며, 지연 로딩이나 UI 동기화에 활용할 수 있다.
- 크롬 2022년, 파이어폭스 2025년 5월, 사파리 2025년 9월(기술 미리보기)로 지원 시점 격차가 크다. 미지원 브라우저에서는 콘텐츠가 계속 숨겨져 있을 뿐 사라지거나 오류가 나지는 않는 우아한 성능 저하가 일어난다.
- 클릭으로 여닫는 상호작용은 `<details>`/`<summary>`가 맡고, `hidden="until-found"`는 검색·딥링크로 발견되어야 하는 콘텐츠에 쓴다.
