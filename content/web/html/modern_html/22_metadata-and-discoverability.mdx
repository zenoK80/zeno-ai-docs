## 왜 필요한가 — 브라우저 밖의 독자들

지금까지 다룬 `<dialog>`·popover·폼 요소들은 전부 "브라우저 안에서 보는 사람"을 위한 것이었습니다. 그런데 웹 페이지의 URL(주소)이 실제로 소비되는 자리는 브라우저 탭 하나만이 아닙니다.

- 카카오톡·슬랙·디스코드에 링크를 붙여넣으면, 그 메신저의 **크롤러**(crawler, 링크를 미리 읽어오는 프로그램)가 페이지를 훑어 제목·설명·이미지를 뽑아 카드로 보여줍니다.
- 스마트폰에서 "홈 화면에 추가"를 누르면, 운영체제는 그 사이트에 대한 이름·아이콘·실행 방식 정보를 어딘가에서 찾아야 합니다.
- 브라우저 자체도 주소창이나 작업 표시줄 색을 사이트 브랜드에 맞추려면 어떤 색을 쓸지 알아야 합니다.

이 정보를 아무것도 넣지 않으면 어떻게 될까요? 메신저 카드는 페이지의 `<title>`만 대충 긁어 밋밋한 링크로 뜨고, 홈 화면 아이콘은 브라우저 기본 아이콘으로 뜨고, 주소창은 회색 그대로입니다. **메타데이터**(metadata, 데이터를 설명하는 데이터)는 이런 "브라우저 밖의 독자"들에게 페이지 자신을 소개하는 명함입니다.

이 편은 문서 자체의 콘텐츠 카테고리·시맨틱 태그는 `html/html_fundamentals`에서 이미 다뤘다는 전제 위에서, `<head>` 안에 놓는 **소개용 메타데이터** 세 갈래(소셜 공유, 브라우저 UI 색, 설치 가능성)만 다룹니다.

## 1. Open Graph — 소셜 공유 카드의 표준

### 이름의 뜻과 배경

**Open Graph**(오픈 그래프, 줄여서 **OG**)는 페이스북이 2010년에 처음 제안한 메타데이터 규격으로, "어떤 웹 페이지든 그래프(graph, 관계망)의 한 노드(node, 점)로 취급해 제목·설명·이미지 같은 속성을 붙이자"는 아이디어에서 이름이 나왔습니다. 지금은 페이스북뿐 아니라 카카오톡·슬랙·디스코드·라인 등 대부분의 메신저·소셜 플랫폼이 이 규격을 그대로 읽습니다.

Open Graph 태그는 `<meta>` 요소의 `property` 속성(일반 메타데이터의 `name` 속성 대신)으로 표시합니다.

```html
<meta property="og:title" content="모던 HTML 완전 정복" />
<meta property="og:description" content="최근 몇 년 사이 표준으로 들어온 HTML 기능을 실습으로 익힙니다." />
<meta property="og:image" content="https://example.com/og/modern-html.png" />
<meta property="og:url" content="https://example.com/html/modern-html" />
<meta property="og:type" content="article" />
```

| 속성 | 뜻 | 실무 주의점 |
|------|----|-------------|
| `og:title` | 카드에 큰 글씨로 뜰 제목 | `<title>`과 다르게 소셜 공유용으로 더 짧고 매력적으로 써도 됨 |
| `og:description` | 카드의 설명 문구 | 플랫폼마다 잘리는 글자 수가 달라, 앞부분에 핵심을 배치 |
| `og:image` | 미리보기 이미지의 절대 URL | 반드시 절대 경로(`https://...`)로 적어야 함. 상대 경로는 크롤러가 못 찾는 경우가 많음 |
| `og:url` | 이 콘텐츠의 정규(canonical) URL | 검색 파라미터가 붙은 URL 대신 대표 URL을 적어 중복 카드 생성을 방지 |
| `og:type` | 콘텐츠 종류(`website`, `article` 등) | 종류에 따라 `article:author` 같은 부가 태그를 더 붙일 수 있음 |

> **쉽게 말하면:** Open Graph는 "이 페이지를 카드 한 장으로 요약하면 이렇게 써 주세요"라고 크롤러에게 미리 적어 둔 대본입니다.

### 트위터(X) 카드와의 관계

트위터(현재 X)는 `twitter:` 접두사를 쓰는 자체 태그(`twitter:card`, `twitter:title` 등)를 따로 두고 있지만, 대응하는 Open Graph 태그가 있으면 그것을 대신 읽어오도록 폴백(fallback, 대체 경로)을 지원합니다. 그래서 실무에서는 Open Graph 태그를 기본으로 채우고, `twitter:card` 하나만 추가로 넣는 방식이 흔합니다.

```html
<meta name="twitter:card" content="summary_large_image" />
```

### 크롤러는 자바스크립트를 기다려주지 않는다

여기서 이 과목 전체를 관통하는 중요한 함정이 하나 있습니다. 대부분의 메신저·소셜 크롤러는 **자바스크립트를 실행하지 않거나, 실행하더라도 아주 짧은 시간만 기다립니다.** 페이지를 순수 클라이언트 사이드 자바스크립트(client-side JavaScript)로 렌더링하는 SPA(Single Page Application, 단일 페이지 애플리케이션)에서 `<meta>` 태그를 자바스크립트로 나중에 주입하면, 크롤러는 빈 `<head>`만 보고 카드를 못 만드는 경우가 많습니다. 이 렌더링 방식의 차이는 `javascript/web_apis` 과목이 다루는 영역이므로, 여기서는 "Open Graph 태그는 서버가 내려주는 최초 HTML에 이미 박혀 있어야 안전하다"는 결론만 기억해 둡니다.

<Callout type="warning">
  **자주 틀리는 점:** `og:image`에 상대 경로(`/images/card.png`)를 적는 실수가 흔합니다. 브라우저에서 보는 `<img>`는 상대 경로를 현재 문서 기준으로 잘 풀어내지만, 외부 크롤러는 그 문맥을 모르고 그대로 요청을 보내다 실패하는 경우가 있습니다. 항상 `https://`로 시작하는 완전한 절대 URL을 씁니다.
</Callout>

## 2. `theme-color` — 브라우저 UI를 사이트 색에 맞추기

**`theme-color`**는 `<meta name="theme-color">`로 선언하는 값으로, 모바일 브라우저의 주소창·상태 표시줄이나 최근 앱 목록 카드의 색을 이 색으로 물들입니다. 데스크톱에서는 브라우저마다 지원 여부와 적용 범위가 다릅니다.

```html
<meta name="theme-color" content="#0f172a" media="(prefers-color-scheme: dark)" />
<meta name="theme-color" content="#ffffff" media="(prefers-color-scheme: light)" />
```

`media` 속성으로 `prefers-color-scheme`(사용자의 밝은/어두운 테마 선호)에 따라 서로 다른 값을 줄 수 있습니다. 같은 이름의 `<meta>` 태그를 여러 개 두고 미디어 쿼리(media query)로 조건을 나누는 것은 표준에서 허용하는 패턴입니다.

## 3. 웹 앱 매니페스트 — 설치 가능한 앱의 시작점

### 왜 필요한가

브라우저 탭으로만 열리던 웹사이트를 "홈 화면에 추가"해서 마치 네이티브 앱처럼 아이콘을 누르면 실행되게 하려면, 운영체제에게 앱 이름·아이콘·실행 화면 색 같은 정보를 알려줘야 합니다. 이 정보를 담는 JSON(제이슨) 파일이 **웹 앱 매니페스트**(Web App Manifest)이고, HTML 문서는 `<link rel="manifest">`로 이 파일의 위치를 알려줍니다.

```html
<link rel="manifest" href="/manifest.webmanifest" />
```

manifest.webmanifest 파일의 예시입니다.

```json
{
  "name": "모던 HTML 학습 사이트",
  "short_name": "모던HTML",
  "start_url": "/web/html/modern-html",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#0f172a",
  "icons": [
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

| 필드 | 뜻 |
|------|----|
| `name` / `short_name` | 전체 이름 / 홈 화면 아이콘 아래 짧게 표시할 이름 |
| `start_url` | 아이콘을 눌렀을 때 열리는 시작 경로 |
| `display` | `standalone`(주소창 없이 앱처럼), `fullscreen`, `browser` 등 실행 화면 형태 |
| `background_color` | 앱이 뜨는 순간(스플래시 화면)의 배경색 |
| `theme_color` | 매니페스트 안에서도 지정 가능 — `<meta name="theme-color">`와 값을 맞춰 두는 것이 자연스럽다 |
| `icons` | 여러 해상도의 아이콘 목록. 운영체제가 상황에 맞는 크기를 골라 씀 |

> **쉽게 말하면:** 매니페스트는 "이 웹사이트를 앱처럼 설치한다면 이런 이름·아이콘·화면으로 열어 주세요"라는 신분증입니다.

<Callout type="warning">
  **단정하지 않기:** 매니페스트 파일을 연결했다고 해서 곧바로 "설치 가능한 PWA(Progressive Web App)"가 완성되는 것은 아닙니다. 브라우저가 설치 배너를 띄우려면 일반적으로 **Service Worker**(서비스 워커, 오프라인·백그라운드 동작을 담당하는 스크립트)가 등록되어 있어야 하는 등 추가 조건이 있습니다. Service Worker 자체는 `javascript/web_apis` 20편에서 다루므로, 이 편은 매니페스트가 "설치 가능성의 필요조건 중 하나"라는 점까지만 정리합니다.
</Callout>

## 핵심 정리

- Open Graph(`og:title`, `og:description`, `og:image`, `og:url`, `og:type`)는 메신저·소셜 플랫폼 크롤러가 읽는 공유 카드 규격이다. `og:image`는 반드시 절대 URL로 쓴다.
- 자바스크립트로 나중에 주입한 메타데이터는 크롤러가 못 읽는 경우가 많다. 최초 HTML 응답에 이미 포함되어 있어야 안전하다.
- `theme-color`는 `media="(prefers-color-scheme: ...)"`와 함께 밝은/어두운 테마별로 다르게 선언할 수 있다.
- `<link rel="manifest">`가 가리키는 JSON 파일은 앱 이름·아이콘·시작 URL·표시 방식을 정의한다. 다만 매니페스트만으로 설치 배너가 뜨는 것은 아니고, 대개 Service Worker 등록 같은 추가 조건이 필요하다.
