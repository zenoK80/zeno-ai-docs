## 이번 편에서 만드는 것

지금까지 04·06·07·08편에서 `<dialog>`, popover, `<details name>`, `inert`를 각각 따로 배웠습니다. 실무 화면에는 이 네 가지가 한 페이지에 동시에 존재합니다. 헤더에는 메뉴 popover가, 어딘가에는 확인 모달이, 목록 옆에는 아코디언이 함께 있는 식입니다. 이번 편은 그 네 가지를 실제로 한 페이지에 모아 보면서, "서로 다른 오버레이(overlay, 화면 위에 겹쳐 뜨는 층)가 동시에 열리면 무슨 일이 벌어지는가"를 직접 확인합니다.

> **쉽게 말하면:** 지금까지 따로 만든 부품 네 개를 실제 제품 하나에 조립하는 실습입니다.

완성할 페이지의 요구사항은 다음과 같습니다.

1. 상단에 "설정" 버튼을 누르면 `<dialog>` 모달이 뜨고, 포커스가 모달 안에 갇힌다.
2. 상단에 "메뉴" 버튼을 누르면 popover 메뉴가 뜨고, 메뉴 바깥을 클릭하거나 `Esc` 키를 누르면 라이트 디스미스(light dismiss, 가볍게 닫힘)된다.
3. 작업 목록에 "일괄 삭제" 버튼을 누르면 처리 중인 동안 목록 전체가 `inert` 처리되어 클릭·포커스·텍스트 검색이 모두 막힌다.
4. 자주 묻는 질문 영역은 `<details name>`으로 묶여, 하나를 펼치면 나머지가 자동으로 접히는 아코디언(accordion, 손풍금처럼 접었다 펴는 목록)이 된다.

| 오버레이 | 포커스를 다루는 방식 | 배경 처리 |
|---|---|---|
| `<dialog>`(모달) | 열리면 자동으로 내부 첫 포커스 가능 요소로 이동, 안에 갇힘(trap) | 나머지 문서가 자동으로 비활성화되고 클릭이 통과하지 않음 |
| popover(auto 모드) | 열려도 포커스를 강제로 옮기지 않을 수 있음(구현체에 따라 초기 포커스 이동 방식이 다름) | 배경은 그대로 조작 가능, 바깥 클릭·`Esc`로만 자동 닫힘 |
| `<details name>` | 포커스 이동 없음, `summary`만 토글 | 다른 `<details>`는 자동으로 닫히지만 비활성화되지는 않음 |
| `inert` | 포커스를 아예 받을 수 없게 트리 전체를 제외 | 개발자가 직접 켜고 꺼야 하는 수동 처리 |

이 표가 이번 편의 핵심입니다. 넷 다 "무언가를 못 건드리게 막는다"는 점은 같지만, **누가 자동으로 처리해주고 누가 수동으로 처리해야 하는지**가 다릅니다.

## Steps로 조립하기

<Steps>

### 1단계 — 뼈대 HTML 작성하기

먼저 네 가지 오버레이가 들어갈 자리를 잡습니다. 이 시점에는 동작 없이 구조만 잡습니다.

```html
<header>
  <h1>업무 대시보드</h1>
  <button id="openSettingsBtn">설정</button>
  <button popovertarget="navMenu">메뉴</button>
  <div id="navMenu" popover>
    <ul>
      <li><button type="button">프로필 보기</button></li>
      <li><button type="button">알림 설정</button></li>
      <li><button type="button">로그아웃</button></li>
    </ul>
  </div>
</header>

<dialog id="settingsDialog">
  <form method="dialog">
    <h2>설정</h2>
    <p>
      <label>표시 이름
        <input type="text" name="displayName" required minlength="2">
      </label>
    </p>
    <menu>
      <button value="cancel">취소</button>
      <button value="confirm">저장</button>
    </menu>
  </form>
</dialog>

<section id="taskSection">
  <h2>작업 목록</h2>
  <ul id="taskList">
    <li>분기 보고서 초안 작성</li>
    <li>디자인 리뷰 피드백 반영</li>
    <li>배포 체크리스트 점검</li>
  </ul>
  <button id="bulkDeleteBtn" type="button">선택 항목 일괄 삭제</button>
  <p id="bulkStatus" role="status"></p>
</section>

<section>
  <h2>자주 묻는 질문</h2>
  <details name="faq">
    <summary>배송은 얼마나 걸리나요?</summary>
    <p>영업일 기준 2~3일이 소요됩니다.</p>
  </details>
  <details name="faq">
    <summary>환불은 어떻게 하나요?</summary>
    <p>주문 내역에서 환불 요청 버튼을 누르면 됩니다.</p>
  </details>
  <details name="faq">
    <summary>결제 수단을 바꿀 수 있나요?</summary>
    <p>설정 메뉴에서 언제든 변경할 수 있습니다.</p>
  </details>
</section>
```

`popover` 속성만 붙은 `#navMenu`는 기본값인 auto 모드로 동작합니다. `popovertarget`으로 버튼과 연결하면 별도의 자바스크립트 없이도 토글·라이트 디스미스가 전부 작동합니다. 반면 `<dialog>`는 `popover`처럼 속성 하나로 열리지 않습니다. 자바스크립트로 `showModal()`을 불러야 모달로 뜹니다.

### 2단계 — 설정 모달의 열기·닫기·포커스 확인하기

```js
const dialog = document.getElementById('settingsDialog');
const openBtn = document.getElementById('openSettingsBtn');

openBtn.addEventListener('click', () => {
  dialog.showModal();
});

dialog.addEventListener('close', () => {
  if (dialog.returnValue === 'confirm') {
    console.log('설정이 저장되었습니다.');
  }
});
```

`showModal()`로 연 `<dialog>`는 문서의 최상위 렌더링 층인 **top layer**(탑 레이어)에 올라갑니다. 같은 층에서는 브라우저가 알아서 배경을 비활성화하므로, 모달이 떠 있는 동안 `#taskSection`이나 popover 버튼을 클릭해도 반응하지 않습니다. `Tab` 키로 포커스를 옮겨 봐도 모달 밖으로 나가지지 않는지 실습기에서 직접 확인하세요.

### 3단계 — popover 메뉴에 라이트 디스미스 스타일 입히기

```css
[popover] {
  border: 1px solid #d0d5dd;
  border-radius: 8px;
  padding: 0.5rem;
  inset: unset;
  top: 3.5rem;
  right: 1rem;
}

[popover]:popover-open {
  animation: fadeIn 0.12s ease-out;
}

@keyframes fadeIn {
  from { opacity: 0; transform: translateY(-4px); }
  to { opacity: 1; transform: translateY(0); }
}
```

`inset: unset`으로 popover의 기본 중앙 정렬을 풀고 헤더 아래 오른쪽에 붙였습니다. `:popover-open` 의사 클래스(pseudo-class, 조건부로 붙는 가짜 클래스)는 popover가 열려 있는 동안에만 적용되므로, 열리는 애니메이션을 이 선택자에 걸면 됩니다.

### 4단계 — 일괄 삭제 중 목록을 `inert` 처리하기

popover와 `<dialog>`는 배경 처리를 브라우저가 대신 해 주지만, "처리 중인 동안 이 목록만 잠깐 막아 두기" 같은 상황은 브라우저가 자동으로 알아서 해 주지 않습니다. 이럴 때 `inert` 전역 속성을 직접 켜고 끕니다.

```js
const bulkDeleteBtn = document.getElementById('bulkDeleteBtn');
const taskList = document.getElementById('taskList');
const bulkStatus = document.getElementById('bulkStatus');

bulkDeleteBtn.addEventListener('click', () => {
  taskList.inert = true;
  bulkDeleteBtn.disabled = true;
  bulkStatus.textContent = '삭제 처리 중입니다. 잠시만 기다려 주세요.';

  setTimeout(() => {
    taskList.innerHTML = '<li>남은 작업이 없습니다.</li>';
    taskList.inert = false;
    bulkDeleteBtn.disabled = false;
    bulkStatus.textContent = '삭제가 완료되었습니다.';
  }, 1500);
});
```

`taskList.inert = true`가 걸리는 동안에는 목록 안의 어떤 항목도 클릭·포커스·브라우저 페이지 내 검색(Ctrl+F)의 대상이 되지 않습니다. `disabled` 속성이 버튼 하나만 막는 것과 달리, `inert`는 그 아래 트리 전체를 한 번에 막습니다. 처리가 끝나면 반드시 `inert`를 다시 `false`로 되돌려야 합니다. 켠 채로 남겨두면 사용자는 화면에 보이는 요소를 영영 조작하지 못합니다.

<Callout type="warning">
  **자주 틀리는 점:** `<dialog>`의 `showModal()`과 popover는 배경 비활성화를 브라우저가 알아서 처리하므로 개발자가 별도로 `inert`를 걸 필요가 없습니다. 반대로 이번 4단계처럼 오버레이 요소를 전혀 쓰지 않고 "특정 영역만 잠그기"가 목적이라면 `inert`를 직접 다뤄야 합니다. 이 둘을 혼동해 모달 안에서까지 수동으로 `inert`를 걸면 이중 처리가 되어 포커스 흐름이 꼬입니다.
</Callout>

### 5단계 — `<details name>` 아코디언 동작 확인하기

3단계까지 만든 HTML의 `<details>` 세 개는 이미 `name="faq"`로 묶여 있으므로 추가 자바스크립트가 필요 없습니다. 하나를 펼치면 브라우저가 같은 `name` 값을 가진 나머지를 자동으로 닫습니다. DOM(Document Object Model, 문서 객체 모델) 상에서 서로 떨어져 있어도, `name` 값만 같으면 그룹으로 묶입니다.

```css
details {
  border: 1px solid #e4e7ec;
  border-radius: 8px;
  padding: 0.5rem 0.75rem;
  margin-bottom: 0.5rem;
}

summary {
  cursor: pointer;
  font-weight: 600;
}
```

구형 브라우저는 `name` 속성을 그냥 무시합니다. 이 경우 각 `<details>`가 독립적으로 열리고 닫힐 뿐, 오류가 나거나 레이아웃이 깨지지 않습니다. 즉 점진적 향상(progressive enhancement, 기본 기능은 항상 동작하고 지원 브라우저에서만 추가 효과가 붙는 설계)의 좋은 예입니다.

</Steps>

## 핵심 정리

- `<dialog>`의 `showModal()`은 top layer로 올라가면서 배경 비활성화·포커스 트랩을 브라우저가 자동으로 처리한다.
- popover(auto 모드)는 라이트 디스미스만 자동으로 처리하고, 배경 자체를 막지는 않는다.
- `<details name>`은 DOM 위치와 무관하게 같은 `name` 값끼리 자동으로 exclusive accordion을 이룬다.
- `inert`는 브라우저가 자동으로 걸어주지 않는 임의의 영역을, 개발자가 직접 켜고 꺼서 비활성화할 때 쓴다.
- 네 오버레이를 한 페이지에 둘 때는 "누가 자동으로 처리하고 누가 수동으로 처리해야 하는가"를 표로 정리해 두면 설계 실수를 줄일 수 있다.
