<Callout type="info">
  **이번 문서의 목표:** 이 문서를 다 읽고 실습기를 직접 조작하면, 한 페이지 안에서 화면 최상단 이미지(LCP 후보)와 화면 아래쪽 이미지의 로딩 전략을 서로 다르게 설계하고, 자막이 붙은 `<video>`까지 함께 배치할 수 있습니다.
</Callout>

## 이번 편에서 만드는 것

16~20편에서 `srcset`/`sizes`, `<picture>`, `loading`/`decoding`/`fetchpriority`, `<video>`/`<track>`, 리소스 힌트를 각각 배웠습니다. 실제 페이지에서는 이 속성들이 **한 이미지 안에서 동시에** 쓰입니다. 화면 맨 위에 크게 뜨는 히어로(hero) 이미지와, 스크롤을 한참 내려야 보이는 목록 이미지는 로딩 전략이 정반대여야 합니다. 이번 편은 그 대비를 실제로 만들어 확인합니다.

> **쉽게 말하면:** "제일 먼저 보여줄 이미지는 서두르고, 나중에 볼 이미지는 미뤄두는" 전략을 실제 페이지 하나에 구현하는 실습입니다.

완성할 페이지의 요구사항은 다음과 같습니다.

1. 화면 상단 히어로 이미지는 뷰포트(viewport, 화면에 실제로 보이는 영역) 폭에 맞춰 다른 해상도 파일을 받도록 `srcset`/`sizes`를 쓴다.
2. 좁은 화면에서는 세로로 자른 사진을, 넓은 화면에서는 가로로 긴 사진을 보여주는 아트 디렉션(art direction, 화면 크기에 따라 구도 자체를 바꾸는 것)을 `<picture>`로 구현한다.
3. 히어로 이미지는 `fetchpriority="high"`와 `preload`로 최대한 빨리 받게 하고, 목록 이미지는 `loading="lazy"`로 필요할 때만 받는다.
4. 자막 트랙이 붙은 `<video>`를 페이지 하단에 배치한다.

| 위치 | 역할 | 우선순위 전략 |
|---|---|---|
| 히어로 이미지(최상단) | 화면에 가장 먼저, 가장 크게 보임 — LCP(Largest Contentful Paint, 가장 큰 콘텐츠가 그려지는 시점) 후보 | `fetchpriority="high"`, `<head>`에 `preload`, `loading` 속성은 생략(기본값 eager) |
| 목록 이미지(스크롤 하단) | 처음엔 화면 밖에 있어 안 보임 | `loading="lazy"`로 뷰포트 근처에 올 때까지 요청을 미룸 |
| 비디오 | 클릭해야 재생되는 부가 콘텐츠 | `preload="none"` 또는 `metadata`로 초기 대역폭 절약 |

이 표가 이번 편의 설계 기준입니다. "**이 미디어가 화면에 언제 보이는가**"를 먼저 정하고, 그에 맞는 속성 조합을 고릅니다.

## Steps로 조립하기

<Steps>

### 1단계 — 히어로 이미지에 해상도 스위칭 적용하기

같은 그림을 여러 해상도로 준비해 두고, 브라우저가 뷰포트 폭과 화면 배율(DPR, Device Pixel Ratio, 기기 화소 밀도)에 맞는 파일을 스스로 고르게 합니다.

```html
<img
  src="/hero-960.jpg"
  srcset="/hero-480.jpg 480w, /hero-960.jpg 960w, /hero-1600.jpg 1600w"
  sizes="100vw"
  alt="봄맞이 신제품 컬렉션 대표 이미지"
  fetchpriority="high"
  width="1600"
  height="900"
>
```

`srcset`의 `480w`·`960w`·`1600w`는 너비 서술자(width descriptor)로, 각 파일이 **실제로 몇 픽셀 너비인지**를 브라우저에 알려줍니다. `sizes="100vw"`는 "이 이미지는 항상 뷰포트 전체 폭만큼 표시된다"는 레이아웃 정보입니다. 브라우저는 이 둘을 곱해, 지금 화면에 필요한 실제 픽셀 수에 가장 가까운 파일을 고릅니다. `width`/`height`를 함께 적어 두면 이미지가 로드되기 전에도 브라우저가 공간을 미리 확보해 레이아웃 밀림(layout shift, 콘텐츠가 뒤늦게 밀리는 현상)을 막습니다.

### 2단계 — 좁은 화면과 넓은 화면에서 다른 구도 보여주기

1단계는 같은 그림을 크기만 바꿔 보여주는 **해상도 스위칭**입니다. 이번에는 화면 폭에 따라 **구도 자체**가 달라지는 아트 디렉션이 필요한 경우를 다룹니다. `srcset`만으로는 이 문제를 풀 수 없습니다. 브라우저는 파일 크기만 비교할 뿐 사진 안의 구도까지는 판단하지 못하기 때문입니다. 이럴 때 `<picture>`를 씁니다.

```html
<picture>
  <source media="(min-width: 800px)" srcset="/hero-wide.jpg">
  <source media="(max-width: 799px)" srcset="/hero-tall.jpg">
  <img src="/hero-wide.jpg" alt="봄맞이 신제품 컬렉션 대표 이미지" fetchpriority="high">
</picture>
```

`<picture>`는 여러 `<source>` 후보를 위에서부터 순서대로 검사해, `media` 조건에 맞는 첫 번째 후보의 이미지를 씁니다. 어떤 `<source>`도 조건에 맞지 않으면 마지막의 `<img>`가 폴백(fallback, 대체 수단)으로 쓰입니다. 즉 `<img>`는 항상 있어야 하는 필수 요소입니다.

<Callout type="warning">
  **자주 틀리는 점:** `srcset`의 너비 서술자와 `<picture>`의 `media` 조건을 섞어서 "화면이 좁아지면 무조건 작은 파일이 온다"고 오해하기 쉽습니다. `srcset`은 **같은 그림의 해상도만** 바꾸고, `<picture>`는 **다른 그림(구도)** 자체를 바꿉니다. 둘은 푸는 문제가 다릅니다.
</Callout>

### 3단계 — 우선순위 속성으로 로딩 순서를 실제로 갈라놓기

히어로 이미지는 최대한 빨리, 목록 이미지는 필요할 때만 받도록 만듭니다.

```html
<head>
  <link rel="preload" as="image" href="/hero-960.jpg" imagesrcset="/hero-480.jpg 480w, /hero-960.jpg 960w" imagesizes="100vw">
</head>
```

```html
<img
  src="/list-item-1.jpg"
  alt="목록 항목 1 썸네일"
  loading="lazy"
  decoding="async"
  width="320"
  height="200"
>
```

`<head>`의 `preload`는 "이 파일이 곧 필요하니 파싱이 끝나기 전에 미리 받아 두라"는 힌트이고, 히어로 `<img>`의 `fetchpriority="high"`는 "이미 받기 시작한 여러 리소스 중에서 이것부터 처리하라"는 힌트입니다. 둘은 겹치는 개념이 아니라 "**언제 시작할지**"와 "**어떤 순서로 처리할지**"를 각각 담당합니다. 반대로 목록 이미지의 `loading="lazy"`는 뷰포트 근처에 올 때까지 요청 자체를 미루고, `decoding="async"`는 다운로드된 이미지를 화면에 그리는 디코딩(decoding, 압축된 파일을 화면에 그릴 수 있는 픽셀 데이터로 푸는 작업) 작업이 메인 스레드를 막지 않게 합니다.

<Callout type="warning">
  **자주 틀리는 점:** 히어로 이미지처럼 화면에 즉시 보여야 하는 요소에 `loading="lazy"`를 실수로 붙이면, 브라우저가 이 이미지를 "당장 필요 없다"고 판단해 오히려 로딩이 늦어질 수 있습니다. `loading="lazy"`는 화면 밖 콘텐츠 전용입니다.
</Callout>

### 4단계 — 자막 있는 비디오 배치하기

```html
<video controls preload="metadata" poster="/video-poster.jpg" width="640" height="360">
  <source src="/product-tour.mp4" type="video/mp4">
  <track kind="captions" src="/captions-ko.vtt" srclang="ko" label="한국어 자막" default>
  <track kind="descriptions" src="/descriptions-ko.vtt" srclang="ko" label="화면 해설">
  자막을 지원하는 최신 브라우저에서 보시길 권장합니다.
</video>
```

`controls`를 붙이면 재생·일시정지·음량 같은 기본 UI가 자동으로 제공되어 별도 구현이 필요 없습니다. `preload="metadata"`는 재생 시간·크기 같은 메타데이터만 미리 받고 실제 영상 데이터는 재생 버튼을 눌러야 받게 합니다. `<track kind="captions">`는 대사를 그대로 옮긴 자막이고, `kind="descriptions"`는 화면에 보이는 상황을 말로 풀어주는 화면 해설(audio description) 트랙입니다. 스크린 리더 사용자뿐 아니라 소리를 켤 수 없는 환경의 모든 사용자에게 자막은 필수 접근성 요소입니다.

</Steps>

## 자주 틀리는 점 모아보기

- `srcset`에 너비 서술자(`480w`)와 밀도 서술자(`2x`)를 한 이미지에 섞어 쓸 수 없습니다. 둘 중 하나로 통일해야 합니다.
- `sizes`를 빼먹으면 브라우저가 레이아웃 정보를 몰라 `srcset` 후보 중 가장 큰 파일을 기본값처럼 고를 수 있어, 최적화 효과가 사라집니다.
- `preload`로 미리 받아 둔 리소스를 실제로 그 페이지에서 쓰지 않으면, 콘솔에 "사용되지 않은 preload" 경고가 뜨고 대역폭만 낭비합니다.
- `loading="lazy"`는 `<img>`와 `<iframe>`에는 쓸 수 있지만 `<picture>`의 `<source>`에는 붙이지 않습니다. 실제 로딩 여부를 결정하는 것은 `<picture>` 안의 `<img>` 쪽입니다.

## 핵심 정리

- 화면에 언제 보이는 미디어인지에 따라 로딩 전략을 반대로 설계한다 — 히어로는 서두르고, 화면 밖 콘텐츠는 미룬다.
- `srcset`/`sizes`는 같은 그림의 해상도를, `<picture>`는 화면 크기에 따른 구도(아트 디렉션) 자체를 바꿀 때 쓴다.
- `preload`는 "언제 받기 시작할지", `fetchpriority`는 "이미 받는 것들 중 어떤 순서로 처리할지"를 각각 담당하며 서로 대체할 수 없다.
- `loading="lazy"`는 화면 밖 콘텐츠 전용이며, 화면에 즉시 보이는 요소에 붙이면 오히려 로딩이 늦어질 수 있다.
- `<video>`의 자막(`captions`)과 화면 해설(`descriptions`) 트랙은 접근성 필수 요소이며 `preload="metadata"`로 초기 대역폭을 아낄 수 있다.
