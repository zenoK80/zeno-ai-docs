## 개념 정리

시작하기 전에 지금 다루는 언어와 실행 환경의 이름부터 정리합니다.

| 용어 | 정체 | 역할 |
|------|------|------|
| ECMAScript | 언어 문법 명세(TC39가 관리) | `let`, `class`, `Promise` 같은 문법과 내장 객체를 정의 |
| JavaScript | ECMAScript를 구현한 실제 언어 | 브라우저·서버에서 실행되는 코드 자체 |
| Node.js | JavaScript 실행 런타임 | V8 엔진 + 파일시스템·네트워크 같은 시스템 API를 붙여 브라우저 밖에서 실행 |
| npm | Node.js의 패키지 매니저 | 라이브러리 설치, `package.json` 스크립트 실행 |

브라우저용 JavaScript에는 `document`, `window` 같은 DOM API가 있지만 Node.js에는 없습니다. 대신 Node.js는 `process`, `fs` 같은 시스템 API를 제공합니다.

### npm 명령 정리

| 명령 | 역할 |
|------|------|
| `npm init -y` | 기본값으로 `package.json` 생성 |
| `npm run <스크립트 이름>` | `scripts` 필드에 등록된 명령 실행 |
| `npm install <패키지>` | 의존 패키지 설치(이 과목은 외부 패키지 없이 Node.js 내장 기능만 사용) |

`todo-cli`는 외부 패키지 없이 Node.js 내장 모듈(`fs/promises`, `node:test` 등)만으로 완성합니다. 그래서 `package.json`에 `dependencies` 항목이 생기지 않습니다.

### package.json 핵심 필드

| 필드 | 의미 |
|------|------|
| `name`, `version` | 패키지 이름과 버전 |
| `type` | `"module"`이면 `import`/`export`(ESM) 문법 사용, 없으면 `require`(CommonJS) |
| `main` | `import`로 이 패키지를 불러올 때 진입점 |
| `bin` | 터미널 명령으로 등록할 실행 파일 매핑 |
| `scripts` | `npm run 이름`으로 실행할 명령 모음 |

`"type": "module"`을 지정하지 않으면 Node.js는 `.js` 파일을 CommonJS(`require`/`module.exports`)로 해석합니다.
