## 문제를 푸는 기준

그리디는 지금 좋아 보이는 것을 고르는 기법이 아니라 그 선택이 이후 최적 가능성을 해치지 않는다는 근거가 있는 알고리즘입니다.

## 핵심 개념

| 개념 | 코딩테스트에서의 역할 |
|---|---|
| 탐욕적 선택 | 현재 단계에서 이후 가능성을 가장 많이 남기는 후보를 고릅니다. |
| 교환 논리 | 최적해의 선택을 그리디 선택으로 바꿔도 손해가 없음을 보입니다. |
| 반례 탐색 | 작은 사례로 선택 기준이 깨지는지 확인합니다. |

## 대표 문제

### 최대 회의 개수

회의 [start,end] 배열 meetings에서 서로 겹치지 않게 선택할 수 있는 최대 개수를 반환하세요. 끝나는 시각에 다음 회의를 시작할 수 있습니다.

**함수 시그니처:** `solution(meetings)`

### 제한사항

- meetings의 길이는 0 이상 200,000 이하입니다.
- start는 end 이하입니다.

### 입출력 예

| 매개변수 | 반환값 |
|---|---|
| `[[1,4],[2,3],[3,5],[5,7]]` | `3` |
| `[]` | `0` |

### 풀이 설계

1. 종료 시각 오름차순으로 정렬합니다.
2. 가장 빨리 끝나는 회의를 먼저 선택합니다.
3. 다음 시작이 마지막 종료 이상이면 선택합니다.

### JavaScript 풀이

```js
function solution(meetings) {
  const sorted = [...meetings].sort((a, b) => a[1] - b[1] || a[0] - b[0]);
  let count = 0;
  let lastEnd = -Infinity;
  for (const [start, end] of sorted) {
    if (start < lastEnd) continue;
    count += 1;
    lastEnd = end;
  }
  return count;
}
```

### 복잡도

- 시간복잡도: `O(n log n)`
- 공간복잡도: `O(n)`
- 핵심 패턴: 가장 빨리 끝나는 구간부터 선택
- 경계 사례: 끝과 시작이 같으면 연속 선택 가능

## 자주 하는 실수

- 정당성 없이 직감으로 기준을 정하는 실수
- 시작 시각이 빠른 회의를 먼저 고르는 실수
- 동률 정렬 기준을 빼는 실수
- 끝과 시작이 같은 경우를 확인하지 않는 실수

## 핵심 정리

- 완성한 `solution` 함수가 입력을 불필요하게 바꾸지 않는지도 확인합니다.
