## 핵심 범위

React 중급에서는 컴포넌트를 만드는 문법보다 애플리케이션의 책임을 나누는 방법이 중요합니다.

| 주제 | 해결하는 문제 | 핵심 도구 |
|------|---------------|-----------|
| 라우팅 | URL에 따라 다른 화면을 표시 | React Router, 중첩 라우트 |
| 커스텀 훅 | 여러 컴포넌트의 상태 로직 중복 | `use`로 시작하는 함수 |
| 폼 검증 | 잘못된 입력이 상태에 들어오는 문제 | 제출 전 검증, 오류 상태 |
| 성능 측정 | 불필요한 리렌더 추측 | React Profiler |
| 오류 처리 | 렌더링 오류로 화면 전체가 멈추는 문제 | Error Boundary, `Suspense` |
| 상태 정규화 | 중첩·중복 데이터 갱신의 복잡성 | `byId`, `allIds` 구조 |
| 스타일 격리 | 전역 선택자 충돌 | CSS Modules |
| 컴포넌트 테스트 | 사용자 관점 동작 회귀 | Vitest, Testing Library |

## 개념 사이의 연결

라우팅은 화면을 나누고, 커스텀 훅은 화면에서 상태 로직을 분리합니다. 폼 검증과 오류 처리는 잘못된 입력과 예외가 다른 영역으로 번지는 것을 막습니다. 성능 최적화는 구조를 만든 뒤 Profiler로 병목을 확인했을 때만 적용해야 합니다.

상태 정규화와 CSS Modules는 규모가 커질 때 변경 범위를 좁히는 방법입니다. 테스트는 이 구조가 사용자 행동 기준으로 계속 동작하는지 확인합니다.
