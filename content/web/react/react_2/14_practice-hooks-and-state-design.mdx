## 문제를 푸는 기준

> **쉽게 말하면:** 상태 도구는 규모가 아니라 **누가 읽고, 누가 쓰며, 얼마나 오래 살아야 하는가**로 고릅니다.

다음 네 질문을 순서대로 적용합니다.

1. 이 값은 서버에서 온 원본인가, UI가 잠깐 기억할 클라이언트 상태인가?
2. 가장 가까운 공통 부모는 어디인가?
3. 여러 하위 컴포넌트가 읽기만 하는가, 서로 멀리 떨어진 기능이 자주 갱신하는가?
4. UI와 분리해 재사용할 상태 전이·외부 동기화 로직이 있는가?

지역 입력값은 대개 `useState`, 관련된 복잡한 전이는 `useReducer`, 깊은 트리에 같은 값을 전달할 때는 Context, 서로 먼 기능이 빈번하게 공유하는 클라이언트 상태는 Zustand가 후보입니다. 커스텀 훅은 저장소 종류가 아니라 **React 로직의 재사용 경계**입니다.
