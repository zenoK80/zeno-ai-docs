## 개념 정리

06편에서 페이지 단위 조회를, 09편에서 필터·정렬 상태를 Zustand로 옮겼습니다. 이번 편은 이 둘을 하나의 표 컴포넌트로 묶습니다. 핵심은 **정렬·검색·페이지 상태가 바뀔 때마다 TanStack Query의 `queryKey`도 함께 바뀌어야** 새 조합에 맞는 데이터를 다시 조회한다는 점입니다.

| 상태 | 저장 위치 | queryKey 포함 여부 |
|---|---|---|
| `statusFilter` | Zustand(09편) | 포함 |
| `sortBy`, `sortOrder` | Zustand(09편) | 포함 |
| `searchQuery` | Zustand(이번 편 추가) | 포함(디바운스 후) |
| `page` | Zustand(이번 편 추가) | 포함 |

테이블 헤더 클릭으로 정렬을 바꾸는 로직은 규칙이 단순합니다. 같은 컬럼을 다시 클릭하면 방향을 뒤집고, 다른 컬럼을 클릭하면 오름차순으로 새로 시작합니다.

검색어는 `react_2`에서 만든 `useDebounce` 훅으로 타이핑이 멈춘 뒤에만 스토어에 반영합니다. 매 타이핑마다 서버에 요청을 보내면 네트워크가 낭비되고 화면이 깜빡입니다.

## 실습

<Steps>

### 1. 스토어에 검색·페이지 상태 추가

```js
// src/store/useUiStore.js (필드·액션 추가/수정 — 나머지는 09편 코드 유지)
searchQuery: '',
page: 1,
setStatusFilter: (statusFilter) => set({ statusFilter, page: 1 }),
setSearchQuery: (searchQuery) => set({ searchQuery, page: 1 }),
setPage: (page) => set({ page }),
setSort: (sortBy) =>
  set((state) => ({
    sortBy,
    sortOrder: state.sortBy === sortBy && state.sortOrder === 'asc' ? 'desc' : 'asc',
    page: 1,
  })),
```

검색어·필터·정렬이 바뀌면 `page`를 1로 되돌립니다. 3페이지를 보다가 필터를 바꿨는데 빈 페이지가 뜨는 것을 막기 위해서입니다. `setSort`의 방향 토글 로직 자체는 09편과 같고, 이번 편에서 `page: 1` 초기화만 더했습니다. `resetFilters`도 `searchQuery: ''`, `page: 1`을 포함하도록 09편 정의에 추가합니다.

### 2. api/books.js에 파라미터 반영

```js
// src/api/books.js (getBooks 함수만 발췌 — 나머지는 04~06편 코드 유지)
const API_BASE = 'http://localhost:3001';

export async function getBooks({ status, sortBy, sortOrder, search, page, pageSize = 5 }) {
  const params = new URLSearchParams({
    _sort: sortBy,
    _order: sortOrder,
    _page: String(page),
    _limit: String(pageSize),
  });
  if (status !== 'all') params.set('status', status);
  if (search) params.set('q', search);

  const response = await fetch(`${API_BASE}/books?${params.toString()}`);
  if (!response.ok) throw new Error('책 목록을 불러오지 못했습니다');

  const total = Number(response.headers.get('X-Total-Count') ?? 0);
  const items = await response.json();
  return { items, total, page, pageSize };
}
```

`X-Total-Count` 헤더로 전체 개수를 받아 총 페이지 수를 계산합니다. `json-server`(04편부터 사용)는 `_page`·`_limit` 페이지네이션에서 이 헤더를 기본으로 응답에 포함합니다.

### 3. BookTable 컴포넌트 작성

```jsx
// src/components/BookTable.jsx
import { useUiStore } from '../store/useUiStore';

const COLUMNS = [
  { key: 'title', label: '제목' },
  { key: 'author', label: '저자' },
  { key: 'pages', label: '쪽수' },
  { key: 'status', label: '상태' },
];

function BookTable({ books }) {
  const sortBy = useUiStore((state) => state.sortBy);
  const sortOrder = useUiStore((state) => state.sortOrder);
  const setSort = useUiStore((state) => state.setSort);

  return (
    <table className="book-table">
      <thead>
        <tr>
          {COLUMNS.map((column) => (
            <th key={column.key}>
              <button type="button" onClick={() => setSort(column.key)}>
                {column.label}
                {sortBy === column.key ? (sortOrder === 'asc' ? ' ▲' : ' ▼') : ''}
              </button>
            </th>
          ))}
        </tr>
      </thead>
      <tbody>
        {books.map((book) => (
          <tr key={book.id}>
            <td>{book.title}</td>
            <td>{book.author}</td>
            <td>{book.pages}</td>
            <td>{book.status}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}

export default BookTable;
```

헤더 버튼은 컬럼 키 하나만 `setSort`에 넘깁니다. 방향을 뒤집을지 새로 시작할지는 스토어의 `setSort` 액션이 판단합니다.

### 4. BookListPage에서 검색·페이지네이션 연결

```jsx
// src/pages/BookListPage.jsx
import { useState } from 'react';
import { useUiStore } from '../store/useUiStore';
import { useDebounce } from '../hooks/useDebounce';
import { useBooks } from '../hooks/useBooks.js';
import BookTable from '../components/BookTable';

function BookListPage() {
  const statusFilter = useUiStore((state) => state.statusFilter);
  const sortBy = useUiStore((state) => state.sortBy);
  const sortOrder = useUiStore((state) => state.sortOrder);
  const searchQuery = useUiStore((state) => state.searchQuery);
  const setSearchQuery = useUiStore((state) => state.setSearchQuery);
  const page = useUiStore((state) => state.page);
  const setPage = useUiStore((state) => state.setPage);

  const [searchInput, setSearchInput] = useState(searchQuery);
  const debouncedSearch = useDebounce(searchInput, 300);

  if (debouncedSearch !== searchQuery) {
    setSearchQuery(debouncedSearch);
  }

  const { data, isPending, isError } = useBooks({
    status: statusFilter,
    sortBy,
    sortOrder,
    search: searchQuery,
    page,
  });

  if (isPending) return <p>불러오는 중...</p>;
  if (isError) return <p role="alert">목록을 불러오지 못했습니다</p>;

  const totalPages = Math.max(1, Math.ceil(data.total / data.pageSize));

  return (
    <section>
      <input
        type="search"
        aria-label="책 검색"
        value={searchInput}
        onChange={(e) => setSearchInput(e.target.value)}
        placeholder="제목으로 검색"
      />
      <BookTable books={data.items} />
      <nav className="pagination" aria-label="페이지 이동">
        <button type="button" disabled={page <= 1} onClick={() => setPage(page - 1)}>
          이전
        </button>
        <span>
          {page} / {totalPages}
        </span>
        <button type="button" disabled={page >= totalPages} onClick={() => setPage(page + 1)}>
          다음
        </button>
      </nav>
    </section>
  );
}

export default BookListPage;
```

렌더링 중간에 `setSearchQuery`를 호출하는 부분이 낯설 수 있습니다. 디바운스된 값이 스토어 값과 달라졌을 때만 실행되므로 무한 렌더로 이어지지 않고, 다음 렌더에서 `searchQuery`가 갱신된 값으로 반영됩니다. `useBooks`는 06편에서 `placeholderData: keepPreviousData`를 이미 적용해 두었으므로, 검색·정렬·페이지가 바뀌어도 이전 목록을 화면에 유지해 깜빡임 없이 전환됩니다.

### 6. 확인

- "제목" 헤더를 클릭하면 오름차순으로 정렬되고, 한 번 더 클릭하면 내림차순으로 바뀝니다(헤더 옆 화살표로 확인).
- 검색창에 타이핑을 멈추고 약 0.3초 뒤에 목록이 필터링됩니다.
- "다음"을 눌러 페이지를 넘기면 새 목록이 나타나고, 마지막 페이지에서는 "다음" 버튼이 비활성화됩니다.
- 검색어를 바꾸면 페이지가 1로 초기화됩니다.

## 자주 하는 실수

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 검색창에 한 글자만 쳐도 요청이 계속 나감 | `useDebounce` 없이 `searchInput`을 바로 `queryKey`에 사용 | 디바운스된 값만 스토어·`queryKey`에 반영 |
| 페이지를 넘길 때마다 화면이 로딩 스피너로 깜빡임 | `placeholderData` 옵션 누락 | `placeholderData: (previous) => previous` 추가 |
| 정렬 컬럼을 바꿔도 방향이 항상 오름차순으로 시작 안 됨 | `setSort`에서 같은 컬럼 여부를 확인하지 않음 | 클릭한 컬럼이 현재 `sortBy`와 같은지 비교하는 조건 확인 |
| 필터를 바꿨더니 존재하지 않는 페이지가 표시됨 | 필터·검색 변경 시 `page`를 초기화하지 않음 | `setStatusFilter`, `setSearchQuery`, `setSort`에서 `page: 1` 반영 |
