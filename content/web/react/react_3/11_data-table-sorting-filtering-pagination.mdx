## 개념 정리

06편에서 페이지 단위 조회를, 09편에서 필터·정렬 상태를 Zustand로 옮겼습니다. 핵심은 **정렬·검색·페이지 상태가 바뀔 때마다 TanStack Query의 `queryKey`도 함께 바뀌어야** 새 조합에 맞는 데이터를 다시 조회한다는 점입니다.

| 상태 | 저장 위치 | queryKey 포함 여부 |
|---|---|---|
| `statusFilter` | Zustand(09편) | 포함 |
| `sortBy`, `sortOrder` | Zustand(09편) | 포함 |
| `searchQuery` | Zustand(이번 편 추가) | 포함(디바운스 후) |
| `page` | Zustand(이번 편 추가) | 포함 |

테이블 헤더 클릭으로 정렬을 바꾸는 로직은 규칙이 단순합니다. 같은 컬럼을 다시 클릭하면 방향을 뒤집고, 다른 컬럼을 클릭하면 오름차순으로 새로 시작합니다.

검색어는 `react_2`에서 만든 `useDebounce` 훅으로 타이핑이 멈춘 뒤에만 스토어에 반영합니다. 매 타이핑마다 서버에 요청을 보내면 네트워크가 낭비되고 화면이 깜빡입니다.

## 자주 하는 실수

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 검색창에 한 글자만 쳐도 요청이 계속 나감 | `useDebounce` 없이 `searchInput`을 바로 `queryKey`에 사용 | 디바운스된 값만 스토어·`queryKey`에 반영 |
| 페이지를 넘길 때마다 화면이 로딩 스피너로 깜빡임 | `placeholderData` 옵션 누락 | `placeholderData: (previous) => previous` 추가 |
| 정렬 컬럼을 바꿔도 방향이 항상 오름차순으로 시작 안 됨 | `setSort`에서 같은 컬럼 여부를 확인하지 않음 | 클릭한 컬럼이 현재 `sortBy`와 같은지 비교하는 조건 확인 |
