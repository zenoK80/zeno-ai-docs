## 개념 정리

### 구조적 타이핑의 한계

TypeScript는 구조가 같으면 같은 타입으로 취급합니다. `TransactionId`와 `ExpenseCategory`를 둘 다 그냥 `string`으로 선언했다면, 거래 `id`를 받는 자리에 카테고리 문자열 `'food'`를 넣어도 타입 오류가 나지 않습니다.

### 브랜디드(명목) 타입

원래 타입에 실제로는 존재하지 않는 표시 프로퍼티를 교차 타입으로 붙여, 구조가 같아도 이름표가 다르면 서로 대입할 수 없게 만드는 패턴입니다.

```ts
declare const brandSymbol: unique symbol
type Brand<T, B extends string> = T & { readonly [brandSymbol]: B }
type TransactionId = Brand<string, 'TransactionId'>
```

`declare const`는 실제 값을 만들지 않고 이름과 타입만 컴파일러에 알립니다. `unique symbol`은 다른 어떤 값과도 같을 수 없는 전용 타입이라, 표시 키로 평범한 문자열(`'__brand'` 같은) 대신 이 심벌을 쓰면 우연히 같은 이름의 프로퍼티를 가진 객체가 브랜드 조건을 실수로 만족해버리는 상황까지 막을 수 있습니다.

### 브랜드 생성 헬퍼 함수

일반 문자열을 브랜디드 타입으로 바꾸려면 `as`로 단언해야 하는데, 여기저기서 직접 단언하면 실수로 아무 문자열이나 브랜딩하기 쉽습니다. 브랜드 이름마다 전용 변환 함수를 하나씩 만들어 두면, 어디서 브랜딩이 실제로 일어나는지 함수 이름만 보고 알 수 있습니다.

```ts
function toTransactionId(value: string): TransactionId {
  return value as TransactionId
}
```

## 자주 하는 실수

| 증상 | 원인 | 고치는 법 |
|------|------|-----------|
| 아무 문자열이나 as TransactionId로 캐스팅해 사용 | 브랜딩 헬퍼를 거치지 않고 직접 단언 | 신뢰할 수 있는 생성 지점에서만 toTransactionId를 호출하도록 규칙을 지킨다 |
| 브랜드 표시가 런타임에도 있다고 착각 | 표시용 심벌 키는 타입 전용이며 컴파일 후 사라짐 | 실제 값 검증이 필요하면 별도의 런타임 검사 로직을 둔다 |
| DOM에서 꺼낸 문자열을 그대로 넘겨 컴파일 에러 | dataset 값은 항상 평범한 string이라 TransactionId와 다름 | toTransactionId로 다시 감싼 뒤 전달한다 |
