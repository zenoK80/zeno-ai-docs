## 시험 보듯 풀고 오답 노트 작성하기

실전처럼 시간을 정해 두고(예: 25문항을 40분 이내) 끝까지 풀어 본 뒤 채점하는 것을 권한다. 채점 후에는 다음 방식으로 오답 노트를 작성하면 같은 실수를 반복하지 않는 데 도움이 된다.

<Steps>

1. **틀린 문제의 코드를 다시 손으로 한 줄씩 따라간다.** 어느 줄에서 자신의 예상과 실제 동작이 갈렸는지 정확히 표시한다.
2. **틀린 이유를 개념 이름으로 못박는다.** "실수로 잘못 봤다"가 아니라 "정적 바인딩과 동적 바인딩을 헷갈렸다", "checked 예외 처리 규칙을 놓쳤다"처럼 구체적인 개념 이름으로 적는다.
3. **같은 개념을 다루는 다른 편의 문제를 찾아 한 번 더 풀어 본다.** 23편의 오개념 패턴 표를 참고하면 관련 문제를 빠르게 찾을 수 있다.
4. **오답 노트에 옳은 설명과 틀린 설명을 나란히 적는다.** 보기 하나하나가 왜 맞는지, 왜 틀렸는지를 한 줄씩 적어 두면 다음에 비슷한 보기를 만났을 때 바로 판단할 수 있다.

</Steps>

```java
interface Payable {
    double calculatePay();
}

class Employee implements Payable {
    double baseSalary;

    Employee(double baseSalary) {
        this.baseSalary = baseSalary;
    }

    @Override
    public double calculatePay() {
        return baseSalary;
    }
}

class Manager extends Employee {
    double bonus;

    Manager(double baseSalary, double bonus) {
        super(baseSalary);
        this.bonus = bonus;
    }

    @Override
    public double calculatePay() {
        return super.calculatePay() + bonus;
    }
}

public class Main {
    public static void main(String[] args) {
        Payable[] staff = { new Employee(2000), new Manager(3000, 500) };
        double total = 0;
        for (Payable p : staff) {
            total += p.calculatePay();
        }
        System.out.println(total);
    }
}
```
