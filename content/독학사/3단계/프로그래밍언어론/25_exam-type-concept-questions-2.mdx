## 문제 1

<Quiz
  questionNumber={1}
  question={"이름(name)에 관한 여러 바인딩 중 형 바인딩(type binding)과 저장 바인딩(storage binding)의 관계를 가장 정확히 설명한 것은?"}
  options={["형 바인딩은 변수가 어떤 자료형을 갖는지를 이름에 연결하는 것이고, 저장 바인딩은 그 변수가 실행 중 어느 메모리 위치를 차지할지를 연결하는 것으로, 두 바인딩은 서로 독립적으로 다른 시점에 이루어질 수 있다.","형 바인딩과 저장 바인딩은 항상 완전히 동시에 이루어지며 절대 분리될 수 없다.","저장 바인딩이 이루어져야만 비로소 형 바인딩이 가능해지므로 저장 바인딩이 항상 형 바인딩보다 논리적으로 먼저다.","형 바인딩은 실행 중에는 절대 일어날 수 없고 반드시 컴파일 이전에 사람이 직접 지정해야 한다."]}
  correctAnswer={1}
  explanation={"형 바인딩은 이름과 자료형 사이의 연결이고, 저장 바인딩은 이름과 실제 메모리 위치(주소) 사이의 연결입니다. 예를 들어 정적 타입 언어에서는 컴파일 시점에 형 바인딩이 끝나지만, 저장 바인딩은 함수가 호출될 때(스택 활성화 레코드가 만들어질 때)까지 늦춰지는 경우가 흔합니다. 이렇게 두 바인딩은 서로 다른 시점에 독립적으로 일어날 수 있습니다."}
/>

<Quiz
  questionNumber={2}
  question={"매개변수 바인딩(parameter binding)에 대한 설명으로 가장 적절한 것은?"}
  options={["하위프로그램이 호출될 때 형식 매개변수(formal parameter)라는 이름이 실제 인자(actual argument)가 가리키는 값이나 위치에 연결되는 것을 말한다.","매개변수 바인딩은 하위프로그램을 정의하는 시점에 딱 한 번만 일어나고 이후 호출과는 무관하다.","매개변수 바인딩은 전역 변수에만 적용되는 개념이다.","매개변수 바인딩이 이루어지면 그 하위프로그램은 다시는 다른 인자로 호출될 수 없다."]}
  correctAnswer={1}
  explanation={"매개변수 바인딩은 하위프로그램이 호출될 때마다 새로 이루어집니다. 형식 매개변수는 하위프로그램 정의에 등장하는 이름일 뿐이고, 실제로 어떤 값·변수·주소에 연결되는지는 호출 시점마다 실제 인자에 따라 달라집니다."}
