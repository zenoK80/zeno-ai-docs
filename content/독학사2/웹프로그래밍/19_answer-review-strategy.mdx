## 왜 오답을 유형별로 나눠서 봐야 하는가

> **쉽게 말하면:** 틀린 문제를 "몰라서"로 뭉뚱그리지 말고, 어떤 종류의 실수였는지 이름을 붙여야 다음에 같은 실수를 피할 수 있다.

15편부터 18편까지 100문항 가까이 풀었다면 이제 중요한 것은 정답 개수가 아니라 **왜 틀렸는가**다. 같은 "몰라서 틀렸다"도 실제로는 원인이 다르다. 개념 자체를 반대로 외운 경우, 계산 중 한 단계를 빼먹은 경우, 비슷한 두 개념을 뒤바꿔 고른 경우, "옳지 않은 것을 고르시오"인데 옳은 것을 찾아 헤맨 경우는 각각 대처법이 다르다. 원인을 구분하지 않으면 오답 노트를 만들어도 같은 실수를 반복한다.

### 오답 유형 분류

| 유형 | 설명 | 예시 실수 | 대처법 |
|------|------|-----------|--------|
| 정의 뒤바뀜 | 두 개념의 정의나 역할을 서로 반대로 외운 경우 | 클라이언트와 서버의 역할을 반대로 알고 있었다 | 두 개념을 항상 짝으로 놓고 "A는 무엇, B는 무엇"을 문장으로 완성해 본다 |
| 계산 단계 누락 | 공식은 알지만 대입 과정에서 한 항목을 빠뜨린 경우 | 박스 모델 너비 계산에서 테두리 두께를 더하는 것을 잊었다 | 계산형 문제는 답을 쓰기 전에 공식의 모든 항목을 손으로 하나씩 짚는다 |
| 비슷한 용어 혼동 | 표기나 발음이 비슷해 다른 개념을 고른 경우 | display:none과 visibility:hidden의 차이를 혼동했다 | 헷갈리는 짝을 표로 정리해 두고 시험 직전 다시 훑는다(아래 표 참고) |
| 발문(질문) 오독 | "옳은 것"과 "옳지 않은 것"을 헷갈려 반대로 답한 경우 | 옳지 않은 것을 고르라는 문제에서 옳은 보기를 정답으로 골랐다 | 발문에서 부정어(옳지 않은, 아닌, 해당하지 않는)를 보이면 동그라미로 표시하고 시작한다 |
| 예외·경계 사례 누락 | 일반 규칙은 알지만 예외 상황을 놓친 경우 | 명시도 규칙은 알았지만 인라인 스타일이 항상 더 우선한다는 예외를 몰랐다 | 규칙을 외울 때 "예외가 있는가"를 항상 한 번 더 확인한다 |

## 헷갈리는 개념 재점검

시험 직전에는 새로운 내용을 배우기보다 **자주 뒤바뀌는 짝 개념**을 다시 대조하는 것이 효율적이다. 아래 표는 지금까지 편에서 다룬 개념 중 실제로 혼동이 잦은 짝을 모아 정리한 것이다.

### HTML 관련

| 구분 A | 구분 B | 핵심 차이 | 구분법 한 줄 |
|--------|--------|-----------|--------------|
| section 요소 | article 요소 | section은 문서 안의 주제별 구획, article은 독립적으로 재사용 가능한 콘텐츠 단위 | 이 부분만 떼어 다른 곳에 옮겨도 말이 되면 article |
| readonly 속성 | disabled 속성 | readonly는 수정만 막고 값은 그대로 전송, disabled는 입력도 전송도 막음 | 서버로 값이 전송되는가를 기준으로 구분한다 |
| id 속성 | class 속성 | id는 문서 안에서 유일해야 하는 식별자, class는 여러 요소에 반복해서 붙일 수 있는 분류표 | 한 문서에 두 번 이상 붙일 수 있으면 class |

### CSS 관련

| 구분 A | 구분 B | 핵심 차이 | 구분법 한 줄 |
|--------|--------|-----------|--------------|
| display:none | visibility:hidden | display:none은 공간까지 사라짐, visibility:hidden은 공간은 남고 안 보이기만 함 | 숨긴 자리에 다른 요소가 밀려 들어오면 display:none |
| position:relative | position:absolute | relative는 자기 원래 위치 기준 이동, absolute는 위치가 지정된 가장 가까운 조상 기준 배치 | 기준점이 자기 자신인지 조상인지로 구분한다 |
| margin | padding | margin은 테두리 바깥 여백(다른 요소와의 간격), padding은 테두리 안쪽 여백(내용물과의 간격) | 테두리를 기준으로 안쪽인지 바깥쪽인지로 구분한다 |

### JavaScript 관련

| 구분 A | 구분 B | 핵심 차이 | 구분법 한 줄 |
|--------|--------|-----------|--------------|
| var | let·const | var는 함수 스코프, let·const는 블록 스코프 | 반복문 블록을 벗어나도 값이 남아 있으면 var로 선언된 것 |
| 동등 비교(느슨한 비교) | 일치 비교(엄격한 비교) | 느슨한 비교는 자료형을 자동으로 맞춰서 비교, 엄격한 비교는 자료형까지 같아야 참 | 자료형이 다른 값끼리 비교했을 때 결과가 갈리면 느슨한 비교였다는 뜻 |
| 이벤트 버블링 | 이벤트 캡처링 | 버블링은 하위에서 상위로 전파, 캡처링은 상위에서 하위로 전파 | 전파 방향이 자식에서 부모로 올라가면 버블링 |

### 개념 전반

| 구분 A | 구분 B | 핵심 차이 | 구분법 한 줄 |
|--------|--------|-----------|--------------|
| HTML | XML | HTML은 태그와 표시 방식이 표준으로 고정, XML은 태그 이름을 사용자가 정의 | 새 태그 이름을 마음대로 만들 수 있으면 XML |
| GET | POST | GET은 조회 위주이며 데이터가 URL에 노출, POST는 요청 본문에 데이터를 담아 전송 | 주소창에 데이터가 그대로 보이면 GET일 가능성이 높다 |
| 동기 통신 | Ajax(비동기 통신) | 동기 통신은 응답이 올 때까지 다음 동작이 멈춤, Ajax는 응답을 기다리는 동안에도 다른 조작이 가능 | 페이지 전체가 새로고침되면 동기, 일부만 갱신되면 Ajax |
