</Callout>

<Callout type="info">
  **이번 문서의 목표:** 이 파일을 다 읽으면 작업형과 에뮬레이터형, 단답·선택형이 섞인 한 세트를 정해진 시간 안에 배분해 풀 수 있고, 로컬 보안 정책과 백업 방식 같은 종합 영역의 정답 근거를 설명할 수 있으며, 실수했을 때 되돌리는 절차를 알 수 있습니다.
</Callout>

## 시간 배분 전략

실기는 **80분에 18문항** 구성으로 안내되어 왔습니다. 단순히 나누면 한 문항에 약 4분이지만, 문항마다 걸리는 시간은 전혀 다릅니다.

| 유형 | 문항 수 대략 | 한 문항 소요 | 특징 |
|------|--------------|--------------|------|
| 작업형(케이블 제작 등) | 1–2 | 10–15분 | 손이 느리면 시간을 크게 먹음 |
| 에뮬레이터 설정 | 6–8 | 3–5분 | 메뉴를 알면 빠르고 모르면 헤맴 |
| 단답형 | 4–6 | 1분 이내 | 알면 즉답, 모르면 붙잡아도 소용없음 |
| 선택·연결형 | 2–4 | 1–2분 | 판별 문제 |

### 권장 순서

<Steps>

### 전체를 1분간 훑는다

어떤 유형이 몇 개인지, 작업형이 어디 있는지 먼저 파악합니다. **아는 문제와 모르는 문제를 나누는 데 쓰는 1분이 가장 값진 1분**입니다.

### 단답·선택형을 먼저 쓸어 담는다

1분 이내에 끝나는 문항을 먼저 처리해 확실한 점수를 확보합니다. 아는 것을 못 써서 잃는 점수가 가장 아깝습니다.

### 에뮬레이터 문항을 순서대로 처리한다

각 문항마다 값 변경 후 **저장·적용까지 마치고** 다음으로 넘어갑니다. "나중에 한꺼번에 저장하겠다"는 생각은 미반영 사고의 원인입니다.

### 작업형을 남은 시간에 집중해 수행한다

케이블 제작 같은 작업형은 중간에 끊으면 처음부터 다시 해야 하는 경우가 많으므로 **연속된 시간 덩어리**를 확보해 수행합니다.

### 막힌 문항은 표시하고 넘어간다

한 문항에 5분 이상 쓰지 않습니다. 5분을 넘기면 그 문항의 기대 점수보다 남은 문항의 기대 점수가 큽니다.

### 마지막 5분은 검토에 쓴다

에뮬레이터 문항을 다시 열어 값이 남아 있는지 확인합니다. 특히 저장 여부를 재확인합니다.

</Steps>

<Callout type="warning">
  **가장 많은 점수가 새는 곳은 어려운 문제가 아니라 저장 누락과 오타입니다.** 값은 맞게 넣었는데 적용을 안 눌러서, IP 한 자리를 잘못 쳐서, 볼륨 이름의 띄어쓰기가 달라서 잃는 점수가 난이도 때문에 잃는 점수보다 많습니다. 검토 시간은 어려운 문제를 더 푸는 데 쓰지 말고 **이미 푼 문제의 반영 여부 확인**에 쓰는 편이 기대값이 높습니다.
</Callout>

## 종합 모의 세트

### 과제 1. 로컬 보안 정책

#### 문제

> 로컬 보안 정책에서 다음 조건을 설정하시오.
> ① 암호는 복잡성을 만족해야 함: 사용 ② 최소 암호 길이: 12자 ③ 최대 암호 사용 기간: 60일 ④ 계정 잠금 임계값: 5회 ⑤ 계정 잠금 기간: 30분

#### ① 정답

실행 명령어는 `secpol.msc` 입니다.

| 조건 | 위치 | 설정값 |
|------|------|--------|
| 암호 복잡성 | 계정 정책 → 암호 정책 | 사용 |
| 최소 암호 길이 | 계정 정책 → 암호 정책 | 12 문자 |
| 최대 암호 사용 기간 | 계정 정책 → 암호 정책 | 60 일 |
| 계정 잠금 임계값 | 계정 정책 → **계정 잠금 정책** | 잘못된 로그온 시도 5회 |
| 계정 잠금 기간 | 계정 정책 → **계정 잠금 정책** | 30 분 |

#### ② 원리 — 두 정책은 목적이 다르다

| 정책 묶음 | 막으려는 것 | 핵심 항목 |
|-----------|-------------|-----------|
| 암호 정책 | 애초에 **약한 암호가 만들어지는 것** | 복잡성, 최소 길이, 사용 기간, 암호 기록 |
| 계정 잠금 정책 | **무차별 대입 시도가 계속되는 것** | 잠금 임계값, 잠금 기간, 카운터 초기화 시간 |

암호 정책은 문을 튼튼하게 만드는 일이고, 계정 잠금 정책은 문을 계속 두드리는 사람을 쫓아내는 일입니다. 문제가 다섯 항목을 섞어 내는 이유는 **어느 항목이 어느 묶음에 속하는지**를 묻기 위해서입니다.

#### 암호 정책 항목의 의미

| 항목 | 의미 | 기본 감각 |
|------|------|-----------|
| 암호는 복잡성을 만족해야 함 | 영문 대문자, 소문자, 숫자, 특수문자 중 세 종류 이상 포함하고 계정 이름을 포함하지 않을 것 | 사용으로 두는 것이 안전 |
| 최소 암호 길이 | 최소 글자 수 | 길수록 대입 공격에 강함 |
| 최대 암호 사용 기간 | 이 기간이 지나면 변경 요구 | 0으로 두면 만료 없음 |
| 최소 암호 사용 기간 | 바꾼 뒤 다시 바꾸기까지의 최소 기간 | 암호 기록 우회를 막음 |
| 최근 암호 기억 | 과거 암호 재사용 금지 개수 | 같은 암호 돌려쓰기 방지 |

**최소 암호 사용 기간이 왜 필요한가**는 자주 나오는 응용 문항입니다. 최근 암호를 기억하도록 설정해도, 사용자가 한자리에서 암호를 여러 번 바꿔 기억 목록을 밀어낸 뒤 원래 암호로 되돌릴 수 있습니다. 최소 사용 기간을 두면 이 우회가 불가능해집니다.

#### 계정 잠금 정책 항목의 의미

| 항목 | 의미 |
|------|------|
| 계정 잠금 임계값 | 몇 번 틀리면 잠글 것인가. `0` 이면 잠그지 않음 |
| 계정 잠금 기간 | 잠긴 뒤 자동으로 풀릴 때까지의 시간. `0` 이면 관리자가 풀 때까지 |
| 다음 시간 후 계정 잠금 수를 원래대로 설정 | 틀린 횟수 카운터를 초기화하는 시간 |

<Callout type="warning">
  **임계값을 0으로 두면 잠금이 비활성화됩니다.** 보안 강화 조건에서 `0` 을 입력하면 정반대의 설정이 됩니다. 또한 임계값을 지정하면 Windows가 잠금 기간과 카운터 초기화 시간을 자동으로 제안하는 대화상자를 띄우는데, **제안값을 그대로 확인하면 문제가 요구한 값과 달라질 수 있습니다.** 제안을 받아들인 뒤 각 항목을 다시 열어 지정값으로 고쳐야 합니다.
</Callout>

#### ③ 조작 절차

<Steps>

### 로컬 보안 정책 실행

실행 창에 `secpol.msc` 를 입력합니다.

### 암호 정책으로 이동

왼쪽 트리에서 계정 정책을 펼치고 암호 정책을 선택합니다.

### 항목별 설정

각 항목을 더블클릭해 값을 입력하고 확인을 누릅니다. 사용·사용 안 함 항목은 라디오 버튼입니다.

### 계정 잠금 정책으로 이동

같은 계정 정책 아래의 계정 잠금 정책을 선택합니다.

### 임계값 먼저 설정

계정 잠금 임계값을 5로 지정합니다. 제안 대화상자가 뜨면 확인합니다.

### 제안값 덮어쓰기

계정 잠금 기간을 다시 열어 30분으로 고칩니다. 카운터 초기화 시간도 문제가 지정했다면 함께 고칩니다.

### 최종 확인

오른쪽 목록의 보안 설정 열을 훑어 다섯 값이 모두 지시대로인지 대조합니다.

</Steps>

### 과제 2. 백업 방식 배열

#### 문제

> 백업 방식을 **백업 수행에 걸리는 시간이 짧은 것부터 긴 순서**로 배열하시오.
> ㉠ 전체 백업 ㉡ 차등 백업 ㉢ 증분 백업

#### ① 정답

**㉢ 증분 백업 → ㉡ 차등 백업 → ㉠ 전체 백업**

#### ② 원리 — 무엇을 복사하는가가 시간을 정한다

| 방식 | 복사 대상 | 백업 시간 | 복원 시 필요한 것 | 복원 시간 |
|------|-----------|-----------|-------------------|-----------|
| 전체 백업 | 전체 데이터 | 가장 김 | 전체 백업 1개 | 가장 짧음 |
| 차등 백업 | **마지막 전체 백업 이후** 바뀐 것 전부 | 중간 | 전체 1개 + 최신 차등 1개 | 중간 |
| 증분 백업 | **마지막 백업(종류 무관) 이후** 바뀐 것만 | 가장 짧음 | 전체 1개 + 그 이후 증분 전부 | 가장 김 |

핵심 차이는 **기준점**입니다.

```mermaid
graph LR
  F[일요일 전체 백업] --> M1[월요일]
  M1 --> T1[화요일]
  T1 --> W1[수요일]
```

- **차등**: 월요일은 일요일 이후 변경분, 화요일도 **일요일 이후** 변경분, 수요일도 일요일 이후 변경분. 갈수록 양이 커집니다.
- **증분**: 월요일은 일요일 이후 변경분, 화요일은 **월요일 이후** 변경분, 수요일은 화요일 이후 변경분. 매번 조금씩만 담습니다.

그래서 증분이 가장 빠르고 용량도 작지만, 복원할 때는 전체 백업에 이어 그 뒤의 증분을 **하나도 빠짐없이 순서대로** 적용해야 합니다. 중간의 하나만 손상돼도 이후 복원이 불가능합니다. 차등은 전체 하나와 가장 최근 차등 하나만 있으면 됩니다.

| 관점 | 유리한 방식 |
|------|-------------|
| 백업 시간·용량 | 증분 |
| 복원 속도·단순함 | 전체 |
| 둘의 절충 | 차등 |
| 백업 손상에 대한 견고함 | 전체, 차등 |

<Callout type="info">
  **문제 문장을 반드시 확인하세요.** "백업 속도"인지 "복원 속도"인지에 따라 순서가 **정반대**가 됩니다. 백업 속도는 증분이 가장 빠르고, 복원 속도는 전체가 가장 빠릅니다. 이 한 단어를 놓쳐 틀리는 경우가 매우 많습니다.
</Callout>

### 과제 3. 원격 데스크톱 연결

#### 문제

> 원격 데스크톱 연결에서 다음 조건을 설정하시오.
> ① 컴퓨터: `192.168.20.115` ② 사용자 이름: `ADMIN02` ③ 전체 화면 사용 시 연결 표시줄이 표시되도록 설정 ④ 원격 세션에서 클립보드를 사용하도록 설정

#### ① 정답

실행 명령어는 `mstsc` 이며, 먼저 **옵션 표시**를 눌러야 탭이 나타납니다.

| 조건 | 탭 | 조작 |
|------|-----|------|
| 컴퓨터, 사용자 이름 | 일반 | 입력란에 정확히 입력 |
| 연결 표시줄 | **디스플레이** | 전체 화면 사용 시 연결 표시줄 표시 체크 |
| 클립보드 | **로컬 리소스** | 로컬 장치 및 리소스에서 클립보드 체크 |

#### ② 원리

RDP의 기본 포트는 `3389` 입니다. 로컬 리소스 탭의 항목들은 **리디렉션** 기능으로, 원격 세션의 입출력을 내 컴퓨터 쪽으로 되돌립니다. 클립보드를 체크하면 원격에서 복사한 내용을 내 PC에 붙여 넣을 수 있고, 프린터를 체크하면 원격의 인쇄 명령이 내 프린터로 나옵니다.

**연결 표시줄이 디스플레이 탭에 있는 이유**는 그것이 화면 표시에 관한 옵션이기 때문입니다. 반대로 클립보드와 프린터는 장치 연결에 관한 것이라 로컬 리소스 탭입니다. 이 구분 하나만 잡아 두면 탭을 헤매지 않습니다.

| 실수 | 결과 |
|------|------|
| 옵션 표시를 누르지 않음 | 탭에 접근 불가 |
| 연결 표시줄을 로컬 리소스에서 찾음 | 시간 손실 |
| IP 한 자리 오타 | 전면 오답 |
| 사용자 이름의 대소문자·자릿수 오류 | 오답 |

### 과제 4. 보안 위협 용어

#### 문제

> 사용 가능한 문자 조합을 순서대로 모두 대입해 암호를 알아내려는 공격 기법은?

#### ① 정답

**무차별 대입 공격**(Brute Force Attack)

#### ② 비슷한 용어와의 구분

| 용어 | 설명 | 구분 포인트 |
|------|------|-------------|
| 무차별 대입 공격 | 가능한 모든 조합을 순서대로 시도 | 조합을 전부 만들어 봄 |
| 사전 공격 | 흔히 쓰이는 단어 목록을 시도 | 미리 만든 목록 사용 |
| 레인보우 테이블 공격 | 해시값과 원문의 대응표를 미리 만들어 역추적 | 미리 계산된 표 사용 |
| 크리덴셜 스터핑 | 다른 사이트에서 유출된 계정 정보를 그대로 시도 | 유출 자료 재사용 |
| 사회 공학 | 사람을 속여 정보를 얻어냄 | 기술이 아닌 심리 |
| 피싱 | 위장한 화면·메일로 정보를 입력하게 유도 | 사회 공학의 한 형태 |

**계정 잠금 정책이 왜 존재하는지**가 여기서 연결됩니다. 무차별 대입은 시도 횟수가 많아야 성립하므로, 몇 번 틀리면 잠가 버리면 공격 자체가 불가능해집니다. 과제 1과 과제 4는 같은 이야기의 앞뒤입니다.

### 과제 5. 단답형 종합

| 문제 | 정답 |
|------|------|
| 클라우드 서버를 거치지 않고 기기 내부에서 직접 AI 연산을 처리하는 기술 | 온디바이스 AI |
| 로컬 보안 정책을 실행하는 명령어 | `secpol.msc` |
| 원격 데스크톱 연결을 실행하는 명령어 | `mstsc` |

| 네트워크 설정 정보를 확인하는 명령어 | `ipconfig` |

**온디바이스 AI**가 주목받는 이유는 세 가지입니다. 첫째, 데이터가 기기 밖으로 나가지 않아 **개인정보 보호**에 유리합니다. 둘째, 네트워크 왕복이 없어 **응답이 빠릅니다.** 셋째, 인터넷이 끊겨도 동작합니다. 대신 기기 자체에 연산 성능이 필요해 **NPU**(Neural Processing Unit, 신경망 처리 장치)를 탑재한 프로세서가 늘고 있습니다.

## 실수를 되돌리는 절차

시험 중 잘못 건드렸을 때의 복구 방법을 미리 알아 두면 당황하지 않습니다.

| 상황 | 복구 방법 |
|------|-----------|
| BIOS 설정을 엉망으로 만듦 | 최상위 메뉴의 Load Optimized Defaults로 초기화 후 다시 설정 |
| BIOS를 저장하고 나왔는데 잘못됨 | 다시 진입해 해당 항목만 수정 후 재저장 |
| 파티션을 잘못 만듦 | 해당 볼륨 우클릭 후 볼륨 삭제, 비할당으로 되돌린 뒤 재작업 |
| 드라이브 문자를 잘못 지정 | 우클릭 후 드라이브 문자 및 경로 변경 |
| 레지스트리 값을 잘못 만듦 | 해당 값 우클릭 후 삭제, 다시 생성 |
| 서비스를 잘못 중지 | 시작 유형을 원래대로 되돌리고 시작 버튼 클릭 |
| 시각 효과를 전부 꺼 버림 | 사용자 지정에서 필요한 항목만 다시 체크 |
| LAN 케이블 배선을 틀림 | 커넥터를 잘라 내고 재제작. 재사용은 불가 |

<Callout type="warning">
  **재작업이 불가능한 것은 LAN 케이블의 압착뿐입니다.** 한 번 압착한 RJ-45 커넥터는 되돌릴 수 없으므로 잘라 내고 다시 만들어야 합니다. 그래서 압착 직전에 **커넥터 앞쪽 투명한 부분으로 색 순서를 한 번 더 확인하는 습관**이 시간을 가장 크게 아껴 줍니다. 3초의 확인이 5분의 재작업을 막습니다.
</Callout>

## 채점표 관점에서 다시 보기

같은 문항이라도 채점은 **여러 항목으로 쪼개져** 이루어집니다. 하나를 놓쳐도 나머지는 살아 있으니 포기하지 않는 것이 중요합니다.

| 문항 | 채점이 쪼개지는 방식 |
|------|----------------------|
| LAN 케이블 | 배선 순서 / 압착 상태 / 겉피복 물림 / 도통 |
| 디스크 파티션 | 크기 / 파일 시스템 / 드라이브 문자 / 볼륨 이름 |
| 로컬 보안 정책 | 다섯 항목 각각 |
| 원격 데스크톱 | 주소 / 사용자 이름 / 표시줄 / 리디렉션 |
| 가상 메모리 | 드라이브 / 처음 크기 / 최대 크기 / 반영 여부 |

한 항목이 틀렸다고 그 문항 전체가 0점이 되는 것이 아닙니다. **막혔다면 할 수 있는 항목만이라도 정확히 채우고 넘어가는 것**이 총점을 지키는 방법입니다.

## 핵심 정리

- 시간 배분은 단답·선택형을 먼저 쓸어 담고, 에뮬레이터는 문항마다 저장까지 끝낸 뒤 넘어가며, 작업형에 연속 시간을 확보하는 순서가 안전합니다.
- 암호 정책은 약한 암호 생성을 막고 계정 잠금 정책은 무차별 대입 시도를 막으며, 임계값 `0` 은 잠금 비활성화를 뜻합니다.
- 백업은 수행 속도가 증분, 차등, 전체 순으로 빠르고 복원 속도는 정확히 그 반대입니다.
- 원격 데스크톱에서 연결 표시줄은 디스플레이 탭, 클립보드와 프린터는 로컬 리소스 탭에 있습니다.
- 채점은 항목별로 쪼개지므로 한 항목이 막혀도 나머지를 정확히 채우는 것이 총점에 유리합니다.
