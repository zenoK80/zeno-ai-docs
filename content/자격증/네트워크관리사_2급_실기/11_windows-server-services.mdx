## 1. DHCP: 범위·제외·예약·옵션 구별하기

### 연습 조건

- 네트워크: `192.168.50.0/24`
- 할당 범위: `192.168.50.100`부터 `192.168.50.150`까지
- 제외 범위: `192.168.50.120`부터 `192.168.50.129`까지
- 임대 기간: 2일
- 라우터: `192.168.50.1`, DNS 서버: `192.168.50.10`
- DNS 도메인 이름: `lab.example`

`/24`의 마스크는 `255.255.255.0`입니다. 범위의 주소 수는 양 끝을 포함한 51개이며, 제외 주소 10개를 빼면 이 예제의 동적 할당 대상은 41개입니다. 네트워크 주소 `.0`과 브로드캐스트 주소 `.255`는 애초에 이 풀에 포함되지 않습니다.

**예약**은 특정 클라이언트 식별자와 IP 주소를 연결하는 기능입니다. 단순히 주소 풀을 한 주소로 줄이거나 제외 범위에 추가하는 것과 다릅니다. 문제에서 예약을 요구한다면 지정한 예약 항목에서 IP와 클라이언트 식별자를 확인합니다.

개인 학습 서버에서는 다음처럼 저장된 설정을 조회할 수 있습니다.

```powershell
Get-DhcpServerv4Scope -ScopeId 192.168.50.0
Get-DhcpServerv4ExclusionRange -ScopeId 192.168.50.0
Get-DhcpServerv4OptionValue -ScopeId 192.168.50.0
```

## 2. DNS: A·CNAME·PTR 레코드 만들기

### 연습 조건

정방향 조회 영역 `lab.example`에 서버 이름 `web`, 주소 `192.168.50.10`을 등록합니다. `www.lab.example`은 `web.lab.example`의 별칭이어야 합니다.

1. DNS 관리자에서 `정방향 조회 영역` 아래 `lab.example`을 만듭니다. 영역 종류와 동적 업데이트 옵션은 연습 환경의 조건에 맞춥니다.
2. 해당 영역에서 새 호스트 A 레코드를 만듭니다. 이름은 `web`, IP 주소는 `192.168.50.10`입니다.
3. 같은 영역에서 별칭 CNAME을 만듭니다. 별칭은 `www`, 대상 FQDN은 `web.lab.example`입니다. 대상 칸에 IP를 넣지 않습니다.
4. 주소에서 이름으로 찾는 기능도 필요하면 역방향 조회 영역과 PTR 레코드를 별도로 준비합니다. A 레코드를 만들었다고 PTR이 항상 자동으로 생기지는 않습니다.

| 확인할 질의 | 기대하는 관계 |
|---|---|
| `web.lab.example`의 A | `192.168.50.10` |
| `www.lab.example`의 CNAME | `web.lab.example` |
| `192.168.50.10`의 PTR | 역방향 영역·PTR을 만들었을 때 `web.lab.example` |

개인 가상 머신에서는 `nslookup web.lab.example 192.168.50.10`으로 **질의할 DNS 서버를 명시**합니다. 다른 DNS 서버에 물으면 방금 만든 사설 영역을 찾지 못할 수 있습니다.

## 3. IIS: 사이트 이름·경로·바인딩 구별하기

### 연습 조건

| 항목 | 지정값 |
|---|---|
| 사이트 이름 | `LabWeb` |
| 콘텐츠의 물리 경로 | `C:\inetpub\lab` |
| 프로토콜 | `http` |
| IP 주소 | `192.168.50.10` |
| 포트 | `8080` |
| 호스트 이름 | `www.lab.example` |

IIS 관리자에서 사이트를 추가하고 각 값을 대응되는 칸에 입력합니다. **사이트 이름은 관리용 이름**이고, 호스트 이름은 클라이언트가 요청할 때 사용하는 이름입니다. 바인딩의 IP·포트·호스트 이름 조합이 요청을 어느 사이트에 보낼지 결정합니다. 기존 사이트와 충돌하는 바인딩을 만들지 않습니다.

개인 학습에서는 물리 폴더에 `index.html`을 만들고 필요한 읽기 권한을 부여합니다. 이후 `http://www.lab.example:8080/`에 접속합니다. 호스트 이름 바인딩이 있으므로 IP 주소만 입력한 요청이 같은 사이트로 갈 것이라고 가정하지 않습니다.

진단 순서는 다음과 같습니다.

1. DNS가 `www.lab.example`을 서버 IP로 해석하는지 확인합니다.
2. IIS 사이트가 시작되어 있고 바인딩이 조건과 일치하는지 확인합니다.
3. 요청 포트의 방화벽 규칙과 네트워크 연결을 확인합니다.
4. 물리 경로·기본 문서·파일 읽기 권한을 확인합니다.

DNS 레코드를 추가하는 것은 IIS 사이트를 생성하는 작업이 아닙니다. 반대로 IIS 사이트를 만들어도 DNS 레코드가 자동 생성되지는 않습니다.

## 4. 사용자·그룹·권한 설정

연습 조건을 “로컬 사용자 `labuser`를 만들고 `LabReaders` 그룹에 추가”로 정합니다. 사용자 생성 화면에서 계정 이름·암호·암호 관련 체크박스를 확인하고, 그룹의 구성원 화면에서 `labuser`가 실제로 포함되었는지 확인합니다.

**그룹에 들어가는 것과 폴더 권한을 얻는 것은 다릅니다.** `LabReaders`를 새로 만들었다면 필요한 폴더의 보안 탭에서 그 그룹에 읽기 권한을 부여해야 합니다. 네트워크 공유에 접근할 때는 공유 권한과 NTFS 권한을 모두 검토합니다.

실제 도메인 컨트롤러의 계정 관리는 일반 서버의 로컬 계정 관리와 다릅니다. 화면에 로컬 사용자 도구가 보이지 않을 때 모든 서버에서 똑같은 메뉴가 존재한다고 단정하지 않습니다.

## 5. 서비스: 지금 멈추기와 앞으로 시작하지 않기

`services.msc`에서 서비스의 **표시 이름과 서비스 이름**을 구별합니다. 연습 조건이 “Print Spooler를 중지하고 시작 유형을 사용 안 함으로 변경”이라면 다음 두 상태를 모두 확인합니다.

- 현재 서비스 상태: 중지됨
- 시작 유형: 사용 안 함

시작 유형만 바꾸어도 이미 실행 중인 서비스가 즉시 중지되는 것은 아닙니다. 반대로 중지 버튼만 누르면 다음 부팅이나 요청에 의해 다시 시작될 수 있습니다. 의존 서비스와 인쇄 기능에 영향이 있으므로 개인 학습에서는 가상 머신에서만 수행하고 원래 상태를 기록해 복구합니다.

## 핵심 정리

- DHCP 풀·제외·예약·옵션은 서로 다른 객체입니다.
- DNS의 A는 이름과 IPv4 주소, CNAME은 이름과 다른 이름을 연결합니다.
- IIS 바인딩과 DNS 레코드는 따로 설정하고 검증합니다.
- 계정 생성·그룹 소속·파일 권한은 각각 확인합니다.
- 서비스의 실행 상태와 시작 유형은 별개입니다.
